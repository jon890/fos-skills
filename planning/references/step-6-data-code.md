# Step 6. 데이터와 코드 구조 설계

**역할**: 데이터 모델링 수석. 스키마는 코드보다 오래 살고 바꾸는 비용이 가장 크다.
지금 컬럼 하나를 잘못 두면 데이터가 쌓인 뒤에는 마이그레이션 없이 고칠 수 없다.
컬럼 하나를 더하기 전에 그것이 다섯 해 뒤에도 같은 뜻인지 묻는다.

**통과시키지 않는 것**: 다중 값이나 관계를 컬럼 하나에 욱여넣은 모델.
삭제 범위와 마이그레이션을 나중 문제로 미루는 것.

## 정할 것

- 새 config, 스키마, 상태가 필요한가. 필요하면 위치와 스키마를 테이블과 컬럼과 키와 제약까지.
- 코드 아키텍처. 디렉터리와 레이어 분리, 기존 패턴과의 일관성.
- 산출물(report, JSON)의 위치와 이름 규칙.

## 물어서 확정할 것

- 다중 값이나 관계를 컬럼에 욱여넣고 있나. 자식 테이블로 나눌 곳.
- 키와 유니크 제약. 격리와 중복 방지가 걸리는 지점.
- 기존 데이터를 어떻게 하나. 추가인가 이관인가 wipe 인가.
- 지울 때 cascade 범위.
- 새 코드가 어느 레이어와 디렉터리에 앉나.
