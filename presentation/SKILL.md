# presentation

**이 문서의 `scripts/`, `references/`, `assets/` 는 이 스킬 번들 기준 상대경로다.**
하네스가 알려주는 스킬 base 디렉터리에 붙여 쓴다. 설치 위치를 가정하지 않는다.

발표 자료를 HTML 한 파일로 만든다. 슬라이드 도구를 쓰지 않는 이유는 셋이다.
장 구성을 명령으로 검사할 수 있고, 발표자 노트를 발표 중에 고칠 수 있고, git 으로 차이를 볼 수 있다.

## 시작하기 전에 인터뷰한다

**덱을 짜기 전에 아래를 정한다. 한 번에 몰아 묻지 않고 하나씩 묻는다.**
정하지 않고 시작하면 장을 만든 뒤에 방향이 바뀌어 전부 다시 쓴다. 실제로 그렇게 됐다.

| 물을 것 | 왜 필요한가 |
| --- | --- |
| 발표 성격 | 방법 공유인가, 결과 보고인가, 기술 설명인가. 장의 구성이 여기서 갈린다 |
| 청중이 놀랄 한 지점 | 이 한 문장이 모든 장의 채택 기준이 된다 |
| AI 나 도구를 어떻게 드러내나 | 프롬프트를 각 장에 분산할지, 정리 장에 모을지 |
| 시간과 질문 시점 | 장 수와 스크립트 분량을 여기서 역산한다 |
| 데모 여부 | 라이브, 녹화, 자료 안 재현 중 무엇인가 |
| 부 구성 | 몇 부로 나누고 각 부가 무엇을 말하는가 |

정한 것은 그 자리에서 짧게 적어 두고 판정에 쓴다. 별도 기준 문서를 만들 필요는 없다.

## 파일

이름은 `<YYYYMMDD>_<이름>_<주제>.html` 로 한다. 예: `20260831_홍길동_메모리누수.html`

발표 자료는 기본적으로 저장소에 커밋하지 않는다. 발표가 끝나면 저장소 밖으로 옮긴다.
사내 식별자와 내부 구현이 섞이기 쉬워 공개 저장소에 남기면 위험하다.
커밋하려면 사용자에게 먼저 확인한다.

## 만드는 순서

1. **인터뷰**로 위 여섯 가지를 정한다.
2. `assets/deck-template.html` 을 위 이름으로 복사한다. 골격과 컴포넌트가 다 들어 있다.
3. 부 전환 장과 목차를 먼저 만든다. 전체 흐름이 여기서 정해진다.
4. 장을 채운다. 한 장에 주장 하나다.
5. 장마다 발표자 노트를 함께 쓴다. 화면 본문은 최소로 두고 말할 내용은 노트로 내린다.
6. `python3 scripts/check-deck.py <파일> --browser` 로 검사한다.
7. `references/slide-rules.md` 로 덱 전체를 훑는다.

경로는 절대 경로로 쓴다. 덱은 저장소 밖에서 만들므로 상대 경로는 그 디렉터리를 가리켜
없는 파일이 된다. 스킬 설치 경로가 다르면 그 경로의 `assets/`·`scripts/` 를 쓴다.

캡처는 `data:image/png;base64,` 로 파일 안에 박는다. 외부 파일에 의존하면 다른 기기에서 깨진다.

## 고칠 때

발표 준비는 수정이 수십 번 반복된다. 그래서 고치는 방식 자체에 규칙이 필요하다.

- **단건 수정으로 그치지 않는다.** 한 장에서 지적을 받으면 같은 문제가 다른 장에도 있다고 보고 전체를 훑는다.
- **지적을 받은 뒤 그것을 규칙으로 올릴지 묻는다.** 규칙이 되면 다음 훑기에서 자동으로 걸린다.
  올리지 않기로 한 것도 그 자리에서 정하고 넘어간다.
- **사용자가 확정한 장은 고치지 않는다.** 명시적으로 풀어 줄 때만 손댄다.
  규칙과 어긋나 보이면 모아서 보고한다. 본문과 스크립트 둘 다 대상이다.
- **본문을 고치면 그 장의 스크립트도 같이 고친다.** 스크립트가 없는 화면을 가리키면 발표 중에 막힌다.
- **장을 빼면 앞 장의 스크립트를 함께 본다.** 「뒤에서 다시 돌아옵니다」 가 없는 장을 가리키게 된다.

## 시간

리허설로 실제 속도를 잰다. 추정하지 않는다.

`S` 를 눌러 한 장의 스크립트를 소리 내어 읽고 초를 잰다. 글자 수를 그 시간으로 나누면 분당 글자 수가 나온다.
그 값으로 전체 스크립트 글자 수를 나누면 실제 소요 시간이다.

분량이 넘치면 장을 빼는 것이 먼저다. 스크립트만 줄이면 화면과 말이 어긋난다.

## 참조

| 파일 | 언제 읽나 |
| --- | --- |
| `references/slide-rules.md` | 장을 만들 때와 전체를 훑을 때. 판정 가능한 규칙 목록이다 |
| `references/deck-mechanics.md` | 골격을 손볼 때. 조작키, 컴포넌트, 애니메이션, 편집 함정이다 |

언어 규칙은 `~/.claude/rules/korean-style.md` 와 `writing-structure.md` 가 소유한다.
`slide-rules.md` 는 그 위에 얹히는 발표 고유 판정만 담는다.
