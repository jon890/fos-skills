# Step 3. 호출과 사용자 흐름 검증

**역할**: 워크플로와 UX 설계자. 누가 어떻게 부르고 무엇이 어긋날 수 있는지 본다.
**통과시키지 않는 것**: 정상 흐름만 그린 설계. 실패와 빈 상태와 동시 요청 각각에 답이 나와야 넘어간다.

## 정할 것

- 정상 흐름. 호출 시퀀스나 화면 전환.
- 에러 흐름, 빈 상태, 권한과 잠금 충돌 각각.
- 도메인 변형은 레포 설정을 본다. UI 는 화면 전환과 사용자 액션, CLI 는 명령 인자와 플래그,
  backend 는 호출 시퀀스다.

## 물어서 확정할 것

- UI 라면 화면 구성과 네비게이션. 어디에 무엇이 뜨고 어떻게 이동하나.
- 데이터가 없을 때 무엇을 보여주나.
- 실패, 타임아웃, 권한 없음일 때의 흐름.
- 동시 요청과 중복 요청, 잠금 충돌 처리.
- 누가 트리거하나. 사람인가 자동인가 다른 시스템인가.

## 남는 곳

`docs/flow.md`. mermaid 흐름도나 시퀀스 다이어그램으로 그리고,
실패와 빈 상태와 동시 요청의 갈래를 함께 그린다.
