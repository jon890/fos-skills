# build-to-learn

회사에서 겪을 수 없는 판단을 모의로 훈련해, 가설을 세우고 재서 결정하는 능력을 기른다.

## 왜 필요한가

한 회사에서 쌓는 경험에는 그 회사가 다루는 문제의 범위가 있다.
그 밖의 판단은 겪을 기회가 없어 자료로만 알게 되고, 자료로 아는 것은 상황에서 쓰이지 않는다.

실패해야 배우는 것이 특히 그렇다. 실서비스에서는 일부러 실패할 수 없다.

## 무엇을 하는가

**계획 도구가 아니라 함께 배우는 상대다.**
답을 먼저 주지 않고, 사용자가 가설을 세우면 반박하고, 검증을 함께 설계한다.

| 단계 | 하는 일 |
| --- | --- |
| 1 | 회사에서 겪을 수 없는 것을 고른다 |
| 2 | 핵심 역할, 결정 기준, 트레이드오프 측정 셋으로 주제를 연다 |
| 3 | 계층으로 펼치고 각 계층에 멈추는 조건을 붙인다 |
| 4 | 자료를 갈래로 나눠 병렬로 모은다 |
| 5 | 실습 저장소를 설계한다 |
| 6 | 가설을 세우고 함께 검증한다 |
| 7 | 의사결정을 훈련한다 |
| 8 | 공개 학습 시리즈를 설계한다 |

6번이 본체이고 나머지는 그것을 할 수 있게 만드는 준비다.

## 만들지 않는 것

실습 저장소와 공개 학습 저장소는 별도 저장소라 이 스킬이 쓰지 않는다.
설계가 서면 각 저장소 세션으로 넘기고, 검증 루프는 이 세션이 계속 함께 돈다.
