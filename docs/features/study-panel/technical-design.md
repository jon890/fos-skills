# 공부·피드백 패널 기술 설계

fosbot이 화면에 필요한 요약을 파일 하나로 내보낸다. Orca 패널은 파일이 바뀌면 화면을 갱신하고, 버튼에서 받은 답은 대기열을 통해 fosbot으로 보낸다. 후보와 PR 상태를 바꾸는 일은 fosbot이 맡는다.

## 요구사항 연결

| ID | 해결 방법 |
| --- | --- |
| REQ1 | worker가 버전이 있는 요약을 검증하고 파일 교체를 감시한다. 패널은 마지막 정리 시각과 읽기 상태를 표시한다. |
| REQ2 | 공부 후보, 피드백 묶음, 기각·보류 수를 요약에 넣는다. 각 카드의 버튼은 후보 종류에 따라 정해진 답을 보낸다. |
| REQ3 | fosbot은 답을 처리하거나 PR 상태가 바뀔 때 진행 목록을 갱신한다. 머지·닫힘을 확인한 PR은 목록에서 뺀다. |
| REQ4 | fosbot이 요약에 저장소별 개수를 넣는다. 패널은 각 저장소의 원본 후보를 조회하지 않는다. |
| REQ5 | worker가 요청을 발행한 뒤 카드를 잠그고, 후보별 변경 번호나 10분 경과로 잠금을 푼다. 같은 버튼의 전송은 60초 동안 한 번만 허용한다. |
| REQ6 | 패널과 worker가 이유를 확인한다. 대기열 쓰기·자동화 호출 실패는 worker가 반환하고, fosbot의 처리 오류는 다음 요약에 표시한다. |
| REQ7 | 주 체크아웃의 폴더에서 설치하고 같은 폴더에서 코드만 바꿔 다시 설치한다. 권한 추가는 별도로 승인을 확인한다. |

## 책임과 경계

| 담당 | 읽고 쓰는 데이터와 호출 |
| --- | --- |
| fosbot | 기존 공부·피드백 후보, Orca 항목의 질문과 답, 작업·PR 상태를 확인한다. 후보와 답을 기록하고 패널용 요약을 발행한다. |
| worker | 로컬 요약을 읽고 감시한다. 패널 요청을 검증하고 대기열에 JSON을 쓴 뒤 자동화를 깨운다. 봇 상태를 직접 바꾸지 않는다. |
| 패널 | 시제품의 요약 숫자와 「오늘의 공부」, 「스킬 피드백」, 「저장소별」 탭을 Orca 컴포넌트로 그린다. worker가 보내는 화면 상태를 표시하고 버튼과 이유 입력을 받는다. |

공부와 피드백의 원본 상태는 기존 [공부 후보](../../../skills/orch/references/study-candidates.md)와 [피드백 검토](../../../skills/orch/references/feedback-review.md) 규칙을 따른다. 반영 요청을 받는 저장소도 [ADR-035](../../adr/035-orch-main-coordinator.md)의 메인 코디네이터 규칙을 따른다. 패널은 두 흐름의 결과를 읽기 편한 형태로 받아 그린다.

플러그인 루트는 `extensions/study-feedback-panel/`이다. [확장 기능 배치 결정](../../adr/022-extension-directory-layout.md)의 디렉터리 관례를 따르고, Orca 배포는 루트의 `orca-plugin.json`으로 관리한다. `orca plugin create --template worker-panel`이 만드는 구조를 출발점으로 쓴다. `src/panel.tsx`에 뷰, `src/worker.ts`에 호스트 연결, `src/protocol.ts`에 패널과 worker가 공유하는 요청·응답 타입을 둔다. JSON 읽기와 전송 규칙은 Orca 모듈을 불러오지 않는 TypeScript에 둔다. 배포 단위는 [기여 안내](../../contributing.md)의 `extensions/` 규칙을 따른다. [Orca 플러그인 작성 안내](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-authoring.md)

`trusted-worker`가 Node 파일 API와 로컬 Orca CLI를 사용한다. 매니페스트 권한은 설정 조회용 `settings:own`과 마지막 정상 요약·전송 기록용 `storage:own`이다. Orca 설정에서 `botHome`(fosbot 홈 절대 경로), `panelAutomationId`(전용 자동화의 전체 UUID)를 받는다. Orca 앱에서 실행한 worker의 PATH에 CLI가 없으면 같은 설정의 `orcaExecutable`에 실행 파일의 절대 경로를 지정한다. 패널에서 파일 경로나 명령을 받는 인터페이스는 두지 않는다. [Orca 호스트 API](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-host-api.md)

## 인터페이스와 데이터

### 요약 파일

경로는 `<botHome>/state/study-panel-summary.json`이다. UTF-8 JSON 객체 하나를 매번 전체 교체한다. 시각은 시간대 오프셋이 있는 ISO 8601 문자열이다. 아래 필드는 모두 필수다. 개수가 없으면 0, 목록이 비면 `[]`, 아직 없는 값은 표에 적힌 곳에서 `null`을 쓴다.

| 필드 | 의미 |
| --- | --- |
| `schemaVersion` | 정수 `1`. 읽는 쪽이 지원하지 않는 버전은 형식 버전 불일치로 표시한다. |
| `curatedAt` | 마지막으로 일일 정리를 끝낸 시각. 첫 정리 전에는 `null`이다. |
| `updatedAt` | 이 요약을 발행한 시각. 버튼 답이나 PR 상태만 바뀌어도 갱신한다. |
| `study` | 오늘의 공부 카드 배열. 공통 필드와 `question`(핵심 질문), `outline`(개요 줄 배열), `sources`(각각 `label`, 선택 `url`), `repoIds`(합친 원본이 있는 저장소 ID 배열)를 갖는다. |
| `feedback` | 오늘의 피드백 묶음 배열. 공통 필드와 `number`(화면에 보이는 양의 정수), `skill`(스킬 이름), `candidates`(각각 `id`, `title`, `repoId`)를 갖는다. |
| `feedbackTotals` | 이번 일일 정리에서 fosbot이 이미 처리한 `rejected`, `held`의 수. 답·PR 사건으로 다시 발행할 때 같은 정리의 수를 유지한다. |
| `inProgress` | `item`, `title`, `activity`(`writing` 또는 `applying`), `repoId`(작업 또는 PR의 저장소), `pr`을 갖는 배열. PR이 생기기 전에는 `pr: null`, 열린 뒤에는 `{ number, state: "open", draft }`를 쓴다. 번호는 양의 정수, `draft`는 불리언이다. |
| `repositories` | `{ id, name, studyCount, feedbackCount }` 배열. 개수는 일일 정리에서 집계하는 저장소별 열린 후보 수를 최신 원본 상태로 갱신한 값이다. 같은 이름의 저장소도 `id`로 구분한다. 이 목록에는 진행 목록에서만 참조하는 저장소도 넣는다. |

공부 카드와 피드백 묶음의 공통 필드는 `id`, `title`, `round`, `revision`, `state`, `error`다.

- `id`는 fosbot이 부여하고 기억하는 문자열이다. 같은 후보가 여러 날에 걸쳐 보이거나 같은 피드백 묶음이 다시 발행돼도 유지한다. 제목, 화면 순서, 피드백 번호로 답을 찾지 않는다. 합친 공부 후보는 대표 하나에 원본 목록을 연결한다.
- `round`는 같은 후보의 몇 번째 선택인지 나타내는 양의 정수다. 답을 기다리는 동안에는 정리 날짜가 바뀌어도 유지한다. 이미 답한 후보를 기존 규칙에 따라 다시 올릴 때만 증가한다. 예를 들어 「나중에」를 골라 14일 후 돌아온 후보는 같은 ID로 새 답을 받을 수 있다.
- `revision`은 카드마다 증가하는 양의 정수다. `round`, 선택 가능 상태, 처리 오류, 선택 대상이 되는 원본의 구성이 바뀌면 올린다. 같은 내용으로 요약 전체를 다시 써도 유지한다.
- `state`는 `selectable`(선택 가능) 또는 `recorded`(답이 이미 기록됨)다. `error`에는 `null`이나 `{ code, message }`를 쓴다. `message`는 화면에 보일 한 줄 설명이다. 답을 기록하기 전에 실패했으면 선택 가능 카드에 오류를 표시하고, 기록 뒤 실패했으면 기록 상태를 유지하면서 오류를 표시한다. 종료된 카드는 기존 정리 규칙에 따라 목록에서 빠질 수 있다.
- 모든 개수는 음이 아닌 정수다. 후속 버전에서 필드를 추가할 때 버전 1의 의미를 유지하면 소비자는 모르는 필드를 무시한다. 필수 필드의 형식이나 의미가 바뀌면 버전을 올린다.

### 버튼 메시지와 자동화

대기열은 `<botHome>/inbox-study-panel/`이다. 기존 AI 비서 패널에서 확인한 JSON 파일명 규칙과 `orca automations run` 호출을 따른다. AI 비서 패널은 자체 `inbox-panel/`과 「AI 비서 패널 요청」 자동화를 사용한다. 두 자동화는 같은 봇에서 실행되지만 각자 다른 대기열과 프롬프트를 쓴다. 공부·피드백 패널의 전용 자동화는 「공부·피드백 패널 요청」이다. 평일 09:00 일일 정리 자동화도 그대로 둔다.

파일명은 `<sentAt에서 콜론과 마침표를 하이픈으로 바꾼 값>-<requestId>.json`이다. `sentAt`은 worker가 정한 UTC ISO 8601 시각, `requestId`는 요청마다 생성한 UUID다. `item`에는 요약의 카드 `id`를 넣고 `round`에는 그 카드의 선택 회차를 넣는다. 화면 번호와 Orca 항목 번호는 화면 표시와 항목 조회에만 사용한다.

| `action` | `answer` | 화면 버튼 | `reason` |
| --- | --- | --- | --- |
| `choose_study_candidate` | `write` | 글로 쓰기 | 생략 |
| `choose_study_candidate` | `later` | 나중에 | 생략 |
| `choose_study_candidate` | `drop` | 빼기 | 한 줄 필수 |
| `choose_feedback_bundle` | `apply` | 반영 | 생략 |
| `choose_feedback_bundle` | `hold` | 보류 | 한 줄 필수 |
| `choose_feedback_bundle` | `reject` | 기각 | 한 줄 필수 |

공부 후보를 빼면 다음 요청을 쓴다.

```json
{
  "action": "choose_study_candidate",
  "item": "study-example",
  "round": 1,
  "answer": "drop",
  "reason": "기존 글과 주제가 겹침",
  "sentAt": "2026-11-26T01:12:00.000Z",
  "requestId": "0cd523ca-fe1c-48a6-aa32-ce1eea9ebe53"
}
```

필수 이유는 앞뒤 공백을 뗀 뒤 비어 있거나 개행을 포함하면 거절한다. 패널과 fosbot은 제목, 출처, 이유 같은 문자열을 데이터로 처리한다. 정해진 답만 해당 동작에 연결한다.

### 패널과 worker

패널이 열리면 `studyPanel.changed`를 먼저 구독하고 `studyPanel.get`으로 현재 화면 상태를 요청한다. 이벤트와 응답은 worker의 화면 갱신 순번을 포함한다. 패널은 늦게 도착한 이전 응답을 무시한다. 화면 상태에는 검증된 요약, 파일 상태, 카드별 전송 시각과 잠금이 들어간다.

`studyPanel.choose({ item, revision, action, answer, reason? })`는 이 패널에서 호출한다. worker는 최신 파일을 다시 읽고, 카드와 변경 번호, 선택 가능 여부, 답과 이유를 확인한 뒤 전송한다. 이미 바뀐 카드에는 현재 화면 상태를 반환한다. 성공 응답은 `sentAt`을 반환한다. 대기열 쓰기와 봇 깨우기의 실패는 각각 `queue_write_failed`, `wake_failed`로 반환한다.

worker는 파일을 바꿔치기해도 이벤트를 받을 수 있도록 `state/`의 디렉터리를 감시한다. 대상 파일 이름의 이벤트만 반영하고, 파일명이 없는 이벤트는 다시 읽어 확인한다. 디렉터리가 아직 없다면 가장 가까운 상위 디렉터리에서 생성을 감지해 감시를 다시 건다. 이벤트를 놓쳤거나 감시 오류가 난 경우 패널이 열릴 때와 주기적 재확인 때 복구한다. worker가 종료되면 감시와 타이머를 해제한다.

## 실패와 일관성

- 파일 없음과 지원하지 않는 버전은 각각 표시하고 버튼을 끈다. 버전을 읽을 수 있으면 파일에서 검증된 `curatedAt`을, 없으면 마지막 정상 요약의 시각을 쓴다. 둘 다 없으면 마지막 정리 기록이 없다고 표시한다. 파싱·필수 필드 검증·읽기 실패 시 마지막 정상 요약을 유지하고 「읽기 실패」를 표시한다. 최신 후보를 확인할 수 없으면 전송을 거절한다.
- `curatedAt`에서 평일 하루가 지나는 시각을 Asia/Seoul 기준으로 계산한다. 토요일과 일요일은 경과 시간에서 빼고, 평일 하루를 넘으면 「오래됨」을 표시한다. 금요일 09:00에 정리했다면 월요일 09:00을 넘긴 뒤 표시한다. 파일이 바뀌지 않아도 시간 경계에서 화면을 갱신한다.
- worker는 카드마다 전송을 직렬화한다. 전송 성공 시 `id`, `revision`, 답과 시각을 플러그인 저장소에 기록한다. 여러 패널이나 패널을 다시 열어도 같은 전송 기록을 쓴다. `action`·`item`·`answer`가 같은 성공 전송은 60초 동안 억제한다. 실패는 이 시간에 넣지 않는다. 유효한 새 요약에서 카드가 없어지거나 `revision`이 달라지면 「보냄 hh:mm」 잠금을 푼다. 같은 카드에 다른 변화가 없으면 10분 뒤 「처리 대기」로 바꾼다. 이후 선택 가능 여부는 최신 카드 상태를 따른다.
- worker는 권한 `0700`인 대기열 안의 `.staging/`에 권한 `0600`으로 요청을 쓴 뒤 `orca automations run <panelAutomationId> --json`을 실행한다. 셸 없이 인자 배열로 호출한다. 기존 AI 비서 worker처럼 상속된 `ORCA_*` 환경 변수를 빼서 로컬 앱을 대상으로 호출한다. 종료 코드와 JSON의 `ok`로 접수를 확인하며, Orca가 실행을 대기열에 넣었으면 접수 성공으로 본다.
- 깨우기에 실패하면 준비 파일을 지운다. 깨우기가 접수된 뒤에만 같은 파일시스템에서 `rename`으로 대기열 최상위에 공개한다. 이 순서면 이미 실행 중인 봇이 깨우기에 실패한 요청을 먼저 가져가는 일이 없다. 공개가 실패하면 준비 파일을 지우고 대기열 쓰기 실패로 알린다. 파일을 공개하기 전에 worker가 죽어도 준비 파일은 처리 대상이 되지 않는다.
- 요약은 fosbot이 같은 디렉터리의 임시 파일에 쓴 뒤 `rename`으로 교체한다. 여러 계기가 겹치면 한 쓰기 경로에서 최신 상태를 읽어 요약을 발행한다. 늦게 끝난 PR 조회가 더 새로운 결정이나 진행 상태를 덮어쓰지 않게 한다.

| 맡을 일 | 계약 |
| --- | --- |
| 요약 발행 | 첫 정리와 이후 평일 09:00 정리가 끝날 때 `curatedAt`을 갱신해 전체 요약을 쓴다. 새 후보가 없는 날도 파일을 쓴다. 답을 처리하거나 오류가 생길 때, 추적 중인 PR이 열리거나 상태가 바뀔 때, 머지·닫힘을 확인했을 때는 `curatedAt`을 보존하고 `updatedAt`을 갱신한다. PR은 작업 보고·PR 사건이 들어오는 경로에서 갱신하고, 일일 정리 때 누락된 사건을 대조한다. |
| 대상 연결 | 요약의 카드 ID와 회차를 원본 후보들과 해당 Orca 항목·질문에 연결해 내부 상태에 보관한다. 패널·항목 버튼·채팅 답은 같은 기록 단계를 거친다. 카드 ID와 회차가 현재 선택과 맞는지 확인한 뒤 같은 회차에서 먼저 기록한 답만 후속 처리를 시작한다. 지난 회차나 이미 답한 회차로 온 요청은 그 상태를 사용자에게 알린다. |
| 자동화 | fosbot Home 채팅에서 「공부·피드백 패널 요청」이 실행되도록 등록하고 전체 ID를 설치 담당자에게 전달한다. 예약 실행은 기존 AI 비서 패널처럼 10분 간격 precheck로 최상위 `*.json`이 있을 때만 실행한다. 버튼의 수동 실행은 precheck를 건너뛴다. 먼저 실행된 봇이 준비 중인 파일을 발견하면 발행 또는 삭제까지 제한 시간 안에서 다시 확인한다. CLI 제한 시간은 30초, 봇의 재확인 범위는 60초다. 준비 파일 본문은 소비하지 않으며 10분 넘게 남은 준비 파일은 지운다. |
| 대기열 가져오기 | 최상위 JSON만 파일명 순서로 읽고 `processing/`으로 원자적으로 옮겨 잡는다. 알려진 `action`·`answer` 조합과 이유, 파일명과 본문의 요청 ID를 검증한다. 처리 결과를 기록한 파일은 `processed/`로 옮긴다. 가져온 시각부터 10분이 지난 파일을 다시 볼 때는 요청의 기록 여부와 처리 중인 실행의 생존을 확인한다. 처리된 파일은 7일 뒤 삭제한다. |
| 중복과 장애 복구 | 같은 `requestId` 재처리와 다른 경로의 동시 응답을 각각 확인한다. 진행 중인 답의 기록과 후속 요청 번호를 보관한다. 중간에 끊겼으면 기존 작업이나 PR을 먼저 찾은 뒤 같은 답의 나머지 처리를 이어 간다. 상태를 확인할 수 없으면 중복 작업을 띄우지 않고 요약에 처리 오류를 기록한다. |
| 기존 답 처리 | 공부 「나중에」는 기존 14일 규칙, 「빼기」는 연결된 원본 후보와 이유 기록을 따른다. 반영·보류·기각은 기존 피드백 처리와 메인 코디네이터 경로를 쓴다. 공개 글로 넘기기 전의 비공개 정보 확인은 기존 절차에서 계속 맡는다. |

## 검증 전략

| 로컬 Orca와 fosbot | 테스트 후보로 패널·항목 버튼·채팅에서 답이 경합할 때 한 번만 처리되는지 확인한다. 답 처리 직후와 PR 열림·머지·닫힘 뒤 요약과 화면이 함께 바뀌는지 본다. 설치와 권한 확인 결과를 구현 PR에 적는다. |

### 설치와 재설치

1. fosbot 쪽에서 요약 파일 버전 1과 전용 자동화를 먼저 준비한다.
2. fos-skills 주 체크아웃에서 `orca plugin install ./extensions/study-feedback-panel`을 실행한다. 첫 설치에서 Orca가 출력한 접근 범위를 확인하고, 사용자가 승인한 뒤 출력에 나온 `--approve <fingerprint>`를 붙여 설치한다.
3. Orca 플러그인 설정에 `botHome`과 `panelAutomationId`를 넣고 사이드바를 연다. worker가 Orca CLI를 찾지 못하면 `orcaExecutable`을 지정한다.
4. `git pull`로 소스를 갱신하고 같은 체크아웃 폴더의 설치본에 `orca plugin update local.study-feedback-panel`을 실행한다. 폴더 재복사와 승인 재사용은 `orca plugin update --help`의 동작을 따른다. 로컬에서 코드만 바꾼 재설치는 승인 없이 반영되고, 새 권한을 추가한 재설치는 새 승인 없이는 적용되지 않는지 확인한다. 검증 PR에는 Orca 버전, 실행 명령, 종료 상태와 화면 확인 결과를 남긴다.
