# browser

CLI 나 API 로 안 되는 웹 작업을 「사람이 직접 해 주세요」 로 돌려받는 수고를 덜어 준다.
에이전트가 `browser-driver` 로 브라우저를 직접 조작하고, 사용자는 로그인과 되돌리기 어려운 버튼의 확인만 한다.
작업마다 브라우저 공간을 따로 열고 끝나면 닫아서 다른 에이전트의 탭과 섞이지 않는다.

## 이럴 때 쓴다

- 웹 콘솔에서만 만들 수 있는 설정(배포 시나리오, 보안 그룹 같은 것)을 대신 만들게 하고 싶다
- 웹 화면에 실제로 어떻게 보이는지 확인하고 싶다
- 신청 양식처럼 화면으로만 되는 작업을 맡기고 싶다

「브라우저로 해 줘」, 「콘솔에서 만들어 줘」, 「웹 화면에서 확인해 줘」, 「CLI 나 API 로 안 되는 작업이야」 처럼 말하면 이 스킬이 뜬다.
브라우저를 말하지 않아도, 에이전트가 웹 화면에서만 되는 일을 사람에게 넘기려 할 때 이 스킬로 할 수 있는지 먼저 본다.

## 사용 예시

```text
나:   테스트 서버에 배포할 시나리오를 콘솔에서 만들어 줘

스킬: (CLI 와 API 로 시나리오를 만들 수 있는지 먼저 보고, 안 되면 오버레이의 화면 순서대로 콘솔을 연다)
      로그인 화면에서 멈췄어요. ego 브라우저의 「my-repo feat-x 시나리오 생성」 공간에서 로그인해 주세요.

나:   로그인했어

스킬: (시나리오를 만들고 목록에 새 항목이 보이는지 확인한 뒤 공간을 닫는다)
      시나리오를 만들었어요. 새로 안 화면 순서는 .claude/browser-overlay.md 에 더했어요.
```

## 받는 것

- 브라우저로 끝낸 작업과, 그 결과를 화면에서 다시 읽어 확인한 근거
- 브라우저로 간 이유 한 줄. CLI 나 API 로 되는 일이면 브라우저를 쓰지 않고 그 길로 간다
- 갱신된 저장소 오버레이(`.claude/browser-overlay.md`). 다음 작업이 같은 화면을 바로 따라간다

로그인은 사용자가 직접 한다. 결제, 삭제, 권한 변경처럼 되돌리기 어려운 버튼은 누르기 전에 묻는다.

## 준비

`browser-driver` 와 그 백엔드(기본은 ego 브라우저)가 있어야 한다.
플러그인으로 설치하면 드라이버는 함께 받는다. `browser-driver doctor` 가 백엔드 준비 상태를 판정한다.
개인 계정 서비스를 쓰려면 설정 파일의 `egoProfiles` 에 `personal` 용도를 적는다. 형식은 [`browser-driver/README.md`](browser-driver/README.md) 의 「로그인 세션과 프로필」 에 있다.
