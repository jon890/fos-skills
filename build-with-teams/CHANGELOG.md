## 2.3.0

code-reviewer 와 docs-verifier 를 순차에서 병렬로 바꿨다.

- **두 검토는 서로의 입력이 아니다.** 이전에는 "code-reviewer PASS 와 review fix 가 끝난 뒤"
  docs-verifier 를 한 번만 돌리게 했고, 근거는 유효한 판정이 최종 HEAD 것뿐이라는 점이었다.

- **대가는 조건부 재검증 한 번**이다. 리뷰 반영이 docs 를 바꿨을 때만 docs-verifier 를 다시 돌린다.
  코드만 바뀌었으면 첫 판정을 그대로 쓴다. 판단 시점을 code-reviewer 판정 수신 직후로 못박았다.
- 1단계의 스폰 시점 서술을 "7·8단계 검사 시점" 에서 "모든 phase 구현이 끝난 검토 시점에 둘을 함께" 로 고쳤다.
- 실행 절차 흐름도를 두 검토가 갈라지는 형태로 바꾸고 재검증 분기를 넣었다.
- 제거한 지시: docs 를 더 일찍 보려면 code-reviewer 지시에 docs 축을 얹으라는 우회.
  병렬이 기본이 되어 우회할 이유가 없어졌다.

## 1.3.0

실행 등급과 저비용 executor 적합성을 분리했다.

- `standard` 등급을 저비용 모델로 일괄 매핑하지 않도록

- critic이 계획 판정과 별개로 phase별 실행 형태를 회신하게 했다.

  실행 중 새로운 판단이 필요하면 `EXECUTOR_ESCALATE`로 중단·승격하게 했다.
- 상세 계약은 `references/executor-routing.md`로 분리해 critic 평가 전과 executor 스폰 직전에 읽도록 했다.
