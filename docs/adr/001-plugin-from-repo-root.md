## ADR-001: 저장소 루트를 플러그인으로 삼고 스킬 디렉터리는 옮기지 않는다

- **status**: `accepted`
- **결정**: 이 저장소가 마켓플레이스 `fos-skills` 와 플러그인 `fos-skills` 를 함께 갖는다.
  플러그인의 소스는 저장소 루트(`./`)다. 스킬 디렉터리는 루트에 그대로 두고 `.claude-plugin/plugin.json` 의 `skills` 배열에 경로를 하나씩 적는다.
  이 저장소의 스킬 일곱 개를 모두 담는다.
- **맥락**: 지금은 `~/.claude/skills/<이름>` 심볼릭 링크로 설치해 쓴다. 개인 프로젝트와 사외 머신에서는 저장소를 clone 하고 링크를 일곱 번 걸어야 한다.
  스킬 디렉터리가 루트에 있다는 사실에 기대는 것이 여럿이다.
  `scripts/export-to-team.sh` 는 `<저장소>/<이름>` 을 원본 경로로 읽고, `hooks/post-commit` 은 커밋이 건드린 최상위 디렉터리 이름으로 공용 스킬을 판정한다.
  `~/.claude/scripts/` 와 `~/.claude/rules/` 의 개인 링크는 스킬 안의 파일을 직접 가리키고, 스킬 문서는 `../korean-check/` 같은 형제 경로로 서로를 가리킨다.
  2026-10-01 에 Claude Code 2.1.286 과 격리된 `CLAUDE_CONFIG_DIR` 로 세 배치를 설치해 보았다.
  세 배치 모두 스킬 일곱 개가 인식되고, 설치 캐시에서 형제 경로가 풀리고, `content-preview` 가 `tools/browser-driver` 를 찾았다.
  루트 배치에서 `skills` 배열을 쓰면 `claude plugin validate` 가 오류 없이 통과했다.
- **대안 기각**:
  - 스킬을 `skills/` 아래로 옮긴다. 관례 배치라 `skills` 배열이 필요 없다. 그러나 내보내기 스크립트의 원본 경로, `post-commit` 의 판정, `~/.claude` 의 개인 링크 열 개, README 의 링크, `harness-cleanup` 의 `../../korean-check` 참조를 함께 고쳐야 한다. 팀 저장소의 플러그인 계획이 전제로 삼은 내보내기 동작도 다시 확인해야 한다.
  - 루트 배치를 두고 `plugin/skills/<이름>` 에 상대 링크를 둔다. 설치할 때 링크가 실제 파일로 복사되어 캐시가 가장 작다. 그러나 `claude plugin validate --strict` 가 링크를 읽지 않았다는 경고로 실패하고, 스킬을 더할 때 링크를 하나 더 만들어야 하는 점은 배열과 같다.
  - `fos-brain` 마켓플레이스에 올린다. 그 마켓플레이스는 `fos-brain` 저장소의 하위 디렉터리를 directory 소스로 등록한 것이다. 사외 머신에서는 `fos-brain` 을 먼저 clone 해야 하고, 다른 저장소의 매니페스트가 이 저장소의 배포를 소유하게 된다.
  - 플러그인 이름을 `fos` 로 줄인다. 부르는 이름은 짧아지지만 저장소, 마켓플레이스, 플러그인의 이름이 서로 달라진다.
  - 개인 용도가 짙은 `harness-cleanup` 을 뺀다. 이 스킬이 가리키는 개인 파일은 `~/.claude/references/skill-structure.md` 한 곳뿐이고 절차는 어느 저장소에나 적용된다. 빼면 그 스킬만 링크 설치로 남아 설치 방식이 둘이 된다.
- **결과**:
  - 얻는 것: 새로 생기는 파일은 `.claude-plugin/` 의 매니페스트 둘뿐이다. 내보내기 스크립트, git 훅, 개인 링크, 스킬 사이의 상대 경로가 그대로 동작한다.
  - 얻는 것: 사외 머신에서는 마켓플레이스 등록과 설치 두 명령으로 일곱 스킬을 받는다.
  - 감당할 것: 스킬을 더하거나 이름을 바꾸면 `skills` 배열을 함께 고쳐야 한다. 빠뜨리면 그 스킬이 플러그인에 실리지 않는다. 매니페스트 시험이 루트의 `SKILL.md` 를 가진 디렉터리 집합과 배열을 대조한다.
  - 감당할 것: 소스가 저장소 루트라 `scripts/`, `hooks/`, `docs/`, `tasks/` 같은 저장소 관리 파일도 설치 캐시에 복사된다. 스킬로 읽히지 않으므로 동작에는 영향이 없다.
  - 감당할 것: 스킬은 `fos-skills:planning` 처럼 접두사가 붙은 이름으로 불린다. 같은 이름의 `~/.claude/skills/<이름>` 링크와 함께 두면 둘 다 목록에 뜬다.
- **적용 범위**: 배치와 모듈 책임은 [code-architecture.md](../code-architecture.md) 가, 설치와 전환의 순서는 [flow.md](../flow.md) 가 소유한다.
