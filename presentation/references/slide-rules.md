# 장을 판정하는 규칙

한 장씩 눈으로 보며 고치면 같은 지적이 반복된다.
판정 가능한 문장으로 적어 두고 덱 전체를 이 목록으로 훑는다.

## 내용

| 규칙 | 판정 |
| --- | --- |
| 한 장에 주장 하나만 둔다 | 제목이 말하는 것과 본문이 보여 주는 것이 하나로 맞는가 |
| 여러 단계를 다루면 제목이 전체를 덮는다 | 첫 단계만 말하는 제목이 아닌가 |
| 부가 숫자와 각주를 넣지 않는다 | 그 값이 없으면 주장이 성립하지 않는가. 아니면 뺀다 |
| 결론 수치를 조치 항목에 섞지 않는다 | 「무엇을 했나」 와 「무엇이 바뀌었나」 를 나눠 적었는가 |
| 결과 칸에는 바뀐 것을 먼저 쓴다 | 한계가 첫 문장에 오지 않았는가. 조치가 무엇을 이뤘는지 먼저 말했는가 |
| 캡처가 뒷받침하지 않는 주장을 제목에 쓰지 않는다 | 제목의 사실이 그 장의 캡처에 실제로 보이는가 |
| 근거 없는 숫자를 쓰지 않는다 | git, PR, ADR, 업무 기록 중 하나로 짚을 수 있는가 |
| 시점이 다른 숫자는 시점을 함께 적는다 | 조치 전과 조치 후를 섞지 않았는가 |
| 숫자의 단위를 밝힌다 | 파일 수인지 요청 수인지 건수인지 구분했는가. 언제 어떻게 센 값인지 적었는가 |
| 사내 시스템은 이름과 역할만 쓴다 | 내부 구현을 설명하지 않았는가. 청중이 알 필요가 없고 노출 위험도 있다 |
| 청중이 모르는 도구 이름을 설명 없이 쓰지 않는다 | 그 이름이 빠져도 문장이 성립하면 뺀다 |

## 형태

| 규칙 | 판정 |
| --- | --- |
| 박스로 감싸는 형태를 남용하지 않는다 | 규칙선과 좌우 대비로 대신할 수 있는가 |
| 항목이 셋 이하면 세로로 늘어놓는다 | 가로 배치가 정보를 더하는가 |
| 숫자는 한 장에 둘까지 둔다 | 셋째 숫자가 앞 둘의 파생값이면 뺀다 |
| 세로 넘침이 없어야 한다 | `check-deck.py --browser` 가 통과하는가 |
| 애니메이션 블록은 높이를 고정한다 | 재생 중 아래 내용이 밀려 내려가지 않는가 |

## 제목

| 규칙 | 판정 |
| --- | --- |
| 무엇이 일어났는지, 무엇을 만들었는지 그대로 쓴다 | 문장을 읽고 청중이 무슨 일인지 아는가 |
| 비유로 사실을 대체하지 않는다 | `재시작이 끝나지 않았다` 는 AI 어투로 읽힌다 |
| 지시어를 제목에 쓰지 않는다 | `이 순서`, `그때` 처럼 앞에서 받을 것이 없는 말이 없는가 |
| 문장형을 금지하지는 않는다 | 사실을 담은 문장이면 문장형으로 둔다 |
| 기능만 하는 장은 명사구 이름표로 둔다 | 목차와 부 전환이 여기 해당한다 |
| `data-title` 을 제목과 함께 고친다 | 개요 판에 뜨는 이름이 제목과 어긋나지 않는가 |

## 프롬프트

| 규칙 | 판정 |
| --- | --- |
| 프롬프트는 대화로 보여 준다 | 내 지시, AI 답, 내 되물음 순으로 읽히는가 |
| 내 프롬프트는 원문을 쓴다 | 명백한 오타만 고쳤는가. 말투와 구어체를 남겼는가 |
| 원문이 스스로 상충하면 고쳐 쓴다 | 고쳤으면 화면에 `재현` 이라고 표시했는가 |
| AI 쪽 발언은 그날 산출물에서 인용한다 | ADR, PR 본문, plan 파일 중 하나에서 왔는가. 출처를 밝혔는가 |
| 질문만 두지 않는다 | 그 질문이 무엇을 밝혀냈고 무엇이 바뀌었는지까지 그 장에 있는가 |
| 「실제로 쓴 프롬프트」 전용 장을 두지 않는다 | 프롬프트를 모아 두면 그 대목을 지나간 뒤에 나온다 |
| 결과에는 무엇으로 검증했는지 함께 적는다 | 「좋아졌다」 로 끝내지 않았는가 |

원문 출처는 `~/.claude/history.jsonl` 이다. 사람이 입력한 프롬프트가 전량 남는다.
`~/.claude/projects/**` 의 세션 기록은 최근 것만 남아 AI 답까지 찾으려면 그날 산출물을 뒤져야 한다.

## AI 를 드러내는 방식

| 규칙 | 판정 |
| --- | --- |
| 도구를 만든 이야기로 끝내지 않는다 | 그 도구가 AI 와 무엇을 같이 하게 만들었는지가 있는가 |
| 지표는 AI 와 볼 화면으로 설명한다 | 「내가 보려고 붙였다」 가 아니라 「AI 와 같이 볼 값을 만들었다」 로 읽히는가 |
| 프롬프트는 성격이 다른 것을 고른다 | 지시, 모르는 것을 물은 것, 근거를 요구한 것 중 그 장에 맞는 것인가 |
| 「AI 가 한 것과 내가 판단한 것」 표는 한 번만 쓴다 | 장마다 반복하지 않았는가 |
| 스킬 자체를 설명하는 장은 두지 않는다 | 그 절차가 무엇을 검증하는지로 말했는가. 스킬 이름은 칸의 꼬리표로만 쓴다 |

## 내가 하지 않은 것

| 규칙 | 판정 |
| --- | --- |
| 내가 하지 않은 측정을 내가 한 것처럼 쓰지 않는다 | 주체가 불분명하면 「기록에 남아 있다」 로 쓴다 |
| 내가 잘 모르는 기술 항목은 넣지 않는다 | 발표자가 되물음에 답할 수 있는 내용인가 |
| 인용 숫자의 단위를 확인한다 | 분과 프로세스 실행 시간처럼 단위가 다른 것을 섞지 않았는가 |

## 부 전환과 목차

| 규칙 | 판정 |
| --- | --- |
| 부가 바뀔 때 전환 장을 하나 둔다 | 각 부 앞에 그 부만 알리는 장이 있는가 |
| 전환 장에는 부 번호와 이름, 한 줄 설명만 둔다 | 다른 내용이 섞이지 않았는가 |
| 목차의 부 설명이 그 부의 실제 장 목록과 맞는다 | 목차에 있는 항목이 자료에 장으로 있는가 |
| 부끼리 주제가 겹치지 않는다 | 앞 부 설명에 뒤 부 주제가 섞이지 않았는가 |
| 목차, 부 전환 장, 부 전환 스크립트가 같은 문구를 쓴다 | 셋이 서로 다른 말을 하지 않는가 |
| 장을 빼면 앞 장의 스크립트를 함께 본다 | 「뒤에서 다시 돌아옵니다」 처럼 없는 장을 가리키지 않는가 |

## 반복해서 나오는 실수

검사기가 잡지 못한다. 출력 직전에 직접 본다.

| 실수 | 확인 |
| --- | --- |
| 주어를 생략한다 | 「올랐다」, 「남았다」, 「끊겼다」 앞에 무엇이 있는가 |
| 목적어를 생략한다 | 「띄울 곳」, 「확인할 방법」 처럼 대상이 빠지지 않았는가 |
| 추상 명사구로 현상을 말한다 | 「오르는 양」 처럼 명사로 뭉치지 않고 문장으로 썼는가 |
| 대비를 만들려고 한쪽을 깎는다 | 「당연히 된다」 처럼 정보 없이 태도만 넣지 않았는가 |
| 도식이 보여 주는 것을 캡션에서 반복한다 | 캡션이 그림에 없는 것을 말하는가 |
| 추상 명사로 항목을 묶는다 | 「축」, 「항목」 처럼 뭉친 말 대신 그것의 이름을 썼는가 |

## 발표 고유 금지어

어휘 일반은 `~/.claude/rules/korean-style.md` 의 매핑 표가 소유한다.
아래는 발표 자료에서만 걸리는 것이다.

| 쓰지 않는 말 | 대신 |
| --- | --- |
| 굳혔다, 굳혀 | 만들었다, 언제든 돌릴 수 있게 했다 |
| 좁혔다, 좁혀 갔다 | 파악했다 |
| 지도, 관문, 루프 밖 | 전체 구조, 접속, 자동화하지 못한 것 |
| 띄울 곳이 없다 | 검증할 수단이 없다 |
| 확인할 방법이 없다 | 검증할 수단이 없다 |
| 첫 지점만 된다 | 코드는 고칠 수 있었지만 그 뒤가 막혀 있었다 |
| 이건 당연히 된다 | 아무것도 쓰지 않는다 |
| 정직하게, 솔직히 말하면 | 쓰지 않는다. 태도를 넣지 말고 사실만 쓴다 |
| 축 (검증하는 네 축 등) | 그것의 이름. 테스트라면 테스트라고 쓴다 |

## 말

| 규칙 | 판정 |
| --- | --- |
| 공손체 하나로 유지한다 | 제목과 표, 목록 항목을 뺀 평문이 섞이지 않았는가 |
| 본문은 최소로 두고 말할 내용은 스크립트로 내린다 | 화면에 문단이 쌓여 있지 않은가 |
| 글로 풀지 않고 캡처와 그림을 먼저 쓴다 | 같은 것을 그림과 글로 두 번 말하지 않았는가 |
