# report 스킬: 있는 내용을 읽기 좋은 HTML 보고서로 만들어 브라우저로 띄운다

확인: 2026-11-03

## 목표

사용자가 「HTML 로 시각화해서 설명해 줘」, 「보고서로 만들어 줘」 라고만 말해도, 매번 형식을 설명하지 않고 결론이 먼저 보이는 읽기 좋은 HTML 보고서를 받는다.

## 범위

이번 범위:

- fos-skills 에 `report` 스킬을 새로 둔다. `/report` 와 위 같은 자연어 요청으로 불린다
- 이미 있는 내용(대화, 파일, 조사 결과, 코드, 문서)을 보고서로 구성한다
- 공통 틀(CSS 와 부품) 하나와 내용 종류별 구성 셋을 둔다
- 만든 HTML 을 실행하는 맥의 기본 브라우저로 띄운다

범위 밖:

- 웹 조사. 조사가 필요하면 조사를 먼저 하고 그 결과를 넘긴다(스킬은 검색하지 않는다)
- 발표 슬라이드(`presentation`), 외부 게시 전 미리보기(`content-preview`)
- 다른 맥에서 보이게 내보내기(Tailscale 서버 등)
- 외부에 게시하거나 공유 링크를 만드는 일

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| R1 | 부르는 말로 스킬이 불린다 | 스킬 description 에 `/report`, 「HTML 로 시각화해서 설명」, 「보고서로 만들어」, 「한눈에 보이게 정리」 가 있고, `presentation`·`content-preview` 와 나뉘는 기준이 적혀 있다 |
| R2 | 결과는 외부 자원 없는 HTML 한 파일이다 | 밖에서 불러오는 script, CSS, 글꼴, 이미지가 없다. 본문의 `<a href="https://…">` 출처 링크는 허용한다. 검사 스크립트가 불러오는 외부 자원만 실패로 낸다 |
| R3 | 파일 자리와 띄우기 | git 저장소 안이면 `<저장소>/.omc/previews/<슬러그>.html`, 밖이면 세션 임시 폴더에 둔다. 슬러그는 주제를 나타내는 영문 소문자와 `-` 다. 같은 주제를 다시 만들면 같은 파일을 덮어쓴다. 만든 뒤 `open` 으로 기본 브라우저에 띄우고 응답에 경로를 적는다. `open` 이 실패하면 경로만 알린다 |
| R4 | 모양이 늘 같다 | 모든 보고서가 스킬의 공통 틀(CSS, 부품)을 쓴다. 부품: 머리(제목, 날짜, 한 줄 요약), 목차, 결론 카드, 비교표와 상태 칩(예/일부/아니오/미확인), 단계 목록, 강조 상자, 접는 절(`details`), 출처 각주 |
| R5 | 내용 종류별 구성 | 조사 보고서, 개념 설명, 비교·결정 자료 세 구성이 절 순서로 정해져 있고, 스킬이 내용을 보고 하나를 고른다. 어느 구성이든 결론이 첫 화면에 있다. 애매하면 묻지 않고 가장 가까운 구성을 고르고, 응답에 고른 구성을 한 줄로 알린다 |
| R6 | 글 규칙 | 단락은 2~3문장, 비교는 표다. 원문이 길면 본문에는 줄인 글과 표를 두고, 원문의 상세는 접는 절에 빠짐없이 넣는다. 출처도 접는다. 원문의 사실·수치·날짜·출처·「추정」 표시를 그대로 둔다. 내보내기 전에 `korean-check` 를 돈다 |
| R7 | 깨진 곳이 없다 | 검사 스크립트가 태그 짝, 본문의 각주 링크와 출처 id 의 짝, 외부 자원을 보고 0 으로 끝나야 띄운다. 실패하면 스스로 고쳐 두 번까지 다시 검사하고, 그래도 실패하면 띄우지 않고 실패 내용을 알린다 |
| R8 | 다른 스킬과 나뉜다 | description 과 SKILL.md 에 「청중 앞에서 넘기며 말하는 발표는 `presentation`, 외부에 게시할 글은 `content-preview`, 혼자 읽는 설명과 보고서는 `report`」 가 적혀 있다 |

## 설계

- 위치: `fos-skills/report/`. `SKILL.md`(목표, 개요 표, 단계), `references/layouts.md`(세 구성의 절 순서), `assets/template.html`(공통 CSS 와 부품 예시), `scripts/check-report.(ts|py)`(R2, R7 검사)
- 본보기: 2026-11-03 의 메모리 사례 보고서(`fos-assistant/.omc/previews/agent-memory-report.html`)의 구성과 CSS 를 틀의 출발점으로 쓴다. 그 파일의 내용은 옮기지 않는다
- 단계: 1 재료 모으기(넘겨받은 내용만) → 2 구성 고르기 → 3 틀에 채우기 → 4 검사 스크립트와 korean-check → 5 띄우고 경로 알리기
- 스킬을 만들 때 `skill-creator` 를 쓰고 `~/.claude/references/skill-structure.md`, `skill-sync.md` 를 따른다. 플러그인 버전과 CHANGELOG 는 저장소 규칙대로 한다
