# CHANGELOG: spec

## 2.1.0 (2026-11-02)

- 「~을 만들자」, 「~ 기능을 추가하자」, 「~하게 바꾸자」 처럼 새 동작을 요청하면 스킬 이름을 말하지 않아도 spec 이 먼저 불린다. 버그 수정, 정리, 설정 변경, 측정, 조회에는 불리지 않는다

## 2.0.0 (2026-11-02)

- 호환성: 스펙의 `## 미결정` 절을 `## 결정` 표(ID, 결정, 답, 누가, 근거)로 바꾼다. 진행 중인 스펙은 표로 옮겨야 planning 검사를 통과한다
- 호환성: 사용자가 확인한 날을 제목 아래 `확인: YYYY-MM-DD` 줄로 남긴다. 이 줄이 없으면 planning 이 시작하지 않는다
- 인터뷰 절차를 더했다. 첫 라운드는 열린 질문, 이후 결정은 4개씩 선택지와 권장안으로 묻고, 대화를 모르는 검토자가 빠진 결정을 찾는다
- 사용자에게 직접 묻지 못하는 orch worker 는 질문과 확인을 `worker-ask` 로 보내고, 확인 전에는 planning 하지 않는다
- 「기능 설계해 보자」, 「인터뷰해 줘」 요청도 spec 이 받는다

## 1.x

- 기능별 요구사항, 인수 조건과 구현에 필요한 설계를 한 스펙으로 정리했다
