# 공부 후보 모으기와 다시 보기

코디네이터 세션에서 사용자가 뜻을 물은 개념을 그때마다 후보로 적고, 하루 끝에 사용자가 남길지 뺄지 고른 뒤, 공부할 가치가 있는지 다시 보고 글로 쓰는 절차다.
설명이 대화에만 남으면 압축될 때 사라지고, 모아 두기만 하면 다시 볼 때마다 기준이 달라 같은 후보가 오간다.
글을 쓰는 스킬과 글이 놓일 저장소는 사용자마다 달라 오버레이가 정한다. 이 문서는 어느 저장소에서나 같은 자리와 형식, 기준만 소유한다.

## 후보 파일

후보 하나가 `<orch 루트>/study/<slug>.md` 파일 하나다. 폴더 경로는 `"$SKILL_DIR/bin/orch.ts" orch_paths study` 로 받는다.
파일은 `---` 사이의 머리와 그 뒤의 본문으로 나뉜다. 머리는 명령이 고치고, 본문은 근거, 메모, 글 초안 경로를 자유롭게 쌓는 자리라 에이전트가 직접 고친다.

```markdown
---
주제: 여러 서버에서 한 번만 실행하기
질문: ShedLock 같은 분산 잠금과 선점 테이블은 각각 무엇을 막는가
생긴 곳: 예약 알림이 서버마다 한 번씩 나간 문제
참고: ShedLock README
상태: 후보
적은 날: 2026-11-02
---

## 메모

- 잠금은 같은 시각의 중복 실행을 막고, 선점 테이블은 이미 처리한 대상을 다시 처리하지 않게 막는다
```

| 칸 | 담는 것 |
| --- | --- |
| 주제 | 일반 기술 개념의 이름 |
| 질문 | 사용자가 실제로 물은 것을 일반 질문으로 바꾼 것 |
| 생긴 곳 | 어떤 일을 하다 나왔는지 한 줄. 내부 맥락은 뺀다 |
| 참고 | 근거로 댈 공식 문서나 널리 알려진 글의 이름 |
| 상태 | `후보`, `리뷰함: <이유>`, `뺌: <이유>`, `글 씀: <글 경로>` 가운데 하나 |
| 적은 날 | 후보로 적은 날(`YYYY-MM-DD`). 하루 끝 고르기가 이 칸으로 그날 후보를 찾는다 |

**회사 이름, 서비스 이름, 내부 식별자, 대상자 정보는 적지 않는다.** 머리와 본문 모두 공개 글의 재료가 되므로, 적는 자리에서 일반 개념과 질문으로 바꾼다.

slug 는 영문 소문자, 숫자, 하이픈으로 주제를 짧게 줄인 이름이다(`run-once-cluster`). 적는 에이전트가 짓는다.
한글 파일 이름은 길고, macOS 의 파일 이름 정규화 차이로 같은 이름 비교가 어긋날 수 있어 쓰지 않는다.
slug 가 같거나 주제가 같으면(빈칸, 대소문자, 한글 정규화 차이는 무시) 같은 후보다. 뺀 후보도 같은 후보로 본다.

머리는 명령으로 고친다. 칸 이름이나 상태 낱말이 틀리면 명령과 doctor 가 그 후보를 세지 못하기 때문이다. 명령의 옵션과 출력은 `--help` 가 소유한다.

```bash
"$SKILL_DIR/bin/orch.ts" study-candidates list --open
```

## 모으기

**사용자가 개념의 뜻을 물으면 답한 뒤 그 자리에서 `후보` 로 적는다.** 사용자에게 적을지 묻지 않는다. 남길지는 하루 끝에 사용자가 고른다.
대화가 압축되면 그날 물은 개념을 다시 찾을 수 없어, 나올 때 적어 두는 것이다.

```bash
"$SKILL_DIR/bin/orch.ts" study-candidates add --slug "$SLUG" --topic "$TOPIC" --question "$QUESTION" --origin "$ORIGIN" --ref "$REF"
```

`$TOPIC`, `$QUESTION`, `$ORIGIN`, `$REF` 는 위 표의 네 칸이다. `--memo` 를 주면 본문이 된다.
같은 후보가 이미 있으면 명령이 만들지 않고 종료 코드 1 로 끝나며 그 파일을 알린다. 새 질문에서 얻은 근거가 있으면 그 파일의 본문에 더한다.
같은 후보가 `뺌` 이면 사용자가 이미 뺀 개념이라 다시 적지 않는다.

## 하루 끝 고르기

**하루 끝에 그날 적은 후보를 묶어 보이고, 사용자가 뺀다고 한 것만 `뺌` 으로 바꾼다.** 나머지는 `후보` 그대로 남긴다.

```bash
"$SKILL_DIR/bin/orch.ts" study-candidates list --today --open
"$SKILL_DIR/bin/orch.ts" study-candidates set --slug "$SLUG" --status 뺌 --note "하루 끝에 뺌"
```

보이는 때는 기본값으로 사용자가 하루 끝 정리를 요청할 때다. 코디네이터가 먼저 보일지, 어떤 말로 보일지는 오버레이의 「공부 후보」 칸이 정한다.
오버레이가 「먼저 묻지 않는다」 로 정했으면 모으기는 그대로 하고, 고르기만 사용자가 요청할 때 한다. 적는 일은 사용자에게 묻는 일이 아니라 그 규칙과 부딪치지 않는다.
고르지 않고 지난 날의 후보는 남긴 것으로 본다. 사용자가 빼지 않았고, 다음 주기 알림과 다시 보기에서 다시 판정한다.
다른 날의 후보를 함께 보고 싶으면 `--date YYYY-MM-DD` 로 그날 것을 본다.

## 주기

**`orch-doctor` 가 `STUDY-OPEN <개수> <폴더>` 를 내면 그 개수와 폴더를 사용자에게 한 줄로 알린다.** 스킬을 열 때마다 doctor 가 상태가 `후보` 나 `리뷰함` 인 파일을 센다.
언제 다시 볼지는 사용자가 정한다. 무엇을 공부할지는 사용자의 결정이라, 코디네이터가 알린 자리에서 상태를 바꾸지 않는다.
`리뷰함` 도 열린 후보로 센다. 공부할 가치가 있다고 정해 두고 글을 쓰지 않으면 같은 개념을 다음에 또 물게 된다.

## 다시 보기

사용자가 다시 보자고 하면 후보마다 아래 세 기준으로 판정안을 만들어 근거와 함께 보이고, 사용자가 확인한 것만 상태를 바꾼다.

- **다시 나올 만하다:** 다음 일에서 같은 질문이 다시 나올 만하다. 그날 그 일에만 있던 사정이 아니다
- **근거를 댈 수 있다:** 공식 문서나 널리 알려진 글로 설명의 근거를 댈 수 있다
- **이미 쓴 글이 없다:** 글이 놓일 저장소에 같은 주제의 글이 없다. 있으면 그 글을 고칠 거리로 보고 뺀다

| 바꿀 상태 | 조건 |
| --- | --- |
| `후보` → `리뷰함` | 세 기준을 모두 채운다. 이유에 어느 기준을 어떻게 채웠는지 적는다 |
| `후보` → `뺌`, `리뷰함` → `뺌` | 기준 가운데 하나라도 채우지 못한다. 이유에 그 기준을 적는다 |
| `리뷰함` → `글 씀` | 글을 실제로 썼다. 메모에 글 경로를 적는다 |

```bash
"$SKILL_DIR/bin/orch.ts" study-candidates set --slug "$SLUG" --status 리뷰함 --note "$REASON"
```

`$SLUG` 는 `list` 가 낸 첫 칸, `$REASON` 은 이유나 글 경로다. 이 표에 없는 전이는 명령이 거부한다. 판정의 긴 근거는 본문에 적는다.

## 글 쓰기

`리뷰함` 인 후보는 오버레이가 정한 글쓰기 스킬로 쓴다. 오버레이에 글쓰기 스킬이 없으면 어느 스킬로 어디에 쓸지 사용자에게 묻고, 그 답을 오버레이에 적는다.
글을 쓰기 전에 후보 파일과 세 기준의 판정을 그 스킬에 넘긴다. 글의 범위와 공개 판단은 그 스킬이 소유한다. 글 초안 경로는 본문에 적어 둔다.

## 옛 표 파일 옮기기

orch 5.16.0 전에는 `study/candidates.md` 한 파일의 표 한 줄이 후보 하나였다. 이 파일이 남아 있으면 doctor 와 명령이 stderr 로 알린다. 그 안의 후보는 세지 않는다.
줄마다 slug 를 지어 한 번 옮긴다. 번호는 표의 위에서부터 1 이다.

```bash
"$SKILL_DIR/bin/orch.ts" study-candidates migrate --slug 1=minio-object-key-length --slug 2=... --slug 8=expand-contract
```

slug 가 빠진 줄이 있으면 `NEED-SLUG <번호> <주제>` 를 내고 아무 파일도 만들지 않는다. 그 목록을 보고 slug 를 채워 다시 부른다.
상태는 그대로, 적은 날은 옛 파일의 수정 날짜로 옮기고 옛 파일은 휴지통(`~/.Trash/orch-study-<날짜>/`)으로 옮긴다.
표 앞의 규칙 글은 옮기지 않는다. 그 저장소만의 규칙이었으면 오버레이의 「공부 후보」 칸에 옮겨 적는다.
