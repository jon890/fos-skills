# orch: 사용량이 바닥난 모델로는 worker 를 띄우지 않고 같은 등급의 다른 모델로 띄운다

확인: 2026-11-23

## 목표

`orch worker launch` 가 평소에는 모델 표대로 띄운다.
고른 모델의 사용 한도가 바닥났을 때만 「사용 한도에 걸렸을 때」 표의 같은 등급 모델로 띄운다.
남은 사용량을 보고 제공자를 바꾸는 규칙([usage-routing](../usage-routing/spec.md), PR 557)은 없앤다.

usage-routing 은 Claude 사용량만 보고, Claude 의 남은 양이 남은 시간보다 조금만 많아도 Codex 행을 Claude 로 바꿨다.
그래서 Codex 에 여유가 있어도 사용자가 따로 말하지 않으면 Codex 를 거의 쓰지 않았다.
2026-11-23 에 지시서에 Codex 로 적은 worker 셋이 모두 「사용량: 남은 95%, 남은 시간 83%」 로 Claude 로 떴다. 11/20 뒤로 이렇게 바뀐 worker 가 47개다.
사용자 결정(2026-11-23): 남는 양을 보고 바꾸는 규칙은 모델 표보다 앞서지 않는다. 바닥난 모델로만 보내지 않는다.

## 범위

이번 범위:

- usage-routing 의 전환과 설정 `routing.usage_boost` 를 없앤다.
- 띄우기 직전에 고른 worker 모델의 한도를 읽고, 바닥났으면 같은 등급의 바닥나지 않은 모델로 띄운다. Claude 와 Codex 양쪽에 같은 규칙을 쓴다.
- 대체 모델도 모두 바닥났으면 띄우지 않고 알린다.

범위 밖:

- 남은 사용량이 많은 쪽으로 바꾸는 것.
- 계정을 고르거나 바꾸는 것. 계정은 사용자가 정한다(사용자 결정 2026-11-23, model-auto-routing DECISION31).
- 이미 떠 있다가 한도에 걸린 worker 의 대응. 지금처럼 「사용 한도에 걸렸을 때」 의 차례(계정 교체, resume, relaunch)와 루프의 `LIMIT-CHECK` 가 맡는다.
- 하위 에이전트와 코디네이터 세션 자신의 모델.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 평소에는 모델 표대로 띄운다 | 고른 모델의 한도가 바닥나지 않았거나 한도를 읽지 못했으면, 지시서의 `worker 선택:` 그대로 띄운다. Claude 의 남은 사용량이 남은 시간보다 많아도 Codex 행을 바꾸지 않는다 |
| REQ2 | 바닥난 모델로 띄우지 않는다 | 고른 모델에 걸리는 한도(주간, 5시간, 모델별 주간 묶음) 가운데 하나라도 100% 이거나 한도에 걸렸다는 표시가 있고, 그 한도가 풀리는 시각이 아직 오지 않았으면 그 모델로 띄우지 않는다. 풀리는 시각이 없는 걸림 표시(예: 계정 크레딧 소진)는 바닥으로 보지 않는다 |
| REQ3 | 같은 등급의 다른 모델로 띄운다 | REQ2 이면 「사용 한도에 걸렸을 때」 표의 그 모델 줄 「같은 등급 대응」 칸을 앞에서부터 보고, 바닥나지 않은 첫 모델로 띄운다. 칸에 effort 가 없으면 원래 행의 effort 를 쓴다. 칸에 없는 모델로 올리지 않고, 한 단계 아래로 내리지 않는다. 리뷰 worker 도 같은 표로 바꾸며, 만든 쪽과 같은 제공자가 되면 리뷰 결과에 `같은 제공자 리뷰(한도)` 를 남긴다 |
| REQ4 | 바꾼 이유가 남는다 | 바꿔 띄우면 `LAUNCH-EFFECTIVE` 와 띄우기 기록의 `candidateOverride` 에 원래 모델, 띄운 모델, 이유(`한도: <모델> <한도 종류> 100%, <풀리는 시각>` 꼴)가 남는다. 지시서의 `worker 선택:` 과 달라도 이 경우는 거절하지 않는다 |
| REQ5 | 대체도 바닥나면 띄우지 않는다 | 같은 등급 대응이 모두 바닥났거나, 칸이 비었거나, 표에 그 모델의 줄이 없으면 띄우기를 거절하고, 바닥난 모델마다 한도 종류와 풀리는 시각, 가장 먼저 풀리는 시각을 한 줄씩 낸다. 워크트리와 Task 를 만들지 않는다 |
| REQ6 | 읽지 못하면 막지 않는다 | 한도 출처가 없거나 읽지 못하면 그 모델은 바닥나지 않은 것으로 보고 `USAGE-UNKNOWN <제공자> <이유>` 한 줄을 낸다. 띄우기는 막지 않는다 |
| REQ7 | 지금 고른 계정을 본다 | 한도는 새 worker 가 쓸 계정의 값만 본다. Codex 는 Orca 에서 지금 고른 Codex 계정, Claude 는 Orca 에서 지금 고른 Claude 프로필이다. 다른 계정의 값은 보지 않는다 |
| REQ8 | 지시서의 직접 선택도 같다 | 지시서에 `후보 밖:` 으로 고른 모델이 바닥났어도 REQ2, REQ3, REQ5 를 따른다 |
| REQ9 | 옛 설정은 알려 준다 | 설정에 `routing.usage_boost` 가 남아 있으면 띄우기를 막지 않고, 그 키가 없어졌으니 지우라는 경고 한 줄을 낸다 |
| REQ10 | 새로 띄울 때마다 본다 | 새 띄우기, `--task` 재시도, `orch worker relaunch` 가 이 규칙을 따른다. 같은 세션을 잇는 `orch worker resume` 과 `--terminal` 이어 쓰기는 모델을 바꿀 수 없어 보지 않는다 |

## 도메인 규칙 변경

도메인 규칙 변경 없음: orch 의 worker 선택 규칙만 바뀐다.
