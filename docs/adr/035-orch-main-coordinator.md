# ADR-035: 저장소마다 메인 코디네이터 Run 하나만 루프를 맡고, 다른 코디네이터는 요청을 보낸다

- **status**: `accepted`
- **decision-type**: `architecture`
- **areas**: `operations`
- **현재 규칙의 원본**: [기능 스펙](../features/orch-main-coordinator/spec.md)의 REQ1~REQ13, [기술 설계](../features/orch-main-coordinator/design.md), `skills/orch/scripts/loop/lifecycle.ts` 와 `skills/orch/scripts/loop/takeover.ts` 머리 주석
- **결정**: 저장소의 메인은 그 저장소 루프에 등록된 Run 가운데 코디네이터 터미널에서 에이전트가 실행 중인 첫 Run 이다. 메인이 있으면 다른 Run 은 루프에 등록하지 않고 `orch request send` 로 메인에게 일을 요청한다.
  메인이 없으면 `orch loop start` 를 부른 세션이 넘겨받는다. 도는 루프를 멈추고 자기 명의로 다시 띄우며, 앞 Run 의 그 저장소 worker 를 자기 Run 으로 옮긴다. 메인이 살아 있어도 사용자 확인을 받은 명시적 넘겨받기는 허용한다.
  요청 기록과 요청 번호는 받는 저장소가 소유한다.
- **대체 관계**: [ADR-012](superseded/012-orch-loop-multi-run.md) 의 「여러 세션의 Run 이 루프 하나를 함께 쓴다」 를 대체한다. 이미 여러 Run 이 등록된 루프는 그 Run 들이 스스로 빠질 때까지 둔다.
- **맥락**: 2026-11-17 PR 517 의 worker 는 ai-analysis 의 메인 Run 이 fos-skills 에 직접 띄운 것이었다. fos-skills 에는 따로 메인 Run 이 있었지만 그 PR 을 맡은 코디네이터가 없어, 다른 세션이 띄우기 기록에서 Run 을 찾아 머지했고 정리 때 남의 Run 상태 파일이 남았다.
  같은 날 fos-skills 루프는 터미널이 없어진 옛 메인 Run 의 명의로 계속 돌아, 새 세션의 `loop start` 가 `LOOP-START-FENCED` 로 막혔다. 루프는 띄운 터미널의 명의를 물려받으므로 명의가 다른 Run 은 합류할 수 없다. [ADR-012](superseded/012-orch-loop-multi-run.md) 의 공유는 루프가 어느 Run 에도 묶이지 않았을 때만 실제로 동작했다.
  Orca 의 Run 에는 저장소 정보가 없고, 저장소마다 있는 것은 루프 등록뿐이다. 그래서 메인을 저장소의 루프 등록으로 정한다.
- **대안 기각**:
  - 지금처럼 여러 Run 이 한 루프를 함께 쓴다. 명의가 다른 Run 은 합류하지 못하고, 머지와 정리와 보드 쓰기를 두 세션이 겹쳐 한다.
  - 새 세션이 `run-use` 로 앞 메인 Run 에 옮겨 붙는다. worker 를 옮기지 않아도 되지만 새 세션의 Run 메일이 끊겨, 새 세션이 다른 저장소에서 맡은 worker 의 보고를 잃는다.
  - 메인을 Orca 의 Run 생존(터미널이 있는가)만으로 정한다. 셸만 남은 터미널이 메인을 차지해 새 세션이 계속 막힌다. 에이전트가 실행 중인지까지 본다.
  - 요청 기록을 보낸 저장소에 둔다. 받는 메인이 바뀌면 새 메인이 요청을 찾을 수 없고, 보낸 세션에 루프가 없으면 답 없음 알림을 잴 곳이 없다.
- **결과**:
  - 얻는 것: 저장소의 worker, 머지, 정리, 보드를 한 세션이 맡는다. 옛 메인의 명의가 남아도 새 세션이 루프를 넘겨받는다.
  - 얻는 것: 다른 저장소의 일은 요청 번호로 추적되고 완료가 보낸 쪽 보드와 메시지로 돌아온다.
  - 감당할 것: 메인 판정이 `run-list` 와 `terminal list` 조회에 기댄다. 조회가 실패하면 넘겨받지 않고 멈춘다.
  - 감당할 것: 작업 중인 worker 는 옮기지 않는다. 앞 Run 에 남은 worker 는 출력과 `state/takeover.json` 에 남고, 일이 끝나 쉬면 메인이 `orch loop start --take-over` 로 다시 옮긴다. 다른 저장소의 worker 는 옮기지 않고 출력에 보이기만 한다. 그 저장소에서 남은 worker 를 알리는 일은 같은 스펙의 PR2(doctor)가 한다.
  - 감당할 것: 넘겨받기는 옛 루프를 먼저 멈춘 뒤 새 루프를 띄운다. [ADR-032](032-loop-bundle-handover.md) 가 「루프가 하나도 남지 않는 틈」 때문에 기각한 순서다. 새 루프는 넘겨받는 터미널의 명의로 떠야 해서 옛 루프가 자식으로 띄울 수 없다. 띄우기가 실패하면 그 Run 이 이미 메인이므로 같은 명령을 다시 부른다.
  - 감당할 것: 받는 저장소의 루프가 죽어 있으면 답 없음 알림이 나가지 않는다. 다음 세션이 넘겨받아 루프가 다시 뜨면 잰다.
  - 감당할 것: 명시적 넘겨받기의 사용자 확인은 스크립트가 확인하지 못하는 채팅 답을 옵션으로 받는다. 보드 승인과 같은 한계다.
  - 감당할 것: 메인이 아닌 세션의 쓰기 명령은 이 결정만으로는 막히지 않는다. 막는 일은 같은 스펙의 PR2 가 한다.
