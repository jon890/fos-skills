# 보드 파일 위치 이전 기술 설계

## 요구사항 연결

| ID | 해결 방법 |
| --- | --- |
| REQ1 | `modules/work-board/path.ts`의 경로 목록을 보드 명령과 창이 함께 쓰고, `boardPath`에서 기존 설정 우선순위를 적용한다 |
| REQ2 | 새 보드가 없으면 기존 orch가 먼저 찾던 `.omc/handoffs/board.json`, 다음으로 `.omc/board.json`을 확인한다. 읽거나 쓸 때 같은 경로를 쓴다 |

| REQ4 | 이전 명령이 선택된 옛 보드를 확인해 이동과 충돌을 보여 주고, 적용할 때만 옮긴다 |
| REQ5 | 요청 저장소, 보드가 있는 저장소, Orca 등록 저장소에서 같은 옛 경로를 가리키는 설정을 모아 한 명령으로 갱신한다 |
| REQ6 | git 루트를 찾지 못한 세션은 같은 경로 목록을 홈 디렉터리 기준으로 적용한다 |

## 책임과 경계

work-board 모듈은 기본 위치와 옛 위치 순서를 소유한다. orch의 `boardPath`는 명시 경로와 `finish.board`를 해석한다. 보드 창은 실행한 폴더 기준으로 경로를 묻고, 저장소에서 명령이 실패하면 같은 목록을 쓴다. 기존 호출자가 주 checkout과 현재 워크트리 중 어디를 넘기는지는 유지한다.

이전 명령만 옛 파일을 옮긴다. [ADR-008](../../adr/008-orch-own-dir.md)의 orch 설정과 작업 파일 이전 규칙은 유지하고, 보드의 기본 경로는 [확인된 스펙](spec.md)을 따른다. 옛 경로 읽기는 이전이 필요한 동안 유지하며 제거 시점은 별도 결정으로 남긴다.

## 인터페이스와 데이터

기존 `orch doctor migrate [--apply]`에서 이동과 충돌은 기존 `WOULD-MOVE`, `MOVED`, `CONFLICT` 줄을 쓴다. 직접 지정한 설정은 `WOULD-BOARD-CONFIG`와 `BOARD-CONFIG`로 보여 준다. 상대경로, 절대경로, 홈 경로를 해석해 비교하고, 설정 파일이 놓인 저장소 기준으로 새 경로를 다시 적는다. 같은 설정 파일은 한 번 갱신한다. 보드 JSON 바이트와 항목 스키마는 유지한다.

## 실패와 일관성

보드를 쓰는 세션을 멈춘 뒤 적용한다. 명령은 이전 대상 저장소의 worker와 머지 작업을 확인하고, 기존 보드 파일 잠금을 사용한다. 새 자리에 같은 파일을 먼저 연결하고 설정을 잠금 안에서 다시 읽어 값이 여전히 옛 보드를 가리킬 때만 갱신한다. 설정 변경을 마치면 옛 파일 이름을 지운다. 중간에 끊기면 두 경로의 파일이 같은 경우 이어서 진행한다. 새 자리에 별개 파일이 있으면 적용 전에 충돌을 보고한다.

## 검증 전략

임시 저장소와 임시 홈에서 CLI·창의 기본 경로, 옛 보드 우선순위, doctor 안내를 확인한다. 이전 테스트는 미리보기 시 파일이 그대로인지, 충돌에서 설정과 보드가 보존되는지, 공유 설정이 함께 바뀌고 재실행할 일이 없는지 확인한다. 실제 저장소는 미리보기만 실행한다.
