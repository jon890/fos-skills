# 기능 PR 완료 근거

아래 블록은 코드 블록 밖에 한 번만 넣고 실제 값으로 채운다. 문서·검증 결과 파일이나 PR 본문의 해당 절을 근거로 가리킨다.
상태 뒤 `|` 다음에는 실제 증거를 적는다. 인수 검증과 문서 대조는 PR 생성 전에 통과해야 한다.
PR 자동 코드 리뷰만 대기로 PR 을 열 수 있고, 머지 전에 통과로 갱신한다. 이미 받은 독립 리뷰는 재사용한다.
검증 커밋은 PR HEAD 의 40자리 SHA 다. 코드·계약이 바뀌면 영향받는 검증과 리뷰를 다시 받고 근거를 갱신한다.
머지 큐나 상주 루프가 `update-branch` 로 base 를 합쳐 HEAD 가 바뀐 것은 다시 적지 않는다. 검증 커밋 뒤에 base 쪽 변경만 들여온 merge 커밋만 있으면 통과로 보고, 그 HEAD 의 CI 통과로 대신한다(`lib/feature-evidence.ts` 의 `baseMergesOnly`). 충돌을 풀었거나 merge 커밋에서 고친 것이 있으면 다시 적는다.
후속 검증이 없으면 없음과 이유를, 있으면 대기와 담당·선행 조건·실행 위치를 적는다. 실제 명령·기대값은 연결된 기록에 보존한다.
머지 뒤 후속 검증을 끝내면 통과와 실행 결과로 바꾸고 finish-pr 을 재개한다. 이 양식은 실제 실행이나 리뷰 정책을 대신하지 않는다.

<!-- fos-feature-evidence -->
검증 커밋: <현재 PR HEAD 의 40자리 SHA>
인수 검증: 통과 | <요구사항별 실제 결과 위치>
문서 대조: 통과 | <검토 범위·정합성·후보 또는 없음의 근거 위치>
독립 리뷰: 대기 | <PR 자동 리뷰 또는 실제 독립 검토 결과 위치>
후속 검증: 없음 | <후속 검증이 필요 없는 이유>
<!-- /fos-feature-evidence -->

## 스펙만 담은 PR

스펙 문서만 담은 PR(코드 변경 없음)도 같은 블록이 필요하다. 머지 큐가 블록 여부를 PR 본문이 아니라 지시서의 「루프를 쓴다」 줄과 브랜치로 정하기 때문이다.
코드가 없어 실행할 것이 없으므로 줄마다 아래를 적는다. 값은 실제 결과 위치로 바꾼다.

```
<!-- fos-feature-evidence -->
검증 커밋: <현재 PR HEAD 의 40자리 SHA>
인수 검증: 통과 | 사용자가 스펙을 확인한 기록(결정 블록 응답 위치)과 문서 검사(spec-lint, korean-check) 결과
문서 대조: 통과 | 기존 도메인 문서·계약과 대조한 범위와 어긋난 곳이 없다는 근거
독립 리뷰: 통과 | 독립 리뷰 결과 위치와 반영한 지적 목록(반영하지 않은 것은 이유)
후속 검증: 없음 | 코드 변경이 없어 머지 뒤 실행할 검증이 없다
<!-- /fos-feature-evidence -->
```

- 인수 검증은 사용자 확인과 문서 검사로 채운다.
- 독립 리뷰는 리뷰 결과와 반영을 적는다. 자동 리뷰를 기다려야 하면 대기로 열 수 있고, 머지 전에 통과로 바꾼다.
- 위 예시는 코드 블록 안이라 검사기가 읽지 않는다. 실제 PR 본문에는 코드 블록 밖에 한 번만 둔다.
