## 1.6.0

제목을 금지어 검사 대상에 넣고, 매핑 표의 `가르다` 계열 등록 형태를 다시 잡았다.
검사기 둘의 검출력 검사를 `tests/` 에 새로 두었다.

**종료 코드 0 이 위반 없음을 뜻하지 못하던 자리 둘이다.**
실측으로, 두 결함이 겹쳐 머지된 스킬 문서에 금지어 세 곳이 남았다.

| 자리 | 통과하던 이유 | 고친 것 |
| --- | --- | --- |
| `## 무엇을 가른다` 같은 제목 | 제목을 통째로 건너뛰었다 | 건너뛰기를 없앴다 |
| 본문의 `가르지 않으면` | 등록 형태가 셋뿐이었다 | 활용형 넷을 더했다 |

제목을 건너뛰던 근거가 문서에 없었다.
제목에 쓴 금지어는 본문과 같은 무게로 읽히므로 제외할 이유가 없다.
저장소의 `.md` 58개에 돌려 새로 걸리는 것이 없음을 확인했다.

등록 형태는 `가른 / 가르는 / 갈랐다 / 가르지 / 가르고 / 가르며 / 가름` 이다.
`가른다` 를 뺐다. `가른` 이 그것을 부분 문자열로 품어 한 위반이 두 줄로 보고됐다.

**`갈라` 는 등록할 수 없다.** 예외 목록이 음절 단위로만 동작하기 때문이다.
`갈라질` 에는 `갈라지` 가 부분 문자열로 들어 있지 않다.
한글 완성형에서 `질`(U+C9C8) 과 `지`(U+C9C0) 가 다른 문자다.
`갈라지` 를 예외에 넣어도 `갈라질`, `갈라진`, `갈라짐` 이 그대로 걸린다.

그래서 `갈라` 를 타동사로 쓴 두 곳은 검사기 대신 사람이 고쳤다.
`tools/browser-driver/README.md` 와 이 스킬의 `SKILL.md` 다.

오탐이 없는 것을 표본으로 확인했다.
`가르치다` 는 `가르치` 라 걸리지 않고,
`의견이 갈리다` 와 `판정이 갈린다` 는 1.2.0 의 판단대로 등록하지 않아 그대로 통과한다.

가독성 검사기는 제목을 이미 검사하고 있었다. 이 변경으로 둘의 대상이 같아졌다.
`references/markdown-readability.md` 의 검사 대상 표를 함께 고쳤다.

**제외 규칙을 넓히는 변경은 검사기가 알리지 않는다.** 그래서 `tests/` 를 두었다.
금지어 검사기에 33개, 가독성 검사기에 20개다.
제목 건너뛰기를 되돌리고, 매핑 표를 좁히고, NEST 검사를 무력화해
각각 시험이 실패하는 것을 확인했다.

검사기 둘의 주석에 남아 있던 같은 금지어 세 곳도 함께 고쳤다.
검사기가 `.md` 만 보므로 자기 코드 주석은 검사하지 않는다.

| --- | --- |

## 1.4.0

파일을 새로 만드는 자리에는 `정답지를 세운다` 가 아니라 `정답지를 추가한다` 를 쓴다.

산출물 하나를 더하는 일이라 `추가한다` 가 맞다.
사용자가 지적했고, 그 표현이 커밋 메시지와 PR 본문에 반복해서 쓰인 것이 확인됐다.

**`세운다` 자체는 남긴다.** 없던 기준을 처음 정하는 자리에는 뜻이 맞는다.
`출력 표기 규약을 세운다` 가 그런 경우다. 산출물 하나를 더하는 자리에만 어긋난다.

검사기가 잡을 수 없는 축이다. `세운다` 를 금지어로 걸면
규약과 기준을 세우는 정당한 문장까지 걸린다. 그래서 사람이 보는 예시 표에 둔다.

이 판정은 2026-09-10 에 커밋 `92e7464` 로 만들어졌으나,
이미 머지된 PR #27 의 브랜치에 얹혀 main 에 반영되지 않았다. 그것을 여기서 되살린다.

## 1.2.0

비유어 「가르다」 계열을 외래어 매핑 표에 등록했다.

| 금지 | 권장 |
| --- | --- |
| 가른다 / 가르는 / 갈랐다 | 나눈다, 고른다, 구분한다, 정한다 |

**무엇을 어떻게 나누는지가 문장에 없다.**
`5단계가 이 자리의 성격을 가른다` 를 읽은 사용자가 무엇을 나눈다는 뜻인지 되물었다.
뜻이 나눈다, 고른다, 구분한다, 정한다, 판정한다로 문맥마다 달라 독자가 복원할 수 없다.

등록한 형태는 셋뿐이다.
「가르다」, 「가르」로 넓히면 「가르치다」, 「가르침」, 「가르마」까지 걸린다.
「의견이 갈리다」, 「판정이 갈린다」는 사전에 있는 관용 표현이라 등록하지 않았다.
검사기 코드는 고치지 않았다.

## 1.1.0

금지어 검사기를 셸에서 python 으로 옮겼다.

| 옛 파일 | 새 파일 |
| --- | --- |
| `scripts/korean-style-check.sh` | `scripts/korean-style-check.py` |

**bash 안에 awk 가 들어 있어 읽히지 않았다.**
줄을 걸러내는 규칙과 링크 URL 을 지우는 함수가 awk 안에 있어,
고칠 자리를 찾으려면 셸과 awk 두 문법을 함께 읽어야 했다.
같은 스킬의 `check-readability.py` 와 언어가 갈려 있던 것도 함께 풀렸다.

`jq` 의존을 없앴다.
훅 모드가 `jq` 로 stdin 의 JSON 을 읽었고, `jq` 가 없으면 결과를 내지 않고 0 으로 끝났다.
이제 표준 라이브러리로 읽어 검사기 둘 다 `jq` 없이 돈다.

옮기기 전 출력을 기준으로 삼았다.
저장소 `.md` 전부와 위반 시험지, 훅 입력 두 경로, 종료 코드 2 의 두 경우,
심링크 한 겹과 두 겹에서의 매핑 표 탐색까지 출력과 종료 코드가 모두 같다.
훅 모드가 내는 JSON 만 여러 줄에서 한 줄로 바뀌었다.
키와 문자열 내용은 같고 훅이 JSON 을 파싱하므로 그대로 뒀다.

**심링크 경로가 바뀐다.** 훅에 걸어 둔 사람은 다시 걸어야 한다.
설치 명령은 `README.md` 가 소유한다.

## 1.0.0

흩어져 있던 판정 기준 셋과 검사기 둘을 한 스킬로 묶었다.

| 무엇 | 옮긴 곳 |
| --- | --- |
| 어휘와 문장 구성 | `references/korean-style.md` |
| 분량과 구조 | `references/writing-structure.md` |
| 렌더링과 편집기 함정 | `references/markdown-readability.md` |
| 금지어 검사기 | `scripts/korean-style-check.sh` |
| 가독성 검사기 | `scripts/check-readability.py` |

**검사기와 매핑 표는 이미 한 몸이었다.**
`korean-style-check.sh` 가 `korean-style.md` 의 매핑 표를 런타임에 읽는데
둘이 다른 디렉터리에 있어, 한쪽만 옮기면 표를 찾지 못해 종료 코드 2 로 끝났다.
기본 경로를 개인 홈의 절대경로에서 스크립트 옆의 상대경로로 바꿨다.
심링크로 걸어 두고 부르는 것이 기본 사용법이라 `$0` 을 실체까지 따라간다.

매핑 표를 찾지 못하면 종료 코드 2 로 끝낸다.
전에는 0 으로 끝나 검사기가 돌지 않은 것이 통과로 보였다.

검사기 둘을 함께 돌리는 `scripts/check.sh` 를 더했다.
따로 부르면 앞의 것이 실패해도 뒤의 것이 그대로 돌아,
호출한 쪽이 종료 코드를 하나만 읽고 통과로 판단한다.

**검사기가 돌지 않은 것이 통과로 보이는 경로 넷을 검토에서 찾아 막았다.**
넷 다 실행으로 재현했다.

| 무엇 | 어떻게 보였나 |
| --- | --- |
| 종료 코드를 뒤에 돈 검사기가 덮었다 | 매핑 표를 찾지 못한 2 가 1 로 내려와 위반 하나만 고치게 됐다 |
| 없는 경로를 인자로 받았다 | 검사기 둘이 각각 건너뛰고 「통과: 2개 파일」 을 내며 0 으로 끝났다 |
| 확장자가 `.md` 가 아니었다 | 금지어 검사기만 건너뛰어 같은 내용이 `.txt` 에서는 통과로 나왔다 |
| 임시 디렉터리 생성이 실패했다 | 빈 경로에 쓰다 실패한 뒤에도 검사기를 불러 0 으로 끝났다 |

종료 코드는 둘 중 큰 값을 내고, 대상이 없거나 확장자가 다르면 2 로 끝낸다.
`mktemp` 템플릿의 `X` 를 명시했다. `-t` 에 접두사만 주면 GNU coreutils 가 거부한다.

검토자에게 주는 기준을 `references/review-axes.md` 로 만들었다.
`content-preview` 의 자가 점검 목록에 있던 다섯 축이 출발점이고,
실측에서 검토자가 잡은 본문 내부 모순과 지어낸 번역어를 더했다.
반영 전에 검토자가 든 사실을 확인하는 조건도 통과 조건에 넣었다.
