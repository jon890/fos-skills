# 검토자에게 주는 기준

검사기가 종료 코드로 판정하지 못하는 축을 사람이나 별도 검토 역할이 본다.
**쓴 쪽이 자기 글을 평가하면 수행 여부가 산출물에 남지 않는다.**
그래서 이 축들은 본문을 쓰지 않은 쪽이 읽고 발견 목록을 낸다.

## 검토자에게 주는 것

- 본문 파일 경로와 함께 나가는 파일 경로
- 누가 읽는 글인지. 독자 구간이 쓸 수 있는 말을 정한다
- 이 스킬의 `references/` 파일들. 판정 기준은 그것들이 소유한다
- 이 문서의 축 목록
- 「대상 형식」 축을 볼 때는 그 매체를 소유한 스킬 경로

## 왜 이 층을 따로 두나

**종료 코드 0 은 본문이 통과했다는 뜻이 아니다.**
실측으로, 검사기 둘을 통과하고 자가 점검 목록도 짚은 PR 본문 둘에서 별도 검토자가 18곳을 찾았다.
아래 「축」 표의 축마다 걸렸다.

## 검토자가 내는 것

발견마다 세 줄을 담은 목록이다. 파일을 고치지 않는다.

| 칸 | 담을 것 |
| --- | --- |
| 위치 | 파일과 줄 번호 |
| 판정 | 어느 축의 어떤 위반인가 |
| 근거 | 그렇게 판정한 이유. 사실 주장이면 무엇을 보고 그렇게 말하는지 |

## 축

검사기가 이미 잡는 것은 여기 없다. 종료 코드가 남는 자리를 다시 보면 시간만 든다.

| 축 | 무엇을 찾나 | 판정 기준 |
| --- | --- | --- |
| 독자 구간 | 밖으로 나가는 글에 저장소 관용구와 문서 번호가 남은 자리 | `writing-structure.md` 「독자 구간」 |
| 분량 구간 | 훑어 찾는 글인데 헤더와 표가 없는 자리, 짧은 글에 층을 쌓은 자리 | `writing-structure.md` 「분량 구간」 |
| 비유 | 실제 동작이나 수치로 바꿀 자리 | `korean-style.md` 「비유를 수치나 동작으로」 |
| 지어낸 이름 | 제품, 도구, 지표를 그 조직이 부르지 않는 표기로 쓴 자리 | `korean-style.md` 「용어를 옮기지 않는다」 |
| 문장 성분 | 주어와 목적어가 빠져 독자가 관계를 짐작하는 자리, 주술이 어긋난 자리 | `korean-style.md` 「문장 구성」 |
| 중복 | 표가 이미 말하는 것을 아래 문장이 다시 쓴 자리 | `writing-structure.md` 「내용 점검」 |
| 본문 내부 모순 | 제목과 본문, 요약과 표가 서로 다른 것을 말하는 자리 | 아래 |
| 매체 | heredoc 의 escape 잔존, 압축된 표 셀, 위지윅에서 사라질 태그 | [`render-traps.md`](../../content-preview/references/render-traps.md) |
| 대상 형식 | 그 매체가 요구하는 절과 항목이 빠진 자리 | 그 매체를 소유한 스킬 |

**아홉 축 중 본문 내부 모순을 먼저 본다.** 실측 사례로, 제목이 「원인을 규명한다」인데
같은 본문이 「7건 중 2건은 이 원인으로 설명되지 않음」이라고 적고 있었다.

## 반영 전에 검토자가 든 사실을 확인한다

검토자도 사실을 틀린다.

실측 사례로, 저장소가 `py-spy` 를 쓴다는 근거로 「스택 표본」을 `py-spy 스택 덤프` 로
바꾸라는 발견이 나왔는데, 그 작업에서 실제로 쓴 것은 `faulthandler.dump_traceback_later` 였다.
그대로 반영했으면 표기를 맞추려다 사실이 틀렸다.

사실 주장을 담은 발견은 근거를 확인한 뒤에 반영한다.

## 통과 조건

- 발견마다 반영했거나, 반영하지 않은 이유를 적었다
- 사실 주장을 담은 발견은 근거를 확인한 뒤에 반영했다
- 반영하지 않은 발견을 보고에 남겼다
