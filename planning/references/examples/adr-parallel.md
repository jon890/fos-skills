# 예시: 병렬 PR 용 ADR 파일과 색인

7단계에서 ADR 을 만들 때, 여러 에이전트나 사람이 같은 저장소에 동시에 PR 을 여는 저장소라면 이 형식을 쓴다.
기본 템플릿은 [`task-create.md`](../task-create.md) 의 ADR 구조 템플릿 절이고, 이 예시는 파일 이름과 색인만 다르게 한다.
작업 PR 이 한 번에 하나뿐인 저장소는 기본의 `NNN-<슬러그>.md` 로 충분하다.

## 왜 번호를 쓰지 않는가

`NNN` 은 다음 번호를 각 브랜치가 main 을 보고 미리 고른다.
브랜치 둘이 같은 번호를 고르면 머지 순간에 충돌하고, 한쪽이 번호를 바꾸면 그 ADR 을 가리킨 링크도 함께 고쳐야 한다.

사용자 저장소 두 곳에서 같은 일이 있었다.

| 사례 | 증상 | 고친 방식 |
| --- | --- | --- |
| 한 파일에 결정을 이어 붙이던 저장소 | 서로 다른 결정을 더하는 PR 이 같은 파일 끝에서 반복해서 충돌했다 | 결정마다 파일 하나로 나누고 색인으로 잇는다 |
| 번호 파일을 쓰던 저장소 | 병렬 브랜치가 main 의 다음 번호를 미리 골라 번호가 겹쳤고, 번호를 옮기고 CI 를 다시 돌리느라 변경과 무관한 대기가 늘었다 | 번호를 버리고 결정한 날짜와 슬러그로 구분한다 |

두 번째 사례가 이 예시의 방식이다. 날짜는 브랜치가 혼자 정할 수 있고 합쳐도 바뀌지 않는다.
같은 날의 ADR 은 슬러그가 다르면 구분된다.

## 파일 이름과 머리

```
docs/adr/
  INDEX.md
  ADR-20261007-cache-key-scheme.md
  ADR-20261009-queue-per-tenant.md
  superseded/
    ADR-20261001-shared-queue.md
```

- 파일 이름은 `ADR-YYYYMMDD-slug.md` 다. 날짜는 결정한 날이고 파일 안의 `Date` 와 같다.
- 슬러그는 내용을 나타내는 짧은 소문자 영문, 숫자, 하이픈이다.
- `superseded` 가 되면 기본 템플릿의 위치 규약에 따라 옮기고 링크를 고친다. 파일 이름과 식별자는 유지한다.
- 머리는 `task-create.md` 와 같은 불릿형이다. 결정, 맥락, 대안 기각, 결과가 한 화면에 들어와야 한다.

```markdown
## ADR-20261007 / cache-key-scheme: 캐시 키에 테넌트 id 를 접두사로 둔다

- **status**: `accepted`
- **Date**: 2026-10-07
- **결정**: 모든 캐시 키를 `{tenantId}:{resource}:{id}` 로 만든다. 키 조립은 `CacheKeys` 한 곳에서만 한다.
- **맥락**: 테넌트 둘이 같은 `resource:id` 를 쓰면 한쪽 캐시가 다른 쪽에 보였다.
- **대안 기각**: 테넌트마다 캐시 인스턴스를 나누면 운영 비용이 테넌트 수에 비례해 기각한다.
- **결과**:
  - 얻는 것: 키 충돌이 구조로 막힌다.
  - 감당할 것: 기존 키는 배포 때 한 번 비워진다.
```

식별자를 가리킬 때는 `ADR-20261007 / cache-key-scheme` 를 링크 글로 쓰고 그 ADR 파일로 링크를 건다.

## INDEX.md

색인은 ADR 마다 한 행이다. 열은 식별자, 한 줄 요약, status 다. 식별자 칸은 그 ADR 파일로 가는 링크로 쓴다.

```markdown
# ADR 목록

## 현행

| ADR | 요약 | status |
| --- | --- | --- |
| [ADR-20261007 / cache-key-scheme](ADR-20261007-cache-key-scheme.md) | 캐시 키에 테넌트 id 를 접두사로 둔다 | accepted |
| [ADR-20261009 / queue-per-tenant](ADR-20261009-queue-per-tenant.md) | 큐를 테넌트마다 나눈다 | accepted |

## 대체됨

| ADR | 요약 | status |
| --- | --- | --- |
| [ADR-20261001 / shared-queue](superseded/ADR-20261001-shared-queue.md) | 공유 큐를 쓴다 | superseded |
```

- 각 절 안의 정렬은 날짜 오름차순, 같은 날짜는 슬러그 사전순이다. 정렬을 정해 두면 두 PR 이 서로 다른 행을 더해도 같은 줄을 고치지 않는다.
- 색인은 여러 PR 이 함께 고치는 파일이므로 새 행은 정렬 순서의 자리에 한 줄만 더한다. 대체할 때는 해당 행을 옮기고 링크와 status 를 고친다. 그 밖의 기존 행 정리는 같은 PR 에 섞지 않는다.
- 이 파일이 있어도 두 PR 이 같은 위치에 행을 더하면 충돌할 수 있다. 충돌이 나면 실제 ADR 파일과 대조해 합친다.

## 색인 일치 테스트

색인과 파일이 어긋나면 링크가 깨지거나 ADR 이 목록에서 빠진다. 사람이 대조하지 않고 테스트가 잡게 한다.

| 검사 | 어긋남의 증상 |
| --- | --- |
| ADR 폴더와 하위 폴더의 모든 `ADR-*.md` 가 색인에 한 행씩 있다 | 목록에서 빠진 ADR |
| 색인의 모든 링크가 실제 파일을 가리킨다 | 깨진 링크 |
| 링크 글과 제목 머리의 식별자가 파일 이름에서 나온 값과 같다 | 이름을 바꾸다 어긋난 링크 글과 머리 |
| 행이 정렬 규칙대로 놓였다 | 같은 위치를 고쳐 충돌하는 PR |
| 파일 안의 status 와 색인의 status 가 같다 | 대체된 ADR 이 accepted 로 남음 |
| 파일 안의 status 와 색인의 「현행」·「대체됨」 구분이 같다 | 대체된 ADR 이 현행 목록에 남음 |

테스트는 새 파일을 읽어야 하므로 [`test-boundaries.md`](test-boundaries.md) 의 `convention` 디렉터리에 둔다.
파일 이름에서 식별자를 얻는 함수 하나만 정확하면 나머지 검사는 그 함수의 결과를 비교하는 일이다.

## 사용자 결정 로그와의 관계

사용자가 정한 취향과 범위를 한 줄씩 남기는 결정 로그(`DECISIONS.md` 같은 표)를 따로 두는 저장소가 있다.
짧은 기록은 그 표에 두고, 이유와 기각한 대안이 필요한 기술 결정만 ADR 로 옮긴 뒤 표의 행에서 ADR 을 가리킨다.
같은 결정을 두 곳에 풀어 쓰지 않는다.
ADR 감인지 가르는 두 조건은 [`step-7-docs.md`](../step-7-docs.md) 가 소유한다.

## 근거

사용자 저장소 네 곳이 `NNN-slug.md` 와 불릿형 머리와 `INDEX.md` 를 쓰고, 한 곳이 번호 충돌 뒤 `ADR-YYYYMMDD-slug.md` 와 색인 일치 테스트로 옮겼다.
번호 충돌 사례는 위 표의 두 건이다.
