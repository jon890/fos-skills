# 스킬 개선 후보 다시 보기

worker 가 공통 지시서의 「스킬 개선 후보 보고」 절을 따라 쌓은 후보와 코디네이터가 직접 겪은 후보를 코디네이터가 다시 보고, 고칠 것만 골라 사용자에게 올리는 절차다.
모으기만 하고 다시 보지 않으면 같은 후보가 쌓이기만 하고, 다시 볼 때마다 기준이 달라 같은 후보가 개선 필요와 제외를 오간다.

## 후보 파일

후보는 `orch feedback add` 로만 적는다. worker 와 코디네이터가 같은 명령을 쓰며, `<orch 루트>/feedback/<slug>.md` 에 후보 하나당 파일 하나를 만든다. 워크트리에서 불러도 주 checkout 의 orch 루트에 모인다. 공통 지시서의 `{{FEEDBACK_DIR}}` 는 이 폴더다.
필수 옵션과 사용법은 `orch feedback add --help`, 값을 채운 호출 양식은 `templates/spec-common.md` 의 「스킬 개선 후보 보고」 에 있다.

명령이 만드는 칸과 순서는 고정이다. 값 안의 줄바꿈은 빈칸으로 바꾼다.

```text
## 한 줄 제목: 무엇이 안 됐는지, 쉬운 말로
- 스킬: 스킬 이름 (파일)
- 상황: 어떤 일을 하다가
- 문제: 무엇이 잘못됐고 무엇을 잃었는지
- 바라는 기능: core 가 무엇을 해 주면 되는지
- 근거: 세션·로그·파일과 줄
- 판단: 유의미한가: 이유 / 단순 함정이 아닌가: 이유 / 구조로 막을 수 있는가: 방법
- 상태: 후보
```

`orch feedback list` 는 이름·상태·제목을 탭으로 나눠 낸다. `--open` 은 후보와 보류만 낸다.
`README.md` 와 하위 폴더는 읽지 않는다. doctor 는 새 양식의 후보·보류와 아직 옮기지 않은 옛 메모 파일을 `FEEDBACK-OPEN` 으로 센다. 옛 메모는 옮기라는 안내를 함께 낸다.

### 옛 메모 옮기기

`orch feedback migrate` 는 옛 파일의 `##` 절마다 새 후보를 만드는 미리보기다. 「다시 보기」 와 「보류」 로 시작하는 추가 기록은 앞 후보에 붙인다. 절이 없으면 파일 하나를 후보 하나로 본다. 새 파일 이름은 원본 파일 이름과 순번으로 정한다.
명시된 칸만 옮기고 채울 수 없는 값은 「확인 필요」 로 남긴다. 상태를 읽을 수 없으면 보류로 두고 원문 전체를 근거 칸에 남긴다. 옛 제목도 그대로 가져오므로 실제 반영 전에 문제를 드러내는 쉬운 제목인지 확인한다.
`--apply` 를 줘야 파일을 쓰고 옛 파일을 휴지통으로 옮긴다. 기본 휴지통은 `~/.Trash/orch-feedback-날짜-시각-프로세스번호/` 이며, `--trash` 로 후보 폴더 밖의 다른 폴더를 줄 수 있다. 기존 후보나 휴지통 파일을 덮어쓰지 않는다. `feedback/reviewed/` 는 이미 검토한 기록이라 옮기지 않는다.

## 주기

**`orch-doctor` 가 `FEEDBACK-OPEN <개수> <폴더>` 를 내면 그날 안에 다시 본다.** 스킬을 열 때마다 doctor 가 열린 후보와 아직 옮기지 않은 옛 메모를 센다.
여러 worker 의 머지가 끝난 뒤처럼 후보가 한꺼번에 늘어난 때에도 본다. 다음 worker 가 같은 함정에 다시 빠지기 전에 고칠 것을 정하려는 것이다.

## 판정

후보마다 근거(파일과 줄, 로그, 재발 기록)를 지금 설치본과 대조한 뒤 결과를 정한다. 상태는 `orch feedback set --slug "$SLUG" --status "$STATUS"` 로 바꾼다. `SLUG` 는 목록의 이름이고 `STATUS` 는 아래 상태 값이다.

| 판정 | 조건 |
| --- | --- |
| 채택 #PR | 아래 세 기준을 모두 채우고 사용자가 고른 개선의 PR 이 열렸다 |
| 보류(이유와 다시 볼 조건) | 원인이나 재발 근거가 부족해 세 기준을 판단할 수 없다 |
| 기각(이유) | 세 기준 가운데 하나라도 채우지 못하거나, 지금 설치본에서 이미 고쳐졌다 |

세 기준(유의미하다, 단순 함정이 아니다, 구조로 막을 수 있다)의 원문은 공통 지시서 틀 `templates/spec-common.md` 의 「스킬 개선 후보 보고」 다. worker 에게 시킨 기준 그대로 판정한다.

**추정만으로는 채택이나 기각으로 정하지 않고 보류로 둔다.** 보류에는 다시 볼 조건(같은 일이 한 번 더 나면, 앞 개선이 머지되면)을 한 줄 적는다.
보류한 후보는 그 조건이 채워진 다음 다시 보기에서 판정한다. 근거 없이 채택으로 올리면 쓰지 않을 코드가 늘고, 기각하면 같은 실패가 되풀이된다.

## 올리기와 반영

개선할 후보는 스킬과 저장소로 나눠 사용자에게 한 번에 올린다. 같은 스킬의 후보는 PR 하나로 묶을 수 있게 모은다.
판정마다 근거를 붙인다. 사용자가 고른 것만 지시서로 써서 worker 에게 맡긴다. 스킬 파일은 후보를 쓴 worker 가 아니라 그 지시서를 받은 worker 가 고친다.
PR 이 열리면 `채택 #PR`, 제외하면 `기각(이유)`, 더 확인해야 하면 `보류(이유와 다시 볼 조건)` 로 상태를 바꾼다. 모두 같은 폴더에 남기고 상태로 구분한다. 다시 검토해야 하면 `후보` 로 돌릴 수 있다.
