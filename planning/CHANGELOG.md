# CHANGELOG: planning

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준은 저장소 README 의 「버전과 변경 이력」 을 따른다.

## 2.6.0

`docs/` 와 맞는 것만으로는 기억으로 적은 틀린 이름을 걸러내지 못한다.

## 2.5.0

task 를 만든 뒤 사용자의 원래 요청과 1단계에서 확정한 성공 기준을 다시 확인한다.
모든 phase 를 실행했을 때 그 기준이 관측되는지 대조하며, `docs/` 와 코드를 비교하는 것으로 대신하지 않는다.

## 2.4.1

레포 설정을 찾는 순서는 유지하고, `CLAUDE.md` 만 둔 저장소 개수처럼 시간이 지나면 낡는 문장을 지웠다.

## 2.4.0

`verify_task.py` 의 `TEST_WORD` 에 「검사」를 더했다.
한국어 저장소는 테스트를 그 말로 부르는 곳이 많아, 실제 테스트 항목이 위반으로 잡혔다.
저장소 20개의 문서를 세어 여덟이 「검사」 우세였다.

「…동작을 보는 검사」는 통과하고 「문서를 다시 읽는다」는 그대로 위반으로 잡히는 것을
표본 둘로 확인했다.

## 2.3.0

`scripts/plan_number.sh` 를 더했다.
「번호는 원격까지 훑어 정한다. 확보 방식은 저장소 관례가 정한다」가
관례를 두지 않은 저장소에서 멈춰 있었다. 이제 기본값이 그 스크립트다.
로컬 `tasks/` 만 보면 머지되지 않은 브랜치가 쥔 번호가 보이지 않는다.

`verify_task.py` 를 부르는 블록의 경로를 고쳤다.
`# cwd: 타깃 레포 root` 와 `python3 scripts/verify_task.py` 를 함께 적어,
타깃 저장소의 없는 경로를 가리키는 것으로 읽혔다.
스크립트는 스킬 번들에 있고 cwd 는 타깃 레포라는 것을 블록에 드러낸다.

## 2.2.1

phase 파일 구조 템플릿의 작업 항목 제목에서 엠대시를 뺐다.

`korean-check` 의 가독성 검사기는 제목의 엠대시를 `DASH` 위반으로 잡는다.
템플릿이 `### 1. {파일} — 변경 요약` 형식이라, 그대로 옮겨 쓴 phase 파일의 제목이
편집 훅에서 모두 걸렸다. 엠대시 없이 한 덩어리로 읽히는 명사구로 바꿨다.

## 2.2.0

`docs/` 와 `tasks/` 가 계획서를 번호로 가리키지 않게 한다.

계획서는 구현이 끝나 운영에 반영되면 제거된다.
`docs/` 와 ADR 과 phase 파일이 번호로 가리킨 자리는 그때 깨진 참조가 된다.

기본은 아무것도 적지 않는 것이다. 무엇이 언제 왜 바뀌었는지는 git 이력이 이미 추적한다.
결정의 근거가 필요하면 ADR 번호를, 변경의 이력이 필요하면 PR 번호를 적는다.
커밋 SHA 는 rebase 와 squash 로 값이 바뀌어 쓰지 않는다.

**내용을 계획서에 맡기지 않는다.** 계획서를 읽으라고 적으면 그 내용을 아직 옮기지 않은 것이라,
계획서를 지울 수 없다.

레포 설정의 폴백에서 `CLAUDE.md` 하나만 보던 것을 `AGENTS.md` 와 함께 보도록 바꿨다.
Codex 를 비롯한 다른 에이전트는 `AGENTS.md` 를 읽는다.
## 2.0.0

목표를 셋으로 세우고, 그 셋을 실제로 강제하는 것만 남겼다.

- 사용자와 합의한 것을 `docs/` 에 남긴다
- 그것만 읽고 구현할 수 있는 `tasks/` 를 만든다
- 구현된 것이 합의한 것과 같다

### 만드는 문서와 담을 내용

- 관리하는 문서 다섯에 「담는 것」 과 「정하는 단계」 를 붙였다.
  `docs/flow.md` 는 mermaid 흐름도나 시퀀스 다이어그램으로 그린다.
- 각 단계가 자기 결정이 어느 문서로 가는지 적는다.
- ADR 형식을 정했다. 상태는 `accepted` 와 `superseded` 두 값이고,
  결과 절에 얻는 것과 감당할 것을 둘 다 적으며, ADR 은 지우지 않는다.
  자격은 되돌리는 비용이 크거나 시스템의 핵심 개념을 정할 때다.
- phase 파일을 프롬프트 순서로 두고 `## 컨텍스트` 와 `**근거 문서**` 를 넣었다.
  마지막 작업 항목은 그 phase 를 검증하는 테스트다.

### 판정 가능한 지시만 남긴다

- 통과 조건이 아홉 곳에 흩어져 있던 것을 한 곳으로 모았다.
  「모호점 0」 은 스스로 판정할 수 없어 「남은 질문이 없다」 와
  「사용자만 답할 결정이 남지 않았다」 로 바꿨다.
- self-check 여덟 항목을 지웠다. 같은 컨텍스트가 짚는 목록은 자기 승인이라
  수행 여부를 알 수 없다. 넷은 `verify_task.py` 로 옮겼다.
- `verify-task.sh` 를 `verify_task.py` 로 바꿨다. 위반 아홉 건에도 종료 코드가 0 이었다.
  검사는 여섯에서 열하나가 됐다.
- step 파일 여덟의 절 구성을 통일하고 재진술 절 열을 지웠다.

### 책임 경계

- git 조작을 이 스킬의 책임에서 뺐다. 브랜치와 커밋과 rebase 는 저장소 관례가 정한다.
- 하네스 전용 도구 이름을 제거했다. 다른 에이전트에서도 돌아야 한다.
- 레포 고유 값을 오버레이, `CLAUDE.md`, 사용자 확인 순으로 찾는다.
- `task-create.md` 를 `references/` 로 옮겼다.

### 실측으로 고친 것

- `index.json` 의 `current_phases` 는 오타였다. 실제 191개 중 65건이 `current_phase` 다.
- `depends_on`, `related_docs`, `prerequisites` 를 스키마에서 뺐다.
- `step-8` 이 `SKILL.md` 의 없는 절을 가리키고 있었다.
- 번들이 627줄에서 432줄로, description 이 493자에서 225자로 줄었다.
