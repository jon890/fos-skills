# work-board: 보드 항목에서 연결된 업무를 바로 연다

확인: 2026-11-13

## 목표

코디네이터와 사용자가 work-board 창에서 보드 항목의 업무(두레이, Jira 등)를 한 번에 연다. 항목마다 업무 번호와 주소를 따로 저장하고, 창은 제목 앞에 PR 링크와 같은 꼴의 업무 칩을 보인다.

- 배경(ai-analysis 코디네이터 요청 2026-11-13): ai-analysis 보드 열린 항목 18개 가운데 업무 주소가 채워진 것은 2개였다. 제목에 「423 …」, 「AI-스마트홈-AI/458 …」 처럼 업무 번호가 있어도 링크가 없었다.

## 범위

이번 범위:

- 보드 항목의 업무 번호 칸, 그리고 `orch board set` 으로 업무 번호와 주소를 넣고 고치는 옵션
- 창이 제목 앞에 업무 칩을 그리기
- 업무 도구 어댑터(dooray, 주소 틀)와 저장소 설정
- 업무 번호를 자동으로 저장하는 두 때(worker 를 띄울 때, PR 이 항목에 붙을 때)
- 상주 루프가 번호만 있는 항목의 주소를 만들기
- 새 항목 제목에 업무 번호를 붙이지 않고, 같은 업무의 기존 항목은 번호 칸으로 찾기

범위 밖:

- 제목에서 업무 번호를 읽어 내기. 기존 항목은 코디네이터가 `orch board set` 으로 넣는다
- 하위 항목(후속 worker·PR 을 부모 항목 아래에 묶기). 별도 스펙으로 다룬다
- release 뒤에 채우기
- 한 저장소에서 업무 도구 둘 이상 쓰기
- Notion 처럼 따로 조회가 필요한 도구의 어댑터. 어댑터 구조만 열어 두고 쓸 때 더한다

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 보드 항목이 업무 번호와 업무 주소를 따로 저장한다. `orch board set` 이 상태를 바꾸지 않고 두 칸을 넣고 고치고 지운다 | `orch board set <id> --task-ref AI-스마트홈-AI/458` 뒤 그 항목의 번호 칸이 바뀌고 상태는 그대로다. `--task <주소>` 도 같다. 빈 값을 주면 그 칸만 지워진다. `http`·`https` 가 아닌 주소는 거절된다 |
| REQ2 | 창이 제목 앞에 `[<도구 이름> <번호>]` 칩을 그린다. 주소가 있으면 링크, 번호만 있으면 링크 없는 흐린 글자다. 주소만 있으면 `[<도구 이름>]` 링크다. 둘 다 없으면 칩이 없다. 제목 글은 보지도 바꾸지도 않는다 | 번호와 주소가 있는 항목은 `[두레이 AI-스마트홈-AI/458] 제목` 의 칩이 그 주소로 열린다. 주소를 지우면 같은 칩이 흐린 글자가 되고 눌리지 않는다. 제목 안의 `#342` 는 더는 링크가 아니다. 진행 중·대기·목표·완료 줄과 결정 줄 모두 같다. 진행 중·대기 줄에서 칩 뒤의 제목을 누르면 지금처럼 상태 확인 요청문이 채워진다 |
| REQ3 | 저장소 설정에 업무 도구 어댑터를 둔다. 처음 어댑터는 `dooray`(사내 주소 앞부분, 기본 프로젝트)와 `url-template`(번호를 넣을 주소 틀)다 | `orch config set` 으로 두 어댑터의 설정을 넣으면 통과하고, 모르는 어댑터 이름이나 빠진 값은 저장 전에 거절된다 |
| REQ4 | worker 를 띄울 때 지시서의 업무 연결 줄에서 업무 번호를, 같은 줄에 주소가 있으면 주소도 저장한다. 업무 도구를 부르지 않는다 | `두레이 업무: AI-스마트홈-AI/458` 줄이 있는 지시서로 띄우면 항목의 번호 칸이 채워지고 띄우기 출력에 업무 도구 호출이 없다. 본문의 다른 주소(위키 등)는 들어가지 않는다. 새 항목, 기존 항목, 다시 연 항목 모두 같다 |
| REQ5 | 상주 루프가 PR 을 항목에 붙일 때(보드 맞추기, worker 완료 확인) PR 제목의 업무 번호(`finish.task_pattern`)로 빈 번호 칸을 채운다 | 번호 칸이 빈 항목의 브랜치로 업무 태그가 붙은 PR 을 열면, 사용자가 직접 연 PR 이라도 루프의 다음 틱 뒤 번호 칸이 채워진다. PR 칸이 이미 찬 항목은 이 길로 채우지 않는다(코디네이터가 `orch board set` 으로 넣는다). 주소 칸이 이미 찬 항목은 이 길로 번호를 채우지 않는다(주소와 PR 의 업무가 다를 수 있다. DECISION11). 코디네이터가 `orch board set --task-ref` 로 넣는다 |
| REQ6 | 상주 루프가 번호만 있고 주소가 없는 열린 항목의 주소를 어댑터로 만들어 채운다. 실패하면 루프 로그에 항목과 번호마다 한 번 남기고 30분 뒤에 다시 해 본다 | 번호만 넣은 항목은 루프의 다음 틱 뒤 주소 칸이 채워지고 칩이 링크가 된다. `dooray` CLI 가 실패하게 두면 루프 로그에 이유 한 줄이 남고, 그 뒤 30분마다 다시 해 보는 동안 같은 항목·번호의 로그는 더 남지 않는다. 루프를 다시 띄워도 30분 간격은 이어진다. 설정이 없는 저장소는 주소를 만들지 않는다 |
| REQ7 | 자동 경로(띄울 때, PR 연결, 루프의 주소 만들기)는 이미 있는 번호와 주소를 바꾸지 않는다 | 번호 A 가 있는 항목에 번호 B 의 PR 이 붙어도 번호 칸은 A 이고, 루프는 A 로 주소를 만든다 |
| REQ8 | 참조 문서와 데이터 스키마가 새 칸, 설정, 명령을 설명한다 | `docs/data-schema.md` 와 orch·work-board 참조 문서에 업무 번호 칸, 어댑터 설정, `orch board set` 의 두 옵션이 있다 |
| REQ9 | worker 를 띄울 때 새 항목의 제목 앞에 업무 번호를 붙이지 않는다. 같은 업무의 기존 항목은 번호 칸으로 먼저 찾고, 번호 칸이 빈 옛 항목만 지금처럼 제목으로 찾는다 | `두레이 업무: AI-스마트홈-AI/458` 지시서로 새 항목을 띄우면 제목에 `AI-스마트홈-AI/458` 이 없고 번호 칸에 있다. 같은 번호의 열린 항목이 있으면 그 항목을 쓴다. 번호 칸이 비고 제목에 그 번호가 든 옛 항목도 지금처럼 찾는다. 기존 제목은 바뀌지 않는다 |

| DECISION16 | 업무 번호 규칙의 몫 | 지시서는 `board.task_line`, PR 제목은 `finish.task_pattern` 이 읽는다. 어댑터는 번호를 주소로 바꾸기만 하고 번호를 읽지 않는다. `dooray` 어댑터에서는 번호에 `/` 가 없으면 기본 프로젝트를 붙여 저장하고, 손으로 넣은 `--task-ref 458` 도 같다. `url-template` 은 받은 번호를 그대로 저장한다 | 작성자 | 같은 규칙을 두 곳에 두지 않는다. 저장하는 번호 꼴을 하나로 맞춘다 |
| DECISION17 | 지시서의 주소 | 업무 연결 줄 안의 `http`·`https` 주소 가운데 어댑터의 주소 호스트와 같은 첫 주소만 읽는다. 어댑터 설정이 없으면 읽지 않는다 | 작성자 | 본문의 위키 주소를 업무 주소로 잘못 넣지 않는다(조사한 사실 「지시서 본문의 주소」) |
| DECISION18 | 띄울 때 채우는 길 | 지시서에 업무 연결 줄이 있으면 항목을 다루는 네 길 모두에서 빈 칸만 채운다 | 작성자 | 어느 길로 띄워도 같은 결과다. 이미 있는 값은 DECISION11 을 따른다 |
| DECISION19 | 설정이 없는 저장소 | 번호는 저장하고 흐린 칩으로 보인다. 주소는 만들지 않는다 | 작성자 | 설정 없이 업무 도구를 부르지 않는다 |
| DECISION20 | 루프가 주소를 만드는 대상 | 완료가 아닌 항목만 | 작성자 | 끝난 항목에 업무 도구 호출을 쓰지 않는다. 필요하면 `orch board set --task` 로 넣는다 |
| DECISION21 | 새 항목 제목의 업무 번호 | 붙이지 않는다. 같은 업무 찾기는 번호 칸을 먼저 보고, 번호 칸이 빈 옛 항목만 제목으로 찾는다. 이미 있는 제목은 바꾸지 않는다 | 사용자 2026-11-13 | 칩과 제목에 번호가 두 번 보이지 않는다 |
| DECISION22 | 결정 줄의 칩 | 결정 항목 줄에도 같은 칩을 그린다 | 작성자 | 결정도 업무에서 나온 항목이라 같은 길로 연다 |
| DECISION23 | 칩과 제목 누르기 | 칩은 제목 버튼 밖, 앞에 둔다. 제목을 누르는 동작은 그대로다 | 작성자 | 버튼 안에는 링크를 넣지 못한다(`extensions/work-board/hooks/register.js` 1850-1872행). 제목을 눌러 작업하는 지금 습관을 지킨다 |
| DECISION24 | 주소만 있는 항목의 PR 업무 번호 | 주소 칸이 이미 찬 항목은 PR 연결 때 번호를 채우지 않는다. 코디네이터가 `orch board set --task-ref` 로 넣는다 | 사용자 2026-11-13 | 주소와 PR 이 서로 다른 업무일 수 있어 DECISION11 의 짝 보존을 유지한다 |
| DECISION25 | 칩의 자리 | 칩은 제목 윗줄(상태 표시 옆)에 두고 제목은 다음 줄에 들여 쓴다. 칩이 없는 항목은 한 줄이다 | 사용자 2026-11-13 | 좁은 창(40칸 안팎)에서 제목이 폭을 차지해 칩이 한 글자 폭으로 눌려 세로로 내려갔다. 칩을 따로 윗줄에 두면 칩 글자가 그대로 보인다 |
