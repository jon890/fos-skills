# Orca 사이드바 「공부·피드백」 패널에서 오늘 고를 것과 진행 중인 일을 보고 바로 고른다

확인: 2026-11-26

## 목표

fosbot 이 평일 09:00 에 정리한 공부 후보와 스킬 피드백 묶음을 Orca 사이드바 패널에서 계속 보며, 버튼으로 바로 고른다. 고른 뒤 진행 중인 일(글 쓰는 중, 반영 요청 중, PR 번호와 상태)도 같은 패널에서 따라간다.

지금은 Orca 항목 버튼과 채팅으로만 고른다. 근거: 요청 R26(fosbot, 2026-11-26), fosbot 1단계 스펙 `<fosbot 홈>/docs/specs/study-feedback-curation.md`(확인 2026-11-24)의 범위 밖 「사이드바 패널은 2단계」, 정적 시제품 `<fosbot 홈>/prototypes/fos-curation-panel/`.

## 범위

이번 범위:

- fos-skills 저장소의 Orca 패널 플러그인(trusted-worker). 시제품의 화면 구성(요약 숫자, 「오늘의 공부」, 「스킬 피드백」, 「저장소별」 탭)을 출발점으로 한다.
- 패널이 읽는 요약 파일의 계약과, 버튼이 fosbot 에게 보내는 메시지의 계약.

범위 밖:

- fosbot 쪽 변경(요약 파일 쓰기, 버튼 요청 처리, 정리 흐름). 계약이 확정되면 fosbot 이 자기 홈에서 맡는다.
- Orca 카탈로그 배포.
- 패널에서 공부 글이나 반영 PR 본문을 직접 쓰는 일.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 요약 파일을 읽어 그린다 | 패널은 fosbot 이 쓰는 요약 파일 하나만 읽는다. 파일이 바뀌면 다시 그린다. 파일이 없거나 형식 버전이 다르면 그 사실과 마지막 정리 시각을 보이고 버튼을 끈다. JSON 이 깨졌으면 직전에 읽은 내용을 두고 「읽기 실패」 를 보인다. 마지막 정리가 평일 기준 하루 넘게 지났으면 「오래됨」 을 보인다 |
| REQ2 | 오늘 고를 것 | 「오늘의 공부」 에 후보마다 제목, 핵심 질문, 개요, 출처가 보이고 「글로 쓰기」, 「나중에」, 「빼기」 버튼이 있다. 「스킬 피드백」 에 반영 제안 묶음마다 번호, 제목, 대상 스킬, 포함 후보가 보이고 「반영」, 「보류」, 「기각」 버튼이 있다. 이미 정리된 기각·보류 수도 보인다 |
| REQ3 | 진행 중인 일 | 고른 뒤의 일(글 쓰는 중, 반영 요청 중)이 저장소와 PR 번호, PR 상태와 함께 보인다. PR 이 머지되거나 닫히면 빠진다. fosbot 은 09:00 정리에 더해 답을 처리하거나 PR 이 열리고 머지·닫힐 때 요약 파일을 다시 쓴다 |
| REQ4 | 저장소별 | 저장소마다 공부 후보 수와 피드백 후보 수가 보인다 |
| REQ5 | 버튼은 봇에게 선택을 보낸다 | 버튼을 누르면 패널이 fosbot 에게 선택(대상 후보 id, 답)을 보내고 카드를 「보냄 hh:mm」 으로 잠근다. 다음 요약에서 그 후보가 바뀌면 풀리고, 10분 안에 바뀌지 않으면 「처리 대기」 로 바꿔 다시 누를 수 있게 한다. 패널은 상태를 직접 바꾸지 않는다. 같은 버튼을 60초 안에 다시 누르면 보내지 않는다 |
| REQ6 | 이유와 보내기 실패 | 「빼기」, 「보류」, 「기각」 은 한 줄 이유를 받아야 보낸다. 「글로 쓰기」, 「나중에」, 「반영」 은 이유 없이 보낸다. 패널이 알리는 실패는 대기열에 쓰기 실패와 봇 깨우기 실패까지다. 깨우기에 실패하면 쓴 요청을 지운다. 봇이 받은 뒤의 처리 실패는 요약 파일의 후보 상태로 돌려받는다 |
| REQ7 | 설치 | fos-skills 주 체크아웃의 플러그인 폴더에서 `orca plugin install` 로 설치한다. 승인은 처음과 새 권한이 생길 때만 묻는다. 로컬 Orca 에서 설치, 코드만 바꾼 재설치(다시 묻지 않음)를 확인한 결과를 PR 에 적는다 |

## 결정

| ID | 결정 | 답 | 누가 | 근거 |
| --- | --- | --- | --- | --- |
| DECISION1 | 코드 위치 | fos-skills 저장소 안(PR, CI, 리뷰) | 사용자 2026-11-26 | 요청에 적힌 사용자 결정 |
| DECISION2 | 패널이 읽을 데이터 | 봇이 정리 때마다 쓰는 패널용 새 요약 파일 하나(봇 내부 `state/curation.json` 과 분리). 형식 버전 칸을 둔다 | 사용자 2026-11-26 | 봇 내부 형식이 바뀌어도 패널이 깨지지 않는다 |
| DECISION3 | 버튼 동작 | 봇에게 선택을 보내고, 봇이 항목에 기록한 뒤 처리 | 사용자 2026-11-26 | 요청에 적힌 사용자 결정 |
| DECISION4 | 보일 범위 | 오늘 고를 것 + 진행 중인 일 추적 | 사용자 2026-11-26 | 요청에 적힌 사용자 결정 |
| DECISION5 | 버튼 계약 | AI 비서 패널과 같은 대기열 방식: 봇 홈의 대기열 폴더에 JSON 을 쓰고 `orca automations run` 으로 fosbot 을 깨운다 | 사용자 2026-11-26 | 패널 worker 는 Orca 터미널 밖이라 `orchestration send` 를 못 쓴다. 같은 봇이 두 패널 요청을 같은 규칙으로 처리한다 |
| DECISION6 | 설치 | fos-skills 폴더에서 설치 | 사용자 2026-11-26 | 개인 도구라 카탈로그는 과하다. git pull 로 갱신된다 |
| DECISION7 | 플러그인 종류 | trusted-worker(패널 + worker). 파일 읽기·감시와 `orca` 명령 실행은 worker 가 한다 | 작성자 | sandboxed-ui 는 파일을 읽거나 명령을 실행하지 못한다(조사: AI 비서 패널 README) |
| DECISION8 | 대기열 메시지 꼴 | AI 비서 패널의 꼴(`action`, `item`, `answer`, `reason`, `sentAt` 등)을 따르고 action 을 더한다(공부 선택, 피드백 묶음 선택). 대기열 폴더와 깨울 automation 은 AI 비서 패널과 같은 것을 쓸지 따로 둘지 technical-design 이 fosbot 과 맞춰 정한다 | 작성자 | 한 봇이 같은 처리 규칙으로 받게 하려는 DECISION5 의 뜻을 따른다 |
| DECISION9 | 둘 곳 | `extensions/<이름>/` 에 플러그인 루트(`orca-plugin.json`)를 둔다. Claude 플러그인 매니페스트는 참조하지 않는다 | 작성자 | 지금 `extensions/work-board` 배치와 변경 단위 규칙(`scripts/skill_changes.ts`)을 따른다 |
| DECISION10 | 테스트 | 요약 파일 읽기, 메시지 만들기, 중복 막기는 node 테스트로 CI 에서 돌린다. `orca plugin test` 는 Orca 가 있는 로컬에서 돌리고 결과를 PR 에 적는다 | 작성자 | CI 에 Orca 가 없다 |
| DECISION11 | 누른 뒤 화면과 답 충돌 | 「보냄 hh:mm」 잠금, 10분 뒤 「처리 대기」. 패널, 항목 버튼, 채팅 가운데 봇이 먼저 기록한 답이 이기고 이미 처리된 후보면 봇이 알린다 | 사용자 2026-11-26 | 1단계는 항목 버튼이 기준이다. 세 경로를 후보 id 로 묶는다 |
| DECISION12 | 이유 입력 | 빼기·보류·기각은 한 줄 필수, 나머지는 이유 없음 | 사용자 2026-11-26 | 1단계 상태 꼴 `뺌: <이유>`, `보류(이유)`, `기각(이유)` 에 맞춘다 |
| DECISION13 | 진행 중인 일 갱신 | fosbot 이 상태가 바뀔 때마다 요약 파일을 다시 쓴다 | 사용자 2026-11-26 | 패널은 파일 하나만 읽는다(DECISION2) |
| DECISION14 | 「나중에」 | 1단계 규칙대로 14일 뒤 다시 본다. 패널은 날짜를 받지 않는다 | 작성자 | fosbot 스킬의 `later` 규칙 |
| DECISION15 | 이틀 치 후보 | 요약 파일의 후보 id 로 합친다. 고르지 않은 후보를 어떻게 남길지는 fosbot 정리 규칙이 정한다 | 작성자 | 후보 선별은 1단계(D3) 몫이다 |

## 도메인 규칙 변경

도메인 규칙 변경 없음: 공부 후보와 피드백 후보의 상태 규칙은 그대로이고, 패널은 그 상태를 보여 주고 봇에게 선택을 넘길 뿐이다.
