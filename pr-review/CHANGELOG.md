# CHANGELOG: pr-review

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준과 쓰는 형식은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 1.7.2 (2026-10-25)

- README 를 스킬을 쓰는 사람 관점으로 다시 쓰고, 이 CHANGELOG 를 버전마다 핵심만 남기도록 줄였다. 동작은 바뀌지 않았다

## 1.7.1 (2026-10-14)

- korean-check 금지어에 걸린 문구를 권장 표현으로 바꿨다. 동작은 바뀌지 않았다

## 1.7.0 (2026-10-12)

- 다른 PR 과 이슈는 백틱 없이 `#102`, 다른 저장소면 `owner/repo#102` 로 쓴다
- `gh-review-post.sh --batch` 의 핵심 낱말은 `--` 앞에만 둔다고 사용법에 적었다. `--` 뒤에 두면 줄 번호 오류로 끝난다

## 1.6.0 (2026-10-12)

- `SKILL.md` 에 목표 문장과, 단계마다 통과 조건을 담은 개요 표를 더했다
- 사용자 문체 파일의 경로는 오버레이가 준다. `SKILL.md` 에 적혀 있던 개인 환경 경로를 지웠다

## 1.5.1 (2026-10-06)

- 문서의 표현 여섯 곳을 권장 표현으로 바꿨다. 동작은 바뀌지 않았다

## 1.5.0 (2026-10-06)

- `gh-review-post.sh` 의 등록 뒤 확인이 줄 번호를 `null` 로 보이던 문제를 고쳤다
- 등록한 인라인 수와 줄에 붙은 수가 다르면 경고하고 종료 코드 1 로 끝낸다
- 등록 뒤 확인과 `--edit` 의 출력이 본문 첫 줄만 보인다. 줄바꿈이 섞여 출력이 깨지던 문제다

## 1.4.0 (2026-10-06)

- 개인 로컬 스킬에서 fos-skills 로 옮겨 플러그인으로 설치된다. 스킬 본문은 바뀌지 않았다

## 1.3.0 (2026-10-06)

- `gh-review-post.sh --batch` 를 더했다. 요약과 인라인 여러 건을 리뷰 하나로 등록한다
- `gh-review-post.sh --edit` 를 더했다. 이미 등록한 인라인 리뷰를 검증을 거쳐 고친다
- 요약 리뷰도 인라인 본문과 함께 미리보기에 띄운다

## 1.2.0 (2026-10-06)

- 등급 표기를 `🟡 **P3 보통**` 처럼 색 원과 등급 이름으로 바꿨다. `gh-review-post.sh` 가 이 표기를 강제한다
- 호환성: 첫 줄이 `(P3)` 꼴인 본문은 `gh-review-post.sh` 의 검증을 통과하지 못한다
- `gh-review-post.sh --summary` 를 더했다. 등급별 건수를 담은 요약 리뷰를 등록한다
- 인라인 리뷰와 요약 리뷰 끝에 AI 가 작성했다는 안내를 스크립트가 붙인다

## 1.1.1 (2026-10-06)

- `gh-review-post.sh --reply` 가 등록 뒤 결과 출력에서 `SyntaxError` 로 끝나던 문제를 고쳤다. 답글은 그때도 등록돼 있었다

## 1.1.0 (2026-09-04)

- SSH config 별칭 리모트에서 호스트를 찾지 못해 접속에 실패하던 문제를 고쳤다. 호스트 판별은 `scripts/gh-host.sh` 가 맡는다
- 오버레이가 정하는 것은 등급 기준이다. 등급 표기는 `references/grading.md` 가 정한다
- 스크립트 경로를 스킬 번들 기준 상대경로로 바꿔 설치 위치와 무관하게 동작한다

## 1.0.0 (2026-08-25)

- 스킬을 처음 만들었다. 대상 확정, 근거 확보, 등급과 범위 판정, 미리보기, 등록과 검증의 다섯 단계로 리뷰를 쓰고 올린다
- 동작, 비용, 관례 주장마다 필요한 근거를 정하고, 근거의 강도로 P1 부터 P5 까지 등급을 매긴다
- 이 PR 이 만든 문제인지로 리뷰와 후속 업무를 나눈다
- `gh-review-post.sh` 가 등록 전에 등급 접두사, 핵심 낱말, 봇 재트리거 토큰을 검증한다. `DRY_RUN=1` 이면 검증만 한다
- `gh-review-list.sh` 로 이미 달린 스레드와 내 댓글을 읽는다
