올리는 기준은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 3.8.0

감사로 찾은 자리를 정리했다.

5단계의 출력 표가 실제와 어긋났다. 「출력 두 줄」 이라 적고 세 행을 두었는데
`탭 위치:` 는 새로 여는 분기에서만 나온다. 재생성 때 볼 것 한 줄만 남기고 나머지는 스크립트에 맡겼다.
같은 절의 `ORCA_WORKTREE` 예시는 상대 경로라 그대로 실행하면 종료 코드 127 이었다.

「공통 주의」 세 항목은 두 생성기의 docstring 이 소유한다.
`</script>` 는 생성기가 종료 코드로 거부하므로 산문이 막을 것이 없다.

4단계에서 검토 대상과 「쓰지 않은 쪽이 읽는다」 를 뺐다. `review-axes.md` 가 소유한다.
그 목록에 없는 제목과 개인 문체 점검 항목만 남겼다.
3단계의 훅 설명도 `markdown-readability.md` 가 소유한다.

README 의 전제 다섯 항목과 `persona.md` 의 표는 `show-preview.sh` 머리말과 겹쳐 줄였다.

「등록 전 확인 방식」 도 무엇을 가리키는지 없는 말이었다.

## 3.1.0

미리보기가 쓸 브라우저 백엔드를 정할 자리를 만들었다.
전에는 드라이버의 자동 감지에 맡겼다. 자동 감지 순서에 자동화용 백엔드가 앞에 서면
미리보기가 그쪽으로 열린다. 그 백엔드에는 `worktree` 명령이 없어 사용자가 보는 곳의
탭인지 대조하지 못하고, 사용자가 로그인해 둔 프로필의 탭을 자동화와 함께 쓰게 된다.

값은 설정 파일(`~/.claude/browser.config.json`)의 `previewDriver` 로 정한다.
`PREVIEW_BROWSER_DRIVER` 로 그 호출만 바꿀 수 있다.
둘 다 없으면 자동 감지를 따르고, 그 백엔드가 `worktree` 를 다루지 않으면
탭 위치를 대조하지 못한다고 알린다.

드라이버 경로를 지정하는 변수를 `BROWSER_DRIVER` 에서 `BROWSER_DRIVER_PATH` 로 바꿨다.
드라이버 자신이 `BROWSER_DRIVER` 를 백엔드 이름으로 읽어, 한 이름이 두 뜻을 갖고 있었다.
`BROWSER_DRIVER=ego` 를 셸에 둔 사람은 그 값이 실행 파일 경로로 해석되는 자리를 만나게 된다.

## 3.0.0

「자가 점검」을 「표기 검사」와 「검토」 둘로 나눴다. 실행 절차가 5단계에서 6단계가 됐다.

앞부분은 그대로 3단계에 남았다. 종료 코드가 남으므로 자기 승인이 아니다.
판정 기준과 검사기의 소유자를 `korean-check` 스킬로 옮기고,
`scripts/style-check.sh` 가 그것을 찾아 부른다.
절대경로를 박지 않는 이유는 저장소마다 스킬 배치가 달라서다.
찾지 못하면 종료 코드 2 로 끝낸다. 전에는 「없으면 건너뛴다」 였다.

뒷부분의 다섯 축을 4단계 검토로 옮겼다. **목록을 지운 것이 아니라 소유자를 옮긴 것이다.**
그 목록이 검토자에게 주는 기준이 되고, `korean-check` 의 `references/review-axes.md` 가 소유한다.

**쓴 쪽이 자기 글을 평가하면 통과 여부가 산출물에 남지 않는다.**
실측 근거가 있다. 검사기 둘을 통과하고 자가 점검 목록도 짚은 PR 본문 둘에서
별도 검토자가 18곳을 찾았다.

| 축 | 검사기 | 검토자 |
| --- | --- | --- |
| 금지어와 렌더링 | 0건 | 해당 없음 |
| 비유 | 못 잡음 | 4곳 |
| 본문 내부 모순 | 못 잡음 | 1곳 |
| 지어낸 번역어 | 못 잡음 | 4개 |
| 주술 불일치와 성분 누락 | 못 잡음 | 2곳 |
| 대상 형식 위반 | 못 잡음 | 7곳 |

같은 실행에서 검토자가 사실을 틀린 것도 하나 나왔다.
그래서 반영 전에 검토자가 든 사실을 확인하는 것을 통과 조건에 넣었다.

분량 구간으로 건너뛰는 조건을 세웠다. 짧은 글은 검토를 수행하지 않는다.
반영하지 않은 발견만 등록 단계의 보고에 한 줄로 덧붙인다.
발견 목록 전문을 그 턴에 내면 미리보기를 가린다.

## 2.1.0

「자가 점검」 단계가 표기 검사기를 직접 돌린다. 두고 있지 않으면 건너뛴다.

편집 훅은 편집 도구로 만든 파일만 검사한다.
Bash 의 heredoc 이나 `sed` 로 만든 본문은 훅이 돌지 않아 위반이 그대로 나간다.
외부로 나가는 글은 모두 이 스킬을 거치므로, 만든 방법과 무관하게 이 자리에서 돌린다.

점검 목록을 검사기가 잡는 것과 사람이 보는 것으로 나눴다.
사람이 보는 축에 비유, 문장 성분, 표와 본문의 중복을 넣었다.
검사기가 보지 못하는데 목록에 없던 것들이다.

## 2.0.0

**목표: 외부로 나갈 본문을 등록 전에 실제 렌더링으로 보여주고, 사용자가 읽은 뒤에 등록한다.**

- 본문 전문을 채팅에 다시 쓰지 않는다.
- 미리보기 턴은 미리보기로 끝낸다.

실행은 5단계다. 단계마다 통과 조건이 정해져 있다.

| 단계 | 통과 조건 |
| --- | --- |
| 수신자와 문체 | 누가 읽는지 정했고, 개인 문체 참조가 있으면 본문을 쓰기 전에 읽었다 |
| 본문 작성 | 본문 파일의 첫 줄이 새 내용이다 |
| 자가 점검 | 점검 목록을 통과했다 |
| 미리보기 | 사용자가 보는 워크트리의 탭에 새 본문이 떠 있다 |
| 등록 | 사용자가 읽고 응답한 다음 턴이다 |

개인 문체 참조를 어디에 두고 무엇을 적는지는 `references/persona.md` 로 옮겼다.

브라우저 드라이버를 저장소가 함께 배포한다.
`show-preview.sh` 가 호출자 지정, 저장소 안, 개인 심링크 순으로 찾는다.
저장소마다 스킬 배치가 한 단 달라 고정 상대경로로는 둘 다 맞출 수 없어, 위로 올라가며 찾는다.

PUBLIC 저장소에 들어 있던 사내 프로젝트와 저장소 이름을 뺐다.
`--project` 의 기본값이 사내 프로젝트명이라 인자를 주지 않으면 미리보기 머리에 그대로 렌더됐다.
기본값을 비우고, 값이 없으면 그 줄을 그리지 않는다.
