# harness-cleanup

CLAUDE.md, AGENTS.md, 스킬 문서 같은 하네스 지침이 지금 환경과 맞는지 문장마다 대조하는 수고를 덜어 준다.
깨진 참조, 지침 파일 사이의 반복, 문서에 적힌 개수, 돌지 않는 명령을 검사 스크립트로 먼저 찾고, 남은 문장은 감사 축으로 판정한다.
절마다 판정과 근거를 붙인 판정표를 먼저 보여 주고, 사용자가 승인한 항목만 고친 뒤 처음과 같은 범위에서 검사를 다시 돌린다.

승인 전에는 파일을 고치지 않는다.
다만 문서의 코드 블록이 실제로 도는지 보려고 블록을 실행하므로, 스킬이 블록과 위험 표시를 먼저 읽고 무엇이 도는지 확인한다.

## 이럴 때 쓴다

- 지침이 가리키는 파일, 절, 스킬이 아직 있는지 확인하고 싶다
- 세션 모델이 바뀌어, 이전 모델에 맞춰 쓴 지시가 아직 필요한지 보고 싶다
- 여러 지침 파일에 같은 내용이 반복되거나 서로 어긋난다
- 스킬의 절 이름을 바꾼 뒤, 그 절을 가리키는 다른 문서가 따라 바뀌었는지 확인하고 싶다
- 문서에 적힌 명령이 bash 와 zsh 에서 실제로 도는지 확인하고 싶다
- 대화 기록으로 스킬이 실제로 어떻게 쓰였는지 보고 고칠 곳을 찾고 싶다. 비용이 커서 요청할 때만 돈다

"하네스 정리", "지침 감사", "스킬 지침 점검", "프롬프트 교정" 처럼 말하면 이 스킬이 뜬다.
스킬 하나를 지목하면 감사 범위를 그 스킬 디렉터리로 좁힌다.

## 사용 예시

파일 이름, 절 이름, 건수는 예시다.

```text
나:   planning 스킬 지침 감사해줘

스킬: 범위를 planning 디렉터리로 좁혀 검사를 돌렸습니다. 대상 파일은 4개입니다.
      깨진 참조 1건, 반복 구간 1건, 개수 표기 2건이 나왔습니다. 판정표입니다.
        1  SKILL.md 의 「작업 분해」  제거  references/tasks.md 와 같은 내용     실측
        2  SKILL.md 의 「검증」 링크  축소  가리키는 파일이 없다                  실측
        3  SKILL.md 의 「단계 수」    유지  task 형식이 이 값을 쓴다             실측
        4  SKILL.md 의 「모델 주의」  보류  이전 모델에 맞춘 지시. 새 모델로 다시 테스트할 때까지 둔다  가이드
      1번 제목은 tests/test_planning.py 가 요구합니다. 테스트도 함께 고칠까요?
      어느 항목을 고칠까요?

나:   1, 2번. 테스트도 같이

스킬: 승인한 두 항목과 테스트만 고치고 커밋했습니다. 같은 범위로 다시 돌린 결과입니다.
        깨진 참조  1건  ->  0건
        반복 구간  1건  ->  0건
      실행한 검증: 처음과 같은 검사 명령과 저장소 테스트. 명령마다 결과를 아래에 적었습니다
      남은 검증 공백: 4번은 새 모델로 다시 테스트하지 않았습니다
```

## 받는 것

- 판정표. 대상 절마다 판정(유지, 제거, 축소, 추가, 보류), 근거, 근거 등급(실측, 도구 대체, 가이드, 추정)이 붙는다. 사용 기록으로 볼 때는 판정 `해결됨` 과 등급 `세션 실측` 이 더해진다. 고칠 것이 없는 유지와 보류 항목도 들어간다
- 지우거나 이름을 바꿀 문장을 테스트가 요구하면, 테스트도 고칠지 묻는 별도 승인 항목
- 승인한 항목만 고친 diff 와 커밋. 승인 뒤 표에 없던 항목이 생기면 판정표에 줄을 더해 다시 묻는다
- 재검증 결과. 처음 돌린 검사를 같은 범위에서 다시 돌린 값이고, 바꾼 동작에는 걸리는 표본과 걸리지 않는 표본이 붙는다
- 완료 보고. 처리한 판정, 전후 측정, 실행한 명령과 결과, 확인하지 못한 검증 공백을 적는다

## 준비

- `python3` 가 필요하다. 문서의 코드 블록을 bash 와 zsh 양쪽에서 돌리므로 두 셸도 있어야 한다

## 함께 쓰는 스킬

- 일반 제품 문서와 planning 산출물이 코드와 맞는지는 `docs-check` 가 맡는다
- 스킬을 새로 만들거나 파일 구조를 바꾸는 일은 `skill-creator` 가 맡는다
