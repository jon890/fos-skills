# 보드 「결정 필요」 상자에 사람이 답할 것만 보이기

확인: 2026-11-02

## 목표

보드의 「결정 필요」 상자를 열면 사용자가 지금 답하거나 판단해야 하는 것만 보인다. Orca 가 자동으로 만드는 worker 상태 알림은 그 worker 의 줄에 상태로 보이고, 저절로 사라진다.

- 배경: 11/02 ai-analysis Run 에서 답하지 않은 「막힘」 25건 가운데 24건이 Orca 자동 알림(「Worker stopped without reporting」 13건, 「Agent hit an error」 11건)이었다. 사용자는 상자에서 무엇을 확인해야 하는지 알 수 없었다.
- 자동 알림을 지우려고 답장을 달면 worker 를 깨운다. 11/02 에 계정 한도에 걸린 옛 worker 들이 답장에 깨어나 다시 한도 오류를 냈다.

## 범위

이번 범위:

- work-board 질문 상자의 모으기·제외와 표시(`work-board/hooks/register.js` 의 `queryQuestions`, 상자 그리기)
- 항목의 worker 줄에 멈춤·오류 상태 붙이기, 「worker 없음」 줄에 멈춘 시간 붙이기
- 「정할 것 묻기」 요청문(`DECIDE_PROMPT`) 강화
- 모든 저장소 보드의 기본 동작으로 바꾼다. 저장소별 설정은 두지 않는다

범위 밖:

- 보드에서 질문·막힘을 넘기는 단축키(사용자 결정 D6). 알림 상자의 x 넘기기는 그대로다
- orch 상주 루프의 `WORKER-IDLE`·`STAGE-STALLED` 알림 자체(orch 5.18.0, #297). 보드는 같은 판정을 읽기만 한다
- Orca 가 자동 알림을 만드는 방식 변경

## 요구사항과 인수 조건

| ID | 요구사항 | 인수 조건 | 검증 |
| --- | --- | --- | --- |
| R1 | 「결정 필요」 상자에는 worker 의 `question` 과 worker 가 직접 보낸 `escalation` 만 보인다 | Run 에 「Worker stopped without reporting」 과 「Agent hit an error」 escalation 이 있어도 상자에 그 줄이 없고, 결정 필요 수에도 세지 않는다 | register 단위 테스트(메시지 묶음 → 상자 줄) |
| R2 | Orca 자동 알림인지는 메시지 id 접두(`msg_stop_`, `msg_chaterr_`)로 가린다 | 같은 제목이라도 worker 가 보낸 메시지(id 가 `msg_` + 일반 id)는 자동 알림으로 보지 않는다 | 단위 테스트 |
| R3 | worker 가 직접 올린 막힘은 코디네이터가 답했거나, 그 worker 가 해제·중지됐으면 상자에서 사라진다 | 답장이 달린 막힘, 해제된 dispatch 의 막힘이 상자에 없다. worker 가 다시 움직여도 답 없는 막힘은 남는다 | 단위 테스트 |
| R4 | 항목의 worker 줄에 그 worker 가 멈췄으면 「멈춤 N분」 을 붙인다 | orch 상주 루프와 같은 입력(답을 기다리는 질문, 머지 대기, 화면 변화 포함)으로 판정해 멈춤(마지막 움직임 30분 이상 전, 또는 터미널 종료)인 worker 줄에만 표시가 붙고, 움직이면 사라진다. 질문을 보냈거나 머지를 기다리는 worker 에는 붙지 않는다. 기준은 orch 설정 `pipeline.idle_min`, `pipeline.idle_exited` 를 따른다 | 단위 테스트(판정 함수는 orch 것을 재사용) |
| R5 | 항목의 worker 줄에 그 worker 의 최근 에이전트 오류를 「오류: <요약>」 으로 붙인다. 요약은 「계정 한도」 같은 분류어이고, 분류하지 못한 오류는 본문 첫 줄이다 | 오류 escalation 뒤 그 worker 가 움직이지 않았으면 표시가 있고, 움직였거나 해제·중지됐으면 없다. 같은 오류가 여러 번 와도 한 줄이다 | 단위 테스트 |
| R6 | doing 항목에 끝나지 않은 단계가 있는데 맡은 worker 가 없으면 「worker 없음 · N시간」 을 보인다 | board.ts 가 단계를 바꿀 때 항목마다 시각을 남기고, worker 없이 30분(idle_min)이 지나면 지금 「⚙ worker 없음」 줄에 경과 시간이 붙는다. 시각이 없는 기존 항목은 다음 단계 갱신부터 보인다. wait·decide 항목에는 붙지 않는다. orch 루프가 없는 저장소에서도 동작한다 | 단위 테스트 |
| R7 | 「정할 것 묻기」 요청문이 막힘과 자동 알림을 다루는 방법을 담는다 | 요청문에 D7 의 지시가 들어 있다 | 요청문 문자열 테스트 |

## 설계

- 제외: `queryQuestions` 가 모은 `escalation` 가운데 id 가 `msg_stop_`, `msg_chaterr_` 로 시작하는 것은 질문 상자 후보에서 뺀다. 오류(`msg_chaterr_`)는 R5 의 worker 줄 표시 재료로 따로 넘긴다.
- 멈춤 판정: orch `lib/movement.ts` 의 판정 함수를 work-board 가 읽는다. 두 플러그인이 같은 번들에 있으므로 import 로 재사용하고, 판정 기준값은 orch 설정을 읽는다.
- 막힘이 사라지는 조건: 지금의 「답장이 달림」 에 「dispatch 가 해제·중지됨」 을 더한다. 살아 있는 worker 를 판정하는 기존 `active` 목록을 쓴다.
- 「worker 없음 · N시간」: board.ts 가 항목의 단계를 바꿀 때 그 항목에 갱신 시각을 남기고, 그 시각부터 잰다.
- 멈춤 판정 입력: orch-loop 의 `waitingOf` 와 `movement.json` 의 화면 변화를 함께 넘겨 루프와 같은 판정을 낸다.
