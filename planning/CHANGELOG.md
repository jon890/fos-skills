## 2.26.0

`verify_task.py` 가 playwright 를 테스트 실행으로 세지 않던 문제를 고친다.

- `playwright test` 를 테스트 실행으로 센다. `npx playwright test`, `pnpm exec playwright test`, `pnpm playwright test` 도 포함한다. 위치 인자는 jest, vitest 와 같이 경로 필터로 다뤄, `cd web && npx playwright test e2e/a.spec.ts` 가 `web/e2e/a.spec.ts` 선언을 실행한 것으로 인정된다. `playwright install` 처럼 테스트를 돌리지 않는 하위 명령은 세지 않는다
- npm 스크립트 값을 읽는 구조가 없어(이름이 `test` 이거나 `test:` 로 시작할 때만 센다) `"e2e": "playwright test"` 스크립트 인식은 넣지 않았다
- 테스트를 더했다. playwright 를 부르지 않는 줄은 그대로 위반이다

## 2.25.0

## 2.24.0

`verify_task.py` 가 운영 코드를 테스트로 세던 오탐과 호출자 경고의 잡음을 줄인다.

- `bottom-panel-spec.js`, `hud-spec.ts` 처럼 `-spec.` 으로 끝나는 운영 코드를 테스트로 보지 않는다. spec 은 `.spec.ts`, `_spec.rb` 처럼 `.` 나 `_` 로 이은 것만 테스트다. `-test.` 는 그대로 테스트다. 오탐이 있으면 코드만 바꾸는 phase 가 검증 없이 통과했다
- `print`, `get`, `map` 같은 어느 저장소에나 있는 이름은 호출자 경고에서 뺐다. 낱말로 grep 하는 한 거의 모든 파일이 걸려 경고 28건 중 23건이 이 이름이었다
- 「코드 변경을 검증할 테스트 파일 … 없다」 위반이 코드로 센 변경 파일을 함께 보여 준다. 어떤 항목 때문에 걸렸는지 찾으러 phase 를 다시 읽지 않는다
- 걸리는 표본(`-spec.js` 만 신규인 phase)과 걸리지 않는 표본(`.spec.ts`, `_spec.rb`, `-test.js`)을 테스트에 더했다

## 2.23.0

검증 절의 `python3 -m unittest .github/...` 처럼 점 디렉터리가 든 경로를 `verify_task.py` 가 위반으로 막는다.

- `python -m unittest` 는 파일 경로를 모듈 이름으로 바꿔 `.github.tests.test_x` 를 import 하므로 `ValueError: Empty module name` 으로 테스트를 하나도 돌리지 않는다. `./` 로 시작해도, 점 디렉터리가 중간에 있어도 같다 (Python 3.14 실측)
- 위반 문구에 `python3 -m unittest discover -s <디렉터리> -p <파일>` 형태를 낸다. `discover` 와 점 디렉터리가 없는 경로, `-k` 의 값은 통과한다
- 막는 명령 셋과 통과하는 명령 넷을 테스트에 더했다
