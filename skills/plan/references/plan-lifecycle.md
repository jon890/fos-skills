# 계획 보존과 삭제

계획 폴더는 PR 하나의 실행 기록이다. 지속할 요구사항·기술 결정은 spec/design/공유 계약/ADR 이 소유한다.
이 문서가 plan·implementation·verify·docs-consolidate·orch·docs-audit 의 계획 수명 기준을 소유한다.

1. 저장소 오버레이·지침이 보존/삭제를 정했으면 우선한다. 기존 계획을 일괄 이동·삭제하지 않는다.
2. 별도 정책이 없으면 기존 기본값을 유지한다. 구현·인수 검증·문서 대조와 기록 보존을 마친 뒤 해당 PR 의 계획 폴더만 제거한다.
   계획이 필요한 verify 전에 implementation 이 지우지 않는다. 기존 spec 없는 호환 절차는 자체 리뷰·검증 완료를 인수 증거로 넘긴다.
3. 제거 전에 orch 가 검증 계획의 사례·절차·기대값과 실제 결과·커밋·환경·증거 위치를 PR 본문 또는 PR 별 증거 파일에 보존한다.
   남은 원격 검증의 선행 조건·시점·위치·명령·기대값, deferred 의 목표·이유·선행 조건도 옮긴다. 삭제될 계획 링크만 남기지 않는다.
4. 중요한 결정이 계획에만 있으면 책임 문서로 옮기고 문서 재검토를 받는다. 보존할 증거가 없거나 검증이 미완료면 지우지 않는다.
5. 보존 정책이면 계획을 남기고 실제 구현·검증 완료 뒤 status 를 completed 로 기록한다. 남은 배포 검증과 기능 전체 완료는 별도로 보고한다.
6. 삭제 범위는 인계된 TASKS_DIR/PLAN 하나다. 기능 폴더·spec/design·다른 계획은 남긴다. 삭제 같은 비제품 변경은 문서/링크 검사만 다시 한다.

문서 감사의 제거 후보는 머지된 PR 또는 completed 계획부터 본다. 보존 정책이면 후보로 올리지 않는다.
후보는 결정·검증 증거가 다른 책임 위치에서 복원되는지 확인한 뒤 제안한다. docs-audit 의 기존 승인 절차는 유지한다.
문서·코드는 제거될 계획에 계약의 내용을 맡기지 않는다. 결정은 ADR, 변경 이력은 PR 을 참조한다.
