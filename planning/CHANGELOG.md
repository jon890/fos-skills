## 1.4.0

pitfalls 대조에서 드러난 충돌을 해소했다.

`docs/pitfalls/plan/stale-base-assumption` 은 phase 가 인용하는 파일·심볼을 현재 `origin/main` 에서
검증하고, 선행 plan 이 미머지면 머지를 기다리거나 현재 base 기준으로 다시 쓰라고 요구한다.
그런데 규모 분할 점검은 후속 plan 을 미리 만들고 실행 직전 rebase 하도록 하면서
task 파일에 의존 관계를 남기지 말라고 지시했다.

그 조합이 위험을 숨긴다. 후속 task 가 선행 plan 의 미래 경로를 전제로 써도
그 전제가 task 어디에도 기록되지 않아 실행자가 알 수 없다.

기계 판독용 의존 필드는 계속 만들지 않되, 선행 plan 산출물을 전제하는 phase 는
그 전제를 본문에 적도록 바꿨다. 전제가 없는 phase 는 현재 base 기준으로만 쓴다.

구조:

- 8단계 표를 앞으로 올렸다. 문서 절반을 읽고 나서야 무슨 단계를 밟는지 알 수 있었다.
- `모호함 능동 발굴` 절을 `핵심 원칙` 의 항목으로 흡수했다.
- `plan 네이밍` 을 `동시성 안전` 으로 병합했다. 번호 선점과 같은 주제이고, 자기 참조 한 줄이 사라졌다.

걷어낸 것:

- 동시성 안전의 근거 서술. git 상식이거나 다른 절이 소유한 내용이었다.
  절 자체는 남긴다 — 다른 세션의 존재는 이 세션에서 관측할 수 없어 모델이 자율로 도출할 수 없다.

- 단계 번호는 1~8 그대로여서 재배치가 없다.

중복 제거:

- "모호함 능동 발굴" 절의 추측 금지·하나씩 토론·확정 후 진행 세 항목을 지웠다.
  각각 통과 조건, 핵심 원칙의 질문 규율, 통과 조건과 겹쳤다.
- 핵심 원칙의 "간결한 문서" 를 지웠다. 일반 문서 원칙이다.
- 자체 검토 하위 3항목을 지웠다. `task-create.md` 의 "자체 검토" 절이 같은 내용을 갖고 있다.

  커밋과 push 는 한 항목으로 합쳤다.

수정:

- 사용자만 답할 결정은 그대로 멈춘다 — 취향·범위·되돌리기 어려운 결정, plan 분할안, 새 의존 도입, task 검증 위반.

- 필수 관리 문서 절의 절차를 지웠다. `references/step-7-docs.md` 가 같은 문구로 갖고 있다.
