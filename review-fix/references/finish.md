# 마무리

「마무리」 단계에서 읽는다. resolve, 학습 누적, 결과 보고를 이 순서로 한다.

## 리뷰 스레드 resolve

```bash
python3 scripts/review_threads.py list <owner> <repo> <N>
python3 scripts/review_threads.py resolve --repo <owner>/<repo> <THREAD_ID> ...
```

resolve 는 「이 지적을 처리했다」 는 표시다.
반영했거나 반영하지 않기로 판단하고 그 판단을 회신한 스레드만 resolve 한다.

**머지 전에 미해결 수가 0 인지 이 명령으로 확인한다.**

```bash
python3 scripts/review_threads.py list --count <owner> <repo> <N>
```

출력은 정수 하나다. 0 이 아니면 머지 가능으로 보고하지 않는다.
`list` 출력을 `grep` 으로 세지 않는다. 한 줄 JSON 에 여백이 없어 `"resolved": false` 패턴은 늘 0 이 나온다.
미해결 스레드가 남은 PR 을 머지 가능으로 보고해 브랜치를 정리했다가 PR 이 닫힌 실측이 있다.

resolve 한 뒤 보호 규칙이 풀렸는지 본다.

```bash
gh pr view <N> --json mergeStateStatus
```

## 학습 누적

fix 가 끝났다고 항상 학습하지 않는다. **재현 가능한 패턴**만 누적한다.

| 누적한다 | 누적하지 않는다 |
|---|---|
| 같은 실수가 다른 코드에서도 날 수 있다 | 1회성 오타 |
| grep 이나 lint 룰로 검출할 수 있다 | 특정 PR 맥락에서만 성립한다 |
| | 칭찬과 단순 확인 |

누적 위치를 오버레이나 그 저장소 지침이 지정하면 그것을 따른다.

**지정이 없으면 `docs/pitfalls/code-review/<패턴>.md` 를 기본값으로 쓴다.**
모노레포면 `docs/` 대신 지적이 달린 파일이 속한 하위 프로젝트 오버레이의 docs 경로를 쓴다.
이 구조를 쓰는 저장소는 `docs/pitfalls/` 아래를 `plan/`, `code-review/`, `team/` 으로 나누고
`INDEX.md` 를 함께 둔다. 없는 하위 디렉터리를 미리 만들지 않는다.

- 패턴 하나당 파일 하나로 두고, 같은 패턴이면 기존 파일을 갱신한다.
- `INDEX.md` 가 있으면 함께 갱신한다. 생성기가 있으면 그것을 쓴다.
- **`docs/` 자체가 없는 저장소면 디렉터리를 만들지 않는다.** 결과 보고로만 남긴다.
  문서를 두지 않기로 한 저장소에 구조를 새로 만드는 것은 이 스킬이 정할 일이 아니다.

ADR 급 결정은 구조화 질문 도구가 있으면 그것으로 사용자에게 확인받는다.

학습 커밋은 같은 fix PR 에 커밋 하나로 더한다. fix 커밋과 섞지 않는다. 한 번 호출하면 PR 하나다.

## 결과 보고

```
## 완료: PR #<N>

🔀 Conflict 해결 (<건수>)
  - <파일>: <결정 요약>
✅ 적용된 수정 (<건수>)
  - <파일>: <무엇을 수정했는지>
📋 이슈로 등록 (<건수>)
  - #<번호>: <범위가 커서 이슈로 추적>
💬 회신 완료 (<건수>, 스레드 <건수> / 인라인 <건수>)
🧵 스레드 resolve (<건수>)
⏭️ 건너뛴 항목 (<이유>)
📚 학습 누적 (<건수> 또는 「신규 학습 없음」)

커밋 (<건수>)
  - <해시> <메시지>
```

**커밋을 목록으로 낸다.** 지적별로 나뉘어 있어 하나가 아니다.
「커밋과 push」 단계가 만든 대응 표의 해시를 읽어 채운다.
학습 커밋은 이 목록에 함께 적고, base 동기화 커밋은 fix 가 아니므로 「Conflict 해결」 절에서 다룬다.
