# 브라우저 오버레이

**목표: 같은 사이트의 다음 작업이 화면을 다시 더듬지 않고 오버레이를 따라 바로 끝난다.**

코어 `SKILL.md` 는 어느 사이트에서나 같은 판단과 공간 규칙만 담는다.
사이트마다 다른 주소와 화면 순서는 그 사이트를 쓰는 저장소의 `<repo-root>/.claude/browser-overlay.md` 에 둔다.
fos-skills 는 공개 저장소라 사내 주소와 화면 순서를 코어에 넣지 않는다.

## 담는 것

| 항목 | 담는 것 | 담지 않는 것 |
| --- | --- | --- |
| 사이트 | 작업을 시작하는 주소와 그 사이트가 무엇인지 한 줄 | |
| 프로필 용도 | `BROWSER_EGO_PURPOSE` 에 줄 값(`work`, `personal` 같은 것) | 머신마다 다른 프로필 id |
| 로그인 | 로그인 시작점 주소, 로그인 화면으로 튕겼는지 판정하는 주소 패턴 | 아이디, 비밀번호, OTP, 토큰 |
| CLI 와 API 로 안 되는 이유 | 1단계에서 브라우저로 온 이유. 다음 작업이 같은 조사를 반복하지 않게 한다 | |
| 화면 순서 | 작업 이름마다 메뉴 경로, 누르는 버튼, 채우는 칸을 순서대로 | 그때그때 다른 입력값 |
| 확인받을 버튼 | 그 사이트에서 되돌리기 어려운 버튼과 그 버튼이 바꾸는 것 | |
| 실측한 함정 | 화면에서 겪은 문제와 피하는 방법, 실측한 날짜 | 드라이버 백엔드의 함정. 그것은 `browser-driver/README.md` 가 소유한다 |

## 형식

작업 이름마다 절을 하나 둔다. 화면 순서는 번호 목록으로 쓰고, 버튼과 메뉴 이름은 화면에 보이는 글자 그대로 백틱으로 감싼다.

```markdown
# 브라우저 오버레이

## 공통

- 사이트: https://console.example.com — 사내 클라우드 콘솔
- 프로필 용도: work
- 로그인 시작점: https://console.example.com/login
- 로그인 화면 판정: 주소가 `https://sso.example.com/` 으로 시작한다

## 배포 시나리오 만들기

브라우저로 하는 이유: 시나리오 생성 API 가 공개돼 있지 않다 (2026-11-03 확인).

1. `https://console.example.com/projects/PROJECT_ID/deploy` 를 연다
2. `시나리오` 탭에서 `새 시나리오` 를 누른다
3. `이름`, `대상 서버 그룹` 을 채운다
4. `저장` 을 누른다. 확인받지 않아도 된다(바로 지울 수 있다)

확인받을 버튼: `실행` — 대상 서버에 실제로 배포한다.

함정:

- 서버 그룹 목록은 스크롤해야 다 뜬다. `waitjs` 로 항목 수가 늘었는지 본다 (2026-11-03)
```

`PROJECT_ID` 처럼 작업마다 바뀌는 값은 대문자 자리표시자로 두고, 그 값을 어디서 얻는지 한 줄 덧붙인다.

## 쓰는 법

**작업에서 새로 안 것은 그 자리에서 더한다.** 기억으로 나중에 적으면 메뉴 이름과 순서가 틀린다.
작업을 끝내고 `reset` 을 부른 직후, 화면을 본 기억이 남아 있을 때 쓴다.

- 오버레이가 없으면 위 형식으로 새로 만든다.
- 화면 순서가 바뀌었으면 옛 순서를 지우고 새 순서로 고친다. 옛 순서를 남겨 두면 다음 작업이 어느 쪽을 따를지 헤맨다.
- 함정에는 실측한 날짜를 붙인다. 오래된 함정은 다음에 그 화면을 볼 때 아직 있는지 확인하고 지운다.
- 오버레이를 고친 것도 저장소의 변경이다. 그 저장소의 커밋 규칙을 따르고, 작업 보고에 고쳤다고 적는다.

**공개 저장소에서는 사내 주소와 화면 순서를 커밋하지 않는다.**
그 저장소의 오버레이가 git 에 올라가면 누구나 읽는다. `.gitignore` 에 넣어 로컬에만 두거나, 사내 저장소의 오버레이에 적는다.
