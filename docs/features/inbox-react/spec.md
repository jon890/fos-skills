# inbox: 알림마다 답장·리액션·넘김 가운데 권장 동작을 붙이고 리액션만 남긴다

확인: 2026-11-24

## 목표

「적용된 것 확인했습니다. 감사합니다」 처럼 묻는 것이 없는 알림에 답장을 쓰지 않고 👍 리액션만 남긴다.
inbox 가 알림을 읽을 때 항목마다 답장, 리액션, 넘김 가운데 권장 동작과 이유를 붙여 사용자가 빨리 고른다.

지금은 답장(`reply`)과 넘김(`dismiss`)뿐이다([work-inbox](../work-inbox/spec.md) D5).
dooray-cli 0.34.0 에 업무 댓글 리액션 명령 `dooray post comment react` 가 들어갔다. 0.35.0 부터는 API 키 방식에서도 저장된 웹 세션(`dooray config set session-cookie -`)으로 리액션을 단다. 세션이 없거나 만료면 종료 코드 3 이다.

## 범위

이번 범위:

- inbox: 업무 댓글 멘션에 리액션을 다는 `react` 명령(PR 1).
- inbox: 알림을 읽는 단계에서 항목마다 권장 동작과 이유를 대화에 보인다(PR 1).
- dooray-cli: 메신저 메시지에 리액션을 다는 명령(PR 2). 웹 메신저의 비공개 경로를 사용자 혼자 있는 테스트 방에서 실측해 찾는다.
- inbox: 메신저 멘션에도 `react` 를 쓴다(PR 3, PR 2 뒤).

범위 밖:

- board 화면에 권장 동작을 보이는 것. 권장은 inbox 대화에서만 보인다.
- 새 업무(담당·참조로 온 업무) 알림의 리액션. 댓글이 아니라 달 곳이 없다. 넘김이나 답장을 권한다.
- 리액션 떼기. dooray-cli 의 `--remove` 로 사람이 뗀다.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 업무 댓글 멘션에 리액션을 단다 | `inbox.ts react <id>` 가 그 알림 댓글에 기본 이모지를 단다. `--emoji <이름>` 이면 그 이름을 단다. 이모지 문자나 dooray-cli 가 거절하는 이름은 dooray-cli 의 오류를 그대로 알리고 아무것도 달지 않는다. 중복 리액션은 dooray-cli 결과를 따른다 |
| REQ2 | 리액션을 달 수 없는 항목은 거절한다 | 새 업무(담당·참조), 댓글 id 가 없는 업무 항목, PR 3 전의 메신저 멘션, 이미 답함이나 넘김인 항목에 `react` 를 부르면 `--yes` 가 있어도 아무것도 달지 않고 종료 코드 1 로 이유와 권할 동작(답장이나 넘김)을 알린다 |
| REQ3 | 확인 없이 달지 않는다 | `--yes` 가 없으면 어느 알림에 어떤 이모지를 달지 보여 주고 종료 코드 3 으로 끝난다. `--yes` 가 있을 때만 단다 |
| REQ4 | 리액션을 단 항목은 답함이 된다 | 달기에 성공하면 그 항목은 다음 받기를 기다리지 않고 「답함」 이 되어, work-inbox R5 처럼 흐리게 보이고 새 알림 수에서 빠진다 |
| REQ5 | 기본 이모지를 바꿀 수 있다 | 사람 단위 설정 파일 `inbox.json` 의 값으로 기본 이모지 이름을 바꾼다. 값이 없으면 `+1` 이다. 키 이름은 설계가 정하고 `references/config.md` 표에 적는다 |
| REQ6 | 항목마다 권장 동작을 보인다 | `SKILL.md` 에 권장 기준표가 있다: 묻는 것이나 요청이 있으면 답장, 감사·확인 완료처럼 묻는 것이 없으면 리액션, 내 일과 무관하면 넘김. REQ2 의 항목에는 리액션을 권하지 않는다. 알림을 읽을 때 대화에 항목마다 권장과 한 줄 이유가 나온다. 권장만으로 리액션을 달지 않고 REQ3 의 확인을 거친다 |
| REQ7 | 세션이 없거나 만료면 넘김을 권한다 | dooray-cli 의 `post comment react` 가 종료 코드 3(세션 없음·만료)으로 끝나면 inbox 는 종료 코드 1 로 끝난다. 아무것도 달지 않았다고 알리고, 그 항목에 넘김을 권하며, `dooray config set session-cookie -` 로 세션을 다시 넣는 방법을 한 줄 알린다. 항목 상태는 바꾸지 않는다. inbox 의 종료 코드 3 은 확인 필요 전용으로 남긴다 |
| REQ8 | 필요한 dooray-cli 버전 | API 키 방식에서 리액션을 다는 dooray-cli 0.35.0 이상을 요구한다. 그보다 낮으면 `react` 는 아무것도 달지 않고 종료 코드 1 로 dooray-cli 를 올리라고 알린다 |
| REQ9 | 메신저 리액션 명령을 만든다 | dooray-cli 에 메신저 메시지에 리액션을 달고 떼는 명령이 생긴다. 사용자 혼자 있는 테스트 방에서 그 명령으로 달고 뗀 결과를 명령 출력과 웹 화면으로 확인한다. 경로는 ego 브라우저의 두레이 웹 메신저에서 리액션 요청을 관찰해 찾는다. 다른 사람이 있는 방에는 실험하지 않는다. 경로를 찾지 못하면 PR 2 를 열지 않고 이유를 보고하며 PR 3 은 보류한다 |
| REQ10 | 메신저 멘션에도 리액션을 단다 | REQ9 이 들어간 dooray-cli 버전이면 `inbox.ts react <id>` 가 메신저 멘션 메시지에도 REQ1~REQ4, REQ7 과 같게 동작하고, REQ6 가 메신저 멘션에도 리액션을 권한다. 그 버전이 없으면 메신저 항목의 `react` 는 거절하고 넘김을 권한다 |

## 도메인 규칙 변경

도메인 규칙 변경 없음: inbox 의 처리 방법에 리액션이 하나 더해질 뿐 알림과 답함의 의미는 그대로다.
