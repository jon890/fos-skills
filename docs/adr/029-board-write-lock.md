# ADR-029: 보드 쓰기는 `board.ts` 의 파일 잠금을 지나고, 통째 저장은 읽을 때의 줄 지문으로 거절한다

- **status**: `accepted`
- **decision-type**: `architecture`
- **areas**: `data`
- **현재 규칙의 원본**: [보드 명령 기술 설계의 「잠금」 과 「줄 지문과 낡은 목록 거절」](../features/orch-board-cli/design.md#잠금-pr1), `extensions/work-board/bin/board.ts` 와 `file-lock.ts` 의 파일 맨 위 설명.
- **결정**: 보드 파일(`board.json`)을 쓰는 코드는 `board.ts` 하나이고, 쓰는 동작마다 읽기부터 쓰기까지 보드 파일 옆의 잠금 파일을 잡는다. 못 잡으면 5초 뒤 거절하고, 30초 넘은 잠금은 죽은 프로세스의 것으로 보고 넘겨받는다. 호출자가 미리 읽은 줄 목록을 통째로 저장할 때는 읽을 때의 줄 지문(줄 글과 끝냄 값의 해시)을 함께 넘기고, `board.ts` 가 잠금 안에서 지금 값과 다르면 저장하지 않는다. 잠금 코드는 보드 형식을 모르는 모듈로 떼어 orch 의 다른 상태 파일도 같은 규약으로 쓴다.
- **맥락**: 루프의 동기화, 띄우기, 마무리, 코디네이터가 같은 보드 파일을 따로 도는 프로세스로 고친다. 잠금이 없어 늦게 쓴 쪽이 앞 변경을 지웠고, 동기화가 먼저 읽어 둔 줄 목록을 나중에 통째로 저장해 그 사이 바꾼 단계 글을 옛 글로 되돌렸다(스펙 「조사한 사실」 의 재현). 기다리는 시간과 낡은 잠금의 기준, 낡은 목록을 거절한다는 동작은 사용자가 정했다([스펙](../features/orch-board-cli/spec.md) DECISION7, DECISION16). 이 ADR 은 그 동작을 어디에 어떤 방법으로 두는지를 남긴다.
- **대안 기각**:
  - 새 명령(`orch board`)에만 잠금을 둔다: 루프가 틱마다 `board.ts` 를 직접 불러 겹침이 그대로 남는다.
  - 프로세스가 살아 있는지 확인해 낡은 잠금을 가린다: 확인 방법이 운영체제마다 다르고, 죽은 프로세스의 번호를 다른 프로세스가 다시 받으면 틀린다. 정상 잠금은 한 번 쓰는 동안(밀리초)만 잡혀 나이만으로 충분하다.
  - 낡은 잠금을 지우고 다시 만든다: 둘이 같은 낡은 잠금을 함께 지우면 둘 다 새로 만들어 함께 쥔다. 이름 바꾸기로 덮고 표지를 다시 확인한다.
  - 항목에 버전 번호를 저장해 낡은 목록을 가린다: 보드 형식이 바뀌고 창과 옛 번들이 그 값을 지켜 써야 한다. 지문은 읽을 때마다 계산해 저장하지 않는다.
  - 항목의 `stepAt` 시각으로 가린다: 초 단위라 같은 초에 일어난 두 쓰기를 가리지 못한다.
  - 통째 저장을 없애고 줄 단위 동작으로만 고친다: 호출자 여러 곳의 명령 조립을 다시 써야 한다. 지문 거절은 지금 호출에 옵션 하나를 더하는 것으로 같은 사고를 막는다.
- **결과**:
  - 얻는 것: 서로 다른 항목을 함께 고쳐도 둘 다 남는다. 읽은 뒤 바뀐 줄을 통째 저장이 덮지 않는다. 승인 대기 저장([보드 승인 버튼 스펙](../features/board-approval/spec.md) DECISION12)처럼 뒤에 오는 상태 파일이 같은 잠금 규약을 쓴다.
  - 감당할 것: 잠금을 쥔 채 죽은 프로세스가 있으면 30초 동안 다른 쓰기가 5초씩 기다린 뒤 거절된다. 지문으로 거절된 호출자는 다시 읽어 판정해야 한다(동기화와 릴리스 확인은 그 항목을 건너뛰고 다음 실행에서, 띄우기와 마무리는 바로 한 번 더). 창처럼 node 밖에서 도는 코드는 잠금 모듈을 쓰지 못해 같은 규약을 따로 구현해야 한다. 갱신 전에 띄운 루프는 옛 `board.ts` 로 잠금 없이 써서 다시 띄울 때까지 겹침이 남는다. 보드 파일을 `board.ts` 밖에서 직접 고치면 두 장치 모두 듣지 않는다.
- **확인 방법**: `extensions/work-board/tests/` 의 잠금 테스트(`file-lock.spec.ts`, `board-lock.spec.ts`)와 지문 테스트(`board-exact.spec.ts`), orch 의 `board-sync`, `lib-board`, `finish-pr` 테스트의 낡은 목록 재현.
