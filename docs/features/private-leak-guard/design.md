# 비공개 낱말 검사 기술 설계

스펙: [spec.md](spec.md)

## 요구사항 연결

| ID | 해결 방법 |
| --- | --- |
| REQ1 | 목록 읽기와 비교는 `skills/orch/scripts/lib/private-words.ts` 한 곳에 둔다. 목록 형식은 [데이터 스키마](../../data-schema.md)의 「사용자 설정 파일」 이 소유한다 |
| REQ2 | 목록에 낱말이 없으면 훅, 관문, 자동 머지가 아무것도 하지 않는다. `orch doctor` 는 공개 저장소에서 `PRIVATE-WORDS-MISSING` 줄을 낸다 |
| REQ3 | worker 훅(`githooks/dispatch.mjs`)이 pre-commit 에서 스테이징한 추가 줄과 파일 이름을, commit-msg 에서 메시지를 검사기 사본으로 본다 |
| REQ4 | 머지 조건 함수(`queue/steps/gate.ts` 의 `gateReasons`)가 `queue/steps/private-words.ts` 로 PR 본문, 일반 댓글, 리뷰, 코드 줄 댓글을 본다. `orch queue gate` 와 머지 큐가 같은 판정을 쓴다 |
| REQ5 | 결과는 위치(파일과 줄, 글 종류와 id, 줄 번호)와 목록의 줄 번호만 담는다. 파일 이름의 낱말은 `***` 로 가린다. 관문이 내는 다른 이유와 알림 줄(본문에서 옮긴 근거 값 등)도 내보내기 전에 `***` 로 가린다. 머지 보류 이유가 낱말을 품으면 관문의 HOLD 줄과 루프 로그에 값 대신 위치를 쓴다 |
| REQ6 | 공개 여부는 머신 폴더의 `repo-visibility.json` 에 저장소(공통 git 폴더)마다 기억한다. 읽지 못하면 공개로 보고 검사한다 |

## 책임과 경계

- `lib/private-words.ts`: 목록, 대소문자를 가리지 않는 부분 문자열 비교, 위치 만들기, 값 가리기, 공개 여부 기억, 훅에서 부르는 명령줄. Node 내장 모듈만 쓴다. `lib/commit-check.ts` 가 훅 폴더에 이 파일을 그대로 복사하기 때문이다.
- `githooks/dispatch.mjs`: 목록이 있을 때만 검사기 사본을 띄운다. 검사기가 돌지 못하면 목록이 있으므로 거절한다.
- `queue/steps/private-words.ts`: 관문에서 GitHub 글을 읽어 `private` 이유를 만든다. `private` 은 worker 가 고칠 이유라 머지 큐는 스레드, 근거 블록과 같이 다른 PR 을 먼저 처리한다.
- `queue/steps/spec-hold.ts`, `loop/steps/auto-merge.ts`: 보류 이유를 로그에 쓰기 전에 가린다. 자동 머지는 따로 검사하지 않는다. 띄운 머지 큐의 관문이 막는다.
- `doctor/orch-doctor.ts`: 목록이 없는 공개 저장소를 알린다.

## 인터페이스와 데이터

- 훅 출력: `orch 커밋 검사: 비공개 낱말 목록(<경로>)의 낱말이 있어 커밋하지 않았다` 와 위치 줄(`a.txt:2(목록 2번째 줄)`, `커밋 메시지 3번째 줄(…)`, `파일 이름 ***.txt(…)`).
- 관문 이유: `비공개 낱말 목록의 낱말이 있다(값은 보이지 않는다): PR 본문 8번째 줄(목록 3번째 줄), 일반 댓글 12 1번째 줄(…)`. 댓글을 읽지 못하면 `비공개 낱말 검사: <글 종류> 조회 실패`(lookup).
- doctor: `PRIVATE-WORDS-MISSING <목록 경로>` 와 들여 쓴 안내 줄. 경고라 종료 코드를 바꾸지 않는다.
- 공개 여부 기억의 형식은 데이터 스키마의 「머신 폴더에 두는 파일」 이 소유한다.

## 실패와 일관성

- 훅이 공개 여부를 읽지 못하거나 검사기가 돌지 못하면 막는 쪽으로 정한다(스펙 DECISION5).
- 관문이 댓글을 읽지 못하면 `lookup` 이유로 막는다. 확인하지 못한 것을 통과로 보지 않는 관문의 기존 규칙과 같다.
- doctor 는 공개 여부를 읽지 못하면 알리지 않는다. 알림일 뿐이라 비공개 저장소에 잘못 알리지 않는 쪽을 고른다.
- 공개 여부 기억은 잃어도 되는 값이다. 쓰지 못하면 다음 조회가 다시 묻는다.

## 검증 전략

- 단위: 목록 형식, 더한 줄과 지운 줄, 자르는 줄, 가리기, 댓글 줄 해석, 기억 기한, doctor 줄(`tests/lib-private-words.spec.ts`).
- 훅: 연결된 임시 워크트리에 실제로 훅을 걸고 가짜 홈과 가짜 gh 로 커밋한다(`tests/private-words-hook.spec.ts`).
- 관문과 큐: 가짜 gh 의 REST 응답으로 본문과 댓글을 바꿔 `orch queue gate` 와 머지 큐를 돌린다(`tests/queue-gate.spec.ts`).
- 자동 머지: 보류 이유가 가려지는지 루프 출력으로 본다(`tests/orch-loop-auto-merge.spec.ts`).
- 모든 테스트는 가상 낱말(`example-secret`)만 쓰고 출력에 그 낱말이 없는지 함께 본다.

## 결정

| ID | 결정 | 이유 |
| --- | --- | --- |
| DECISION1 | 대소문자를 가리지 않는 부분 문자열로 찾는다 | 경로나 컨테이너 이름이 더 긴 글에 들어가거나 대소문자만 달리 써도 찾아야 한다. 잘못 막는 비용이 새는 비용보다 작다 |
| DECISION2 | 댓글과 리뷰는 관문 때마다 캐시 없이 끝 페이지까지 읽는다 | 같은 HEAD 에서 댓글만 더하거나 고칠 수 있다 |
| DECISION3 | 훅의 공개 여부는 gh 응답 캐시(5분) 대신 머신 폴더에 1시간(실패는 10분) 기억한다 | 훅 사본은 `lib/gh.ts` 를 쓰지 못하고, 공개 여부는 PR 상태보다 훨씬 드물게 바뀐다. 관문과 doctor 도 같은 기억을 써서 조회를 줄인다 |
| DECISION4 | 검사기를 훅 폴더에 복사한다 | 한국어 검사기와 같은 이유다. 플러그인 설치 경로는 갱신하면 없어진다 |
| DECISION5 | 머지 중(MERGE_HEAD)의 pre-commit 만 보지 않는다. 리베이스, cherry-pick, revert 중에는 본다 | 머지로 스테이징한 줄은 다른 브랜치에서 온 것이다. 리베이스 중 충돌을 풀며 새로 쓴 줄과 amend 는 검사받아야 한다(독립 리뷰 지적) |
| DECISION6 | 보류 이유와 관문 출력 가리기는 공개 여부와 상관없이 한다 | 공개 여부를 묻지 않아도 되고, 로그에 값을 남기지 않는 쪽이 늘 안전하다 |
| DECISION7 | 바이너리로 보이는 파일도 `--text` 로 줄을 본다 | NUL 이 섞인 텍스트나 `-diff` 속성 파일로 검사를 건너뛰지 않게 한다(독립 리뷰 지적). 너무 커서 읽지 못하면 거절한다 |
| DECISION8 | 테스트는 `ORCH_PRIVATE_WORDS` 로 목록 경로를 바꾼다 | 사용자가 실제 목록을 만들어도 관문과 큐 테스트의 결과가 머신마다 달라지지 않게 한다. 사용자 설정 자리는 홈 아래 한 곳 그대로다 |

## 구현 순서

PR 하나다.

1. `lib/private-words.ts` 와 단위 테스트
2. 훅 본체와 훅 폴더 복사, 훅 테스트
3. 관문 이유와 보류 가리기, 관문 테스트
4. 자동 머지 로그 가리기와 테스트
5. doctor 줄과 문서(데이터 스키마, gh 호출 예산, launch, overlay)
