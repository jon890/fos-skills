# 한국어 표현 정책

사용자 응답과 문서는 한국 개발자가 한 번에 이해할 수 있는 자연스러운 한국어로 작성한다.
코드 식별자, 명령어, 경로처럼 원문이 정확해야 하는 문자열은 번역하지 않는다.

## 어색한 말 매핑 표

이 표는 이 스킬의 `scripts/korean-style-check.py` 가 런타임에 읽는 단일 소스다.
**검사기가 실패로 막는 것은 이 표의 금지 열뿐이다.**
누가 봐도 어색한 음차, 비유어, 지어낸 번역어만 둔다. 평범한 우리말의 어색한 쓰임은 의미 점검에서 본다.
원어 열은 검사하지 않는다. 영어 원어를 그대로 쓰는 것은 금지가 아니다.

| 금지 | 원어 | 권장 |
| --- | --- | --- |
| 매트릭스 | matrix | 표, 영향 표, 변경 표 |
| 트리아지 | triage | 분류, 분류 작업 |
| 스파이크 | spike | 사전 조사, 탐색 작업, 실증 |
| 스윕 | sweep | 전수 검사, 한 번에 검사, 훑기 |
| 리포지토리 위생 | repo hygiene | 리포지토리 정리 |
| 외과적 | surgical | 정밀한, 특정 부분만 대상으로 삼는 |
| 단일 진실원 | single source of truth | 단일 소스 |
| 되돌이 | loop | 루프 |
| 오살 | | 엉뚱한 프로세스를 죽이는 문제 |
| 사전 소진 | | 사전 해소 |
| 시험 | test | 테스트 |
| 기계가 / 기계로 / 기계적 | | 자동 검사, CI, 도구, 자동으로 (문맥에 맞춰 고른다) |


## 문장 구성

이 절부터 아래는 지침이다. 검사기는 일부를 경고로 알릴 뿐 실패로 막지 않는다.

- 조사와 어미를 생략하지 않는다. 명사만 이어 붙여 독자가 관계를 짐작하게 만들지 않는다.
- 평문은 서술어와 종결어미로 끝낸다. 제목, 표, 목록 항목은 명사구로 끝내도 된다.
- 한 산출물 안에서 공손체와 평서체를 섞지 않는다.
어느 쪽으로 갈지 먼저 정하고 끝까지 지킨다. 제목과 표, 목록 항목은 이 판단에서 제외한다.
- 문맥에서 복원할 수 없는 주어와 목적어는 생략하지 않는다.
- 서술의 대상을 적는다. `크게 작용한다` 는 무엇에 작용하는지가 없다.
- 지시어가 가리키는 것을 앞에 둔다. `그 경계` 가 무엇인지 앞 문장에 없으면 이름을 쓴다.
- `의`를 한 구에 두 번 겹치지 않는다. 겹친다는 것은 성분이 빠졌다는 신호다.
- 비유어로 일반 명사와 동사를 대체하지 않는다. 해당 분야에서 굳은 관용 표현은 그대로 쓴다.
- 엠대시로 절과 절을 잇지 않는다. 콜론이나 접속사로 바꾼다. 목록과 표에서 이름과 설명을 가르는 용도는 그대로 쓴다.

위 규칙을 어긴 문장의 예시는 문서를 쓰거나 검토할 때 [`korean-examples.md`](korean-examples.md) 에서 읽는다.

### 출력 직전 점검

검사기가 잡지 못하는 축이다. `종료 코드 0` 은 이 축을 통과했다는 뜻이 아니다.

**제목과 표 머리를 질문형으로 쓰지 않는다.** `무엇을 바꿨나`, `어떻게 재는가` 는 제목이 아니다.
`변경점`, `측정 방법` 처럼 명사구로 쓴다.

나머지 축은 `review-axes.md` 의 「축」 표가 소유한다.
비유와 지어낸 이름은 문서를 쓰거나 검토할 때 `korean-examples.md` 의 「고쳐 쓴 예시」 를 읽는다.
독자 구간과 내용 점검은 `writing-structure.md` 가 정한다.

## 문장을 늘어놓는 방식

- 한 문장이나 의미 단위마다 줄을 나눈다. 한 줄에 한 호흡만 담는다.
- 본문에서 `A + B`, `A · B`, `A & B`처럼 항목을 이어 붙이지 않는다. 쉼표나 `와/과`, 목록을 쓴다.
- `=` 나 `→` 로 동치와 인과를 압축하는 것은 한 단락에 한 번까지다. 반복되면 표로 바꾼다.

## 짧은 글에서 하지 않는 것

짧은 글인지는 `writing-structure.md` 의 「분량 구간」 이 정한다.

- 헤더로 층을 쌓지 않는다. 길어져도 빈 줄로 나눈다.
- 짧은 대비를 표로 만들지 않는다.
- 요약 절을 붙이지 않는다.

## 용어를 옮기지 않는다

새 번역어를 만들지 않는다. 옮기기 전에 그 저장소가 이미 쓰는 표기를 찾아 그것을 따른다.
어색한 말 매핑 표는 한글 음차와 비유어를 막는 표다. 영문 원어를 한국어로 옮기라는 뜻이 아니다.

**아래 개발 용어는 번역하지 않는다.** 영어 그대로 쓰거나 굳은 음차로 쓴다.

테스트, 리뷰, 배포, 머지, 브랜치, 커밋, 빌드, 린트, CI, PR, 스냅샷

목록에 없는 용어도 한국 개발자가 영어로 읽고 말하면 옮기지 않는다.
`테스트` 를 `시험` 으로, 자동 검사를 `기계` 로 옮긴 것은 실제로 나온 사례라 매핑 표에 올렸다.

```bash
grep -rn "<후보 표기>" docs/ CLAUDE.md
```

**선례로 삼는 것은 저장소 문서와 코드뿐이다.**
업무 본문, 위키, 댓글, 이전에 내보낸 산출물은 선례가 아니다.
그 글도 에이전트가 쓴 것일 수 있어, 한 번 쓰인 번역어를 근거로 삼으면 같은 말이 계속 번진다.
이미 쓰이고 있다는 사실은 그 표기가 맞다는 근거가 되지 않는다.

기존 표기가 없을 때만 판단한다.

- 코드 식별자, 명령, 경로, 라이브러리 이름은 옮기지 않는다.
- `backend`, `version`, `pipeline`, `rate limit`, `backpressure`, `latency` 처럼
한국 개발자가 영문으로 읽고 말하는 용어는 옮기지 않는다.
- 직역한 한자어를 새로 만들지 않는다. 무엇이 어떻게 됐는지 쓴다.
- 남은 것만 쉬운 말이나 실제 동작으로 풀어 쓴다.

옮겼다가 되돌린 사례는 문서를 쓰거나 검토할 때 `korean-examples.md` 의 「실측으로 되돌린 사례」 에서 읽는다.
금지어 목록은 위 매핑 표 하나뿐이다.

어색한 말 매핑 표에 항목을 더하거나 뺄 때는 [`checker-maintenance.md`](checker-maintenance.md)를 읽는다.
