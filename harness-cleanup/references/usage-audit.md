# 사용 기록 모드

대화 기록(`projects/**/*.jsonl`)으로 스킬이 실제로 어떻게 쓰였는지 보고 판정 근거를 만든다.
발동 조건은 `SKILL.md` 가 소유한다. 이 문서는 발동한 뒤의 절차를 소유한다.

**비용이 크다.** 스킬 묶음 전체를 이렇게 평가했을 때 하위 에이전트 토큰이 약 230만 들었다(2026-10-28).
요청 범위의 스킬만 `--skill` 로 고르고, 읽을 표본 수를 먼저 정한다.

## 순서

| 순서 | 할 일 | 끝난 상태 |
| --- | --- | --- |
| 1 | 집계 | 대상 스킬의 호출 수와 마찰 지표 표가 있다 |
| 2 | 표본 고르기 | 읽을 호출 목록이 세션 id 앞 8자와 시각으로 있다 |
| 3 | 세션 읽기 | 표본마다 발췌 파일이 세션 임시 폴더에 있고, 마찰의 원인을 한 줄로 적었다 |
| 4 | 해결 여부 대조 | 원인마다 세션 날짜 이후의 커밋과 CHANGELOG 를 대조했다 |
| 5 | 판정 | 판정표에 줄을 더했다 |

## 1. 집계

```bash
# cwd: 아무 곳. $SKILL 은 감사할 스킬, $SINCE 는 YYYY-MM-DD, $SCRATCH 는 세션 임시 폴더다
python3 "$SKILL_DIR/scripts/extract_skill_usage.py" --skill "$SKILL" --since "$SINCE" --out "$SCRATCH/usage" --samples 20
```

`--skill` 은 여러 번 줄 수 있다. 인자, 출력 열, 종료 코드는 그 파일의 docstring 이 소유한다.

- **`rg` 나 `grep -r` 로 대화 기록을 세지 않는다.** `~/.claude` 는 숨은 폴더라 `rg` 기본값이 건너뛰어 0건이 나온다.
- **`api-request-blob` 같은 레코드를 함께 세지 않는다.** 메시지를 다시 담아 호출 수가 부풀려진다. 스크립트는 `user`, `assistant` 레코드만 센다.
- `--out` 은 세션 임시 폴더만 준다. 발췌에는 비밀값이 섞이므로 저장소 안이면 스크립트가 거부한다.

## 2. 표본 고르기

`--samples` 가 낸 마찰 점수 상위 호출과, `$SCRATCH/usage/invocations.jsonl` 에서 무작위로 고른 호출을 섞는다.
상위만 읽으면 잘 돈 경우를 보지 못해 유지 판정의 근거가 없다.

**마찰 점수는 표본을 고르는 데만 쓴다.**
정정 정규식은 「다시」 같은 평범한 말과 critic 의 「REVISE」 에 거짓 양성이 많다.
점수나 정정 건수를 판정표의 근거로 적지 않는다.

## 3. 세션 읽기

```bash
# $SID 는 --samples 의 session 열, $TS 는 timestamp 열이다
python3 "$SKILL_DIR/scripts/render_session.py" "$SID" --from "$TS" --out "$SCRATCH/sessions/$SID.txt"
```

발췌 파일을 읽고 마찰의 원인을 한 줄로 적는다. 원인은 지침의 문장, 스크립트, 사용자 정정 중 무엇인지 가른다.
**판정표에는 발췌를 옮기지 않는다.** 세션 id 앞 8자와 시각만 적는다. 대화 기록에는 비밀값이 섞인다.

## 4. 해결 여부 대조

세션 시점의 지침과 지금의 지침이 다를 수 있다. 원인을 찾으면 판정 전에 이미 고쳐졌는지 본다.

```bash
# cwd: $ROOT. $DATE 는 세션 날짜, $SCOPE 는 그 스킬 디렉터리다
git -C "$ROOT" log --since "$DATE" --oneline -- "$SCOPE"
```

그 스킬의 `CHANGELOG.md` 에서 세션 날짜 이후 항목도 읽는다.
고친 커밋이 원인 문장이나 스크립트를 실제로 바꿨으면 `해결됨` 으로 판정하고 그 커밋을 근거로 적는다.
같은 마찰이 고친 날짜 이후 세션에서도 나오면 `해결됨` 이 아니다.

## 5. 판정

판정 값과 근거 등급은 `SKILL.md` 4단계의 판정표를 따른다. 이 모드에서만 쓰는 값은 아래 표에 있다.

| 값 | 쓰는 때 |
| --- | --- |
| 판정 `해결됨` | 4번 대조에서 세션 뒤의 커밋이 원인을 고쳤다 |
| 등급 `세션 실측` | 근거가 실제로 읽은 세션이다. 근거 열에 세션 id 앞 8자와 시각을 적는다 |

세션 사이의 마찰은 [`audit-axes.md`](audit-axes.md) 의 「스킬 경계」 축으로도 본다.
같은 세션에서 형제 스킬 둘이 함께 불렸거나, 한 스킬이 다른 스킬의 일을 즉흥으로 처리했으면 그 축의 근거다.

**지금은 `$ROOT` 저장소 하나가 교정 대상이다.**
다른 저장소(팀 플러그인, `~/.claude`)의 지침이 원인이면 판정표에 그 저장소를 표시해 줄을 남기고, 교정은 `orch` 로 넘긴다.

## 커버리지 공백

세션을 읽다가 스킬 없이 되풀이되는 작업을 찾으면 판정표에 넣지 않는다. 스킬이 없으니 교정할 지침이 없다.
판정표 아래 「커버리지 공백」 절에 작업, 세션 수, 지금 처리 방식을 적어 보고만 한다.
새 스킬로 만들지는 사용자가 정하고, 만드는 일은 `skill-creator` 가 맡는다.

`$SCRATCH/usage/sessions.jsonl` 의 첫 사용자 요청과 쓴 스킬 목록에서 후보를 찾는다.
