# ADR-014: 업무의 마지막 PR 은 마무리가 머지와 배포 뒤에 판정하고, 충돌한 PR 은 머지 큐를 멈추지 않는다

- **status**: `accepted`
- **결정**: `merge-with-finish.ts` 의 PR 표시가 없으면 `finish-pr.ts` 가 배포를 확인한 뒤 업무의 마지막 PR 인지 판정한다.
  조건은 셋이다. PR 제목에서 `finish.task_pattern` 으로 업무 번호를 뽑았고, 같은 업무 번호의 다른 열린 PR 이 없고, `finish.specs_dir` 에 같은 업무를 가리키는 다른 지시서가 없다.
  지시서가 업무를 가리키는지는 `finish.spec_task_pattern` 을 줄마다 맞춰 본다. 이 PR 의 브랜치를 둔 지시서와 브랜치가 모두 머지된 지시서는 세지 않는다.
  판정하지 못하면 중간 PR 이다. `PR!` 는 강제로 마지막, `PR~` 는 강제로 중간이다. 판정은 `orch/scripts/lib/last-pr.ts` 한 곳에 두고 `board-sync.ts` 도 머지를 본 틱에 쓴다.
  그 PR 의 마무리가 돌고 있으면 `board-sync.ts` 는 그 항목을 고치지 않는다. 마무리가 중간 PR 로 정한 항목은 `merged-pr` 에 적혀 다시 판정되지 않는다. 그래서 `PR~` 가 덮이지 않는다.
  보드 항목은 마무리가 판정 뒤에 찾는다. `pr` 필드에 그 PR 이 든 항목, 없으면 `pr` 필드가 빈 항목을 브랜치나 워크트리 이름으로 찾는다.
  머지 큐는 update-branch 가 충돌로 실패하거나 mergeable 이 `CONFLICTING` 인 PR 을 `CONFLICT` 로 빼고 뒤 PR 을 이어 머지한다. 상주 루프의 알림 파일에 `QUEUE-CONFLICT` 를 쓴다.
  앞 PR 이 먼저 들어가야 하는 PR 은 `--chain` 으로 묶고, 묶음 안 앞 PR 이 빠지면 뒤 PR 도 `SKIP` 한다.
  사용자 결정 2026-10-26: 머지 큐에서 머지, 정리, 업무 완료, 보드 갱신이 코디네이터의 추가 지시 없이 이어진다.
- **맥락**: 업무의 마지막 PR 은 코디네이터가 PR 번호 뒤에 `!` 를 붙여야만 알 수 있었다. 하루에 업무 세 건이 `!` 가 빠져 배포 뒤에도 완료되지 않았다.
  보드 항목은 `pr` 필드로만 찾아, 그 칸이 빈 문서 업무와 결정 기록 업무가 머지 뒤에도 진행 중으로 남았다.
  머지 큐는 update-branch 충돌에서 멈춰, 충돌한 PR 하나 때문에 머지할 수 있는 PR 셋이 함께 멈췄다.
- **대안 기각**:
  - 머지 큐를 걸 때(`merge-with-finish.ts`) 판정한다. 같은 큐의 앞 PR 이 아직 열려 있어 뒤 PR 이 늘 중간으로 보이고, 배포를 기다리는 동안 열린 지시서가 바뀌어도 모른다.
  - 판정하지 못하면 마지막으로 본다. 업무 시스템에 완료를 잘못 올리면 되돌리기 어렵다. 늦은 완료는 `PR!` 로 다시 걸어 바로잡는다.
  - 마무리와 보드 동기화가 저마다 판정해 보드를 고친다. 보드 동기화는 표시(`PR!`, `PR~`)를 모르고 배포 전에 돈다. 마무리가 도는 동안 보드 동기화가 그 항목을 고치면 `PR~` 를 준 항목도 done 이 된다.
  - 남은 지시서를 `브랜치:` 줄만으로 센다. 먼저 머지된 중간 PR 의 지시서가 남으면 마지막 PR 이 영영 중간으로 보인다. 그래서 브랜치가 머지된 지시서는 세지 않는다.
  - 지시서가 업무를 가리키는 형식을 코어가 정한다. 저장소마다 브랜치 이름과 업무 번호 형식이 달라 `spec_task_pattern` 설정으로 받는다.
  - 충돌한 PR 을 `--continue-on-hold` 일 때만 건너뛴다. 코디네이터가 옵션을 빠뜨리면 같은 멈춤이 생긴다. 충돌은 worker 가 풀어야 하는 일이라 큐가 기다려도 풀리지 않는다.
  - 충돌한 PR 의 worker 에게 머지 큐가 직접 보낸다. 상주 루프와 `notify-conflicts.ts` 가 같은 기록으로 이미 보낸다. 두 곳에서 보내면 같은 충돌을 두 번 보낸다.
- **결과**:
  - 얻는 것: 코디네이터가 PR 마다 마지막인지 정하지 않아도 업무 완료와 보드 done 이 이어진다. 근거가 마무리 로그에 한 줄로 남는다.
  - 얻는 것: 충돌한 PR 이 큐에서 빠져도 나머지는 머지된다.
  - 감당할 것: `task_pattern` 을 지우려던 계획을 거둔다. 판정이 계속 읽는다.
  - 감당할 것: 같은 업무의 PR 둘을 한 큐에 넣으면 앞 PR 의 마무리가 판정할 때 뒤 PR 이 이미 머지돼 둘 다 마지막으로 볼 수 있다. 업무 완료 명령이 두 번 돈다. 완료 명령은 같은 업무에 두 번 불려도 되는 것이어야 한다.
  - 감당할 것: 판정은 머지 뒤 상태로 본다. 아직 지시서도 PR 도 없는 뒤 작업은 모른다. 그때는 `PR~` 를 붙인다.
  - 감당할 것: 머지 큐와 상주 루프가 같은 알림 파일에 잠금 없이 쓴다. 같은 순간에 쓰면 두 줄이 같은 seq 를 받을 수 있다.
- **적용 범위**: 판정은 `orch/scripts/lib/last-pr.ts`, 마무리 순서와 보드 항목은 `orch/scripts/finish-pr.ts`, 충돌과 묶음은 `orch/scripts/merge_queue.ts` 머리 주석, 코디네이터의 쓰는 법은 [`../../orch/references/cleanup.md`](../../orch/references/cleanup.md) 의 「머지」 가 소유한다.
