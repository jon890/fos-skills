# CHANGELOG: content-preview

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준과 쓰는 형식은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 3.20.0 (2026-10-31)

- 본문을 다시 쓸 때 `rm -f` 로 기존 파일을 지우라는 지시를 뺐다. 자동 승인 검토가 이 명령을 거부해 우회가 필요했다
- 두 생성기가 시작할 때 `--out` 의 이전 파일을 스스로 지우고, 임시 파일에 쓴 뒤 이름을 바꿔 덮어쓴다. 실패해도 이전 미리보기가 남지 않는다

## 3.19.0 (2026-10-28)

- 범위를 밝힌 상시 승인(「이 세션의 PR 은 묻지 말고 올려」)을 인정한다. 범위 안의 건은 미리보기를 만들되 응답을 기다리지 않고 등록하고 미리보기 경로를 보고한다
- 등록 전에 본문 초안을 보여 확인받으려는 순간도 트리거에 넣었다
- 수정본을 쓸 때 기존 파일을 먼저 지우는 근거를 「생성기가 실패하면 이전 preview.html 이 남는다」 로 고쳤다

## 3.18.1 (2026-10-25)

- README 를 스킬을 쓰는 사람 관점으로 다시 쓰고, 이 CHANGELOG 를 버전마다 핵심만 남기도록 줄였다. 동작은 바뀌지 않았다

## 3.18.0 (2026-10-12)

- 부분 수정이면 미리보기를 함께 띄우고, 바뀐 블록만 AS-IS 와 TO-BE 로 채팅에 보인다
- 의미 점검을 할지와 누가 하는지는 `korean-check` 의 「검사기가 잡지 못하는 축을 본다」 를 따른다
- `PREVIEW_DIR` 예시를 그대로 붙여 넣어도 도는 기본값으로 바꿨다

## 3.17.0 (2026-10-07)

- Dooray 생성기에 `--mode messenger` 를 더했다. 멘션과 HTTPS 주소만 링크로 만들고, 확인하지 못한 마크다운은 원문으로 둔다
- 메신저에서 링크로 렌더되지 않는 `dooray://` 업무, 위키 링크를 경고 띠와 stderr 로 알린다. `--strict` 를 주면 경고가 있을 때 종료 코드 1 이다

## 3.16.0 (2026-10-06)

- 예시의 변수 이름 `SP` 를 `PREVIEW_DIR` 로 바꿨다. 스크립트는 이 변수를 읽지 않아 동작은 같다

## 3.15.0 (2026-10-06)

- 한 턴에 등록할 본문이 여럿이면 순번 머리를 붙여 한 파일로 이어 붙이고 미리보기를 한 번 띄운다. 등록은 각자의 본문 파일로 한다
- `rm` 대상 변수를 `${PREVIEW_DIR:?}` 꼴로 써서, 변수가 비면 셸이 `rm` 을 실행하지 않는다

## 3.14.1 (2026-10-05)

- 변경 이력과 예시에서 특정 저장소와 조율 도구를 전제하던 문구를 일반 표현으로 바꿨다. 동작은 바뀌지 않았다

## 3.14.0 (2026-10-03)

- 사용자가 이번 본문의 등록을 대화에서 명시적으로 미리 승인했으면 미리보기를 생략하고 등록한다. 결과에 생략한 사실과 본문 파일 경로를 적는다
- 다른 건에 대한 과거 승인, 일반 위임, 에이전트 자신의 판단은 승인으로 보지 않는다
- 미리보기를 생략해도 표기 검사는 그대로 한다

## 3.13.0 (2026-10-01)

- `show-preview.sh` 가 설정 파일을 `BROWSER_CONFIG`, 드라이버의 `config-path` 출력, `~/.claude/browser.config.json` 순으로 찾는다
- 플러그인 설치본에서 드라이버와 미리보기가 서로 다른 설정 파일을 읽던 문제를 고쳤다

## 3.12.0 (2026-09-30)

- 에이전트 조율 도구의 dispatch 워커는 `show-preview.sh` 를 부르지 않고, 미리보기 HTML 을 만드는 것으로 5단계를 통과한다

## 3.11.0 (2026-09-30)

- Dooray 미리보기가 ` ```mermaid ` 블록을 도표로 그린다. 문법 오류가 난 블록만 오류 메시지와 원문으로 보인다

## 3.10.0 (2026-09-28)

- 별도 검토가 필요한 조건은 `korean-check` 를 따르고, subagent 검토 강제와 사용자 검토 폴백을 없앴다
- 미리보기 보고에 확인 범위와 반영하지 않은 발견을 적는다

## 3.9.0 (2026-09-27)

- dispatch 로 받은 세션은 지시문에 등록이 적혀 있으면 이 턴에 등록하고, 미리보기 파일 경로와 등록한 URL 을 보고한다
- 등록 지시가 없으면 등록하지 않고 지시한 쪽에 등록할지 묻는다

## 3.8.0 (2026-09-22)

## 3.7.0 (2026-09-22)

- 4단계 검토를 subagent 에게 맡기고, subagent 를 띄울 수 없는 환경의 폴백을 남겼다

## 3.6.0 (2026-09-22)

## 3.1.0 (2026-09-17)

- 호환성: 드라이버 경로를 지정하는 환경 변수가 `BROWSER_DRIVER` 에서 `BROWSER_DRIVER_PATH` 로 바뀌었다

## 3.0.1 (2026-09-13)

## 3.0.0 (2026-09-07)

- 「자가 점검」 을 3단계 표기 검사와 4단계 검토로 나눠, 실행 절차가 6단계가 됐다
- 표기 검사기와 판정 기준은 `korean-check` 가 소유하고, `scripts/style-check.sh` 가 그것을 찾아 부른다
- 호환성: `korean-check` 를 찾지 못하면 건너뛰지 않고 종료 코드 2 로 멈춘다
- 짧은 글은 검토를 건너뛰고, 반영하지 않은 발견만 등록 보고에 한 줄로 덧붙인다

## 2.x

- 실행 절차를 5단계로 정하고 단계마다 통과 조건을 세웠다. 본문 전문을 채팅에 다시 쓰지 않고, 미리보기 턴은 미리보기로 끝낸다
- 개인 문체 참조를 어디에 두고 무엇을 적는지 `references/persona.md` 로 옮겼다
- 저장소가 브라우저 드라이버를 함께 배포하고, `show-preview.sh` 가 호출자 지정, 저장소 안, 개인 심링크 순으로 찾는다
- Dooray 생성기 `--project` 의 기본값을 비웠다. 값이 없으면 그 줄을 그리지 않는다
- 자가 점검 단계가 표기 검사기를 직접 돌린다. 편집 훅을 거치지 않은 본문도 검사한다

## 1.x

- 개인 스킬 폴더에서 이 저장소로 옮기고, HTML 생성기를 스킬 번들의 `scripts/` 로 들였다
- `scripts/show-preview.sh` 로 미리보기를 사용자 화면에 띄우고, 같은 파일의 탭이 있으면 새로 열지 않고 갱신한다
- `browser-driver` 가 있으면 그것으로 띄워 에이전트 IDE 안의 탭도 갱신한다
- 미리보기 탭이 사용자가 보는 워크트리에 있는지 대조하고, 어긋나면 기본 브라우저로 다시 띄운다
- Dooray 생성기에 `--mode` 를 더했다. `task` 는 업무 머리를, `comment` 는 댓글 머리를 그린다
- Dooray 본문은 TOAST UI viewer 로만 미리본다. marked 는 줄을 나눈 문장을 한 문단으로 붙이고 물결표를 취소선으로 읽는다
- 개인 문체 참조를 배포에서 빼고 `~/.claude/references/` 에 둔다
