# CHANGELOG: review-fix

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준과 쓰는 형식은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 2.13.0 (2026-10-28)

- 7, 8단계 본문에 회신, 등록 전 검사, resolve, 미해결 수 확인 명령과 종료 코드를 뒀다. reference 를 열지 않고 GraphQL 로 직접 회신하던 문제다
- `review_threads.py list` 가 push 뒤 outdated 가 되어 `line` 이 빈 스레드에 `originalLine` 을 낸다
- 리뷰 본문에만 있는 지적과 스레드 지적이 섞였을 때의 회신 경로를 더했다. P1, P2 를 반영하지 않으려면 먼저 확인받고 「반영하지 않음」 으로 회신한다
- 지적이 PR 본문을 가리키면 `create-pr` 로, 회신 등록 전에는 `content-preview` 로 보낸다
- 명령 블록의 `<owner>`, `<N>` 을 붙여넣어 돌아가는 변수로 바꿨다

## 2.12.1 (2026-10-25)

- README 를 스킬을 쓰는 사람 관점으로 다시 쓰고, 이 CHANGELOG 를 버전마다 핵심만 남기도록 줄였다. 동작은 바뀌지 않았다

## 2.12.0 (2026-10-13)

- `review_threads.py resolve -` 가 표준 입력에서 THREAD_ID 를 읽는다
- 인자 하나에 공백이나 줄바꿈으로 이어진 ID 가 오면 나눠서 resolve 한다. zsh 에서 `$IDS` 가 인자 하나로 넘어가 실패하던 문제다

## 2.11.0 (2026-10-12)

- `scripts/fold_fixup.sh` 를 더했다. 검증 실패의 원인이 앞 커밋이면 수정을 편집기 없이 그 커밋에 접어 넣는다
- `review_threads.py reply-batch` 로 여러 스레드에 한 번에 회신한다. 실패한 줄을 알리고 종료 코드 1 로 끝난다
- `collect_review.py --carried-from` 이 이전 PR 에서 「다음 PR」 로 미룬 스레드를 함께 모은다

## 2.10.0 (2026-10-12)

- fix 커밋 범위와 되돌리기 기준을 base 가 아닌 PR head 의 upstream(`@{u}`)으로 바꿨다. PR 의 기존 커밋까지 범위에 들어오던 문제다
- 모노레포 오버레이를 「리뷰 수집」 단계에서 PR 번호를 정한 뒤 고른다

## 2.9.1 (2026-10-09)

- 마무리 단계 표의 문구를 다듬었다. 동작은 바뀌지 않았다

## 2.9.0 (2026-10-05)

- 반복될 지적을 사건 기록으로 쌓지 않고 검사, 코드 구조, 규칙 문장으로 일반화해 저장소 규칙에 넣는다. 결과 보고의 줄 이름도 「저장소 규칙 반영」 이 됐다

## 2.8.0 (2026-10-02)

- `review_threads.py list --count` 가 미해결 스레드 수를 정수 하나로 낸다. 머지 전에 이 값이 0 인지 확인한다
- `gh_host.py` 가 다른 호스트의 토큰 확인 실패 때문에 로그인된 호스트를 못 찾던 문제를 고쳤다

## 2.7.0 (2026-10-01)

- planning 번들을 이 스킬 번들의 형제 디렉터리에서 찾는다. 플러그인으로 설치했을 때 위치를 알 수 없던 문제다

## 2.6.0 (2026-09-29)

- 모노레포를 지원한다. PR 의 변경 경로로 하위 프로젝트를 정하고 그 오버레이를 루트보다 먼저 읽는다
- PR 이 두 하위 프로젝트에 걸치면 두 오버레이의 검증 명령을 모두 실행한다

## 2.5.1 (2026-09-28)

- 충돌 마커 검색 조건을 지정하는 이유를 문서에 적었다. 동작은 바뀌지 않았다

## 2.5.0 (2026-09-28)

- 테스트를 바꾼 경우에만 diff 에서 테스트 삭제, skip, 단언 완화를 판정한다

## 2.4.1 (2026-09-24)

- 규칙을 넣을 위치 문장이 하위 디렉터리를 모두 만들라는 뜻으로 읽히던 것을 고쳤다

## 2.4.0 (2026-09-24)

- 여러 지적이 같은 원인을 가리키면 설계 문제인지 먼저 보고하고, 설계 변경이 필요하면 이슈로 등록한다

## 2.3.1 (2026-09-24)

- 실행되지 않거나 겹치는 설명을 정리했다. 동작은 바뀌지 않았다

## 2.3.0 (2026-09-15)

- 호스트를 현재 디렉터리가 아닌 저장소 이름으로 정한다. 스킬 디렉터리에서 돌리면 GitHub Enterprise 저장소를 찾지 못하던 문제다
- 호환성: `gh_host.py` 는 `<owner> <repo>` 를 받고, `review_threads.py` 의 `reply` 와 `resolve` 는 `--repo <owner>/<repo>` 로 저장소를 받는다

## 2.2.0 (2026-09-08)

- 지적 하나를 고치면 그 자리에서 커밋한다. 회신의 해시로 그 지적의 수정만 확인하고 되돌릴 수 있다
- 지적과 커밋 해시의 대응 표를 파일로 남기고, 회신과 결과 보고가 그 표의 해시를 쓴다
- 검증이 실패하면 새 커밋을 얹지 않고 원인이 된 커밋을 고친다

## 2.1.0 (2026-09-07)

- 호환성: 셸 스크립트를 python 으로 옮겼다. `gh-host.sh`, `checkout-pr.sh`, `collect-review.sh`, `review-threads.sh` 대신 같은 이름의 `.py` 를 쓴다

## 2.0.1 (2026-09-04)

- 지침 파일 이름을 본문에서 뺐다. 동작은 바뀌지 않았다

## 2.0.0 (2026-09-04)

- 실행을 8단계로 정리하고 단계마다 통과 조건과 읽을 문서를 정했다
- 등급 대응, 충돌 해결, 회신, 마무리 절차를 `references/` 로 나눴다
- `checkout-pr.sh` 가 작업 트리 정렬을 종료 코드로 판정하고, `check_reply_body.py` 가 회신 본문의 재트리거 토큰과 auto-link 를 찾는다

## 1.x

- 1.0.0 은 리뷰 반영, push, 리뷰 스레드 resolve 까지 하던 상태에서 버전 체계를 도입한 시점이다
- 봇의 심각도 표기를 P1 부터 P5 로 읽고, 표기별 행동 규약을 `severity.md` 로 나눴다
- 리뷰 스레드에 GraphQL 로 회신하고, 회신 본문을 파일로 넘긴다
- GitHub Enterprise 저장소에서 호스트를 판별한다. origin 이 SSH config 별칭이어도 실제 호스트를 찾는다
