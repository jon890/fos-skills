# 마무리

「마무리」 단계에서 읽는다. resolve, 규칙 후보, 결과 보고를 이 순서로 한다.

## 리뷰 스레드 resolve

명령과 종료 코드는 `SKILL.md` 의 「마무리」 단계가 소유한다.

resolve 는 「이 지적을 처리했다」 는 표시다.
반영했거나 반영하지 않기로 판단하고 그 판단을 회신한 스레드만 resolve 한다.

resolve 한 뒤 보호 규칙이 풀렸는지 본다.

```bash
gh pr view "$PR" --json mergeStateStatus
```

## 반복될 지적을 후보로 적는다

fix 가 끝났다고 항상 적지 않는다. **같은 실수가 다른 코드에서도 날 수 있는 지적**만 후보로 적는다.
1회성 오타, 특정 PR 맥락에서만 성립하는 지적, 칭찬과 단순 확인은 결과 보고에만 남긴다.

**저장소 규칙 파일을 이 단계에서 고치지 않는다.** 규칙 커밋을 fix PR 에 더하지 않는다.
후보는 아래 결과 보고의 「저장소 규칙 후보」 에 일반화한 규칙 한 줄과 제안하는 넣을 곳을 적는다. 도메인 결정이면 넣을 곳을 레포 ADR 로 적는다.
후보를 저장소 규칙으로 옮기는 일은 `docs-consolidate` 가 한다. 넣을 곳, 규칙 문장, 반복 함정 목록 처리는 [plan 의 rule-placement.md](../../plan/references/rule-placement.md) 가 정한다.
모노레포면 지적이 달린 파일이 속한 하위 프로젝트의 것을 쓴다.

## 결과 보고

```
## 완료: PR #<N>

🔀 Conflict 해결 (<건수>)
  - <파일>: <결정 요약>
✅ 적용된 수정 (<건수>)
  - <파일>: <무엇을 수정했는지>
📋 이슈로 등록 (<건수>)
  - #<번호>: <범위가 커서 이슈로 추적>
💬 회신 완료 (<건수>, 스레드 <건수> / 인라인 <건수>)
🧵 스레드 resolve (<건수>)
⏭️ 건너뛴 항목 (<이유>)
📚 저장소 규칙 후보 (<건수>와 제안하는 넣을 곳, 또는 「없음」)
🔗 PR 밖 위반 (<건수>, 또는 「없음」)
  - <adr-docs.ts 가 `PR 밖 위반:` 아래 낸 줄>

커밋 (<건수>)
  - <해시> <메시지>
```

**커밋을 목록으로 낸다.** 지적별로 나뉘어 있어 하나가 아니다.
「커밋과 push」 단계가 만든 대응 표의 해시를 읽어 채운다.
base 동기화 커밋은 fix 가 아니므로 「Conflict 해결」 절에서 다룬다.

**「PR 밖 위반」 은 고치지 않고 적기만 한다.** 검증 단계의 `adr-docs.ts check` 가 `PR 밖 위반:` 아래 낸 줄을 그대로 옮긴다. 다음 docs-audit 나 그 파일을 고치는 PR 이 처리한다.
