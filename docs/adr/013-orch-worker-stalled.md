# ADR-013: 상주 루프는 멈춘 worker 를 이벤트로 알리고, 다시 시도시키는 일은 저장소 핸들러가 맡는다

- **status**: `accepted`
- **결정**: 상주 루프는 틱마다 등록된 Run 이 띄운 살아 있는 dispatch 의 화면을 `lib/screen.ts` 로 판정한다.
  같은 멈춤이 `pipeline.stall_ticks` 의 틱 수만큼 이어지면 그 Run 으로 `worker-stalled` 를 낸다. 기본은 `error` 2틱이고 `idle` 은 끈다.
  루프는 worker 에게 입력하지 않는다. 다시 시도시킬지와 횟수 상한은 저장소의 `.orch/hooks/worker-stalled.ts` 가 정한다([ADR-009](009-orch-event-handlers.md)).
  핸들러가 없거나 0 이 아니면 그 Run 의 알림 파일에 `WORKER-STALLED` 를 한 번 쓴다. 핸들러가 0 으로 끝나면 같은 화면이 기준 틱 수만큼 더 이어질 때 다시 부른다.
  코어가 `error` 로 보는 오류 줄은 에이전트가 오류를 그리는 공통 형식(Codex 의 `■ ` 줄, Claude Code 의 `API Error` 줄)뿐이다. 그 밖의 문구는 입력의 `lines` 로 핸들러가 판정한다.
  핸들러 환경의 `ORCH_SCRIPTS` 가 코어 명령의 폴더를 알리고, worker 에게 입력하는 코어 명령(`nudge-worker`, `send-to-worker`)은 `ORCH_REAL_ORCA` 로 진짜 orca 를 부른다.
  사용자 결정 2026-10-26: 코어는 이벤트를 내고 저장소 고유의 일은 처리기가 맡는다. 스크립트를 늘리지 않고, 개입은 그 세션(Run)이 띄운 것만 한다.
- **맥락**: 2026-10-26 에 codex worker 가 「Selected model is at capacity. Please try a different model.」 화면에서 멈췄고, 사용자가 터미널에 「계속 진행해」 를 직접 쳐서 이어 갔다.
  코디네이터는 깨어날 때마다 `nudge-worker --state` 로 화면을 확인해야 했다. 그때의 `--state` 는 오류로 멈춘 화면과 백그라운드 에이전트를 기다리는 화면을 같은 `idle` 로 냈다.
  또 핸들러 환경의 `ORCA` 는 `orca terminal send` 를 막는 가드 shim 이라, 가드가 쓰라고 안내하는 코어 명령도 그 안에서 막혔다.
- **대안 기각**:
  - 루프가 직접 「계속」 을 입력한다. 무엇을 입력할지, 몇 번까지 할지, 모델을 바꿀지는 저장소와 에이전트마다 다르다. 코어가 정하면 특정 사례에 얽매인다.
  - 멈춤 감시를 새 스크립트로 둔다. 루프가 이미 Run 마다 worker 목록을 읽고 알림 파일을 쓴다. 스크립트를 늘리지 않는다는 결정에도 어긋난다.
  - 요청 한도나 용량 초과 같은 문구를 코어 정규식에 쌓는다. 에이전트가 바뀔 때마다 코어를 고쳐야 한다. 공통 형식만 코어에 두고 나머지는 `lines` 로 넘긴다.
  - 화면 전체로 해시를 만든다. 입력란 아래 상태 줄(경과 시간, 컨텍스트 사용량)이 틱마다 바뀌어 같은 멈춤을 세지 못한다. 입력란 위 마지막 메시지 묶음만 쓴다.
  - 같은 멈춤에는 핸들러를 한 번만 부른다. 다시 시도한 worker 가 같은 오류로 끝나면 마지막 묶음이 앞과 같아 같은 멈춤으로 보인다. 핸들러가 0 으로 끝났으니 코디네이터도 깨지 않아 worker 가 조용히 멈춘 채 남는다.
  - `idle` 도 기본으로 센다. 백그라운드 에이전트나 긴 빌드를 기다리는 정상 화면과 구분되지 않아 거짓 알림이 난다. 켜는 저장소에서도 그 dispatch 가 답을 받지 못한 질문이 있으면 세지 않는다.
- **결과**:
  - 얻는 것: 모델 오류로 멈춘 worker 를 사람이 터미널을 보지 않아도 안다. 저장소는 핸들러 하나로 자동 재시도를 더한다.
  - 얻는 것: 다른 세션의 worker 화면은 읽지 않는다. 알림은 그 worker 를 띄운 Run 에만 간다.
  - 감당할 것: 틱마다 살아 있는 dispatch 수만큼 `orca terminal read --screen` 이 는다.
  - 감당할 것: 화면 판정은 문자열 휴리스틱이다. 에이전트가 오류를 그리는 꼴을 바꾸면 `error` 를 놓쳐 `idle` 로 남는다. 그때는 `lib/screen.ts` 의 오류 줄을 고친다.
  - 감당할 것: 가드는 실수 방지 장치이고 보안 경계가 아니다. `ORCH_REAL_ORCA` 가 핸들러 환경에 보이므로 핸들러가 일부러 부르면 가드를 거치지 않고 입력할 수 있다. 코어 명령에 입력 길을 열어 둔 것도 같은 전제 위에 있다.
- **적용 범위**: 판정은 `orch/scripts/lib/screen.ts` 머리 주석, 틱 순서와 멈춤 항목은 `orch/scripts/orch-loop.ts` 머리 주석의 「멈춤 확인」, 입력 필드와 환경은 `orch/scripts/lib/events.ts` 머리 주석, 핸들러 예시는 [`../../orch/references/hooks.md`](../../orch/references/hooks.md), 상태 파일은 [`../data-schema.md`](../data-schema.md) 가 소유한다.
