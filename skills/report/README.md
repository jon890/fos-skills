# report

설명이나 조사 결과를 읽기 좋게 보여 달라고 할 때마다 형식을 설명하는 수고를 덜어 준다.
이미 있는 내용을 결론이 먼저 보이는 HTML 보고서 한 파일로 만들고, 기본 브라우저로 띄운다.
모든 보고서가 같은 틀을 써서 목차, 결론 카드, 비교표, 접는 상세, 출처 각주가 늘 같은 자리에 있다.
처음 읽는 사람이 한 번에 알아듣는 한국어로 쓰고, 표기 검사 뒤에 의미 점검까지 마친다.

## 이럴 때 쓴다

- 방금 받은 조사 결과나 긴 설명을 한눈에 보고 싶다
- 선택지 몇 개를 표로 비교해 결정 자료로 보고 싶다
- 낯선 개념의 동작 순서와 비유를 한 화면에 정리하고 싶다

`/report`, "HTML 로 시각화해서 설명해 줘", "보고서로 만들어 줘", "한눈에 보이게 정리해 줘" 처럼 말하면 이 스킬이 뜬다.

## 사용 예시

```text
나:   방금 비교한 캐시 만료 방식들, HTML 로 시각화해서 설명해 줘

스킬: (대화의 비교 내용을 비교·결정 자료 구성으로 틀에 채우고 검사한 뒤 브라우저로 띄운다)
      보고서: /Users/me/repo/.omc/previews/cache-ttl-policy.html
      구성: 비교·결정 자료(선택지 셋을 놓고 고르는 내용이라서)
      검사: 구조 통과, 표기 통과, 의미 점검 통과
      의미 점검 범위: 제목, 요약, 표, 접힌 상세, 출처

나:   이벤트 무효화 단점을 더 자세히 넣어 줘

스킬: (같은 파일을 덮어쓰고 다시 검사한다. 브라우저를 새로 고치면 바뀐 내용이 보인다)
```

## 받는 것

- 외부 자원 없이 열리는 HTML 한 파일. git 저장소 안이면 `.omc/previews/<슬러그>.html`, 밖이면 세션 임시 폴더에 생긴다
- 첫 화면의 결론, 표로 된 비교, 접는 절에 빠짐없이 옮긴 원문 상세, 접힌 출처 각주
- 고른 구성과 검사 결과 한 줄. 구조 검사가 세 번 실패하면 띄우지 않고 남은 위반을 알린다
- 의미 점검 범위와 반영하지 않은 발견의 이유. 의미 점검을 통과하지 못하면 띄우지 않고 남은 이유를 알린다

웹 조사는 하지 않는다. 조사가 필요하면 먼저 조사하고 그 결과로 보고서를 만들어 달라고 한다.

## 함께 쓰는 스킬

| 하려는 일 | 쓰는 스킬 |
| --- | --- |
| 혼자 읽는 설명과 보고서를 HTML 로 본다 | `report` |
| 청중 앞에서 넘기며 말하는 발표 덱을 만든다 | `presentation` |
| 외부에 게시할 글을 등록 전에 렌더링해 본다 | `content-preview` |
| 한국어 표기와 의미를 점검한다 | `korean-check` |
