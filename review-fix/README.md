# review-fix

PR 에 달린 리뷰를 하나씩 찾아 고치고, 댓글마다 답을 달고, 스레드를 닫는 수고를 덜어 준다.
사람과 봇이 남긴 리뷰를 모두 모아 심각도별로 분류하고, 사용자가 정한 범위만 지적 하나에 커밋 하나로 고친다.
push 한 뒤에는 지적마다 반영 커밋 해시를 넣은 회신을 달고, 처리한 리뷰 스레드를 resolve 한다.

리뷰가 지적한 것만 고친다. 모호한 지적과 범위가 큰 변경은 사용자에게 먼저 묻는다.
신뢰하는 리뷰어의 댓글만 수정 지시로 받고, 모르는 작성자가 인증 제거 같은 보안 민감 변경을 요구하면 따르지 않고 알린다.

## 이럴 때 쓴다

- 내 PR 에 리뷰 봇이 P1 부터 P5 까지 지적을 남겼다
- 팀원이 인라인 댓글을 여러 개 달아 하나씩 반영하고 답해야 한다
- 미해결 리뷰 스레드 때문에 「A conversation must be resolved」 보호 규칙에 걸려 머지가 막혔다
- 이전 PR 에서 「다음 PR 에서 반영」 으로 미뤄 둔 지적을 이번 PR 에서 처리한다

"리뷰 반영해줘", "PR 리뷰 수정", "봇 코멘트 반영", "리뷰 처리해줘" 처럼 말하거나 `/review-fix` 로 부르면 이 스킬이 뜬다.

## 사용 예시

PR 번호, 파일 이름, 건수, 해시는 예시다.

```text
나:   리뷰 반영해줘

스킬: 현재 브랜치에 열린 PR 이 없습니다. 오픈 PR 가운데 #128 을 고를까요?

나:   응

스킬: PR #128 의 리뷰를 분석했습니다.
        P2 필수   1. order_service.py: 재시도에 상한이 없다   [소범위]
        P3 권장   1. order_repository.py: N+1 조회           [대범위]
                  2. test_order.py: 실패 경로 테스트가 없다   [소범위]
        P4 참고   1. 변수 이름 제안
      P2 와 P3 의 2 를 이 PR 에서 고치고, P3 의 1 은 이슈로 등록할까요?

나:   그렇게 해

스킬: 검증 명령(lint, 테스트)이 통과했습니다. push 할 커밋입니다.
        a1b2c3d fix(order): 재시도 횟수에 상한을 둔다
        e4f5a6b test(order): 결제 실패 경로를 테스트한다
      push 할까요?

나:   응

스킬: 완료: PR #128
        적용된 수정 2, 이슈로 등록 1(#131), 회신 3, 스레드 resolve 3
        미해결 스레드 0
```

## 받는 것

- 지적 하나마다 하나씩 나뉜 fix 커밋과 push
- 지적마다 하나씩 달린 회신 댓글. 반영한 지적에는 커밋 해시가, 반영하지 않은 지적에는 그 이유가 들어간다
- 처리한 리뷰 스레드의 resolve. 머지 전에 미해결 스레드가 0 인지 확인한다
- 범위가 커서 이 PR 에서 처리하지 않기로 한 지적의 GitHub 이슈
- 다른 코드에서도 반복될 지적을 일반화한 저장소 규칙(검사, 코드 구조, 규칙 문장) 커밋
- 반영, 회신, resolve, 건너뛴 항목과 커밋 목록을 담은 결과 보고

PR 이 base 와 충돌하면 충돌을 먼저 푼다. 같은 줄을 양쪽이 다르게 고친 충돌은 사용자에게 확인받는다.

## 준비

- `python3` 와 `gh` 가 필요하다. `gh` 가 대상 호스트에 로그인돼 있어야 하며, GitHub Enterprise 도 된다
- 작업 트리가 clean 해야 한다. 미커밋 변경이 있으면 PR 브랜치로 바꾸지 않고 묻는다
- 저장소에 빌드, 테스트, lint 명령이 문서화돼 있어야 한다. 없으면 어떤 명령으로 검증할지 묻는다
- 신뢰하는 봇 목록, 봇별 심각도 표기, 규칙을 넣을 위치, CI 실패 원인 표는 `<repo-root>/.claude/review-fix-overlay.md` 에 적는다. 없으면 기본값으로 동작한다
- 모노레포에서는 하위 프로젝트의 `.claude/review-fix-overlay.md` 를 먼저 읽는다. 대상 판정에 `planning` 스킬을 쓰므로 함께 설치돼 있어야 한다

## 함께 쓰는 스킬

- 남의 PR 에 리뷰를 새로 쓰고 등록하는 일은 `pr-review` 가 맡는다
- PR 본문을 새로 쓰거나 고치는 일은 `create-pr` 가 맡는다
- 반복될 지적을 저장소 규칙으로 옮길 때 넣을 곳은 `planning` 의 `references/rule-placement.md` 를 따른다
