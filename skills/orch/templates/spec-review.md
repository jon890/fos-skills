## 할 일

루프 없이: 남의 PR 리뷰라 기능 구현이 아니다

1. worker 는 fetch 하지 않고 준비된 HEAD(PR head)를 리뷰한다. 브랜치를 만들거나 `git fetch origin pull/{{N}}/head` 를 부르지 않는다.
2. 변경 파일과 그 호출 쪽을 읽고 정확성, 회귀, 누락된 테스트와 문서를 본다. 코드를 고치거나 커밋하지 않는다.
3. 리뷰를 PR 에 COMMENT 로 등록한다. 본문은 세션 임시 폴더(scratchpad, 없으면 `$TMPDIR`)에 쓰고 저장소에는 두지 않는다.
4. 본문 머리에 등급별 건수 표를 둔다. `.orch/config.json` 의 `routing.review_pattern` 이 이 표를 읽으므로 칸 이름과 순서를 바꾸지 않는다.

   ```markdown
   | 등급 | 건수 |
   | --- | --- |
   | 🔴 P1 치명 | 0 |
   | 🟠 P2 높음 | 0 |
   | 🟡 P3 보통 | 0 |
   | 🔵 P4 낮음 | 0 |
   | ⚪ P5 참고 | 0 |
   ```

5. 표 아래에 지적을 등급 순으로 쓴다. 지적마다 파일과 줄, 실패 시나리오, 고칠 방향을 적는다. P1, P2 는 차단이다.
6. 결과 status 를 보낸다. 첫 줄은 아래 꼴이다. 앞에 다른 말을 붙이지 않는다.

   ```text
   판정: 머지 가능, 차단 0건, 권장 2건
   ```

   `판정: 수정 필요, 차단 N건, 권장 N건` 도 쓴다. 차단은 P1+P2, 권장은 P3 이하다. 리뷰 링크는 그 줄 뒤에 줄을 바꿔 적는다.

## 완료 기준

- PR #{{N}} 에 COMMENT 리뷰를 등록하고, 첫 줄이 `판정:` 으로 시작하는 결과 status 를 보낸다. 그 뒤 `worker_done` 을 보낸다. 리뷰 PR 은 이 worker 가 머지하지 않는다.
