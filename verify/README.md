# verify

구현자의 완료 보고와 별개로 기능 스펙의 인수 조건을 실행하고 확인한다.

## 이럴 때 쓴다

- build-with-teams 가 구현을 넘겼을 때
- API·화면·작업이 요구사항을 만족하는지 확인할 때

## 사용 예시

> “이 plan 을 스펙 기준으로 검증해 줘.”
> 독립 리뷰와 요구사항별 실행 결과를 모아 통과 여부와 수정할 단계를 알려 준다.

## 받는 것

- 요구사항별 기대값·실제값·실행 증거
- 코드·문서 검토와 남은 원격 검증
- 이번 PR 통과와 기능 전체 완료를 구분한 결과

## 함께 쓰는 스킬

- `build-with-teams`: 구현과 수정
- `docs-consolidate`: 검증 뒤 문서 대조와 공통 후보 추출
- `orch`: 결과에 따른 다음 단계
