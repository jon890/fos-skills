# Claude Code 실행 참고

공통 규칙은 [에이전트 위임 계약](team-spawn.md)이 소유한다. 이 문서는 Claude Code 에서 팀원 도구를 쓸 때만 읽는다.

## 팀과 이름 없는 에이전트

| 기능 | 이름을 가진 팀원 | 이름 없는 에이전트 |
| --- | --- | --- |
| 생성 | 이름을 주고 Agent 호출 | name 없이 Agent 호출 |
| 추가 지시 | 이름으로 SendMessage | 반환된 agentId 로 SendMessage |
| 결과 | SendMessage 로 주 에이전트에게 전달 | 최종 답이 완료 알림으로 반환 |
| 종료 | 구조화된 shutdown_request 전달 | 최종 답으로 턴 종료 |

팀 설정은 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` 이다. 현재 도구와 설정이 지원하는지 먼저 확인한다.
팀을 쓸 수 없어도 이름 없는 에이전트를 쓸 수 있으면 공통 역할 계약으로 실행한다.
둘 다 없으면 공통 계약의 순차 실행·독립 검토 미완료 규칙을 따른다.

작업 공간이 여러 개면 `critic-<기능>-<계획>`, `executor-<기능>-<계획>-<phase>` 처럼 이름을 구분한다.
반환된 이름과 ID 를 확인한다. 같은 이름 때문에 다른 작업 공간의 응답을 받지 않게 한다.

## 결과 전달

이름을 가진 팀원에게는 역할 계약의 회신 형식을 채워 SendMessage 로 보내게 한다.
완료 알림의 텍스트 결과는 약 4,000자에서 잘릴 수 있으므로 길면 파일에 쓰고 그 절대경로를 전하게 한다.
이름 없는 에이전트에게는 같은 회신 형식을 최종 답으로 내게 한다.
팀원은 Orca 조율 명령을 실행하지 않는다. 결과와 질문은 주 에이전트에게만 보낸다.

## 재개와 오류

기존 세션에 추가 지시가 가능하면 재사용한다. 팀원 재스폰은 맥락을 잃으므로 마지막 수단이다.
`idleReason: available` 은 대기, `failed` 는 실패다. 무응답이면 한 번 재요청하고 실패 사유가 있으면 먼저 읽는다.
사용 한도·용량 부족의 모델 대체는 공통 실행 등급과 하네스 지침을 따른다.
`Could not determine current tmux pane/window` 오류면 현재 하네스에서 지원하는 이름 없는 에이전트나 in-process 경로를 사용한다.
`no progress 600s` 가 반복되면 같은 호출을 반복하지 말고 오래 걸리는 외부 검증을 분리해 원인을 보고한다.
