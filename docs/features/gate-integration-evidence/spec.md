# orch: 모듈 코드를 바꾼 PR 은 그 모듈의 통합 테스트 통과 기록이 있어야 머지 관문을 통과한다

확인: 2026-11-20


## 목표

저장소가 규칙을 두면, 머지 관문(`orch queue gate`)이 모듈 코드를 바꾼 PR 의 본문에서 그 모듈의 통합 테스트 통과 기록을 확인한다.
기록이 없으면 머지를 막고 빠진 모듈을 알린다. CI 시간은 늘리지 않는다.

2026-11-20 ai-analysis 의 PR 1996 은 worker 가 통합 테스트를 돌지 않은 채 머지돼 develop 통합 검사가 깨졌고, 릴리스가 1시간 넘게 늦었다. ai-analysis 는 PR CI 에서 통합 테스트를 돌지 않고 매시간 따로 돈다(ai-analysis ADR-082). ai-analysis 의 요청 R8 이다.

## 범위

이번 범위:

- 저장소 orch 설정의 규칙(바뀐 경로 패턴, 필요한 기록 문구)
- `orch queue gate` 의 확인과 막을 때의 안내
- worker 공통 지시서에 「규칙이 있는 저장소면 그 명령을 돌리고 결과를 PR 본문에 적는다」 한 줄

범위 밖:

- 머지 관문이 통합 테스트를 직접 돌리는 것
- 테스트 결과 파일(Gradle 보고서)을 읽는 것
- 규칙이 없는 저장소의 동작 변경

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 저장소가 규칙을 둔다 | 규칙마다 바뀐 파일의 경로 패턴, 기록할 명령, 선택 모듈 목록을 둘 수 있다. 목록을 생략한 규칙은 경로 패턴에 맞는 모든 모듈에 적용한다 |
| REQ2 | 규칙에 해당하는 모듈의 기록을 확인한다 | 바뀐 경로가 패턴에 맞고, 목록이 있다면 그 목록에도 있는 모듈의 통합 테스트 기록을 PR 본문 「검증」 절에서 확인한다. 기록에는 모듈의 명령, 통과, PR head 커밋이 들어간다. 목록 밖의 모듈은 통과 기록과 생략 이유를 요구하지 않는다 |
| REQ3 | 없으면 막는다 | 기록이 없거나 커밋이 head 와 다르면 `GATE-FAIL` 에 `통합 테스트 기록 없음: <모듈> (<명령>)` 이나 `통합 테스트 기록이 head 가 아니다: <모듈>` 줄을 낸다. 머지 큐도 같은 이유로 막는다 |
| REQ4 | 이유를 적으면 넘긴다 | 본문에 `통합 테스트 생략: <모듈> <이유>` 줄이 있으면 그 모듈은 막지 않는다. 관문과 머지 마무리 보고에 `통합 테스트 생략 <모듈>: <이유>` 를 보인다. 이유가 비었으면 생략으로 보지 않는다 |
| REQ5 | worker 가 기록을 남긴다 | worker 는 바뀐 모듈 중 규칙에 맞는 모듈의 명령을 돌리고, 통과와 커밋을 PR 본문 검증 절에 적는다. 리뷰 반영으로 커밋이 바뀌면 다시 돌린다 |

## 결정

| ID | 결정 | 답 | 누가 | 근거 |
| --- | --- | --- | --- | --- |
| DECISION1 | CI 를 늘릴지 | 늘리지 않고 머지 관문이 기록을 확인한다 | 사용자 2026-11-20 | 요청 R8 에 적힌 ai-analysis 사용자 결정 |
| DECISION2 | 기록을 얼마나 엄격하게 볼지 | PR 본문 줄과 지금 head 커밋이 같아야 한다 | 사용자 2026-11-20 | 리뷰 반영으로 코드가 바뀌면 다시 돌리게 한다. 머지 큐가 다른 검증 기록을 보는 방식과 같다 |
| DECISION3 | 통합 테스트가 필요 없는 변경 | 본문에 모듈과 이유를 적으면 넘기고, 관문과 마무리 보고에 보인다 | 사용자 2026-11-20 | 주석·문구만 바꾼 PR 에 통합 테스트를 강제하지 않고, 리뷰어가 이유를 본다 |
| DECISION4 | 규칙을 두는 곳 | 저장소의 orch 설정. 기록 줄의 정확한 꼴과 설정 키 이름은 설계가 정한다 | 작성자 | 저장소마다 모듈 구조와 명령이 다르다 |
| DECISION5 | PR 단위 | PR 하나 | 작성자 | 관문 검사 한 곳, 설정 한 키, 공통 지시서 한 줄이 바뀐다 |
| DECISION6 | 통합 테스트가 없는 모듈의 변경 | 저장소 설정에서 규칙을 적용할 모듈을 지정할 수 있다 | 사용자 2026-11-23 | 테스트가 없는 모듈에 생략 이유를 반복해 적는 일을 줄인다. 목록에 있는 모듈의 생략은 DECISION3 을 따른다 |

## 도메인 규칙 변경

도메인 규칙 변경 없음: orch 머지 관문의 확인 한 가지가 늘어난다.
