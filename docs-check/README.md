# docs-check

코드를 바꾼 뒤 문서가 따라왔는지 파일마다 열어 대조하는 수고를 덜어 준다.
ADR Index 동기화, 표 열 수, 헤딩 레벨, 코드 펜스, 깨진 링크와 앵커, 계획서 번호 참조는 정적 검사로 찾는다.
그 밖의 어긋남은 부패, 과대화, 추론성, 중복, 자명성, 구조 무결성 축으로 코드와 대조해 판정한다.

발견마다 그것을 증명한 코드나 명령을 붙여 리포트로 보이고, 사용자가 승인한 항목만 고친다.
승인 전에는 문서를 고치지 않는다.

## 이럴 때 쓴다

- 코드를 크게 바꾼 뒤 `docs/` 와 ADR 이 아직 맞는지 확인하고 싶다
- ADR 이 쌓여 `INDEX.md` 와 본문 번호가 어긋났거나 낡은 ADR 이 섞였다
- 구현이 끝난 `tasks/` 의 계획서와 그것을 번호로 가리키는 문서가 남았다
- 같은 사실이 여러 문서에 흩어져 어느 쪽이 맞는지 모르겠다

"문서 점검", "docs 감사", "stale ADR", "코드와 문서 불일치", "ADR Index 동기화" 처럼 말하면 이 스킬이 뜬다.

## 사용 예시

파일 이름과 수치는 예시다.

```text
나:   docs 감사해줘

스킬: 범위는 docs/ 와 README.md, ADR 디렉터리는 docs/adr 로 잡았습니다.
      정적 검사에서 1곳이 걸렸고, 각 축으로 코드와 대조했습니다.
        Critical  [부패] docs/flow.md:42
                  문서는 재시도 3회, 코드는 5회 (RetryPolicy.java:18)
        Critical  [구조 무결성] docs/adr/INDEX.md
                  ADR-012 가 본문에만 있다
        Warning   [중복] docs/code-architecture.md:30
                  같은 설정 설명이 ADR-007 에도 있다
        안전      docs/adr/003 은 superseded 라 부패 축에서 뺐다
      어느 항목을 고칠까요?

나:   Critical 둘만

스킬: 두 항목만 고치고 정적 검사와 코드 대조를 다시 돌렸습니다.
        static_check.py  종료 코드 0
      Warning 항목은 손대지 않았습니다.
```

## 받는 것

- `Critical`, `Warning`, `안전` 으로 나눈 감사 리포트. 발견마다 축과 심각도, `파일:줄`, 현재 사실, 증명, 가장 작은 수정안이 붙는다
- 검사 범위, 정적 검사 결과, 검증 공백의 요약
- 사용자가 승인한 항목만 반영한 문서 수정. ADR 파일과 `INDEX.md` 는 함께 고친다
- 수정 뒤 다시 돌린 정적 검사와 코드 대조의 명령과 결과

## 준비

- 검사할 저장소 루트에서 부른다. git 저장소가 아니면 정적 검사가 종료 코드 2 로 멈춘다
- `python3` 가 필요하다. 정적 검사가 Python 으로 돈다
- ADR 디렉터리가 있으면 경로를 알려 준다. 없으면 Index 동기화 검사를 건너뛴다
- 문서 경계, 검증 명령, 저장소 특화 코드 대조 grep 은 `<repo-root>/.claude/docs-check-overlay.md` 에 적을 수 있다. 없으면 `AGENTS.md` 와 `CLAUDE.md` 를 본다

## 함께 쓰는 스킬

- CLAUDE.md, AGENTS.md, rules, 스킬 같은 하네스 지침의 감사는 `harness-cleanup` 이 맡는다
- 문서를 새로 쓰기 전에 설계를 확정하고 `docs/` 를 갱신하는 일은 `planning` 이 맡는다. 어느 문서가 무엇을 담는지의 기본값도 `planning` 을 따른다
