# ADR-016: 상주 루프가 머지할 수 있는 PR 을 스스로 머지 큐에 건다

- **status**: `accepted`
- **결정**: `queue.auto_merge` 가 true 인 저장소에서 상주 루프가 틱마다 머지할 수 있는 PR 을 골라 `merge-with-finish.ts` 를 건다.
  대상은 루프에 등록된 Run 의 지시서(`브랜치:` 줄)로 만든 내 열린 PR 이다. draft 가 아니고, 이번 틱의 CI 판정이 같은 HEAD 에서 passed 이고,
  미해결 리뷰 스레드가 없고, 자동 리뷰의 마지막 판정이 통과이고, 지시서나 보드가 `머지 보류` 로 표시하지 않은 PR 만 건다.
  마무리가 도는 PR 은 빼고, 머지 큐 프로세스가 하나라도 돌면 그 틱에는 걸지 않는다. 같은 (PR, HEAD) 는 한 번만 건다.
  마이그레이션은 새 설정 절 `migrations` 의 모듈별 폴더에서 Flyway 파일 이름(`V<버전>__`)으로 읽는다.
  PR 이 더한 버전이 base 의 최고 버전 이하거나 다른 열린 PR 이 더한 번호와 같으면 걸지 않고 `MIGRATION-CLASH` 로 알린다.
  같은 모듈에 더 낮은 번호를 더한 열린 PR 이 있으면 기다리고, `migrations.blocked_after_sec` 를 넘게 막히면 `MIGRATION-BLOCKED` 로 막는 PR 의 재예약을 권한다.
  큐 순서는 준비를 처음 본 순서이고, 같은 모듈 마이그레이션 PR 끼리는 번호 순으로 자리를 바꿔 `--chain` 으로 묶는다.
  머지 전 백업은 `migrations.before` 의 모듈별 명령을 `PR:명령` 으로 붙인다. 업무의 마지막 PR 판정은 표시 없이 넘겨 [ADR-014](014-orch-auto-last-pr.md) 의 판정에 맡긴다.
  사용자 결정 2026-10-27: 머지할 수 있는 PR 은 코디네이터에게 말하지 않아도 머지된다. Flyway out-of-order 는 켜지 않는다.
- **맥락**: 코디네이터는 `worker_done` 을 받거나 PR 목록을 볼 때만 머지 큐를 걸었다. 대기가 지난 메시지나 재알림으로 끝난 뒤 다시 걸지 않거나,
  코디네이터가 다른 일을 하면 준비된 PR 이 몇 시간씩 머지되지 않았다. 하루에 여러 번 생겼다.
  같은 모듈의 마이그레이션 번호를 PR 끼리 겹쳐 쓰면 두 번째 PR 이 개발 서버 기동을 깨뜨렸다. 한 모듈의 같은 번호를 PR 네 개가 함께 쓴 날이 있었다.
  번호는 코디네이터가 눈으로 확인하고 있었다.
- **대안 기각**:
  - `pipeline.enabled` 로 켠다. 그 키는 ready 슬롯, 문서 PR 머지, 배포 묶기를 함께 켜는 키로 설계됐고 아직 읽는 명령이 없다. 자동 머지만 켜고 싶은 저장소가 나머지까지 켜게 된다.
  - 준비됨 `worker_done` 을 받은 대기(`wait-important`)가 건다. 대기는 코디네이터가 다시 걸어야 돈다. 이번 문제가 그 공백이다.
  - 루프가 머지 큐를 직접 돌린다. 마무리(정리, 배포 확인, 업무 완료, 보드)가 빠진다. 코디네이터와 같은 `merge-with-finish.ts` 를 건다.
  - 큐를 여럿 동시에 건다. 두 큐가 같은 base 를 함께 움직이면 서로의 최신화 판정과 CI 대기가 무효가 된다. 큐는 저장소에 하나만 둔다.
  - 큐가 멈춘 PR 을 다음 틱에 다시 건다. 백업 실패 같은 같은 이유로 틱마다 멈춘다. HEAD 가 바뀌어야 다시 건다. 멈춘 이유는 `AUTO-MERGE-END` 로 코디네이터에게 간다.
  - 마이그레이션 번호를 하나의 정규식(모듈과 버전 그룹)으로 받는다. 번호 예약 명령도 모듈별 폴더를 알아야 해 폴더 표로 받는다.
  - 번호가 막힌 PR 의 파일 이름을 루프가 바꾼다. 이미 적용된 개발 DB 와 체크섬이 어긋날 수 있어 사람이 정한다. 루프는 알리기만 한다.
  - 자동 리뷰 결과를 리뷰 체크의 성공으로만 본다. 리뷰 봇은 지적이 있어도 성공으로 끝난다. 리뷰 본문의 판정 문구로 본다.
- **결과**:
  - 얻는 것: 준비된 PR 이 코디네이터의 다음 동작을 기다리지 않고 틱 하나 안에 머지 큐에 오른다.
  - 얻는 것: 마이그레이션 번호 겹침이 머지 전에 걸리고, 같은 모듈의 번호 순서가 머지 순서로 지켜진다.
  - 감당할 것: 리뷰 판정은 마지막 리뷰 본문으로 본다. 지적을 반영한 뒤에도 그 본문이 보류 판정이면 다시 리뷰를 받거나 코디네이터가 건다.
  - 감당할 것: 큐가 멈춘 PR 은 HEAD 가 바뀌기 전에는 다시 걸지 않는다. 코디네이터가 이유를 보고 직접 건다.
  - 감당할 것: 루프가 건 큐가 도는 동안 코디네이터가 큐를 따로 걸면 큐가 둘이 된다. 코디네이터는 `AUTO-MERGE` 를 받으면 그 PR 을 다시 걸지 않는다.
- **적용 범위**: 판정은 `orch/scripts/lib/auto-merge.ts`, 틱의 자리와 기록은 `orch/scripts/orch-loop.ts` 머리 주석의 「자동 머지」, 설정 키는 [`../data-schema.md`](../data-schema.md) 의 「config.json 에 더하는 절」 이 소유한다.
