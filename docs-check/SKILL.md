# 문서 건전성 감사

문서가 현재 코드와 결정을 최소한의 맥락으로 복원할 수 있는지 검사한다. 감사 중에는 발견만 보고하고, 사용자가 승인한 항목만 수정한다.

## 1. 범위와 단일 출처

저장소의 `.claude/docs-check-overlay.md`가 있으면 먼저 읽는다. 없으면 `AGENTS.md`와 `CLAUDE.md`에서 문서 경계와 검증 명령을 찾는다.

사용자가 지정한 범위를 우선하고, 지정이 없으면 현재 경로와 변경 파일에서 가장 좁은 범위를 추론한다. 다음을 포함한다.

- 범위의 `README.md`, `AGENTS.md`와 책임 문서
- planning이 관리하는 제품, 흐름, 데이터와 코드 구조 문서
- `docs/adr/INDEX.md`와 연결된 ADR
- 변경한 스킬의 문서 계약

문서 목록을 고정하지 않는다. 실제 파일과 소비 코드를 함께 확인한다.

## 2. 여섯 감사 축

세부 판정은 `references/six-axis.md`를 따른다.

| 축 | 질문 |
|---|---|
| 부패 | 제거·변경된 코드, 경로와 정책이 현재 사실처럼 남았는가 |
| 과대화 | 문서가 구현 절차와 파일 목록을 복제해 작은 변경에도 낡는가 |
| 추론성 | 결정의 맥락, 선택과 기각한 대안을 복원할 수 있는가 |
| 중복 | 같은 정의를 여러 문서가 소유하는가 |
| 자명성 | 코드와 설정만 보면 아는 내용을 ADR로 반복하는가 |
| 구조 무결성 | 링크, 표, 코드 펜스, 헤딩과 ADR Index가 올바른가 |

줄 수만으로 과대화를 판정하지 않는다. 고정 개수와 목록은 계약인지 단순 복제인지 코드와 대조한다.

## 3. 정적 검사

`<skill-dir>`은 이번 실행에서 로드한 `docs-check` 디렉터리다.

```bash
bash <skill-dir>/scripts/static-check.sh <ADR_DIR> <scope>
```

검사 대상 저장소 루트에서 실행한다. ADR 디렉터리가 여러 개면 각각 실행하되, 결과를 한 리포트에 합친다. 위반이 있으면 종료 코드 1, 사용 오류는 2로 판정한다. 표준 오류에 표시된 검사 파일 수가 0이면 통과로 보지 않는다.

오버레이가 지정한 코드·설정 대조 명령도 실행한다. 플레이스홀더, 잘못된 작업 디렉터리와 자기참조 때문에 검사가 죽어 있지 않은지 확인한다.

## 4. 의미 검사와 독립 검토

코드와 문서의 실제 소비 관계를 읽고 여섯 축을 판정한다. 저장소에 전용 문서 검토 역할이 있으면 그 도메인 경계를 적용한다. 별도 검토자는 읽기 전용으로 격리하고 수정, commit, push와 외부 게시를 허용하지 않는다.

독립 검토가 불가능하면 메인이 직접 검사하고 그 사실을 리포트에 남긴다. 검토자의 판단도 코드와 실행 결과에 대조한다.

## 5. 리포트와 승인

각 발견에는 다음을 포함한다.

- 축과 심각도
- `파일:줄`과 현재 사실
- 문제를 증명한 코드, 명령 또는 단일 출처
- 가장 작은 수정안과 유지할 수 있는 대안

리포트는 `Critical`, `Warning`, `안전`으로 나누고 검사 범위, 정적 검사 결과와 검증 공백을 요약한다. 사용자 승인 전에는 문서를 수정하지 않는다.

## 6. 승인 후 수정

- 현재 사실은 책임 문서 한곳에만 남긴다.
- ADR에는 코드로 자명하지 않은 장기 결정, 맥락과 기각한 대안만 남긴다.
- 구현 경로와 실행 명령은 책임 문서나 코드로 옮기고 ADR은 그 위치를 짧게 가리킨다.
- 대체된 결정은 저장소의 ADR 정책에 따라 현재 상태와 연결 관계를 명확히 한다.
- ADR 파일과 INDEX를 함께 수정한다.
- 수정한 Markdown에 저장소의 표현·가독성 검사를 실행한다.

수정 뒤 정적 검사와 코드 대조를 다시 실행하고, 승인받지 않은 변경이 없는지 확인한다.
