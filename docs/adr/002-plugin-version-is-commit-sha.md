## ADR-002: 플러그인 버전을 쓰지 않고 커밋 SHA 를 버전으로 삼는다

- **status**: `accepted`
- **결정**: `.claude-plugin/plugin.json` 에 `version` 을 쓰지 않는다. 마켓플레이스 항목에도 쓰지 않는다.
  마켓플레이스는 GitHub 저장소 `jon890/fos-skills` 를 git 소스로 등록한다. 스킬을 만든 머신도 같은 방식으로 설치한다.
  스킬마다 두는 `metadata.version` 과 `CHANGELOG.md` 는 변경 추적용으로 그대로 둔다.
- **맥락**: `version` 을 쓰면 그 문자열이 바뀌어야 설치한 쪽이 새 복사본을 받는다. 이 저장소는 스킬 하나를 며칠에 한 번꼴로 고치므로, 고칠 때마다 스킬 버전과 플러그인 버전을 함께 올려야 한다.
  README 는 스킬 버전을 배포 핀이 아니라 변경 추적으로 정했고 git 태그도 만들지 않는다.
  2026-10-01 에 Claude Code 2.1.286 과 격리된 `CLAUDE_CONFIG_DIR` 로 확인한 동작은 다음과 같다.
  - `version` 이 없으면 설치 캐시의 디렉터리 이름과 `claude plugin list` 의 버전이 커밋 SHA 앞 12자리가 된다.
  - git 소스에서는 새 커밋이 생긴 뒤 `claude plugin update fos-skills@fos-skills` 한 번으로 새 복사본을 받는다.
  - git 소스에서 커밋하지 않은 작업 트리 변경은 받지 않는다.
  - directory 소스에서는 설치하는 순간의 작업 트리가 커밋하지 않은 변경까지 복사된다. 그 뒤 HEAD 가 그대로면 `update` 는 새 복사본을 받지 않는다.
  - `version` 을 두고 올리지 않으면 내용이 바뀌어도 `update` 가 새 복사본을 받지 않는다.
  - `version` 이 없으면 `claude plugin validate` 는 경고 하나를 내고 종료 코드 0 이다. `--strict` 를 붙이면 그 경고로 실패한다.
  - `claude --plugin-dir <작업 트리>` 는 그 세션에만 작업 트리를 `fos-skills@inline` 으로 로드한다. 커밋하지 않은 변경도 읽는다.
- **대안 기각**:
  - `version` 을 두고 변경마다 올린다. 올리지 않은 변경을 막는 검사와 릴리스 단위가 생긴다. 설치하는 사람이 저장소 주인 한 명이라 릴리스 단위로 받을 사람이 없고, 버전 둘을 올리는 일만 남는다.
  - 이 머신은 directory 소스로 로컬 체크아웃을 등록한다. push 없이 커밋만으로 갱신된다. 그러나 체크아웃이 기능 브랜치에 있으면 머지하지 않은 내용이 설치되고, 설치하는 순간의 커밋하지 않은 변경도 캐시에 들어간다. 사외 머신과 받는 내용이 달라진다.
  - 이 머신은 `~/.claude/skills/fos-skills` 링크 하나로 저장소를 `fos-skills@skills-dir` 플러그인으로 로드한다. 고치면 바로 반영된다. 사용자가 이 머신도 `fos-brain` 처럼 마켓플레이스로 설치하기로 정했다.
- **결과**:
  - 얻는 것: 플러그인 버전을 올리는 일이 없다. main 에 들어간 커밋마다 설치한 쪽이 `update` 로 받는다.
  - 얻는 것: 이 머신과 사외 머신이 같은 저장소의 같은 브랜치에서 같은 내용을 받는다.
  - 감당할 것: 스킬을 고친 뒤 커밋하고 main 에 머지해 push 한 다음 `update` 를 해야 이 머신의 설치본에 반영된다. 고치는 동안에는 `claude --plugin-dir` 로 작업 트리를 직접 로드해 확인한다.
  - 감당할 것: `claude plugin validate --strict` 를 쓰지 못한다. 검증은 `--json` 출력에서 오류가 없고 경고가 버전 경고 하나뿐인지를 본다.
  - 감당할 것: 설치한 쪽은 main 의 모든 커밋을 받는다. 특정 시점에 고정하려면 마켓플레이스를 등록할 때 ref 를 지정해야 한다.
  - 감당할 것: `~/.claude/scripts/` 와 `~/.claude/rules/` 의 개인 링크는 로컬 체크아웃을 가리키므로 체크아웃의 현재 내용을 바로 읽는다. 설치본과 체크아웃의 내용이 push 전까지 다를 수 있다.
- **적용 범위**: 갱신과 개발 중 확인의 순서는 [flow.md](../flow.md) 가 소유한다. 배치 결정은 [ADR-001](001-plugin-from-repo-root.md) 이 소유한다.
