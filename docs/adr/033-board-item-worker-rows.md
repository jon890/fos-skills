# ADR-033: 보드 항목은 worker 줄 목록을 갖고, 후속 PR 의 사건 단계는 그 줄이 갖는다

- **status**: `accepted`
- **decision-type**: `architecture`
- **areas**: `data`
- **현재 규칙의 원본**: [보드 항목 하위 worker 기술 설계의 「인터페이스와 데이터」](../features/board-item-workers/design.md#인터페이스와-데이터), [스펙 DECISION2·DECISION8·DECISION22](../features/board-item-workers/spec.md#결정), `extensions/work-board/bin/board.ts` 머리 주석, `skills/orch/scripts/core/milestones.ts` 머리 주석.
- **결정**: 보드 항목에 `workers` 필드(worker 줄 목록)를 둔다. 줄은 역할, dispatch, 워크트리, 브랜치, PR, 상태를 갖는다. 줄 목록과 대표 칸(`worktree`·`branch`)은 work-board 의 보드 명령(`worker-add`, `worker-end`)이 한 잠금 안에서 함께 고친다. 대표 칸은 가장 최근의 작업 중 구현·후속 줄 값이고, 구현 항목에 붙은 리뷰·검증 줄은 대표가 되지 않는다. 줄의 열쇠는 워크트리다. 앞 PR 이 열린 채 새 브랜치로 붙은 후속 줄은 자기 PR·머지 단계 번호(`stages`)를 갖고, 배포·릴리스 단계는 항목 `stages` 에 하나씩 둔다. [ADR-018](018-board-milestone-steps.md) 의 사건 규칙은 PR 마다 그 PR 의 묶음에 적용한다.
- **맥락**: 같은 일의 리뷰, 재리뷰, 검증, 후속 PR worker 를 띄우면 지시서 제목으로 새 항목이 생겨 보드가 흩어졌다(스펙 「배경」). 항목은 worker 를 대표 칸 하나로만 가리켜, 붙이면 앞 worker 가 보드에서 사라진다. 대표 칸은 옛 번들의 창, 다른 저장소의 루프, 보드 맞추기의 닫기 판정이 읽는다. 항목 `stages` 는 사건마다 번호 하나라 PR 둘이 함께 열린 항목의 단계를 나타내지 못한다.
- **대안 기각**:
  - 부모·자식 항목: 단계와 진행률을 두 층에서 세야 하고 보드·동기화·창의 변경이 커진다. 사용자가 고르지 않았다(스펙 DECISION2).
  - orch 가 대표 칸을 계산해 `set --worktree` 로 쓴다: 줄 쓰기와 대표 칸 쓰기 사이에 다른 쓰기가 끼면 둘이 어긋난다.
  - 항목 `stages` 를 묶음 목록으로 넓힌다: 필드의 꼴이 바뀌어 옛 번들이 그 항목의 마일스톤 판정 전체를 건너뛴다. PR 과 묶음을 잇는 칸도 따로 필요하다. 고른 안에서 옛 번들이 놓치는 것은 후속 묶음 단계뿐이다.
  - PR 을 이을 때 후속 단계 글에 PR 꼬리표(`(#N pr)`, `(#N merge)`)를 붙인다: 옛 번들도 기존 꼬리표 파서로 읽는다. 그러나 꼬리표가 있는 항목은 보드 맞추기의 수동 사건 갈래를 타서 마일스톤 갈래(마지막 PR 판정, 배포, done 지점)를 건너뛴다. 두 갈래를 한 항목에 섞는 규칙을 새로 정해야 하고, PR 을 잇기 전까지는 수동 단계로 보인다.
- **결과**:
  - 얻는 것: 한 항목 아래에서 앞 worker 를 잃지 않고 후속·리뷰·검증 worker 를 함께 본다. 옛 번들은 대표 칸으로 지금처럼 읽는다.
  - 얻는 것: PR 을 나눠 열어도 항목이 하나로 남고 각 PR 의 머지가 자기 단계만 끝낸다.
  - 감당할 것: 끝남을 놓친 dispatch 의 줄은 워크트리가 정리될 때까지 작업 중으로 남는다. 루프가 꺼진 동안 지나간 worker_done 은 Orca 행이 사라졌으면 끊김으로 보인다.
  - 감당할 것: 보드 맞추기는 한 틱에 항목마다 머지 하나만 반영해 둘이 함께 머지되면 둘째는 다음 틱에 반영된다.
  - 감당할 것: 사건 단계를 알아보는 자리(자동 진행의 첫 단계, 갱신 필요 알림, 시각 대기, 보드 명령의 사건 단계 검사)가 항목 `stages` 와 줄 `stages` 를 함께 봐야 한다. 옛 번들은 후속 묶음 단계를 수동 단계로 보아 끝내지 못하고 그 항목을 done 으로 바꾸지 않는다. 같은 저장소의 루프와 창은 같은 번들에서 함께 갱신된다.
- **확인 방법**: `extensions/work-board/tests/` 의 `worker-add`·`worker-end` 테스트와 `skills/orch/tests/` 의 `registerBoard`·보드 맞추기 테스트.
