# CHANGELOG: build-with-teams

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준과 쓰는 형식은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 5.26.0 (2026-10-28)

- 사용 한도에 걸려도 더 비싼 모델로 올리지 않는다. 규칙은 `~/.claude/CLAUDE.md` 를 가리킨다

## 5.25.0 (2026-10-28)

- 팀원 회신은 약 4,000자에서 잘린다. 긴 회신은 파일에 쓰고 경로를 보내게 하고, critic 회신은 판정, 실행 형태, 발견 목록 순으로 바꿨다
- 스폰 프롬프트에 「검증 명령은 시간 제한을 주고 앞에서 돌린다」 를 넣고, 팀원은 `shutdown_request` 로 종료한다
- 커밋 전 대조에서 계획 목록에 없는 파일이 phase 목표 안이면 표에 더하고 커밋 메시지에 밝힌다. 목표 밖일 때만 3단계로 돌아간다
- code-reviewer 는 테스트를 다시 돌리지 않고 executor 의 검증 보고를 phase 「검증」 절과 대조한다. 이 스킬의 절차 결함은 직접 고치지 않고 개선 후보로 알린다
- 호환성: plan 하나는 PR 하나이고 계획서는 구현한 PR 에서 지운다. 중간 PR 에서 `current_phase` 를 올려 계획서를 남기던 절차를 없앴다

## 5.24.0 (2026-10-27)

- task 없이 지시서나 ADR 을 계획 입력으로 받아 리뷰 단계부터 도는 경로를 더했다. PR 하나로 끝나는 작은 일에 쓴다
- 계획서는 남은 phase 가 없는 PR(업무의 마지막 PR)에서만 지운다. 중간 PR 은 `index.json` 의 `current_phase` 를 올리고 계획서를 남긴다

## 5.23.1 (2026-10-25)

- README 를 스킬을 쓰는 사람 관점으로 다시 쓰고, 이 CHANGELOG 를 버전마다 핵심만 남기도록 줄였다. 동작은 바뀌지 않았다

## 5.23.0 (2026-10-24)

- PR 본문에 「뒤로 미룬 일」 로 `deferred` 를 옮긴다. 계획서를 같은 PR 에서 지우면 함께 사라지기 때문이다

## 5.18.0 (2026-10-12)

- 스폰 도구가 역할 인자를 받지 않으면 역할 정의를 스폰 프롬프트나 별도 CLI 세션의 개발자 지침으로 넘긴다
- 모델 용량 부족으로 스폰이 실패하면 같은 등급의 다른 모델로 바꾸고, 통과한 검증은 반복하지 않고 이어 간다
