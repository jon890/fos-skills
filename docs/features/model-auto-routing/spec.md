# orch: 새 모델을 알아서 쓰고, 실측으로 행마다 쓸 모델을 정하고, 여러 계정의 남는 사용량부터 쓴다

확인: 2026-11-20

## 목표

새 모델이 나오면 사람이 모델 표를 고치지 않아도 orch 가 알아채 쓴다.
같은 계열의 새 세대는 바로 쓰고, 다른 새 모델은 같은 일을 두 모델에 맡겨 비교한 결과로 행마다 쓸 모델을 정한다.
worker 를 띄울 때는 써도 되는 모델 가운데, 초기화까지 남은 시간에 비해 사용량이 가장 많이 남은 계정을 쓴다.

2026-11-20 에 Codex CLI 가 낡아 `gpt-6.2-sol` 을 받지 못했고, 모델 표를 바꾸려고 스펙을 따로 썼다([model-table-6-2](../model-table-6-2/spec.md)).
같은 날 Claude 주간 사용량이 초기화 37시간 전인데 22% 만 쓰여, 코디네이터가 Codex 행을 직접 Claude 로 바꿔 띄웠다([usage-routing](../usage-routing/spec.md) 은 계정 하나만 본다).
이 머신에는 Orca 가 관리하는 Claude 구독 계정 4개와 Codex 계정 2개가 있다(`orca account list`).

## 범위

이번 범위는 두 층이다.

| 층 | 정하는 것 |
| --- | --- |
| 품질 | 행마다 써도 되는 모델 목록. 새 모델 감지, 같은 계열 자동 전환, 비교 결과로 정한다 |
| 사용량 | 그 목록 안에서 이번에 띄울 모델과 계정 |

PR 은 셋이고 이 순서로 머지한다.

1. 새 모델 감지와 같은 계열 자동 전환, 낡은 Codex CLI 알림. [model-table-6-2](../model-table-6-2/spec.md) 를 대신한다.
2. 여러 계정의 사용량으로 계정과 제공자 고르기. 하지 않는다(사용자 결정 2026-11-23, 아래 DECISION31).
3. 같은 일 두 모델 비교의 절차와 기록 틀. 코디네이터가 절차대로 비교하고, 숨긴 리뷰와 보드 승인으로 표를 바꾼다(DECISION32).

범위 밖:

- 여러 계정의 사용량으로 계정과 제공자를 고르는 PR 2(사용자 결정 2026-11-23). 사용량 때문에 Fable 행이 astra 로 저절로 바뀌는 일도 없다. astra 는 [agent-selection.md](../../../skills/orch/references/agent-selection.md) 「기본 후보에서 뺀 모델」 대로 쓴다.
- 비교의 자동 시작, 두 worker 를 묶는 관리, 숨긴 리뷰와 관문의 자동 계산. 코디네이터가 절차대로 한다(DECISION32).
- Codex CLI 나 Claude Code 를 자동으로 갱신하는 것. 알리기만 한다.
- 이미 떠 있는 worker 의 모델이나 계정을 바꾸는 것.
- 하위 에이전트와 코디네이터 세션 자신의 모델과 계정.
- 비교 결과로 모델 표를 사람 승인 없이 바꾸는 것.

## 요구사항과 인수 조건

### PR 1. 새 모델 감지와 같은 계열 자동 전환

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 새 모델을 알아챈다 | 루프가 하루 한 번 설치된 Codex CLI 의 모델 목록(`codex debug models`)을 읽는다. 첫 실행의 목록을 기준점으로 남기고, 그 뒤에 나타난 모델 가운데 목록에 보이고(`visibility: list`) 설명이 Legacy·Previous generation 이 아닌 것만 새 모델로 보고 보드에 「새 모델 <이름>」 한 줄을 알린다. 같은 모델은 한 번만 알린다. 오늘 나온 `gpt-6.2-astra` 는 기준점에 넣지 않아 첫 새 모델이 된다 |
| REQ2 | 같은 계열의 새 세대로 바로 바꾼다 | 표의 모델과 계열 이름이 같고(예: `sol`) 세대가 높은 모델이 목록에 있으면, 다음 띄우기부터 그 세대로 띄운다. 지시서의 `worker 선택:` 에 옛 세대가 적혀 있어도 거절하지 않고 새 세대로 띄운다. effort 는 행의 값 그대로다. 바꾼 사실은 `LAUNCH-EFFECTIVE` 와 띄우기 기록에 남는다 |
| REQ3 | 낡은 표 행을 알리고 코디네이터가 PR 로 고친다 | 루프가 새 세대를 알아채면 모델 표에서 옛 세대를 가리키는 행마다(띄울 때와 같은 기준) Run 메시지 `MODEL-TABLE-STALE <행> <옛> → <새>` 를, 새 세대마다 보드 항목 「모델 표를 <새> 로 바꿀 때」 를 한 번 남긴다. 루프는 표를 고치지 않는다. 코디네이터가 작은 worker 로 표를 고치는 PR 을 내 머지한다. 머지 뒤 표와 실제로 띄우는 모델이 같다 |
| REQ4 | 새 세대가 실패하면 그 띄우기만 옛 세대로 | 그 계정의 모델 검사가 새 세대를 받지 못하면 그 띄우기 하나만 옛 세대로 띄우고 이유를 남긴다. 다른 띄우기는 계속 새 세대를 쓴다 |
| REQ5 | Claude 는 계열 이름으로 최신을 따른다 | 표의 Claude 행이 계열(opus, sonnet, haiku, fable)의 최신 모델로 띄워진다. 띄우기 기록에는 실제로 쓴 모델 ID 가 남는다 |
| REQ6 | 낡은 Codex CLI 를 알린다 | `codex` 명령이 있는 머신에서 설치된 Codex CLI 가 최신 버전보다 낮으면 `orch doctor` 가 `CODEX-OUTDATED <설치> <최신>` 과 갱신 방법 한 줄을 낸다. `codex` 명령이 없으면 확인하지 않는다. 최신 버전을 확인하지 못하면 줄을 내지 않고 doctor 를 실패시키지 않는다 |
| REQ23 | 직접 고른 옛 세대는 막는다 | 같은 계열에 새 세대가 있는데 지시서가 옛 세대를 `후보 밖` 으로 골랐으면 launch 가 `MODEL-OUTDATED <옛> → <새>` 로 거절한다. worker 가 쓸 계정이 새 세대를 받지 못할 때만 그 띄우기를 옛 세대로 띄우고 이유를 남긴다 |

### PR 2. 여러 계정의 남는 사용량부터 쓴다(하지 않음)

하지 않는다(사용자 결정 2026-11-23): 계정 선택은 사용자가 정한다. 아래 표는 정했던 내용의 기록으로만 남기고 구현하지 않는다. 지금 계정 하나의 사용량으로 Codex 구현 행을 같은 등급 Claude 로 띄우는 동작은 [usage-routing](../usage-routing/spec.md)(PR 557)이 그대로 맡는다.

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ7 | 계정마다 사용량을 읽는다 | Orca 의 Claude 계정과 Codex 계정마다 주간 사용 %, 주간 초기화 시각, 5시간 한도 사용 %, 값을 마지막으로 성공해 읽은 시각을 얻는다. 같은 구독(같은 조직)을 가리키는 계정이 여럿이면 한 후보로 센다 |
| REQ8 | 남는 양이 가장 많은 계정으로 띄운다 | 행의 모델과 그 모델의 같은 등급 짝(아래 표) 가운데, 계정마다 「남은 사용 % − 초기화까지 남은 시간 %」 가 가장 큰 계정과 그 제공자의 모델로 띄운다. 행을 가리지 않고 모든 행에 같은 짝을 쓴다. 고른 계정, 두 값, 다른 후보의 값이 `LAUNCH-EFFECTIVE` 와 띄우기 기록에 남는다 |
| REQ9 | 같은 등급 짝 | Claude Fable ↔ Codex astra, Claude Opus ↔ Codex sol, Claude Sonnet ↔ Codex terra, Claude Haiku ↔ Codex luna. 각 짝은 그 계열의 최신 세대를 쓰고(REQ2, REQ5), effort 는 행의 값 그대로다. 이 짝이 「사용 한도에 걸렸을 때」 표의 같은 등급 대응도 대신한다 |
| REQ10 | 리뷰는 만든 쪽과 다른 제공자 | 리뷰 worker 는 짝으로 바꾸더라도 결과를 만든 worker 와 다른 제공자로 띄운다. 그 제공자 안에서만 계정을 고른다 |
| REQ11 | 5시간 한도가 찬 계정은 뺀다 | 5시간 한도 사용이 90% 이상인 계정은 그 띄우기의 후보에서 뺀다 |
| REQ12 | 남는 계정이 없으면 행의 기본으로 | 모든 후보 계정의 값이 0 이하면, 행의 기본 제공자에서 값이 가장 큰 계정으로 띄운다. 주간 사용이 100% 이거나 한도에 걸린 계정은 이때도 고르지 않고, 기본 제공자에 고를 계정이 없으면 짝의 제공자로 띄운다 |
| REQ13 | 모르는 값은 쓰지 않는다 | 사용량을 읽지 못했거나 마지막 성공이 1시간보다 오래된 계정은 후보에서 빼고 `USAGE-UNKNOWN <계정> <이유>` 를 낸다. 모든 계정을 모르면 지금처럼 띄운다 |
| REQ14 | 사용자 세션의 계정을 건드리지 않는다 | worker 를 띄우는 동안만 그 계정을 쓰고, 끝나면 Orca 의 선택 계정이 띄우기 전과 같다. 동시에 띄우는 두 worker 가 서로의 계정을 바꾸지 않는다 |
| REQ15 | 한도에 걸린 계정은 새 띄우기에서 빠진다 | 새로 띄우는 worker 는 한도에 걸린 계정을 고르지 않는다. 이미 떠 있는 worker 가 한도에 걸리면 지금처럼 「사용 한도에 걸렸을 때」 절차(사용자에게 계정 전환 요청, resume)를 따른다 |
| REQ16 | 끈다, 정한 worker 는 제공자를 지킨다 | orch 설정 `routing.usage_boost: false` 면 계정과 제공자를 바꾸지 않는다. 지시서에 `후보 밖` 으로 정한 worker 와 비교 worker(REQ18)는 제공자와 모델을 바꾸지 않고, 같은 제공자 안에서 계정만 고른다 |

### PR 3. 같은 일을 두 모델에 맡겨 비교하는 절차와 기록 틀

자동 기능을 만들지 않고, 코디네이터가 지금의 `orch worker launch` 로 따르는 절차와 기록 틀을 둔다(DECISION32). 인수 조건은 문서와 틀이 생겼는지, 절차가 결정값을 담는지로 본다.

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ17 | 비교를 시작하는 절차가 있다 | `skills/orch/references/model-compare.md` 가 비교 시작을 적는다. 대상은 같은 계열의 새 세대가 아닌 새 모델이고, 코디네이터가 모델 설명과 등급으로 행을 고르고 보드 항목 하나로 모은다. 첫 대상은 `gpt-6.2-astra`(보드 항목 model-new-gpt-6-2-astra)다. 사용자가 멈추라고 하면 남은 건을 띄우지 않는다. `agent-selection.md` 가 이 문서를 가리킨다 |
| REQ18 | 같은 지시서를 두 모델에 맡기는 절차가 있다 | 절차가 지시서 본문 하나를 두 파일로 복사하고 브랜치와 `worker 선택:` 줄만 바꾸게 한다. 두 줄 모두 `후보 밖:` 을 적어 제공자와 모델을 지킨다. 후보 줄은 `후보 밖: 비교, <지금 모델> 대조(사용자 결정 2026-11-20)` 다. 고른 행마다 5건, 나은 쪽 머지와 다른 쪽 닫기, 숨긴 리뷰가 갈리면 평소 리뷰의 P1·P2 수로 머지하고, 그 수도 같으면 준비까지 분이 짧은 쪽을 머지하며 무승부, 실패한 쪽은 나쁜 건(DECISION4, DECISION17, DECISION34)을 적는다 |
| REQ19 | 숨긴 리뷰 지시서 틀이 있다 | `skills/orch/templates/spec-compare-review.md` 가 두 PR 의 diff 를 모델 이름, PR 번호, 브랜치 없이 A, B 로 넘기고 「어느 쪽을 머지하겠나」 와 이유를 받는다. 절차가 Claude 와 Codex 리뷰어가 같은 쪽을 고른 건만 센다고 적는다(DECISION7) |
| REQ20 | 세 관문 판단 절차가 있다 | 절차가 건마다 기록할 값(리뷰 P1·P2, 첫 CI, 리뷰 뒤 고친 커밋, 막힘·재시도, 준비까지 분, 토큰)과 출처, 5건 뒤 문제 → 시간 → 비용 순서와 기준값, 세 정의(DECISION5, DECISION6, DECISION28, DECISION33)를 담는다 |
| REQ21 | 승인 뒤에만 표를 바꾸는 절차가 있다 | 절차가 판단이 「후보로 바꿈」 이면 보드 승인 대기로 올리고, 승인되면 코디네이터가 표를 바꾸는 worker 를 띄우고, 거절이나 「지금 모델 유지」 면 결과만 남기게 한다(DECISION8) |
| REQ22 | 기록 자리가 있다 | `skills/orch/templates/model-compare-record.md` 기록 표 틀이 있고, `docs/features/orch-routing/evidence.md` 의 「같은 일 두 모델 비교」 절에 쌓는다. 같은 모델과 행은 판단 뒤 다시 비교하지 않는다(DECISION29). `skills/orch/tests/docs-contract.spec.ts` 가 절차, 두 틀, evidence 절이 서로 가리키는지 본다 |
