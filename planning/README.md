# planning

확정한 기능 스펙을 구현자가 실행할 PR 하나의 작업으로 나눈다. 제품 동작은 spec 에서 정하고 여기서는 구현 순서와 검증 명령에 집중한다.

## 이럴 때 쓴다

- 합의한 스펙으로 task 를 만들 때
- 큰 기능에서 지금 구현할 PR 만 상세화할 때

## 사용 예시

> “docs/features/run-cancel/spec.md 의 구현 계획을 만들어 줘.”
> 이번 PR 의 요구사항을 고르고 테스트까지 포함한 phase 를 만든 뒤 계획을 검토한다.

## 받는 것

- 스펙과 요구사항 ID 가 연결된 index.json
- phase 별 작업·변경 파일·검증 명령
- 뒤 PR 의 목표와 선행 조건

기존 spec 필드 없는 계획은 호환 절차로 이어 간다.

## 함께 쓰는 스킬

- `spec`: 요구사항과 설계를 확정한다
- `build-with-teams`: 계획을 구현한다
- `verify`: 인수 조건을 확인한다
