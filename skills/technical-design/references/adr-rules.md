# ADR 규칙

「원칙 대조」와 「설계 문서」 단계에서 ADR 을 만들거나 대체할 때 읽는다.
ADR 을 남길 조건, 양식 쓰는 법, 대체와 이동 규약을 이 문서가 소유한다(사용자 결정 2026-11-05). 새 ADR 의 항목은 [ADR 양식](../templates/adr.md)이 정한다.
`plan` 과 `docs-audit` 는 이 문서를 가리킨다.

## 남길 조건

ADR 은 여러 기능이나 후속 작업이 다시 참조할 중요한 결정의 이유를 남긴다.
이 저장소의 기본 ADR 은 아키텍처뿐 아니라 주요 도메인 정책과 개발 절차의 결정 기록도 포함한다.
대상 저장소가 ADR 을 기술 결정으로 한정하면 그 규칙을 따르고, 정책·절차의 선택 이유는 해당 책임 문서에 남긴다.

아래 영향 가운데 하나가 있고, 코드·설정만 읽어서는 알 수 없는 선택 이유나 기각한 대안이 있을 때 남긴다.

- 되돌릴 때 코드·데이터·외부 계약을 함께 바꿔야 한다.
- 소유 모듈, 데이터 원본, 의존 방향, 동시성·트랜잭션 같은 핵심 경계를 정한다.
- 여러 기능이 따를 정책이나 보안·비용·운영·검증 기준을 정한다.

라이브러리·제품·폴더 선택도 같은 기준으로 판단한다. 이름이나 현재 배치만 나열하면 남기지 않는다.
장기 결정이 없으면 기능 spec/design 이나 PR 에 근거를 적고 빈 ADR 을 만들지 않는다.
작성 예시는 [결정 기록 샘플](adr-examples.md)을 참고한다.

## 결정 종류와 관심 영역

새 ADR 에는 `decision-type` 하나를 적는다. 종류별 폴더나 별도 번호 체계는 만들지 않는다.

| decision-type | 결정하는 것 | 현재 규칙의 원본 |
| --- | --- | --- |
| `architecture` | 시스템 구조·소유권·기술 경계와 그 선택 | design, 공유 설계·계약, 코드·설정 |
| `domain-policy` | 제품의 판단·허용·분류·보존 의미 | 기능 spec, 공통 도메인 문서, 룰 설정 |
| `engineering-process` | 개발·검증·배포 작업의 절차와 통과 기준 | 해당 스킬·절차 문서, 검사기·설정 |

보안·데이터·운영처럼 종류를 가로지르는 관심사는 선택 항목 `areas` 에 적는다. 고정된 분류 목록을 추가하지 않는다.
예를 들어 Memory 접근 경계는 `architecture`, areas 는 `security, data` 다.
독립적으로 바뀌는 정책과 구현 구조만 별도 결정으로 나눈다. 같은 결정을 종류마다 복제하지 않는다.

`현재 규칙의 원본` 에 지금 적용할 규칙을 소유한 문서·코드·설정의 경로를 연결한다.
ADR 은 선택과 이유를 소유하고, 정확한 값·API·운영 명령은 그 원본이 소유한다.
특정 시점의 수치가 선택 이유에 필요하면 당시 조건임을 밝히고 적되 현재 기본값으로 복제하지 않는다.
문서별 책임과 단계 인계는 [문서 소유권](../../spec/references/document-ownership.md#결정-기록의-단계별-책임)이 소유한다.

기존 ADR 은 타입이 없어도 오류로 보지 않고, 이번 변경이 닿는 결정만 분류한다.
기존 경로·식별자·양식·모듈별 배치를 유지한다. 대상 저장소 도입은 별도 작업이며 전체 재작성·이동을 하지 않는다.

## 담는 것과 담지 않는 것

한 ADR 은 무엇을 선택했고, 왜 필요했으며, 다른 선택은 왜 기각했고, 무엇을 감당하는지 답한다.
현재 구조의 전체 목록이나 실행 매뉴얼은 책임 문서를 링크한다.

담지 않는 것:

- 긴 코드 블록과 실행 호출 예시
- 현재 파일·함수·필드 목록의 복제
- 일반적인 스택·프로그래밍 규칙의 반복
- 작업 내역과 중간 구현 단계의 나열

초안은 합의할 선택과 근거가 드러나게 다듬는다. 확정한 뒤에는 당시 맥락과 기각 근거를 보존한다.
새 결론으로 과거 결정을 덮어쓰지 않는다. 결정 변경은 새 ADR 과 대체 관계로 남긴다.
오타·깨진 링크·분류 메타데이터 수정은 결정 변경과 구분한다.

## 코드로 자명한 결정은 남기지 않는다

코드·설정과 git 이력에서 같은 정보뿐 아니라 같은 이유까지 알 수 있는지 본다.
의존성 파일은 무엇을 쓰는지 보여주지만, 보안·호환성·운영 비용 때문에 대안을 기각한 이유까지 보여주지는 않는다.
기술 이름이나 폴더라는 이유만으로 제외하지 않는다.

- 맥락이 선택 이유 없이 현재 구조만 다시 말하는가?
- 저장소 고유 제약, 실험 결과, 기각한 대안이나 트레이드오프가 없는가?
- 이 기록이 없어도 같은 선택 이유를 복원할 수 있는가?

모두 맞으면 중복 기록 정리 후보로 보고 현재 원본과 외부 참조를 확인한다.
확정된 결정 기록은 자동 삭제하지 않는다. 타입이 없다는 이유로 후보로 삼지 않는다.

## 구조

파일명은 `docs/adr/NNN-<슬러그>.md` 다. 한 파일에 결정 하나만 담는다.
여러 에이전트가 동시에 PR 을 여는 저장소는 파일 이름과 색인을 [`adr-parallel.md`](adr-parallel.md) 로 정한다.

새 문서는 [ADR 양식](../templates/adr.md)을 읽고 쓴다. 기존 ADR 양식이 있으면 우선한다.

확정한 ADR 의 `status` 는 둘뿐이다. 승인 전 초안은 현재 결정으로 읽지 않고, 해당 종류의 결정 주체가 합의한 뒤 확정한다.

| 값            | 뜻                              |
| ------------ | ------------------------------ |
| `accepted`   | 현재 유효하다                        |
| `superseded` | 다른 ADR 이 이 결정을 뒤엎었다. 이력으로만 읽는다 |

`status` 가 없는 기존 ADR 은 `accepted` 로 읽는다.

**결과** 는 결정한 뒤에 생기는 트레이드오프를 적는다. 얻는 것과 감당할 것을 둘 다 적는다.

## 대체와 이동

**ADR 은 지우지 않는다.**
결정 전체가 번복돼도 `status` 를 `superseded` 로 바꾸고 `대체된 부분` 에 대체한 ADR 을 가리킨다.
지우면 그때 그 판단을 왜 했는지가 사라진다.

- `superseded` 로 바꾼 파일은 `docs/adr/superseded/` 로 옮긴다. 파일 이름과 번호 또는 날짜 식별자는 바꾸지 않는다.
  현행 결정과 대체된 결정을 폴더만 보고 구분하려는 사용자 결정(2026-10-24)이다.
- 같은 변경에서 그 파일을 가리키는 상대 링크를 모두 고친다. 다른 ADR, docs, 코드 주석, README 와 옮긴 ADR 안의 상대 링크도 확인한다.
- 색인 파일(`INDEX.md` 등 저장소가 쓰는 것)은 「현행」 과 「대체됨」 으로 나눠 적는다.
- 일부만 대체돼 `accepted` 이면서 `대체된 부분` 이 있는 ADR 은 옮기지 않는다.
- `대체된 부분` 은 **결정 바로 아래**에 둔다. 결정만 읽고 지나가는 독자가 낡은 결론을 얻는 것을
  막는 것이 목적이라, 문서 끝이나 대안 기각 안에 넣으면 의미가 없다.
- 대체한 쪽 ADR 에서도 원본을 링크해 양방향으로 찾을 수 있게 한다.
- 전체가 대체된 ADR 은 남은 본문 앞에 그것이 당시의 맥락임을 한 줄로 밝힌다.
- 코드와 경로는 결정을 가리키는 데 필요한 만큼만 인용한다. 구현 호출 방법, 작업 내역,
  스택 규칙 반복은 넣지 않는다. 결정과 근거만 남긴다.
- 계획서 번호를 적지 않는다. ADR 은 계획서보다 오래 남으므로 [plan 의 「계획서를 가리키지 않는다」](../../plan/references/task-create.md#계획서를-가리키지-않는다)를 따르고, 근거는 다른 ADR 번호나 PR 번호로 적고 부족하면 내용을 본문에 옮긴다.

## 대체한 뒤 검사

ADR 을 대체한 뒤 위치와 저장소 Markdown 의 ADR 상대 링크를 검사한다. 종료 코드 0 이어야 한다.
검사기는 plan 번들에 있다. `$PLAN_SKILL_DIR` 은 plan 스킬 번들 경로이고, `$ADR_DIR` 은 오버레이가 정한 ADR 경로다. 지정이 없으면 `docs/adr` 다.

```bash
# cwd: 타깃 레포 root
python3 "$PLAN_SKILL_DIR/scripts/check_adr_layout.py" "${ADR_DIR:-docs/adr}"
```

오버레이가 「superseded 폴더 사용 안 함」 으로 정한 저장소(대체된 ADR 을 `docs/adr` 에 그대로 두고 색인으로 구분)는 `--flat` 을 붙인다.
`--flat` 은 폴더 위치와 `status` 검사를 건너뛰고 링크 검사만 한다. 오버레이가 정하지 않았으면 붙이지 않는다.

```bash
# cwd: 타깃 레포 root
python3 "$PLAN_SKILL_DIR/scripts/check_adr_layout.py" "${ADR_DIR:-docs/adr}" --flat
```

코드 주석의 링크와 색인의 「현행」·「대체됨」 구분은 변경 diff 에서 확인한다.
