# presentation

발표 자료를 만들 때 장 구성을 잡고 일일이 눈으로 훑어 확인하는 수고를 덜어 준다.
발표 자료를 HTML 슬라이드 덱 한 파일로 만들고, 장 수와 발표자 노트, 금지어, 세로 넘침을 명령으로 검사한다.
슬라이드 도구를 쓰지 않으므로 git 으로 차이를 보고, 발표 중에도 노트를 고칠 수 있다.

## 이럴 때 쓴다

- 세미나나 랩 발표 자료를 처음부터 만든다
- 이미 만든 덱의 장을 고치거나 제목을 검수한다
- 발표 스크립트의 분량을 재서 소요 시간을 가늠한다

"발표 자료", "발표 준비", "슬라이드", "세미나 자료", "발표 장 검수" 처럼 말하면 이 스킬이 뜬다.

## 사용 예시

```text
나:   다음 주 세미나 발표 자료 만들어줘

스킬: 덱을 짜기 전에 하나씩 여쭤볼게요. 먼저 발표 성격은 방법 공유인가요, 결과 보고인가요?

나:   방법 공유야

스킬: (인터뷰 여섯 항목을 마치고 골격 템플릿으로 덱을 만든 뒤)
      20261029_홍길동_ai-코딩.html 을 만들고 검사를 돌렸어요.
        장 12개, 노트 누락 0, 금지어 0, 세로 넘침 없음
      리허설 분당 글자 수로 계산한 소요 시간은 27분이에요.
```

## 받는 것

- `<YYYYMMDD>_<이름>_<주제>.html` 한 파일. 장, 발표자 노트, 캡처가 모두 그 안에 들어가 다른 기기에서도 열려요
- `check-deck.py` 의 구조 검사 결과. 종료 코드 0 은 통과, 1 은 위반, 2 는 검사기가 돌지 못한 경우예요
- 리허설로 잰 분당 글자 수에서 계산한 소요 시간

발표 자료는 기본적으로 저장소에 커밋하지 않아요. 커밋하려면 먼저 확인해요.

## 준비

- 덱을 짜기 전에 인터뷰로 발표 성격, 청중이 놀랄 한 지점, 도구를 드러내는 방식, 시간과 질문 시점, 데모 여부, 부 구성을 정해요
- `python3` 가 있어야 검사기가 돌아요. `node` 가 있으면 JS 문법도 검사해요
- 금지어는 같은 저장소의 `korean-check` 스킬이 소유해요. 그 스킬이 없으면 금지어 검사를 건너뛰어요
- `--browser` 로 세로 넘침을 재려면 `tools/browser-driver` 나 `~/.claude/scripts/browser-driver` 가 있어야 해요. 없으면 그 항목만 건너뛰어요
- 글꼴을 Google Fonts 에서 받으므로 망이 없는 발표장에서는 화면이 달라져요. 발표 전에 망 없이 한 번 열어 확인해요

## 함께 쓰는 스킬

| 하려는 일 | 쓰는 스킬 |
| --- | --- |
| 발표 덱을 만들고 장을 검수한다 | `presentation` |
| 외부에 게시하는 본문을 등록 전에 보여준다 | `content-preview` |
| 저장소 문서가 코드와 맞는지 감사한다 | `docs-check` |
| 한국어 산출물을 내보내기 직전에 점검한다 | `korean-check` |
