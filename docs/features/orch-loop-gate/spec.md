# orch: 확인받은 스펙 없이 기능 worker 를 띄우지 않게 막고, 새 기능 요청이면 spec 부터 시작한다

확인: 2026-11-02

## 목표

사용자가 매번 말하지 않아도 모든 코디네이터가 기능 작업을 spec → planning → build-with-teams → verify 순서로 진행한다. 확인받은 스펙 없이 기능 구현 worker 를 띄우려 하면 `launch-worker` 가 막고, 새 기능 요청이 오면 spec 스킬이 먼저 불린다.

- 배경: 11/02 ai-analysis 코디네이터가 지침(`.orch/overlay.md`, orch `references/feature-loop.md`)에 루프가 적혀 있는데도 확인받은 스펙 없이 구현 worker 를 여럿 띄웠다. 지침만으로는 바쁠 때 건너뛴다.
- 사용자 결정(2026-11-02): 엔지니어링 루프를 모든 작업의 기본으로 한다.

## 범위

이번 범위:

- orch `launch-worker` 의 지시서 검사(`spec-lint`)에 루프 선택 검사를 더한다.
- orch 공통 지시서 틀과 `references/feature-loop.md` 에 「할 일」 첫 줄 형식을 적는다.
- spec 스킬 설명(description)의 호출 문구를 넓힌다.

범위 밖:

- 코디네이터가 worker 없이 직접 구현하는 경우(orch 밖). 개인 지침이 맡는다
- planning·build·verify 단계 사이 검사(각 스킬이 이미 확인 줄과 계획을 본다)

| R1 | 새로 띄우는 지시서의 `## 할 일` 제목 아래 첫 줄은 `루프를 쓴다(스펙: <경로>)`, `루프를 쓴다(스펙: 새로 쓴다)`, `루프 없이: <이유>` 중 하나여야 한다. `리뷰 PR:` 이나 `중간 과정:` 표시가 있는 지시서와 이미 떠 있는 worker 의 지시서(`--active`)는 검사하지 않는다 | `## 할 일` 제목이 없거나 첫 줄이 셋 중 하나가 아닌 지시서는 spec-lint 가 막을 발견을 내고 launch-worker 가 worktree 를 만들기 전에 종료 코드 5 로 멈춘다 | spec-lint 단위 테스트, launch-worker 통합 테스트 |

| R4 | 막힌 지시서는 `--lint-ack <이유>` 로만 넘길 수 있고 이유가 기록에 남는다 | 기존 lint-ack 동작과 같다 | 기존 테스트 |

| R6 | spec 스킬 설명이 새 기능 요청에서 불린다 | 설명에 「스펙을 정하자」, 「~을 만들자」, 「~ 기능을 추가하자」, 「~하게 바꾸자」 같은 새 동작 요청 표현이 있고, 버그 수정·정리·조회 요청에는 쓰지 않는다는 문장이 있다 | 스킬 설명 검사(skill-creator 기준) |

## 설계

- 루프 선택 검사는 기존 `spec-lint` 의 발견 규칙 하나로 더한다. launch-worker 는 지금처럼 spec-lint 결과로 막거나 넘긴다(종료 코드 5, `--lint-ack`).
- 스펙 확인 검사는 planning 의 `check_feature.py` 와 같은 규칙(제목 아래 `확인: YYYY-MM-DD`)으로 본다. 경로는 지시서 대상 저장소 루트 기준 상대경로나 절대경로다.
- 공통 지시서 틀과 `feature-loop.md` 에 첫 줄 형식과 예를 적고, 띄우기 보고에 `루프 없이` 이유를 한 줄로 싣는 지시를 더한다.
- spec 스킬 description 은 skill-creator 기준으로 고친다.
