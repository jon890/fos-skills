## 3.5.0

`run_doc_snippets.py` 를 돌릴 때의 안전 지침을 「2. 실측」 에 넣었다.

2단계는 문서의 실행 가능한 블록을 전부 이 스크립트로 돌리라고 지시한다.
그런데 이 스크립트는 블록을 그대로 실행하고 안전장치가 없다.
감사 대상 문서에 `git push`, `gh pr create`, `gh release create`,
`nhncloud configure` 가 들어 있으면 지시를 그대로 따를 때 실제로 실행된다.

사내 저장소의 릴리스 절차 스킬을 감사하며 겪었다.
그 문서에 위 네 명령이 모두 있었고, 같은 날 그 저장소의 운영 배포를 막 끝낸 직후였다.
저장소 밖 디렉터리에서 돌려 `git` 과 `gh` 가 그 저장소에 닿지 않게 했다.
그날은 플레이스홀더가 `<이름>` 형태라 셸이 입력 리다이렉션으로 읽어 대부분 실행 전에 죽었다.
그것은 우연이고, 변수로 값을 채운 문서라면 그대로 실행된다.

위험한 명령을 산문으로 들고, 저장소 밖에서 돌릴 때 무엇이 닿는지를 표로 적었다.

**디렉터리를 옮기는 것으로 다 막히지 않는다.**
`nhncloud configure` 는 사용자 설정 파일을 바꾸므로 디렉터리와 무관하고,
`gh` 도 `--repo` 나 `GH_REPO` 로 저장소를 명시하면 그대로 닿는다.
블록 안에서 `cd` 나 `git -C` 로 경로를 정하는 것도 같다.
닿지 않는 것은 `git` 과 저장소를 현재 디렉터리로 추론하는 `gh` 뿐이다.

**유일한 안전장치는 블록을 먼저 읽는 것이다.**
이 스크립트는 블록 단위로만 돌아 줄 하나를 빼고 돌릴 수단이 없다.
머리말을 주어 블록 하나만 고르는 것이 범위를 좁히는 유일한 방법이다.

**저장소 밖에서 돌리면 블록 안의 상대경로가 풀리지 않는다.**
같은 2단계가 「상대경로가 어느 디렉터리를 전제하는지 함께 본다」 를 요구하는데,
회피법을 쓰는 동안에는 그것을 확인할 수 없다. 나눠 돌리도록 적었다.

스크립트 코드는 이번에 건드리지 않았다.

## 3.4.0

감사 범위를 스킬 하나로 좁힐 수 있게 했다.

실측으로 저장소 스킬 하나만 감사하려는데 검사기가 저장소 전체를 훑었다.
`collect_targets.py` 가 15개 파일을 냈고 그중 대상은 4개였다.
`check_references.py` 와 `check_duplication.py` 는 종료 코드 1 을 냈는데 걸린 자리가 전부 범위 밖의 다른 스킬과 오버레이였다.
좁힐 수단이 없어 조사자가 출력에서 대상 파일을 손으로 골라냈다.

| 위치 | 변경점 |
| --- | --- |
| `scripts/target_files.py` | `iter_targets` 가 `scope` 를 받고, `--scope` 해석과 argv 분리를 함께 소유한다 |
| `collect_targets.py`, `check_facts.py`, `check_duplication.py`, `check_references.py` | `--scope` 를 받는다 |
| `check_rename_drift.py` | `--scope` 를 받고, 기준 커밋에 없던 참조 문서를 드리프트에서 뺀다 |
| `run_doc_snippets.py` | 머리말을 생략하면 파일의 블록을 전부 돈다 |
| 「1. 기준과 범위」 | 범위를 좁히는 방법과 2단계·6단계에서 같은 값을 쓰라는 지시를 넣었다 |
| 「2. 실측」 | 다섯 명령에 `--scope` 를 붙이는 방법을 적었다 |

**`--scope` 는 위치 인자가 아니라 옵션이다.** `check_duplication.py` 가 두 번째 위치 인자를
최소 연속 줄 수로 쓰고 있어 충돌한다. 옵션은 argv 어디에 와도 된다.

대상 판정은 언제나 저장소 루트 기준이다. 좁혀도 같은 파일이 같은 판정을 받는다.

`check_enforcement.py` 는 이번에 건드리지 않는다. 이미 모드마다 대상을 인자로 받아 좁혀져 있다.

**`check_rename_drift.py` 의 오탐도 함께 고쳤다.**
절을 새 참조 파일로 내리는 것은 이 스킬이 처방하는 정상 작업인데,
새 파일은 `git diff` 에 변경으로 잡히지 않아 「안 고친 문서」 로 세어졌다.
그러면 분리 작업마다 종료 코드 1 이 나서 진짜 드리프트가 묻힌다.
기준 커밋에 없던 참조 문서를 대상에서 뺐다.
재현 저장소로 고치기 전 1건, 고친 뒤 0건을 확인했고,
실제 이름 변경은 그대로 잡는 것도 음성 대조로 확인했다.

**이번 변경에서 새로 만든 참조 문서 안의 드리프트는 잡지 못한다.**
참조 문서가 옛 이름을 담고 있는지만 보는 판정도 만들어 돌려 봤으나,
절을 옮긴 경우와 이름을 바꾼 경우가 같게 보여 이동 사례를 다시 오탐으로 잡았다.
무엇을 놓치는지는 `scripts/check_rename_drift.py` 머리말이 소유한다.

## 3.3.0

목표문과 용어 정의를 판정 축으로 넣는다.

**12번 축은 목표문이 입력과 산출물과 다음 행동 셋을 말하는지 본다.**
목표에 입력이 없으면 모델이 판단 근거를 스스로 고르고, 구하기 쉬운 신호가 그 자리를 대신한다.
실측으로 어떤 추천 스킬이 준비가 끝난 건을 1순위로 올렸는데,
사용자가 원한 것은 관심사가 맞는 다른 건이었고 그 선호는 목표문이 입력으로 지정하지 않아 판단에 들어갈 자리가 없었다.

**13번 축은 스킬 안에서 이름 붙인 것이 처음 나오는 자리에서 정의됐는지 본다.**
정의가 없으면 채우는 사람마다 다른 것을 넣는다.
실측으로 「위험」을 정의 없이 적게 한 스킬에서 추천 12건의 위험이 전부 업종 일반론으로 나왔다.

**소유권 중복에 형제 스킬을 더한다.**
어떤 단계가 다른 스킬을 부르면 그 스킬의 절차와 함정은 그쪽이 소유한다.
부르는 쪽에는 넘길 값과 호출 시점만 둔다.

## 3.2.0

조사를 나눠 맡기고 메인은 셋만 한다.
무엇을 맡길지 나누는 것, 돌아온 보고를 종합하는 것, 승인을 받아 고치는 것이다.

**조사는 읽기만 시킨다.** 고칠 권한을 함께 주면 승인 절차를 거치지 않은 수정이 들어온다.
축이 여럿이면 축마다 하나씩 맡겨 한 번에 띄운다. 축끼리 서로의 결과를 기다리지 않는다.

회신 형식을 판정표의 한 줄과 같게 시켜, 모으면 그대로 판정표가 되게 했다.

하위 에이전트를 띄울 수 없는 하네스에서는 메인이 직접 하고 그 사실을 완료 보고에 적는다.
검토자를 다루는 방식과 같다.

## 3.0.0

**목표: 하네스 지침에 모델이 추론할 수 없는 것만 남기고, 사용자가 승인한 것만 고친다.**

- 짧게 만드는 것보다 사실과 실행 가능성을 먼저 확인한다.
- 판정마다 그것을 확인한 실행 결과나 단일 소스가 있어야 한다.

실행은 6단계다. 단계마다 통과 조건이 정해져 있다.

| 단계 | 통과 조건 |
| --- | --- |
| 기준과 범위 | 실행 환경의 설정을 읽었고 감사 대상 목록이 정해졌다 |
| 실측 | 검사 다섯이 각각 돌았고 대상 파일 수가 1 이상이다 |
| 의미 감사 | 문장과 절마다 판정과 근거 등급이 붙었다 |
| 판정표와 승인 | 판정표를 냈고 사용자가 고칠 항목을 정했다 |
| 교정 | 승인 항목만 고쳤다 |
| 재검증 | 실측을 같은 범위에서 다시 통과했다 |

이 스킬을 자신에게 적용해 결함 둘을 찾았다.

`check_rename_drift.sh` 가 「통과가 아니다」 를 출력하면서 종료 코드 0 을 냈다.
`SKILL.md` 가 「대상 파일 수가 0이면 통과가 아니다」 라고 지시하는 자리이고,
`docs-check` 의 정적 검사는 같은 경우에 2 를 낸다. 2 로 맞췄다.

`SKILL.md` 3절의 유지 근거 넷과 제거 근거 여섯이 `references/judgment.md` 의
같은 이름 절과 **항목이 서로 달랐다.** 어느 목록으로 판정할지 정할 수 없는 상태였다.
판정 기준은 `judgment.md` 하나가 소유하고, `SKILL.md` 에만 있던 유지 항목 둘을 그쪽으로 옮겼다.

`<skill-dir>` 상대경로 설명을 뺐다. 다른 스킬 넷에서 같은 문장을 지운 것과 같다.

검사 스크립트를 모두 python 으로 통일했다.
`check_enforcement.sh`, `check_rename_drift.sh`, `run_doc_snippets.sh` 를 옮기고,
`collect_targets.py` 를 부르기만 하던 `collect_targets.sh` 는 지웠다.

이식은 옮기기 전 출력을 기준으로 삼았다.
gitignore 히트와 미스, grep 검출과 통과, lint 검출, 도구 우회 가능과 불가,
모르는 모드, 인자 부족, 머리말 없음, 파일 없음, 드리프트 검출과 대상 없음까지
열네 경로의 출력과 종료 코드가 모두 같다.
