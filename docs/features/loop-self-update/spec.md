# orch: 상주 루프가 옛 번들로 돌면 스스로 새 설치본으로 다시 뜬다

확인: 2026-11-13

## 목표

플러그인을 업데이트하면 상주 루프가 코디네이터의 손 없이 새 설치본으로 다시 뜨고, 그 사실을 코디네이터에게 알린다. 같은 이유로 틱이 연달아 실패하면 모아 보내는 요약을 기다리지 않고 코디네이터를 바로 깨운다.

- 배경(ai-analysis 코디네이터 요청 2026-11-13): ai-analysis 루프가 18.0.0 번들로 도는 동안 설치본은 18.4.0 이었고, loop.log 에 `STALE-BUNDLE` 경고만 83줄 쌓였다. 2026-11-04 에는 옛 번들이 새 설정 절(`adr`)을 몰라 틱이 모두 설정 오류로 실패하고 마무리도 멈췄는데, 루프는 살아 있는 것으로 보여 사용자가 먼저 알아챘다.

## 범위

이번 범위:

- 상주 루프가 틱 사이에 옛 번들인지 보고, 안전한 때 새 설치본으로 다시 뜨기
- 다시 뜬 사실과 다시 뜨지 못한 사실을 코디네이터에게 알리기
- 같은 이유의 틱 실패가 연달아 나면 코디네이터에게 바로 알리기
- `orch loop status` 에 번들 버전 보이기

범위 밖:

- 루프 밖에서 직접 부른 스크립트의 `STALE-BUNDLE` 경고. 지금처럼 경고만 한다
- 체크아웃·링크 설치(개발용)의 번들 판정
- 루프가 뜬 뒤 바뀐 `CLAUDE_CONFIG_DIR`(계정 전환) 알아채기
- 원격(MacBook) 머신의 루프
- worker 세션의 플러그인 갱신

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 부모 루프가 틱이 끝날 때마다 자기 번들이 지금 설치본과 다른지 보고, 처음 알아챈 틱에 `LOOP-STALE <옛 버전> <새 버전> <새 진입점>` 한 줄을 loop.log 에 쓴다. 그 뒤 다시 뜰 때까지는 이 줄도, 틱 자식이 쓰는 `STALE-BUNDLE` 줄도 loop.log 에 옮기지 않는다 | 설치 기록이 새 번들을 가리키게 바꾸면 다음 틱 뒤 loop.log 에 `LOOP-STALE` 줄이 한 번 있다. 그 뒤 기다리는 틱들에는 `LOOP-STALE` 도 `STALE-BUNDLE` 도 없다 |
| REQ2 | 옛 번들이고 이 저장소에 도는 머지 큐·마무리가 없으면, 등록된 Run 전부와 명의, 설정을 그대로 이어받아 새 설치본의 진입점에서 루프를 다시 띄우고 옛 루프는 끝난다 | 다시 뜬 뒤 `orch loop status` 의 번들 버전이 새 버전이고, 등록된 Run 목록이 다시 뜨기 전과 같고, 루프 프로세스는 하나다. 다음 틱 자식이 `STALE-BUNDLE` 을 쓰지 않는다. 다시 뜨는 동안 LOOP-DEAD 알림이 오지 않는다 |
| REQ3 | 이 저장소의 머지 큐나 마무리가 돌고 있으면 끝날 때까지, 처음 알아챈 때부터 최대 60분 기다린다. 60분이 지나거나 틱이 설정 오류(종료 코드 2)로 실패하고 있으면 기다리지 않고 다시 뜬다. 돌고 있던 마무리는 끊지 않는다 | 이 저장소의 마무리 pid 가 살아 있는 동안에는 다시 뜨지 않고, 끝난 뒤 첫 틱 사이에 다시 뜬다. 60분 넘게 살아 있으면 60분 뒤 다시 뜨고 그 마무리 프로세스는 계속 산다. 틱이 종료 코드 2 로 실패하면 그 틱 뒤 바로 다시 뜬다. 다른 저장소의 머지 큐는 기다림에 들지 않는다 |

| REQ5 | 새 루프가 시작 대기 한도 안에 루프 상태를 쓰지 못하면 다시 뜨기에 실패한 것으로 보고, 옛 루프를 그대로 돌리며 이유를 바로 한 번 알린다. 같은 새 진입점으로는 설치본이 다시 바뀌거나 사람이 루프를 다시 띄울 때까지 시도하지 않는다 | 새 진입점이 뜨자마자 끝나게 두면 옛 루프가 계속 틱을 돌고, 이유가 든 알림이 한 번 온다. 다음 틱들에는 다시 시도하지 않는다. 한도 뒤에 새 루프가 죽는 경우는 지금의 루프 생존 확인(LOOP-DEAD)이 맡는다 |
| REQ6 | 부모의 틱 실패도 단계 출처처럼 연속 알림을 받는다. 같은 원인의 실패가 연속 3번째 틱이면 실패 원인 줄을 담아 바로 한 번 알리고, 풀리거나 원인이 바뀔 때까지 다시 알리지 않는다. 단계 출처의 기준도 3번째로 맞춘다 | 틱이 같은 원인으로 3번 실패하면 3번째 틱에 원인 줄(예: `모르는 절이 있다: adr`)이 든 알림 하나가 온다. 4번째부터는 오지 않는다. 틱이 성공한 뒤 다시 3번 실패하면 또 온다. 단계 출처의 같은 오류도 3번째 틱에 온다 |

| REQ8 | 참조 문서와 변경 기록이 새 동작과 첫 배포의 한 번 손 재시작을 설명한다 | `skills/orch/references/waiting.md` 와 루프 참조 문서에 다시 뜨는 조건과 알림 두 가지가 있다. 변경 조각에 「이 버전 전에 띄운 루프는 한 번 `orch loop stop` 뒤 `orch loop start` 로 다시 띄운다」 가 있다 |
