# 예시: docs/code-architecture.md

6단계에서 새 코드가 앉을 자리를 정한 뒤 `docs/code-architecture.md` 를 만들거나 고칠 때 이 뼈대를 쓴다.
이 문서는 현재 구조만 소유한다. 아래 예는 가상의 저장소이므로 이름과 경로를 그대로 복사하지 않는다.

## 뼈대

다섯 절을 이 순서로 둔다. 해당 없는 절은 지우지 말고 한 줄로 이유를 적는다.

| 절 | 담는 것 | 담지 않는 것 |
| --- | --- | --- |
| 디렉터리 책임 | 경로마다 소유하는 것 | 파일 목록, 함수 목록 |
| 의존 방향 | 누가 누구를 부를 수 있는가와 금지 | 호출 순서. 그것은 `docs/flow.md` 가 소유한다 |
| 소유 경계 | 어느 파일이 어느 값의 원본인가 | 값 자체 |
| 검증 경계 | 어떤 검사가 무엇을 지키는가 | 검사 명령 전체. 명령은 `package.json` 이나 `verify` 스크립트가 소유한다 |
| 변경 규칙 | 코드를 바꿀 때 함께 고칠 문서와 지키는 선 | 상세 목록의 복사 |

## 절별 예

### 디렉터리 책임

경로와 책임 두 칸으로 쓴다. 책임은 명사구 하나로 끝낸다.

```markdown
## 디렉터리 책임

| 경로 | 소유하는 것 |
| --- | --- |
| `src/api/` | HTTP 입출력과 입력 검증. 업무 규칙은 두지 않는다 |
| `src/service/` | 업무 규칙과 트랜잭션 경계 |
| `src/repository/` | 저장소 접근. 쿼리는 여기서만 만든다 |
| `scripts/` | 운영 스크립트. 역할마다 폴더 하나다 |
| `tests/` | 목적별 검사. 「검증 경계」 절이 구조를 정한다 |
```

Java 로 비유하면 `controller → service → repository` 의 패키지 책임 표다.
새 디렉터리를 만들면 이 표에 한 줄을 더하는 것까지가 같은 변경이다.

### 의존 방향

화살표 그림 하나와 금지 규칙을 함께 둔다. 금지가 빠진 그림은 규칙이 아니라 설명이다.

```markdown
## 의존 방향

    api → service → repository

- 화살표의 반대 방향으로 import 하지 않는다. `repository` 가 `service` 를 부르면 순환이 생긴다.
- `api` 는 `repository` 를 직접 부르지 않는다. 조회만 하는 경로도 `service` 를 거친다.
```

### 소유 경계

값이 두 곳에 있으면 한쪽만 고쳐진다. 값마다 원본 하나를 정하고 나머지는 그것을 읽게 한다.

```markdown
## 소유 경계

| 값 | 원본 | 읽는 쪽 |
| --- | --- | --- |
| 포트와 호스트 | `config/ports.yaml` | Compose, 검사, 문서. 복사하지 않는다 |
| 명령 목록 | `package.json` 의 `scripts` | 이 문서와 지침 파일은 링크만 건다 |
```

### 검증 경계

무엇을 어느 검사가 지키는지를 표로 둔다. 디렉터리 구조와 이름 규칙은 [`test-boundaries.md`](test-boundaries.md) 가 소유한다.

```markdown
## 검증 경계

| 디렉터리 | 답하는 질문 |
| --- | --- |
| `tests/unit/` | 함수가 계약대로 도는가 |
| `tests/boundary/` | 커밋하면 안 되는 것이 추적되지 않는가 |
| `tests/convention/` | 저장소 표기 규칙을 지키는가 |
```

### 변경 규칙

마지막 절이다. 고칠 때 함께 움직이는 것과 복사하지 않을 것만 쓴다.

```markdown
## 변경 규칙

- 새 디렉터리를 만들면 「디렉터리 책임」 표에 한 줄을 더한다.
- 스키마를 바꾸면 마이그레이션과 `docs/data-schema.md` 를 함께 고친다.
- 코드만 보고 알 수 없는 장기 결정은 ADR 에 이유와 기각한 대안을 남긴다.
- 함수와 응답 필드의 상세 목록을 이 문서에 복사하지 않는다.
```

## 이력 서술을 넣지 않는다

**이 문서에는 현재 상태만 쓴다.** `예전에는 ~ 였으나 ~ 로 바꿨다`, `v2 에서 추가됐다` 같은 문장을 넣지 않는다.

- 이력은 git 과 ADR 이 이미 소유한다. 문서에 쓰면 같은 사실이 두 곳에 있게 된다.
- 이력 문장은 코드가 바뀌어도 고쳐지지 않는다. 읽는 사람은 지금 구조인지 옛 구조인지 가려 읽어야 한다.
- 이력이 섞인 문서는 길어진다. 사용자 저장소 중 한 곳은 이력이 쌓여 문서가 현재 구조를 찾기 어려운 길이로 불었고, 모듈 문서에 상세를 맡기고 경계만 둔 80줄대 문서와 대조됐다.

결정의 이유가 필요하면 ADR 번호나 PR 번호로 가리킨다. 계획서 번호는 가리키지 않는다([`step-7-docs.md`](../step-7-docs.md) 의 「계획서를 가리키지 않는다」).
모듈마다 자기 문서를 두는 저장소는 이 문서에 경계만 두고 상세는 모듈 문서로 위임한다.

## 근거

사용자 저장소 다섯 곳의 `docs/code-architecture.md` 가 같은 이름과 이 다섯 절을 공통으로 쓴다.
`docs-check` 스킬도 이 파일 이름을 전제한다.
