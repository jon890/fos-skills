# ADR-024: 결정 기록은 종류를 나누고 현재 규칙의 원본을 연결한다

- **status**: `accepted`
- **decision-type**: `engineering-process`
- **areas**: `documentation, quality`
- **현재 규칙의 원본**: [ADR 작성 규칙](../../skills/technical-design/references/adr-rules.md), [문서 소유권](../../skills/spec/references/document-ownership.md#결정-기록의-단계별-책임)
- **결정**: 이 하네스의 기본 ADR 은 구조·도메인 정책·개발 절차의 장기 선택 이유를 담는다. 새 기록은 결정 종류 하나와 현재 규칙의 원본을 연결한다. 기존 식별자와 모듈별 위치는 유지한다.
- **맥락**: 저장소마다 ADR 에 구조 선택, 제품 판단 기준과 검증 절차가 함께 쌓였다. 기술 결정만 남긴다는 규칙과 정책 선택의 이유도 남긴다는 규칙이 함께 있어 작성 범위가 불명확했다. 현재 규칙을 찾으려면 과거 결정까지 읽어야 하는 경우도 있었다. 사용자와 2026-11-05 에 공통 기준부터 정리하기로 합의했다.
- **대안 기각**:
  - 모든 기록을 기술 결정으로 한정한다. 이미 중요한 정책·절차 선택의 이유도 기록하고 있어 별도 기록 체계와 이동이 필요하다.
  - 종류별 폴더와 번호를 새로 만든다. 모듈 소유권과 분류가 겹치고 기존 링크를 대량으로 바꿔야 한다.
  - 현재 규칙을 ADR 에 모두 모은다. 과거 맥락 보존과 현재 원본 갱신의 수명이 달라 중복·상충이 늘어난다.
- **결과**:
  - 얻는 것: 단계마다 결정 주체와 적용할 현재 원본을 구분할 수 있다.
  - 감당할 것: 새 기록 작성자는 분류와 원본 연결을 확인해야 한다. 대상 저장소에 별도 관례가 있으면 먼저 대조해야 한다.
- **확인 방법**: 종류별 예시와 단계 인계를 실제 사례로 검토하고 문서 링크·기존 검사와 배포 CI 를 확인한다.
