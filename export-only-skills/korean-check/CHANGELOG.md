# CHANGELOG: korean-check

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준과 쓰는 형식은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 2.1.0 (2026-11-09)

- 사람이 읽는 글(사용자 보고, PR 제목·본문, 리뷰, 커밋 제목, 업무 글, 보드 항목)에서 내부 용어를 풀어 쓰고 제목에 무엇이 좋아지는지 쓰게 하는 규칙과 고쳐 쓴 예시를 더했다
- 의미 점검 축에 「사람이 읽는 글의 내부 용어·명사 나열」 을 더했다. 에이전트가 읽는 지침 문서에는 적용하지 않는다
- 어색한 말 매핑 표에 `갈음` 을 더했다(권장: 대신한다)
- 스킬 설명을 고쳐, 외부에 내보내는 글(PR, 리뷰, 커밋 메시지, 두레이, 메일, 위키)을 등록하기 직전에 모델이 스스로 이 스킬을 열게 했다

## 2.0.0 (2026-11-06)

- 호환성: 스크립트 넷을 Node 24 의 `.ts` 로 바꿨다. `node "$SKILL_DIR/scripts/check.ts" …` 처럼 확장자만 바꿔 부르고 Node 24 이상이 필요하다
- 옵션, 출력, 종료 코드는 그대로다. 저장소 문서 203개와 최근 커밋 40개의 diff 에서 옛 구현과 같은 결과를 확인했다
- 훅의 옛 이름 `~/.claude/scripts/korean-style-check.py`, `check-readability.py` 는 이 major 동안 새 명령을 부르는 진입으로 남는다
- 옛 이름의 훅 모드는 발견이 있을 때 `additionalContext` 맨 앞에 새 명령 안내를 붙이고, 다음 major 에서 지우므로 README 의 새 이름으로 바꾼다
- 옛 `bash …/check.sh`, `python3 …/korean-style-check.py` 직접 호출(허용 규칙과 오버레이 포함)은 새 이름으로 바꿔야 한다

## 1.x

- 흩어져 있던 판정 기준과 검사기를 한 스킬로 묶고, 두 검사기를 합쳐 종료 코드 중 큰 값을 내는 `check.sh` 를 더했다
- 검사기가 돌지 않은 것이 통과로 보이지 않게 매핑 표나 대상이 없거나 확장자가 `.md` 가 아니면, 인자가 없거나 모르는 옵션이면 종료 코드 2 로 끝난다
- 실패로 막는 것은 매핑 표의 금지어뿐이고, 인라인 `+` 와 가독성 네 축은 경고다. 제목도 검사한다
- 금지어 발견 줄에 걸린 글자와 열을 보이고, `check.sh --diff` 가 이번에 더한 줄과 기존 줄을 나눠 판정한다
- 저장소의 `.claude/korean-check-allow.txt` 에 적은 고유명사 안의 발견은 건너뛴다. 저장소 전체 테스트는 `.claude/korean-check-exclude.txt` 로 외부 사본을 제외한다
- 금지어 목록은 어색한 비유와 번역투(`가르다`, `서다`, `견주다`, `판`, DB 의 표와 칸 등)를 추가하고, 평범한 우리말과 영어 원어는 뺐다
- 판정 기준을 `korean-style.md`, `korean-examples.md`, `writing-structure.md`, `review-axes.md` 로 나누고, 렌더링 함정은 `content-preview` 로 옮겼다
