# 탐색 QA

요구사항별 인수 검증을 마친 뒤, 바뀐 사용자 흐름에서 계획에 없던 문제를 찾을 가치가 있으면 실행한다. 스펙을 만족하는 데 필수인 사례는 인수 검증 계획에 보완한다.

1. 실제 앱에서 확인할 경로를 한 개에서 세 개 고른다. 중복 클릭으로 저장이 두 번 될 수 있는 화면, 새로고침 뒤 상태를 다시 읽는 화면, 실패 뒤 재시도할 수 있는 화면처럼 변경점과 맞닿은 경로를 고른다.
2. verify 가 읽은 저장소 오버레이와 지침에서 실행 환경·명령을 가져온다. 준비한 테스트 데이터로 앱을 실행하고 사용자에게 보이는 결과와 필요한 경우 저장 상태를 확인한다.
3. [검증 결과 양식](../templates/verification-result.md)의 「탐색 QA」에 고른 경로마다 결과를 남긴다. 환경이 막혔으면 해당 경로와 막힌 조건을 적고 `미실행`으로 표시한다. 실제로 실행한 경로에만 `문제 없음`이나 `문제 발견`을 쓴다.
4. 발견한 구현 문제는 환경, 재현 단계, 기대 결과와 실제 결과, 스크린샷이나 로그 등 증거를 붙여 implementation 에 넘긴다. 완료를 막는 문제는 verify 의 반환 기준에 따라 미완료로 보고한다. 사소한 범위 밖 개선은 후속으로 남긴다.

다음 변경에서도 같은 회귀를 잡을 만하고 재현 조건을 다시 준비할 수 있다면, 앱 저장소의 기존 검증 오버레이나 테스트 위치에 절차를 남기도록 인계한다. 남길 위치와 함께 실행 명령, 테스트 데이터 준비 방법, 기대 결과, 증거 수집 방법을 적는다. verify 는 검증 결과를 넘기고 앱의 코드와 테스트 수정은 구현 담당자가 맡는다.
