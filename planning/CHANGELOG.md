## 1.2.0

0단계를 폐기하고 중복 지시를 걷었다.
SKILL.md 는 177줄에서 164줄, reference 는 9개에서 8개가 됐다.

0단계 폐기:

- 한 번도 실행된 적이 없었다. 규칙 위반이 아니라 규칙을 지킨 결과다.
  생략 기준이 "사용자가 이미 방향을 명확히 줬으면 생략" 이라, `/planning <기능>` 호출은 거의 다 여기 걸린다.
- 하던 일(지식 수준과 압박 강도 보정)은 상시 주입되는 사용자 배경과 대화 톤으로 대체된다.
- 단계 번호는 1~8 그대로여서 재배치가 없다.

중복 제거:

- "모호함 능동 발굴" 절의 추측 금지·하나씩 토론·확정 후 진행 세 항목을 지웠다.
  각각 통과 조건, 핵심 원칙의 질문 규율, 통과 조건과 겹쳤다.
- 핵심 원칙의 "간결한 문서" 를 지웠다. 일반 문서 원칙이다.
- 자체 검토 하위 3항목을 지웠다. `task-create.md` 의 "자체 검토" 절이 같은 내용을 갖고 있다.
- 완료 후 9항목을 4항목으로 줄였다. 앞 1~4 는 각 단계 통과 조건이 이미 강제하고,
  커밋과 push 는 한 항목으로 합쳤다.

수정:

- `task-create.md` 가 SKILL.md 의 없는 절 이름("plan 네이밍 규칙")을 참조하고 있어 "동시성 안전" 으로 바로잡았다.

## 1.1.0

단계 진행을 자율로 돌리고, 7단계로 옮겨진 절차의 잔상을 코어에서 걷었다.
SKILL.md 는 199줄에서 177줄이 됐다.

자율 진행:

- 실행 절차의 "단계 표기 → 사용자 확정 → 다음" 을 "모호점 0 확인 → 다음" 으로 바꿨다.
  통과 조건을 모호점 0 으로 바꾼 앞 변경(1.0.0 이전)이 절반만 반영돼, 실행 절차 옆의 옛 문구가 이겨 단계마다 턴이 멈췄다.
- 단계 reference 8개 제목에서 "→ 사용자 확정" 을 뗐다. 본문 통과 조건은 이미 모호점 0 이었다.
- 한 턴에 여러 단계를 진행해도 된다는 것을 명시했다.
- 사용자만 답할 결정은 그대로 멈춘다 — 취향·범위·되돌리기 어려운 결정, plan 분할안, 새 의존 도입, task 검증 위반.

중복 제거:

- 필수 관리 문서 절의 절차를 지웠다. `references/step-7-docs.md` 가 같은 문구로 갖고 있다.
- 코어 첫머리의 자기 소개 블록을 지웠다. 개인 경로가 하드코딩돼 있었다.
- 번들 파일 목록 절을 지웠다. 네 항목 모두 다른 곳에 있다.
- rebase 근거에서 git 상식 두 줄을 뺐다. 리뷰 코멘트가 커밋에 묶인다는 도구 동작만 남겼다.

추가:

- 실행 절차 표에 "무엇을 정하는가" 열을 넣었다.
  단계 강제 항목이 "코어의 한 줄 요약" 의 존재를 전제하는데 표에는 요약이 없었다.
