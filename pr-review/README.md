# pr-review

남의 PR 에서 찾은 문제를 리뷰로 올릴 때, 근거를 다시 확인하고 표기를 맞추고 등록 결과를 확인하는 수고를 덜어 준다.
지적마다 주장에 맞는 근거를 붙이고, 근거의 강도로 P1 부터 P5 까지 등급을 매긴다.
이 PR 이 만든 문제가 아니면 리뷰에서 빼 후속 업무로 돌린다.
본문은 미리보기로 먼저 보여 주고, 사용자가 확인한 뒤 등록해 댓글이 줄에 붙었는지까지 확인한다.

문제를 찾는 일은 이 스킬이 하지 않는다. `/code-review`, 직접 읽기, 실행해 보기로 찾은 것을 틀리지 않게 쓰고 안전하게 올린다.

## 이럴 때 쓴다

- `/code-review` 결과나 직접 읽고 찾은 문제를 남의 PR 에 리뷰로 남기려 한다
- 지적이 여럿이라 등급을 붙여 무엇부터 볼지 알려 주고 싶다
- 이미 단 리뷰 스레드에 답글을 달거나, 등록한 인라인 리뷰를 고치려 한다
- 사내 GitHub Enterprise 저장소의 PR 에 리뷰를 올린다

"PR 리뷰해줘", "이 PR 봐줘", "리뷰 남겨줘", "리뷰 댓글 달아줘" 처럼 말하거나 `/pr-review` 를 부르면 이 스킬이 뜬다.

## 사용 예시

PR 번호, 파일 이름, 지적 내용은 예시다.

```text
나:   PR 123 리뷰해줘. 할인 계산 쪽만 봐 줘

스킬: github.example.com 의 PR #123 에서 할인 계산 관련 파일만 봅니다.
      지적 3건을 정리하고 미리보기를 띄웠습니다.
        🟠 P2 높음  DiscountService.java:88  쿠폰 할인을 두 번 뺀다
        🔵 P4 낮음  DiscountService.java:120 반복 조회. 측정하지 않아 P4 로 낮췄다
        후속 업무   같은 계산이 정산 모듈에도 있다. 이 PR 이 만든 문제가 아니다
      미리보기를 읽고 등록할지 알려 주세요.

나:   등록해

스킬: 요약 리뷰와 인라인 2건을 리뷰 하나로 등록했습니다.
        인라인 2건 모두 줄에 붙은 것을 확인했습니다
```

## 받는 것

- PR 에 등록된 인라인 리뷰. 첫 줄에 `🟠 **P2 높음**` 처럼 색 원과 등급이 붙고, 끝에 AI 가 작성했다는 안내가 붙는다
- 등급별 건수 표를 담은 요약 리뷰. 지적이 없어도 하나 등록한다
- 기존 스레드에 단 답글과 고친 리뷰
- 등록 전에 읽는 렌더링 미리보기
- 이 PR 소관이 아니라고 판정한 문제의 후속 업무
- 등록 위치와 등급을 담은 요약 보고. 본문 전문은 채팅에 다시 쓰지 않는다

## 준비

- `gh` 가 대상 호스트에 로그인돼 있어야 한다. 호스트는 git remote 에서 찾고, SSH config 별칭도 실제 호스트로 되돌린다. `GH_HOST` 로 덮어쓸 수 있다
- 미리보기는 `content-preview` 스킬이 맡으므로 그 스킬이 설치돼 있어야 한다
- 저장소마다 `<repo-root>/.claude/pr-review-overlay.md` 를 둘 수 있다. git 호스트, 이 저장소의 P2 기준, 후속 업무를 등록할 곳, 저장소 고유 점검 항목, 사용자 문체 파일의 경로를 적는다
- 오버레이가 없으면 `CLAUDE.md` 와 `REVIEW.md` 를 보고, 셋 다 없으면 사용자에게 묻는다

## 함께 쓰는 스킬

- 내 PR 에 달린 리뷰를 코드에 반영하는 일은 `review-fix` 가 맡는다. 방향이 반대다
- 등록 전 본문의 렌더링은 `content-preview` 가 맡는다
- 문제를 찾는 일은 `/code-review` 내장 명령이나 직접 읽기로 한다
- 후속 업무 등록은 `dooray-task` 스킬이나 이슈 트래커 절차를 따른다
