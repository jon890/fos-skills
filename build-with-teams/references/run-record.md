# 실행 기록 계약

실행 결과는 세션이 끝나면 사라지므로 매 실행 한 줄을 남겨 추세를 남긴다.

회고(`retrospective.md`)와 역할이 다르다.

- 회고 — 사건 하나를 깊게 남긴다. 없으면 안 쓴다.
- 실행 기록 — 실행 하나를 얕게 남긴다. **항상 쓴다.**

## 위치

오버레이가 지정하지 않으면 `docs/retrospectives/RUNS.md` 를 쓴다.
회고와 같은 디렉터리를 쓰되 파일은 분리한다 — 성격이 다르고 갱신 시점도 다르다.

## 형식

```markdown
# 실행 기록

| 날짜 | 스킬 | 대상 | 모드 | phase | REVISE | FIX | DOCS | BLOCK | 개입 | 결과 |
|---|---|---|---|---:|---:|---:|---:|:---:|---:|---|
| 2026-07-27 | build-with-teams | plan012-auth | B | 3 | 1 | 0 | 0 | 없음 | 2 | PR #45 |
```

열 뜻은 아래와 같다.

| 열 | 내용 |
|---|---|
| 대상 | plan 이름 또는 PR 번호 |
| 모드 | 실행 모드 (A executor 위임 / B team-lead 구현). 일부 phase 만 전환했으면 `B→A(p{N})`. 해당 없으면 `-` |
| phase | 이번 실행이 처리한 phase 수 |
| REVISE | critic 이 REVISE 를 낸 횟수 |
| FIX | code-reviewer 가 FIX_NEEDED 를 낸 횟수 |
| DOCS | docs-verifier 가 UPDATE_NEEDED·VIOLATION 을 낸 횟수 |
| BLOCK | `PHASE_BLOCKED` 발생 여부 (있음 / 없음) |
| 개입 | 사용자에게 되물은 횟수와 사용자가 방향을 바로잡은 횟수의 합 |
| 결과 | PR 번호, 또는 중단 사유 |

해당 없는 열은 `-` 로 둔다. 값을 지어내지 않는다.

## 개입 횟수를 세는 법

**이 열이 가장 중요하다** — 나머지는 파이프라인 내부 지표지만 개입 횟수는 사용자가 실제로 겪은 비용이다.

세는 대상은 둘이다.

- 구조화 질문 도구를 호출해 사용자 판단을 받은 횟수.
- 사용자가 진행 방향을 바로잡거나 결과를 되돌리게 한 횟수.

세지 않는 것.

- 사용자가 먼저 꺼낸 새 요구.
- 단순 진행 승인 ("응 계속해").

## 기록 시점

실행이 끝나는 시점에 team-lead(또는 해당 스킬의 주 세션)가 한 줄 추가한다.
중단된 실행도 기록한다 — 중단이야말로 추세에서 보고 싶은 값이다.

기록은 결과물 커밋에 함께 담는다. 별도 커밋으로 나누지 않는다.
