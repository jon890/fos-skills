# CHANGELOG: harness-cleanup

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준과 쓰는 형식은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 4.1.0 (2026-11-12)

- 판정 기준에 「지난 일의 기록은 남기지 않는다」 를 더했다. 지난 조사, 경과, 실측 수치, 사고 기록, 결정 날짜를 제거 대상으로 본다.
- 도구가 지금 어떻게 동작하는지는 사실 한 줄로 남기고, 오버레이 함정의 확인 날짜는 예외로 남긴다.
- 판정 기준과 감사 축에 붙어 있던 지난 감사 사례를 한 줄 예로 줄였다.

## 4.0.1 (2026-11-09)

- 큰 대화 기록을 줄 단위로 읽어 사용 기록 집계와 세션 발췌에서 문자열 길이 제한 오류가 나지 않게 한다.

## 4.0.0 (2026-11-08)

- 호환성: 스크립트 열넷을 Node 24 의 `.ts` 로 바꿨다. `node "$SKILL_DIR/scripts/collect_targets.ts" …` 처럼 확장자만 바꿔 부른다
- 검사기 여덟(`collect_targets`, `check_*`, `find_test_requirements`, `run_checks`)과 `run_doc_snippets`, 사용 기록 셋, 공용 둘이 대상이다
- 옵션, 출력, 종료 코드는 그대로다. 다른 저장소의 `.py`, `.sh` 를 감사하는 판정과 대상 확장자 목록도 그대로다
- `run_doc_snippets` 는 zsh 가 없으면 「zsh 없음, bash 만」 을 한 번 알리고 bash 만 돈다. 전에는 블록마다 건너뛴다는 줄을 냈다
- 옛 `python3 …/<이름>.py` 호출(허용 규칙과 개인 문서 포함)은 새 이름으로 바꿔야 한다. Node 24 이상이 필요하다

## 3.x

- 지침 감사를 6단계로 나누고 단계마다 통과 조건을 뒀다. 유지와 제거의 판정 기준은 `references/judgment.md`, 감사 축은 `references/audit-axes.md` 가 소유한다
- 검사 스크립트가 늘었다: 줄 수와 대상 목록, 참조 무결성(링크, 경로, 절 제목, 스킬 이름, 홈 경로 경고), 개수와 목록 사실 대조, 중복 검출, 절 이름 드리프트, 강제 여부 확인, 테스트가 요구하는 문자열 찾기, 문서 코드 블록 실행(`--list`, `--block`)
- `--scope` 로 감사 범위를 스킬 하나나 디렉터리 하나로 좁히고, `run_checks` 가 검사를 따로 돌려 종료 코드와 판정을 표로 낸다
- 범위에 Markdown 이 없고 스크립트만 있으면 스크립트 감사 절차(`references/script-audit.md`)로 넘어간다
- 대화 기록으로 스킬이 실제로 쓰인 모습을 보는 사용 기록 모드(`references/usage-audit.md`)와 「모델 교체」, 「스킬 경계」 축을 더했다
- 스킬 호출은 `$SKILL_DIR` 절대 경로로 하고, 판정에 `추가`, `해결됨` 과 근거 등급 `세션 실측`, `가이드` 를 더했다

## 2.x

- `adjust-harness` 에서 이름을 바꾸고, 프로젝트에서 따로 자란 `harness-cleanup` 을 흡수했다
- 측정 지시를 검사 스크립트로 바꿨다. 줄 수 집계, 참조 무결성, 사실 대조, 중복 검출, 문서 명령 실행, 강제 여부 확인이다
- 근거 등급 `도구 대체` 는 `check_enforcement` 로 gitignore, 린트 규칙, 도구 제한이 실제로 막는지 확인해야 쓴다
- 「런타임 동작 변화」 감사 축을 더했다
- `check_rename_drift` 를 더했다. 본문에서 절 이름을 바꾸고 그 절을 위임받은 참조 문서를 안 고친 경우를 잡는다
- 감사 대상 선택을 `target_files.py` 로 모았다. 모노레포 워크스페이스의 `AGENTS.md`, 역할 정의, 중첩 스킬, `.claude/rules` 까지 찾는다
- 판정 축에 부정형 지시, 판정할 수 있는 지시, 할 일을 말하는 제목, 실측의 관측 대상(도구 동작과 모델 행동)을 더했다

- 프로젝트 일반 문서의 코드 정합성은 `docs-check` 가 맡도록 대상을 나눴다
