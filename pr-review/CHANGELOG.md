# pr-review 변경 이력

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 1.4.0

개인 로컬 층(`~/.claude/skills/`)에서 fos-skills 로 옮겼다. git 으로 추적되고 플러그인으로 설치된다. 스킬 본문은 바꾸지 않았다.
`.claude-plugin/plugin.json` 의 `skills` 배열과 저장소 README, `docs/` 의 스킬 목록에 더했다.
README 가 가리키는 `~/.claude/references/work-writing-persona.md` 는 이 저장소의 다른 스킬에 선례가 없어 그대로 뒀다. 사용자 전역 파일이라 설치한 환경에 없을 수 있다.

## 1.3.0

- `gh-review-post.sh --batch` 를 더했다. 요약과 인라인 여러 건을 리뷰 하나로 등록한다.
  인라인을 하나씩 등록하면 리뷰가 지적 수만큼 나뉘고 요약이 따로 떨어졌다 (실측).
- `gh-review-post.sh --edit` 를 더했다. 이미 등록한 인라인 리뷰를 검증을 거쳐 고친다.
  모드가 없어 `gh api` 를 직접 불러야 했다.
- 요약 리뷰도 미리보기 대상이라는 것을 4단계에 적었다.

## 1.2.0

- 등급 표기를 `(P3)` 에서 `🟡 **P3 보통**` 처럼 색 원과 등급 이름으로 바꿨다.
  목록만 훑어도 무엇부터 볼지 알 수 있게 하려는 것이다. `gh-review-post.sh` 가 새 표기를 강제한다.
- `gh-review-post.sh --summary` 를 더했다. 등급별 건수를 담은 요약 리뷰를 등록한다.
- 인라인 리뷰와 요약 리뷰 끝에 AI 가 작성했다는 안내를 스크립트가 붙인다.

## 1.1.1

- `gh-review-post.sh --reply` 가 등록한 뒤 결과를 출력하는 줄에서 `SyntaxError` 로 끝나던 것을 고쳤다.
  작은따옴표 안의 `\"` 가 f-string 표현식에 그대로 들어갔다.
  등록은 이미 끝난 뒤라 실패처럼 보여도 답글은 올라가 있었다 (실측).

## 1.1.0

- `detect_host` 복제 22줄을 `scripts/gh-host.sh` 로 바꿨다.
  SSH config 별칭 리모트에서 `github-personal` 을 그대로 내 접속에 실패했다 (실측).
  `review-fix` 가 이미 고친 결함이 이쪽에만 남아 있었다.
  두 번들의 사본은 저장소 루트의 공용 파일 대조 스크립트가 확인한다.
- `SKILL.md` 가 오버레이에 넘기던 「등급 표기」를 「등급 기준」으로 고쳤다.
  표기는 `references/grading.md` 가 소유하고 `gh-review-post.sh` 가 강제한다.
- 절대경로 여덟을 번들 상대경로로 바꿨다.

## 1.0.0

첫 버전. 실제 PR 리뷰 한 건(메일 임베딩 기능, 등급을 매긴 리뷰 16건과 답글 10건)에서 겪은 것만 담았다.

- 다섯 단계로 절차를 고정했다. 대상 확정, 근거 확보, 등급과 범위 판정, 미리보기, 등록과 검증이다.
- `evidence.md` — 주장 전에 재는 규칙. 동작·비용·관례 세 종류의 주장에 각각 요구되는 근거를 나눴다.
  실측이 주장을 뒤집은 다섯 사례를 그대로 실었다. 다섯 번 모두 처음 주장이 틀렸다.
- `grading.md` — P1 부터 P5 까지의 판정을 근거의 강도로 정의했다.
  측정하지 않은 성능 지적은 P4 라는 것과, 등급은 내리기만 한다는 것을 명시했다.
- `scope.md` — 리뷰와 후속 업무를 나누는 질문 하나를 두었다. 이 PR 이 만든 문제인가.
  Anthropic 관리형 Code Review 의 `Pre-existing` 등급을 표기가 아니라 행선지 판정으로 가져왔다.
- `posting.md` — 실행해 보기 전에는 알 수 없는 것만 적었다.
  사내 GHE 에서 `gh api` 가 `GH_HOST` 없이 404 나는 것, 답글 경로에만 PR 번호가 들어가는 것,
  `line: null` 댓글이 목록에서 빠지는 것, zsh `noclobber` 로 옛 payload 가 등록되는 사고.
- `scripts/gh-review-post.sh` — 등록 전 본문 검증을 강제한다.
  첫 줄의 등급 접두사, 핵심 낱말, 봇 재트리거 토큰 셋을 본다. `DRY_RUN=1` 로 등록 없이 확인한다.
  핵심 낱말은 하나 이상 필수다. 접두사만 보는 검증은 접두사가 같은 옛 본문을 통과시킨다.
  호스트는 git remote 에서 찾는다.
- `scripts/gh-review-list.sh` — 스레드와 내 댓글을 골라 읽는다. 출력은 `render-comments.py` 가 맡는다.
  `--paginate` 로 받으므로 댓글이 100 건을 넘어도 잘리지 않는다.

`review-fix` 와 방향이 반대다. 그쪽은 달린 리뷰를 코드에 반영하고, 이쪽은 리뷰를 쓴다.
문제를 찾는 일은 이 스킬이 소유하지 않는다. `/code-review` 내장 명령이나 직접 읽기를 쓴다.
