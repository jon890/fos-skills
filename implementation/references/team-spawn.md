# 에이전트 위임 계약

역할과 입출력은 코어가 정하고 실행 방법은 현재 하네스의 도구가 정한다. Claude Teams 는 필수 조건이 아니다.
시작할 때 실제 도구 스키마와 하네스 지침으로 아래 능력을 확인한다. 제품 이름만 보고 가정하지 않는다.

## 하네스별 대응

| 능력 | 있으면 | 없으면 |
| --- | --- | --- |
| 하위 에이전트 실행 | 역할 지침·범위·입력 경로를 전달 | 구현은 주 에이전트가 같은 계약으로 순차 실행 |
| 결과 수신 | 부모에게 결과를 반환하는 경로 사용 | 실제 읽을 수 있는 결과 파일로 회수 |
| 추가 지시·재개 | 반환된 ID 로 기존 에이전트에 재검토 요청 | 새 에이전트에 필요한 원본과 직전 발견만 전달 |
| 병렬 실행 | 의존과 파일 소유가 겹치지 않을 때만 실행 | 순차 실행 |
| 종료 | 현재 하네스가 제공하는 종료 기능 사용 | 존재하지 않는 종료 명령을 만들지 않음 |

현재 환경에서 확인한 능력과 사용한 실행 경로를 결과에 한 줄 적는다. 새 하네스 프레임워크나 자동 라우터는 만들지 않는다.
Claude Code 의 팀·이름 없는 에이전트·메시지·tmux 세부는 [Claude 실행 참고](claude-teams.md)를 필요한 경우에만 읽는다.
Codex 는 제공된 하위 에이전트 도구의 스키마를 사용한다. 추가 지시·재개 기능이 있으면 활용하며 항상 새로 띄워야 한다고 가정하지 않는다.

## 스폰 프롬프트에 넣는 문구

- 역할 인자가 없으면 해당 `role-*.md` 본문을 지시로 전달한다. 파일을 읽을 수 있으면 절대경로를 전달한다.
- 스펙·설계·계획·작업 공간과 검증 커밋을 전달한다. 상대경로가 다른 작업 공간으로 풀리지 않게 입력은 절대경로로 준다.
- 작업 범위와 변경 가능 파일, 실행할 검사, 결과 형식을 전달한다. 실제 반환된 ID 를 기록한다.
- 구현자는 [executor 계약](role-executor.md), 계획 검토자는 [critic 계약](role-critic.md), 검증자는 해당 코드·문서 계약을 따른다.
- 결과는 주 에이전트에게만 반환한다. `orca orchestration` 의 worker_done·escalation·ask·heartbeat 를 실행하지 않는다.
- 검증은 시간 제한을 주고 앞에서 실행한다. 백그라운드 실행 뒤 결과 없이 대기로 끝내지 않는다.
- 지정한 작업 공간에서 실행한다. 별도 worktree 를 자동 생성해 앞선 phase 커밋을 잃지 않는다.
- 구현자는 커밋·push 하지 않는다. 계획이 지정한 `git mv`·특정 경로의 `git add` 만 허용한다.
  다른 staging·stash·reset·clean 은 금지한다. 범위 밖 수정과 lint 무시 주석을 임의로 추가하지 않는다.
- 주 에이전트가 상태와 diff 를 확인하고 통합·커밋한다. 공유 파일을 여러 에이전트가 동시에 고치게 하지 않는다.

## 독립성

구현은 하위 에이전트 없이도 수행할 수 있다. 독립 검토는 같은 에이전트가 역할 이름만 바꿔 수행한 자기 점검으로 대체하지 않는다.
새 검토자에게 원본 스펙·설계·계획·diff 를 전달하고 구현자의 정당화나 예상 판정을 주지 않는다.
하위 에이전트가 없으면 실제로 실행 가능한 별도 세션이나 저장소가 정한 외부 리뷰로 독립성을 확보할 수 있다.
둘 다 없으면 작성과 실행 가능한 검증은 마치고 `독립 검토 미완료` 로 인계한다. 필수 검토 관문을 통과했다고 보고하지 않는다.
verify 의 PR 자동 리뷰 정책을 쓰면 해당 정책대로 남은 리뷰를 기록하고 orch 가 실제 결과를 확인한다.

## 실패와 재투입

실제 실패 결과와 작업 트리를 확인한 뒤 이어 간다. 사용 한도나 용량 부족에 같은 호출을 반복하지 않는다.
모델 선택은 [실행 등급](executor-routing.md)과 현재 하네스 지침을 따른다. 없는 모델 이름이나 역할 인자를 만들어 전달하지 않는다.
해결할 수 없으면 실패 이유·남은 작업·필요한 능력을 보고한다. 이미 통과한 검증은 변경 영향이 없으면 반복하지 않는다.
