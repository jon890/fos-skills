# 하네스 지침 감사

하네스에는 모델이 추론할 수 없는 환경 사실, 실측 함정, 안전 경계와 검증 계약만 남긴다. 짧게 만드는 것보다 사실과 실행 가능성을 먼저 확인한다.

발견과 판정표를 먼저 제시하고, 사용자가 승인한 항목만 수정한다.

## 1. 기준과 범위

현재 실행 환경의 설정과 도구 설명에서 다음을 확인한다.

- 실제 모델과 하네스 런타임
- 설치된 역할, 스킬과 호출 방법
- 프로젝트가 읽는 지침 파일과 오버레이
- 사용자가 지정한 저장소와 워크스페이스 경계

모델 이름과 버전을 산문에 복제하지 않는다. 설정을 찾지 못하면 추측하지 않고 검증 공백으로 둔다.

감사 대상은 저장소의 모든 `AGENTS.md`, `CLAUDE.md`, rules, 역할 정의, 스킬 본문과 참조, 오버레이와 실행 중 소비되는 회피 패턴이다. 일반 `docs/`와 planning 산출물의 코드 정합성은 `docs-check`로 보낸다. 저장소 밖을 가리키는 심볼릭 링크는 표시만 하고 수정하지 않는다.

## 2. 실측

`<skill-dir>`은 이번 실행에서 로드한 `harness-cleanup` 디렉터리다. 설치 위치를 `~/.claude`나 `~/.codex`로 가정하지 않는다.

```bash
S=<skill-dir>/scripts
bash "$S/collect_targets.sh" <repo-root>
python3 "$S/check_references.py" <repo-root>
python3 "$S/check_facts.py" <repo-root>
python3 "$S/check_duplication.py" <repo-root>
bash "$S/check_rename_drift.sh" <repo-root>
```

각 명령을 따로 실행하고 출력과 종료 코드를 읽는다. 앞 명령의 실패가 뒤 명령에 가려지는 연결 실행은 하지 않는다.

- 대상 파일 수가 0이면 통과가 아니다.
- 깨진 참조와 중복 0건은 정적 검사가 찾지 못했다는 뜻일 뿐 의미 검사의 통과가 아니다.
- 고정 개수, 옵션과 파일 목록은 실제 코드, `--help`와 설정에 대조한다.
- 문서에 검출 명령이 있으면 `run_doc_snippets.sh`로 실제 입력과 대조 표본을 검사한다.
  **이 스크립트만 출력으로 판정한다.** 블록에 문법 오류가 있어도 종료 코드가 0 이다 (실측).
- 스킬을 수정할 가능성이 있으면 변경 전 평가 명령이 있는지 확인하고 기준값을 기록한다.

## 3. 의미 감사

`references/audit-axes.md`와 `references/judgment.md`를 읽고 문장과 절 단위로 판정한다.

유지 근거:

- 현재 환경에서만 알 수 있는 경로, 권한, 상태 전이와 외부 부수 효과
- 실제 실패로 확인된 함정과 재현 가능한 회귀 조건
- 안전, 개인정보, 공개 범위와 승인 경계
- 기계 검증이 보장하지 못하는 산출물 계약

제거 또는 축소 근거:

- 현재 역할과 도구에 없는 이름, 옵션과 호출 절차
- 코드나 설정과 다른 사실
- 실행 대상을 보지 않아 항상 통과하는 검사
- 다른 단일 출처를 그대로 복제한 목록과 설명
- 일반적인 문제 해결, 성실성, 코드 품질처럼 모델이 맥락에서 판단할 수 있는 조언
- 제품 계약이 아닌 고정 단계, 파일 수, 후보 수와 출력 분량

근거는 `실측`, `도구 대체`, `추정`으로 구분한다. 추정만으로 유지하거나 제거하지 않는다.

## 4. 판정표와 승인

수정 전 다음 형식으로 보고한다.

| 대상 절 | 판정 | 근거 | 등급 |
|---|---|---|---|
| `<file>`의 `<section>` | 유지·제거·축소·보류 | 실행 결과와 단일 출처 | 실측·도구 대체·추정 |

오류뿐 아니라 유지와 보류 항목도 포함한다.

## 5. 승인 후 교정

- 중복은 소유 문서에만 남기고 소비자는 짧게 참조한다.
- 조건부 절차는 발동 조건만 본문에 두고 필요할 때 읽는 참조로 옮긴다.
- 런타임과 역할 이름은 현재 환경이 해석하게 하고 저장소 고유 경계만 남긴다.
- 검출 명령은 현재 진입점과 실제 파일을 보도록 고친다.
- 반복 실행 코드가 5줄을 넘으면 `scripts/`로 옮긴다.
- 스킬을 고친 뒤 그 저장소가 제공하는 검사를 실행한다.

## 6. 재검증

처음 실행한 측정을 같은 범위에서 다시 실행한다. 변경한 동작에는 양성·음성 대조 표본을 두고, 문서 명령은 실제 셸에서 확인한다. Markdown은 저장소의 표현·가독성 검사를 통과해야 한다.

가능하면 작성과 분리된 읽기 전용 검토자에게 최종 diff와 검사 근거를 검토시킨다. 검토자에게 수정, commit과 push 권한을 주지 않는다.

완료 보고에는 처리한 판정, 전후 측정, 실행한 검증, 커밋과 남은 검증 공백을 적는다.
