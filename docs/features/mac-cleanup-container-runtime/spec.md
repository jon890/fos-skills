# mac-cleanup: 컨테이너 런타임을 감지해 정리한다

확인: 2026-11-11

## 목표

`mac-cleanup` 이 Colima 만 가정하지 않고, 머신에 깔린 컨테이너 런타임을 감지해 런타임마다 조사, 정리, VM 디스크 회수, 재측정을 한다.

- 배경: 2026-11-11 Docker Desktop(context `desktop-linux`) 머신에서 스킬을 돌렸다. `colima` 명령이 없어 `colima_trim.ts` 를 돌릴 수 없었고, 에이전트가 그 단계를 건너뛸지 직접 판단했다. 빌드 캐시 32.08GB 와 이미지 15개를 지운 뒤 `Docker.raw` 는 5.6G 로 저절로 줄었고 호스트 여유가 늘었다.
- 사용자 요청(2026-11-11): 「container 런타임이 어떤걸 쓰던간에, 내 환경을 감지하고 정리할 수 있도록」.
- 지금 Colima 에 묶인 곳: `skills/mac-cleanup/SKILL.md` 1·3·5단계, `references/targets.md` 의 Docker 절, `scripts/survey_system.ts` 의 `surveyDocker`, `scripts/colima_trim.ts`. `docker_images.ts`, `docker_volumes.ts`, `delete_volumes.ts` 는 `docker` CLI 만 써서 런타임과 무관하지만 현재 context 하나만 본다.

## 범위

- 직접 지원하는 런타임: Docker Desktop, Colima, OrbStack.
- 그 밖의 로컬 런타임(Rancher Desktop, Podman 등 이 맥의 unix 소켓)은 「알 수 없는 런타임」 으로 다룬다. docker CLI 로 조사와 정리는 하고, VM 디스크 회수는 하지 않고 사용자 몫으로 보고한다.
- 이 맥 밖의 엔진(원격 `DOCKER_HOST`, ssh·tcp context)은 크기만 조사해 보이고 승인 묶음에 넣지 않는다.
- 범위 밖: Rancher Desktop 과 Podman 의 디스크 회수, `podman` CLI 지원, 사용자의 현재 docker context 변경, 정리 뒤 런타임 끄기.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 조사 단계가 설치된 런타임을 모두 감지해 런타임마다 이름, 켜짐 여부, docker context, VM 디스크 파일 경로와 점유 크기를 보인다 | 가짜 실행 파일과 가짜 홈으로 Docker Desktop, Colima(프로필 둘), OrbStack 을 각각 또는 함께 둔 테스트에서 런타임별 줄이 나온다. 이 머신에서 돌리면 Docker Desktop 한 줄과 `Docker.raw` 크기가 나온다 |
| REQ2 | 감지한 런타임 어디에도 맞지 않는 로컬 docker 엔드포인트는 「알 수 없는 런타임」 으로 보이고, docker CLI 조사와 정리는 그대로 한다. 원격 엔드포인트는 크기만 보이고 삭제 대상에 넣지 않는다 | 알 수 없는 로컬 소켓을 둔 테스트에서 이미지와 volume 조사가 돌고, 디스크 회수는 사용자 몫이라는 줄이 나온다. ssh·tcp 엔드포인트를 둔 테스트에서 삭제 스크립트가 그 엔드포인트로 삭제 명령을 보내지 않는다 |
| REQ3 | 설치됐지만 꺼진 런타임(꺼진 Colima 프로필 하나하나 포함)은 VM 디스크 크기와 함께 런타임마다 따로 「켜서 조사하기」 승인 묶음 후보로 보이고, 승인한 런타임만 스킬이 켠다. 켠 뒤 `docker info` 가 성공할 때까지 최대 120초 기다리고, 넘으면 그 런타임만 「켜지 못함」 으로 보고하고 나머지를 계속한다 | SKILL.md 3단계가 런타임 이름과 상관없이 같은 문장으로 런타임별 묶음을 요구한다. 켜는 명령은 런타임마다 하나로 정해져 있다(Docker Desktop `open -a Docker`, Colima `colima start -p <프로필>`, OrbStack `orb start`). 꺼진 런타임을 둔 테스트에서 조사 출력에 켜는 명령이 나온다. 준비되지 않는 가짜 런타임으로 켜기를 돌리면 제한 시간 뒤 「켜지 못함」 과 0 이 아닌 종료 코드가 나온다 |
| REQ4 | 켜진 런타임이 둘 이상이면 런타임마다 context 를 지정해 이미지와 volume 을 따로 조사하고, 승인 묶음과 삭제도 런타임별로 나눈다. 심볼릭 링크를 풀어 같은 소켓을 가리키는 context 들은 런타임 하나로 합쳐 한 번만 조사한다. 사용자의 현재 context 는 바꾸지 않는다 | 두 런타임이 켜진 테스트에서 이미지·volume 조사 출력이 런타임별로 나뉘고, 같은 소켓의 context 둘은 한 번만 조사되며, 삭제 명령이 승인한 런타임의 context 로만 간다. 테스트 뒤 현재 context 설정 파일이 그대로다 |
| REQ5 | 정리 뒤 디스크 회수 단계가 런타임마다 맞는 방법을 쓴다. Colima 는 지금의 fstrim 반복을 유지하고, Docker Desktop 과 OrbStack 은 trim 없이 디스크 파일 크기를 정리 전후로 재서 보고한다. 알 수 없는 런타임은 회수하지 않았다고 보고한다 | 런타임별 테스트에서 Colima 만 `fstrim` 이 불리고, Docker Desktop 과 OrbStack 은 전후 크기 줄이 나온다. 기존 `colima_trim` 테스트의 동작(재시도, 시간 상한, 종료 코드 0/1/2)이 유지된다 |
| REQ6 | 스킬 문서가 특정 런타임 이름을 전제로 쓰이지 않는다 | `SKILL.md` 와 `targets.md` 의 Docker 관련 절차가 런타임 표 한곳을 가리키고, Colima 전용 문장은 그 표의 Colima 행이나 Colima 실측 근거로만 남는다 |
| REQ7 | 5단계 보고의 확보량은 지금처럼 호스트 디스크 여유 전후 값이다. 런타임별 디스크 파일 전후 크기는 참고 줄로 따로 두고, 켜지 않았거나 켜지 못한 런타임은 VM 디스크 크기와 함께 「정리하지 않은 런타임」 으로 보고에 남긴다 | SKILL.md 5단계가 이 세 가지를 보고 항목으로 요구한다 |

## 결정

| ID | 결정 | 답 | 누가 | 근거 |
| --- | --- | --- | --- | --- |
| DECISION1 | 직접 지원 범위 | Docker Desktop, Colima, OrbStack 을 지원하고 그 밖은 일반 폴백. 런타임 정의는 표 한곳에 모아 나중에 항목 하나로 더한다 | 사용자 2026-11-11 | 이 머신은 Docker Desktop, 기존 실측은 Colima 다. Rancher Desktop 과 Podman 은 이 머신에서 실측할 수 없다 |
| DECISION2 | 꺼진 런타임 처리 | 모든 런타임에 같은 방식. VM 디스크 크기를 보이고 「켜서 조사하기」 를 승인 묶음으로 묻고, 승인하면 스킬이 켠다. 정리 뒤 끄지 않는다 | 사용자 2026-11-11 | Colima 실측에서 켜 보니 전체 확보량 100Gi 중 50.9GiB 가 Docker 에서 나왔다 |
| DECISION3 | 여러 런타임이 켜져 있을 때 | 켜진 것 모두를 context 를 지정해 따로 조사하고 묶음도 런타임별로 나눈다. 현재 context 는 바꾸지 않는다 | 사용자 2026-11-11 | 현재 context 만 보면 다른 런타임에 쌓인 것을 놓친다 |
| DECISION4 | Docker Desktop 과 OrbStack 의 회수 방법 | trim 명령 없이 1단계 조사 때와 5단계 재측정 때의 디스크 파일 점유 크기(`du`)를 비교해 보고만 한다. 덜 줄었어도 재시도하지 않고, 줄지 않았으면 런타임이 비동기로 줄인다는 문구를 단다 | 작성자 | 두 런타임은 지운 만큼 디스크 파일을 스스로 줄인다(2026-11-11 실측: `Docker.raw` 5.6G). 사용자가 쓸 수 있는 trim 명령이 없다 |
| DECISION5 | 런타임 감지 근거 | `docker context ls` 의 엔드포인트와 런타임별 설치 흔적(앱 번들, CLI, 데이터 디렉터리)을 함께 본다. 엔드포인트가 알려진 런타임과 맞지 않으면 알 수 없는 런타임이다 | 작성자 | 꺼진 런타임은 context 가 응답하지 않으므로 설치 흔적이 있어야 REQ3 를 지킬 수 있다 |
| DECISION6 | Colima 프로필 | 설치된 프로필마다 런타임 하나로 다룬다. 꺼진 프로필도 하나씩 「켜서 조사하기」 후보다. 기존 `--profile` 동작을 유지한다 | 작성자 | 기존 `colima_trim.ts` 가 프로필별 디스크 경로를 이미 다루고, DECISION2·DECISION7 과 같은 방식이다 |
| DECISION7 | 꺼진 런타임이 여럿일 때 켜기 묶음 | 런타임마다 따로 묻는다 | 사용자 2026-11-11 | 쓰지 않는 런타임까지 켜지 않는다. DECISION3 의 런타임별 묶음과 같다 |
| DECISION8 | 켰는데 준비되지 않을 때 | `docker info` 성공을 준비로 보고 최대 120초 기다린다. 넘으면 그 런타임만 「켜지 못함」 으로 보고하고 나머지를 계속한다 | 사용자 2026-11-11 | 120초는 도구의 명령 시간 한도에 맞춘 값이다. `open -a Docker` 는 엔진 준비 전에 반환한다 |
| DECISION9 | 이 맥 밖의 엔진 | 크기만 조사해 보이고 승인 묶음과 삭제에 넣지 않는다 | 사용자 2026-11-11 | 맥 정리 스킬이 다른 서버의 데이터를 지우지 않는다 |
| DECISION10 | 같은 엔진을 가리키는 context | 소켓 경로를 심볼릭 링크까지 풀어 같으면 런타임 하나로 합친다 | 작성자 | Docker Desktop 의 `default`(`/var/run/docker.sock`)는 `desktop-linux` 의 `~/.docker/run/docker.sock` 을 가리키는 링크다(2026-11-11 실측). 따로 보면 같은 이미지가 두 번 나온다 |
| DECISION11 | 확보량 보고 | 호스트 여유 전후가 확보량이고, 런타임별 디스크 파일 전후는 참고 줄, 정리하지 않은 런타임은 크기와 함께 남긴다 | 작성자 | 지금 SKILL.md 5단계가 호스트 여유 전후로 보고한다. 런타임을 건너뛴 사실을 남기는 것은 이 기능의 배경 문제를 막기 위해서다 |
