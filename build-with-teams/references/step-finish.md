# 마감

**team-lead 가 읽는 문서다.** 두 검토가 `PASS` 를 낸 뒤에 연다.

## 목표

**구현한 것을 PR 하나로 닫고, 다음 사람이 이어받을 수 있게 남긴다.**

## 통합 검증

오버레이나 레포 `CLAUDE.md` 의 검증 명령을 실행한다.
phase 마다 통과했어도 누적 후에 깨질 수 있다.

**실패하면 책임을 먼저 가른다.** 자의적으로 이 PR 에 외부 깨짐을 흡수하지 않는다.

| 어디서 깨졌나 | 판정 근거 | 대응 |
| --- | --- | --- |
| plan 범위 내 | 이번 plan 이 바꾼 파일이다 | executor 재스폰. 사용자 결정이 필요 없다 |
| plan 범위 밖 | `git diff origin/main -- <파일>` 이 비어 있다 | 아래 선택지를 사용자에게 제시한다 |

범위 밖일 때 제시하는 선택지다. 무엇을 골랐는지 PR 설명에 남긴다.

- 이 PR 에 fix 를 흡수한다.
- 별도 hotfix PR 을 만든 뒤 rebase 한다.
- 그대로 PR 하고 설명에 의존 관계를 밝힌다.

## 커밋 검토와 완료 마킹

- phase 별 commit 이 의도대로 들어갔는지 본다.
- **완료 마킹은 PR 브랜치 안에서만 한다.** 마지막 phase commit 에 포함하는 것이 가장 좋다.
  **main 에 직접 커밋하거나 push 하지 않는다.** 진실의 출처가 둘로 갈라지고 push 충돌 위험이 있다.

## PR

base 는 `main`, head 는 plan 브랜치다. 오픈 PR 이 없으면 새로 만들고, 있으면 갱신한다.

- 이 PR 하나에 **planning 의 docs 와 tasks 커밋, 구현 phase 커밋이 함께** 담긴다.
- 제목과 본문 형식은 레포 컨벤션을 따른다.
- 기획 커밋과 phase 별 commit 을 구분해 나열하고 「특이사항 및 후속」 절을 넣는다.
- 다른 plan 의 것이 diff 에 섞였으면 브랜치 범위를 정리한 뒤 만든다.

## 팀 종료와 작업 공간 정리

1. 남아 있는 팀원 전부를 종료하고 확인한다.
   대상은 `executor-p{N}`, `critic`, `code-reviewer`, `docs-verifier` 다.
   종료 수단은 [`team-spawn.md`](team-spawn.md)의 하네스별 대응표를 따른다.
2. **PR 생성과 원격 push 가 끝난 뒤에** 작업 공간을 정리한다.
   미커밋 변경과 로컬에만 있는 commit 이 없는지 먼저 확인한다. 정리 방법은 오버레이를 따른다.

## 보고

첫 줄에 PR 번호와 리뷰 반영 명령을 적는다.
작업 공간을 정리한 뒤라 cwd 브랜치가 `main` 이어서, 후속 스킬이 PR 을 자동으로 찾지 못한다.

```
PR #<번호> 생성 완료: 리뷰 반영은 /review-fix <번호>
```

이어서 아래를 담는다.

- **특이사항 4종 누적**: executor 가 phase 마다 보고한 것을 모은다. 후속이 필요하면 이슈 등록을 제안한다.
- **code-reviewer 발견 중 결함이 아닌 것**: 의도된 설계와 범위 밖 후속.
- **이번 세션 누적 노하우** 1줄에서 3줄. 누적하지 않았으면 「신규 노하우 없음」 이라고 적는다.

## 재사용 패턴 승격

발견한 사건 중 아래를 모두 만족하는 것만 저장소의 반복 함정 문서로 승격한다.

- 다른 plan 이나 코드에서도 다시 일어날 수 있다.
- 원인과 회피 방법이 특정 사건을 떠나 일반화된다.
- `grep`, lint, test, build 처럼 구체적인 검출 방법이 있다.

1회성 오타, 특정 plan 의 상황 설명, 단순 실행 통계는 PR 본문과 결과 보고에만 남긴다.

누적 위치는 오버레이가 지정한다. 지정하지 않으면 파일을 만들지 않고 결과 보고에만 남긴다.

| 종류 | 누적 위치 |
| --- | --- |
| 구현과 검토의 반복 함정 | 오버레이가 지정한 문서 |
| 프로세스 결함 | 이 스킬의 `SKILL.md` |
| 도메인 결정 | 레포 ADR |
| 코딩 규칙 | `CLAUDE.md`, `AGENTS.md` |

반복 함정 문서는 패턴 하나당 파일 하나로 둔다. 같은 패턴이면 기존 파일을 갱신한다.

사용자가 PR 을 머지하면 완료 상태가 main 에 반영된다. 후속 작업은 없다.
