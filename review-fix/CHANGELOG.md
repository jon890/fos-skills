## 1.6.0

- 「선택지 제시는 질문 도구로」 를 핵심 원칙에서 뺐다.
  `AskUserQuestion` 도구 설명이 「추천안을 첫 번째에 두고 label 끝에 (Recommended)」 를 이미 소유한다.
- 반복 함정 누적의 기본 경로 `docs/pitfalls/code-review/` 를 넣었다.
  지정이 없으면 파일에 쓰지 않던 규칙이라, 오버레이가 없는 저장소에서 9단계가 아무것도 하지 않았다.
- `~/.claude/skills/review-fix/` 절대경로를 번들 상대경로로 바꿨다.
  Agent Skills 명세가 스킬 루트 기준 상대경로를 쓰라고 한다.
- `gh-host.sh` 가 호스트 이름만 내도록 바꾸고 `GH_HOST` 지정을 존중하게 했다.

## 1.5.2

읽기 전용 검토에서 나온 결함을 고쳤다. 앞의 둘은 1.5.0 이 고쳤다고 적은 것이 실제로는 고쳐지지 않은 자리다.

- `GH_HOST` 를 1단계에서 export 해 7단계와 8단계가 쓰게 한 설계가 성립하지 않았다.
  에이전트 하네스는 명령마다 새 셸을 띄워 환경 변수가 다음 호출에 남지 않는다 (실측).
  스크립트 셋이 `gh-host.sh` 를 스스로 부르게 바꾸고, 직접 호출에는 `gh api --hostname` 을 쓴다.
  `gh-host.sh` 는 `export` 문 대신 호스트 이름만 낸다.
- `conflict-resolution.md` 의 lockfile 채택이 `--ours` 로 적혀 있었다. 방향이 반대다.
  PR 브랜치에서 base 를 머지하면 `--ours` 가 PR 브랜치이고 `--theirs` 가 base 다 (실측).
  install 이 lockfile 을 다시 만들어 주는 경우가 있어 잘못 골라도 드러나지 않았다.
- 7단계의 회신 생략 범위가 `severity.md` 의 회신 규약과 충돌했다.
  생략은 이미 반영돼 있던 항목에만 적용하고, 판단해서 반영하지 않기로 한 항목은 회신 대상으로 명시했다.
- 4단계가 P3 을 무조건 고치게 적어 `severity.md` 의 행동 규약과 어긋났다. 규약 참조로 바꿨다.
- 신뢰된 봇 목록을 오버레이로 넘기면서 판정 근거가 사라졌다.
  오버레이에 목록이 없을 때의 기본 동작을 1단계 보안 절에 넣었다.
- 7단계의 경로 판별을 미해결 스레드 기준으로 정확히 적고, `list-all` 하위 명령을 넣었다.
  `list` 가 resolve 된 스레드를 빼고 내므로, 앞선 실행이 resolve 한 PR 에서 경로를 잘못 골랐다.
- `collect-review.sh` 에 `set -eu` 를 넣었다. 앞 두 호출이 실패해도 종료 코드 0 으로 끝나
  호출한 쪽이 "리뷰가 없다" 로 읽었다.
- `collect-review.sh` 가 미해결 스레드를 넷째 소스로 내고, 스레드 목록에 `path` 와 `line` 을 넣었다.
  REST 댓글의 `id` 와 GraphQL 의 `THREAD_ID` 를 잇는 대조 열이 없었다.
- 2단계 코드 블록이 dirty 가드를 산문에만 두고 구현하지 않았다. 블록에 조건을 넣었다.
- REST 회신 예시만 본문을 셸에 직접 썼다. 세 경로 모두 파일로 넘기게 통일했다.
- 재트리거 토큰 검사가 정의되지 않은 `$REPLY_BODY` 를 읽었다. 본문 파일을 읽게 고쳤다.
- 충돌 마커 검사가 마크다운 setext 제목의 등호 줄을 잡았다 (실측). 정규식을 좁혔다.
- 리뷰 스레드가 100건을 넘으면 경고를 낸다. 뒤쪽 스레드가 조회되지 않아 resolve 가 누락됐다.
- `review-threads.sh` 의 사용법 출력이 `set -u` 줄까지 냈다. 범위를 고쳤다.

## 1.5.1

`harness-cleanup` 감사에서 나온 여섯을 고쳤다.

- 3단계의 참조 발동 조건이 「세 표기를 모두 만나면」 이었다.
  세 표기가 한 PR 에 동시에 오지 않아 조건이 참이 되지 않았고 `severity.md` 가 읽히지 않았다.
  「표기가 무엇이든」 으로 바꿨다.
- 3단계의 표기 표를 `severity.md` 한쪽만 소유하게 했다. 두 파일이 같은 내용을 본문으로 갖고 있었다.
- 봇 로그인 이름을 코어에서 뺐다. 실측으로 다른 저장소는 둘째 봇을 다른 이름으로 부르고 있었다.
  어느 봇이 어느 표기를 내는지는 오버레이가 소유한다.
- 7단계의 `INLINE_COUNT` 대입을 지웠다. 이후 어디서도 참조하지 않고 판정은 아래 표가 소유한다.
- 1단계의 댓글 수집 10줄을 `collect-review.sh` 로 옮겼다. jq 필드 제한도 스크립트가 소유한다.
- 종결어미 없이 `confirm.` 과 `reply.` 로 끝나던 평문 넷을 고쳤다. 표기 검사기가 잡지 못하는 축이다.

## 1.5.0

- 봇의 심각도 표기를 P1 부터 P5 로 갱신했다. 실측한 P3 부터 P5 의 문구를 그대로 옮겼고,
  실측하지 못한 P1 과 P2 는 등급 이름과 색만 적었다.
  옛 표기(🔴 필수 수정, 🟡 개선 권장)와 `codeowl[bot]` 의 Low·Medium·High 도 함께 읽도록 대응표를 뒀다.
  표기 설명과 행동 규약은 `severity.md` 로 분리했다.
- 호스트 판별을 1단계로 올리고 `gh-host.sh` 로 분리했다.
  `gh api` 는 `--repo` 를 받지 않아 기본 호스트를 보므로, 사내 GHE 에서 1단계와 7단계가 `Not Found` 로 실패했다.
  origin 이 SSH config 별칭이면 별칭이 그대로 나와 접속에 실패하므로 `ssh -G` 로 실제 호스트를 되찾는다 (실측).
- 7단계 회신 경로를 셋으로 나눴다. 봇의 발견사항은 리뷰 스레드로 달리는 경우가 많고,
  REST 의 `pulls/<N>/comments` 로는 스레드 ID 를 얻을 수 없어 GraphQL 로 읽고 GraphQL 로 회신한다 (실측).
  기존 인라인 댓글 REST 경로와 통합 댓글 경로는 그대로 남겼다.
  스레드도 인라인 댓글과 같게 지적 하나에 회신 하나를 단다고 명시했다.
- `resolve-threads.sh` 를 `review-threads.sh` 로 바꾸고 `reply` 하위 명령을 넣었다.
  회신 본문은 파일로 받는다. `-f b='...'` 로 직접 넘기면 셸이 본문 안의 백틱과 달러를 명령 치환으로 없앤다 (실측).
