# 검사기 매핑 표 유지보수

## 표에 넣는 기준

매핑 표는 검사기가 실패로 막는 유일한 목록이다.
**누가 봐도 어색한 음차, 비유어, 지어낸 번역어만 넣는다. 넣을지 애매하면 넣지 않는다.**

평범한 우리말은 넣지 않는다. 어색한 쓰임은 의미 점검에서 본다.
버전 뜻의 `판` 은 평범한 우리말이 아니라 version 을 옮긴 말이다. 뺀 뒤 에이전트가 version 을 `판` 으로 옮겨 써서 1.22.0 에서 구절 단위로 다시 넣었다.

영어 원어는 금지어로 넣지 않는다. 원어는 원어 열에 적고, 검사기는 첫 열만 읽는다.

## 부분 문자열로 찾는 데서 오는 제약

검사기는 한국어 금지어를 부분 문자열로 찾는다. 조사가 붙은 형태를 잡으려면 그래야 한다.
그래서 등록할 수 없거나 형태를 골라 등록해야 하는 말이 있다.

| 말 | 처리 | 이유 |
| --- | --- | --- |
| `판`, `정점` | 등록하지 않는다 | `판단`, `판정`, `수정점검` 까지 걸린다 |
| `판을`, `판이`, `판으로`, `판에서`, `판마다`, `판 올리기`, `판 번호`, `판 고정`, `판 접두사` | 버전 뜻으로 쓰이는 구절로 등록한다. `판` 으로 시작하는 금지어는 앞 글자가 한글이면 건너뛴다 | 앞 글자 경계가 있어 `번호판 번호`, `출판 번호`, `초판을 올린다` 같은 `X판` 합성어와 `판단`, `판별`, `판정` 은 걸리지 않는다. `판이하다` 는 `COMPOUND_ALLOW` 에 둔다. 판자 뜻의 `판을 올린다` 는 걸리지만 개발 문서에서는 드물다. `판도` 와 `판의` 는 다른 뜻이 많아 등록하지 않는다 |
| `서는 화면`, `서는 곳`, `서는 자리` | 구절로 등록하고 `서` 를 `WORD_START_PREFIXES` 에 둔다 | 기획서에서 `결과가 서는 화면` 처럼 `보이는 화면` 을 `서다` 로 쓴 말투가 검사기를 지나 문서에 들어갔다. `서는` 만 등록하면 `여기서는`, `문서는` 까지 걸린다. 앞 글자 경계가 있어 `여기서는 화면`, `문서는 곳곳에` 는 걸리지 않는다 |
| `기계` | `기계가`, `기계로`, `기계적` 만 등록한다 | `기계 학습`, `기계 번역` 까지 걸린다 |
| `시험` | 등록하고 `시험적` 을 `COMPOUND_ALLOW` 에 둔다 | `시험적으로 도입한다` 는 테스트 뜻이 아니다 |

**`손으로` 와 `거르/거른/거를/걸러` 는 이 기준의 예외로 넣었다.** 평범한 우리말이지만 사용자 결정과 실측 사례가 근거다.
`손으로` 는 배포가 모두 에이전트의 일인데 `배포 파일을 손으로 옮겨` 라고 써 실제 원인(스크립트가 설정 파일을 갱신하지 않음)을 가리고 사실과 다른 주체를 만든 보고에서 나왔다.
`거르다` 는 filter 를 옮긴 말이라 `거르는 조건` 이 `필터링 조건` 보다 읽기 어렵다는 지적이 있었다.
`근거를`, `증거를` 처럼 `거를` 을 품은 합성어와 `빈손으로`, `맨손으로` 는 `WORD_START_PREFIXES` 에 `거`, `걸`, `손` 을 더해 건너뛴다.
`하루 걸러` (격일) 같은 다른 뜻은 개발 문서에서 드물어 막는다. 오탐이 실제로 나오면 `COMPOUND_ALLOW` 로 푼다.

`재시험` 처럼 금지어를 품은 합성어는 함께 걸린다. 테스트 뜻이면 그대로 고친다.
다른 뜻의 합성어가 걸리면 `scripts/korean-style-check.py` 의 `COMPOUND_ALLOW` 에 더하고 테스트에 표본을 넣는다.

**금지어 앞에 글자가 붙은 합성어가 걸리면 금지어의 첫 글자를 `WORD_START_PREFIXES` 에 더한다.**
`번호판`, `초판` 처럼 앞에 붙는 합성어는 끝없이 늘어 `COMPOUND_ALLOW` 로 하나씩 막을 수 없다.
그 글자로 시작하는 금지어는 모두 앞 글자가 한글이면 건너뛴다.
**앞에 붙은 합성어를 잡아야 하는 금지어는 첫 글자를 더하지 않는다.** `시험` 의 첫 글자 `시` 를 더하면 `재시험` 이 건너뛰어져 위에서 말한 동작이 사라진다.
더하기 전에 같은 글자로 시작하는 금지어를 찾아, 모두 앞 글자 경계를 받아도 되는지 본다.

```bash
grep -n '^| 시' korean-check/references/korean-style.md
```

막아야 하는 구절과 통과해야 하는 합성어를 테스트에 함께 넣는다.

## 문맥으로만 막는 말

`표` 와 `칸` 은 문서 표를 가리킬 때도 쓰여 매핑 표에 올리면 `아래 표` 까지 걸린다.
DB 의 table 과 column 을 옮긴 쓰임만 `scripts/korean-style-check.py` 의 `DB_CONTEXT_PATTERNS` 로 막는다.

| 막는 형태 | 이유 |
| --- | --- |
| `DB 표`, `` `식별자` 표 ``, `` `식별자` 칸 `` | 코드 스팬 바로 뒤의 `표` 와 `칸` 은 DB 개체 이름 뒤에 붙은 쓰임이다. 뒤에 조사, 공백, 문장 부호가 올 때만 걸어 `DB 표준`, `표시` 는 걸리지 않는다. `.md` 같은 확장자로 끝나는 코드 스팬은 파일 이름이라 뺀다 |
| `표를 만들`, `표를 지우`, `표를 합치` | 등록하지 않는다. 문서의 표를 다루는 문장에도 흔해 오탐이 많다 |

패턴을 더하면 막는 표본과 통과하는 표본을 테스트에 함께 넣는다.
