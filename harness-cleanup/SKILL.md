# harness-cleanup

**목표: 하네스 지침에 모델이 추론할 수 없는 것만 남기고, 사용자가 승인한 것만 고친다.**

- 짧게 만드는 것보다 사실과 실행 가능성을 먼저 확인한다.
- 판정마다 그것을 확인한 실행 결과나 단일 소스가 있어야 한다.
- 사용자 승인 전에는 파일을 고치지 않는다.

## 실행 절차

각 단계는 진입 시 해당 reference 를 읽고 수행한다. 통과 조건을 확인한 뒤 다음으로 간다.

| 단계 | 이름 | 통과 조건 | reference |
| --- | --- | --- | --- |
| 1 | 기준과 범위 | 실행 환경의 설정을 읽었고 감사 대상 목록이 정해졌다 | `scripts/target_files.py` |
| 2 | 실측 | 검사 다섯이 각각 돌았고 대상 파일 수가 1 이상이다 | `scripts/` |
| 3 | 의미 감사 | 문장과 절마다 판정과 근거 등급이 붙었다 | `references/audit-axes.md`, `references/judgment.md` |
| 4 | 판정표와 승인 | 판정표를 냈고 사용자가 고칠 항목을 정했다 | |
| 5 | 교정 | 승인 항목만 고쳤다 | |
| 6 | 재검증 | 2단계 측정을 같은 범위에서 다시 통과했다 | |

## 조사를 나눠 맡긴다

**하위 에이전트를 띄울 수 있으면 실측과 의미 감사를 나눠 맡긴다.**
띄울 수 없으면 메인이 직접 하고 그 사실을 완료 보고에 적는다.

메인이 하는 것은 셋이다.

- 무엇을 누구에게 맡길지 나눈다
- 돌아온 보고를 종합해 판정표를 만든다
- 사용자 승인을 받아 고친다

**조사는 읽기만 시킨다.** 고칠 권한을 함께 주면 승인 절차를 거치지 않은 수정이 들어온다.
지시에 읽기 전용임을 밝히고, 고칠 것을 찾으면 위치와 근거만 회신하게 한다.

**나눌 수 있는 축이 여럿이면 한 번에 띄운다.** 축끼리 서로의 결과를 기다리지 않는다.

| 맡기는 것 | 회신 |
| --- | --- |
| 검사 스크립트 실행과 출력 해석 | 종료 코드와 걸린 자리 |
| 축 하나에 대한 문장 단위 판정 | 대상 절, 판정, 근거, 등급 |
| 문서가 준 명령이 도는지 확인 | 실행 결과와 실패한 명령 |

**회신 형식을 판정표의 한 줄과 같게 시킨다.** 그대로 모으면 판정표가 된다.
근거 등급을 붙이지 않은 회신은 되돌려 다시 받는다.

### 1. 기준과 범위

현재 실행 환경의 설정과 도구 설명에서 다음을 확인한다.

- 실제 모델과 하네스 런타임
- 설치된 역할, 스킬과 호출 방법
- 프로젝트가 읽는 지침 파일과 오버레이
- 사용자가 지정한 저장소와 워크스페이스 경계

**모델 이름과 버전을 산문에 복제하지 않는다.**
설정을 찾지 못하면 추측하지 않고 검증 공백으로 둔다.

감사 대상은 `scripts/collect_targets.py` 가 내는 목록과 실행 중 소비되는 회피 패턴이다.
어떤 파일이 대상인지는 `scripts/target_files.py` 가 소유한다.

**사용자가 스킬 하나나 디렉터리 하나만 감사해 달라고 하면 `--scope` 로 좁힌다.**
좁히지 않으면 다른 스킬의 오버레이가 걸려 종료 코드 1 이 나고, 대상이 아닌 자리를 손으로 골라내야 한다.

```bash
python3 scripts/collect_targets.py <repo-root> --scope .claude/skills/<이름>
```

범위는 저장소 루트 밑의 디렉터리나 파일 경로다.
대상 판정은 언제나 저장소 루트 기준이므로, 좁혀도 같은 파일이 같은 판정을 받는다.
**범위를 정했으면 2단계와 6단계에서 같은 값을 쓴다.** 범위가 달라지면 재검증이 다른 것을 본다.

일반 `docs/` 와 planning 산출물의 코드 정합성은 `docs-check` 로 보낸다.
저장소 밖을 가리키는 심볼릭 링크는 표시만 하고 수정하지 않는다.

### 2. 실측

```bash
python3 scripts/collect_targets.py <repo-root>
python3 scripts/check_references.py <repo-root>
python3 scripts/check_facts.py <repo-root>
python3 scripts/check_duplication.py <repo-root>
python3 scripts/check_rename_drift.py <repo-root>
```

1단계에서 범위를 정했으면 다섯 모두에 `--scope <경로>` 를 붙인다.
`check_duplication.py` 는 최소 연속 줄 수를 위치 인자로 받으므로 `<repo-root> 5 --scope <경로>` 처럼 적는다.

맡길 수 있으면 이 절을 하위 에이전트에게 넘기고 종료 코드와 걸린 자리를 회신받는다.

**각 명령을 따로 실행하고 출력과 종료 코드를 읽는다.**
앞 명령의 실패가 뒤 명령에 가려지는 연결 실행은 하지 않는다.
파이프로 출력을 자르면 종료 코드가 뒤 명령의 것으로 바뀐다.

| 종료 코드 | 뜻 |
| --- | --- |
| 0 | 위반 없음 |
| 1 | 위반 있음 |
| 2 | 검사가 돌지 못함 |

- **대상 파일 수가 0이면 통과가 아니다.**
- 깨진 참조와 중복 0건은 정적 검사가 찾지 못했다는 뜻일 뿐 의미 검사의 통과가 아니다.
- 고정 개수, 옵션과 파일 목록은 실제 코드, `--help` 와 설정에 대조한다.
- **문서의 실행 가능한 블록을 전부 `scripts/run_doc_snippets.py <파일>` 로 돌린다.** 검출 명령만이 아니다.
  머리말을 생략하면 그 파일의 블록을 전부 돌고, 머리말을 주면 그 뒤 첫 블록 하나만 돈다.
  검출 명령은 실제 입력과 대조 표본으로 검사하고, 상대경로가 어느 디렉터리를 전제하는지 함께 본다.
  **이 스크립트만 출력으로 판정한다.** 블록에 문법 오류가 있어도 종료 코드가 0 이다 (실측).
  **이 스크립트는 블록을 그대로 실행하고 안전장치가 없다.** 감사 대상 문서에 `git push`,
  `gh pr create`, `gh release create`, `nhncloud configure` 같은 명령이 들어 있으면 그대로 실행된다.
  그런 문서는 블록을 먼저 읽고 무엇이 도는지 확인한 뒤에 돌린다.

  | 무엇이 막히나 | 어떻게 |
  | --- | --- |
  | `git`, 그리고 저장소를 현재 디렉터리로 추론하는 `gh` | 저장소 밖 디렉터리에서 돌린다 (실측) |
  | `--repo` 를 명시한 `gh` | 막히지 않는다. 그 줄을 지우거나 돌리지 않는다 |
  | `nhncloud configure` 처럼 사용자 설정을 바꾸는 명령 | 막히지 않는다. 디렉터리와 무관하다 |

  저장소 밖에서 돌릴 때는 스크립트와 대상 문서를 모두 절대경로로 준다.
  이 스크립트는 부르는 셸의 디렉터리를 그대로 쓰므로 상대경로가 풀리지 않는다.
- 스킬을 수정할 가능성이 있으면 변경 전 평가 명령이 있는지 확인하고 기준값을 기록한다.

### 3. 의미 감사

`references/audit-axes.md` 와 `references/judgment.md` 를 읽고 문장과 절 단위로 판정한다.

**축이 여럿이면 축마다 하나씩 맡겨 한 번에 띄운다.** 각자 자기 축만 보고 판정표 형식으로 회신한다.

축은 무엇을 찾을지를, 판정 기준은 찾은 것을 유지할지 지울지를 소유한다.
스킬을 감사할 때는 `스킬 구조와 유지보수성` 축으로 목표, 책임 분리, 단계별 context, 검증 실행과 사람이 읽는 구조를 함께 본다.
기계가 이미 막는다는 근거로 지우려면 `scripts/check_enforcement.py` 로 확인한다.
발동 조건과 네 모드의 통과 조건은 `references/judgment.md` 가 소유한다.

### 4. 판정표와 승인

나눠 맡겼으면 돌아온 회신을 한 표로 모은다.
같은 절을 둘 이상이 지적했으면 한 줄로 합치고 근거를 함께 적는다.

수정 전 다음 형식으로 보고한다.

| 대상 절 | 판정 | 근거 | 등급 |
|---|---|---|---|
| `<file>` 의 `<section>` | 유지 / 제거 / 축소 / 보류 | 실행 결과와 단일 소스 | 실측 / 도구 대체 / 추정 |

**오류뿐 아니라 유지와 보류 항목도 포함한다.**
**추정만으로 유지하거나 제거하지 않는다.**

### 5. 교정

- 중복은 소유 문서에만 남기고 소비자는 짧게 참조한다.
- 조건부 절차는 발동 조건만 본문에 두고 필요할 때 읽는 참조로 옮긴다.
- 런타임과 역할 이름은 현재 환경이 해석하게 하고 저장소 고유 경계만 남긴다.
- 검출 명령은 현재 진입점과 실제 파일을 보도록 고친다.
- 반복 실행 코드가 5줄을 넘으면 `scripts/` 로 옮긴다.
- 사용자의 기존 변경과 승인 범위 밖 파일을 건드리지 않는다.
- 고친 뒤 그 저장소가 제공하는 검사를 실행한다.

### 6. 재검증

2단계 측정을 같은 범위에서 다시 실행한다.

- 변경한 동작에는 걸리는 표본과 걸리지 않는 표본을 함께 둔다.
- 문서에 적은 명령은 실제 셸에서 확인한다.
- Markdown 은 그 저장소의 표현과 가독성 검사를 통과해야 한다.

검토자를 **읽기 전용으로 띄워** 최종 diff 와 검사 근거를 확인시킨다.
띄울 수 없으면 메인이 직접 확인하고 그 사실을 완료 보고에 남긴다.

완료 보고에는 처리한 판정, 전후 측정, 실행한 검증, 커밋, 남은 검증 공백을 적는다.
