# work-board: 한 보드 항목 아래에 여러 worker 를 붙인다

확인: 2026-11-13

## 목표

구현, 리뷰, 재리뷰, 인수 검증, 후속 PR worker 가 같은 일을 하면 보드 항목 하나 아래 worker 줄로 모인다. 보드가 같은 일의 여러 항목으로 흩어지지 않고, 코디네이터가 리뷰·후속 항목을 따로 닫을 일이 없다.

- 배경(ai-analysis 코디네이터 요청 2026-11-13): 이미 있는 항목의 후속 작업을 새 이름의 worker 로 띄우자 지시서 제목으로 새 보드 항목이 따로 생겼다(tempo-real-export, dooray-browser-fix). 사용자는 보드가 계속 여러 항목으로 나뉘는 것을 문제로 봤다.
- 배경(사용자 2026-11-13): fos-skills 보드도 구현 항목(board-chip-own-line)과 리뷰 항목(review-pr-489)이 따로 생긴다.

## 범위

이번 범위:

- 보드 항목 안의 worker 목록(역할, 워크트리, 브랜치, PR, 상태)
- 띄울 때 리뷰·검증 worker 를 리뷰 PR 의 항목에, 후속 worker 를 겹치는 열린 항목에 더해 붙이기
- 지시서의 `보드 항목: 새로` 줄로 따로 만들기
- 창에서 항목 아래 worker 줄 그리기
- worker 가 끝났을 때 그 worker 줄만 끝내기

범위 밖:

- 부모·자식 항목(항목이 다른 항목을 가리키는 구조)
- 이미 따로 생긴 리뷰 항목을 부모 항목으로 옮기기. 이 항목들은 PR #487 대로 저절로 닫힌다
- 다른 저장소의 PR 을 리뷰하는 항목 묶기

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 보드 항목이 붙은 worker 목록을 갖는다. worker 마다 역할(구현, 후속, 리뷰, 검증), 워크트리, 브랜치, PR, 상태(작업 중, 끝남)를 둔다. 옛 `worktree`·`branch` 칸은 지금 대표 worker 의 값으로 남는다 | worker 둘을 붙인 항목의 `board.json` 에 worker 목록 두 줄이 있고, `worktree` 칸은 가장 최근의 작업 중 구현·후속 worker 를 가리킨다. 목록이 없는 옛 항목도 지금처럼 읽힌다 |
| REQ2 | 지시서에 `리뷰 PR: #N` 이 있으면 PR 칸이나 merged-pr 칸에 N 이 든 항목(done 포함)을 찾아 그 항목의 worker 목록에 리뷰 역할로 더한다. 지시서에 `worker 역할: 검증` 줄이 있으면 검증 역할이고, `리뷰 PR:` 이 없으면 업무 번호·브랜치로 찾는다. 리뷰·검증 worker 는 항목의 상태, 단계, 대표 칸을 바꾸지 않는다. done 항목도 다시 열지 않는다. 못 찾으면 지금처럼 새 항목을 만든다 | PR #N 의 구현 항목이 열려 있거나 머지되어 done 일 때 리뷰 worker 를 띄우면 새 항목이 생기지 않고 그 항목의 worker 줄이 하나 는다. 항목의 상태·단계·워크트리는 그대로다. `보드 항목 id:` 와 `리뷰 PR:` 이 함께 있는 지시서도 그 항목에 리뷰 worker 로 붙고 리뷰가 끝나도 항목은 닫히지 않는다 |
| REQ3 | 지시서에 `보드 항목 id:` 가 없고 같은 업무 번호나 같은 브랜치의 열린 항목이 있으면 그 항목의 worker 목록에 더한다. 원래 worker 를 바꾸지 않는다. 띄우기 출력에 붙은 항목과 역할을 한 줄 낸다 | 업무 번호가 같은 후속 지시서로 띄우면 기존 항목에 후속 worker 줄이 더해지고, 원래 worker 줄은 그대로 남는다. 띄우기 출력에 `BOARD-ATTACH <항목> <역할>` 꼴의 줄이 있다 |
| REQ4 | 후속 worker 가 항목의 지금 브랜치와 다른 새 브랜치면 항목에 다음 번호의 PR·머지 두 단계만 더한다. 앞 PR 이 아직 열려 있어도 받는다. 항목은 열린 PR 여럿을 잇고, 각 PR 의 머지가 자기 머지 단계를 끝낸다. 리뷰·검증 worker 는 단계를 더하지 않는다 | 앞 PR 이 열린 항목에 후속 worker 를 붙이면 전체 단계 수가 둘 늘고, 두 PR 이 모두 PR 칸에 보인다. 뒤 PR 만 머지되면 뒤 머지 단계만 끝난다. 리뷰 worker 를 붙이면 단계 수가 그대로다 |
| REQ5 | 지시서에 `보드 항목: 새로` 줄이 있으면 자동으로 붙이지 않고 새 항목을 만든다. 이 줄과 `보드 항목 id:` 가 함께 있으면 spec-lint 가 막는다 | 같은 업무 번호의 열린 항목이 있어도 새 항목이 생긴다. 두 줄을 함께 쓴 지시서는 spec-lint 가 막는 발견을 낸다 |
| REQ6 | 창은 항목 아래에 작업 중 worker 를 한 줄씩(역할, 워크트리, PR·CI, 상태) 보이고(리뷰·검증 줄의 PR 은 대상 PR, 상태는 Orca 의 실시간 상태), 끝난 worker 는 「✓ 끝난 worker N」 한 줄로 묶는다. 펼친 보기(d)에서는 끝난 worker 도 한 줄씩 보인다 | 작업 중 둘, 끝남 둘인 항목은 접힌 보기에 worker 줄 둘과 「✓ 끝난 worker 2」 가 보이고, 펼친 보기에 네 줄이 보인다 |
| REQ7 | worker 줄은 worker_done, 워크트리 사라짐, Orca dispatch 의 끝난 상태(abandoned, failed, stopped, cancelled)나 터미널 종료 가운데 하나로 끝남이 된다. 오래 움직이지 않는 worker 는 끝남이 아니다. worker_done 없이 끝난 줄은 「끊김」 으로 따로 보인다. 항목은 지금처럼 단계로 끝나고, 리뷰·검증 worker 는 항목 닫기와 자동 진행을 붙잡지 않는다. 작업 중 worker(역할 무관)가 하나라도 있으면 「worker 없음」·멈춤 알림을 내지 않는다. done 항목도 작업 중 worker 줄은 끝날 때까지 보인다 | 리뷰 worker 가 끝나도 구현 worker 가 작업 중이면 항목은 진행 중이다. 리뷰 worker 만 도는 항목에는 멈춤 알림이 없다. 리뷰 중에 마지막 PR 이 머지되면 항목은 done 이 되고, 완료 칸에 그 리뷰 worker 줄이 끝날 때까지 보인다. 워크트리를 지운 worker 줄은 다음 동기화 뒤 「끊김」 이다 |
| REQ8 | 참조 문서, 데이터 스키마, 리뷰 지시서 틀과 새 검증 지시서 틀이 새 동작을 설명한다 | `docs/data-schema.md`, orch·work-board 참조 문서, `skills/orch/templates/spec-review.md` 에 worker 목록, 자동 붙이기, `보드 항목: 새로` 가 있고, 새 `skills/orch/templates/spec-verify.md` 에 `worker 역할: 검증` 줄이 있다 |
