# CHANGELOG: work-board

work-board 는 스킬이 아닌 mod 이므로 이 파일에서 변경 이력을 시작한다.
버전 등급과 쓰는 형식은 저장소 README 의 「버전과 변경 이력」 을 따른다.

## 1.20.0 (2026-11-11)

- 보드 창에 「승인 대기」 상자와 상태 줄의 「승인 n」 을 더했다. 열린 대기마다 미리보기 열기, 「승인」, 「고쳐 달라」 글칸을 보인다.
- `real` 대기는 대상과 되돌리는 법을 빨갛게 보이고 「승인」 을 10초 안에 두 번 눌러야 신호가 간다. `command` 대기는 「명령 채우기」 가 입력란에 `! 명령` 을 채운다.
- worker 터미널에서 연 창은 승인 대기만 보이고 버튼을 그리지 않는다. 예전 화면의 버튼은 기록도 신호도 남기지 않는다.
- 창 전용 명령 `bin/approvals.ts`(where, self, press)를 더했다.

## 1.19.1 (2026-11-10)

- 창의 상태·단계 요청문이 `orch board` 명령을 안내한다. 엄격한 상태 변경은 명시한 빈 상태를 거절한다.
- 단계 추가의 진행률 경고가 부른 도구에서 쓸 수 없는 명령 대신 명시한 진행률 값의 영향을 설명한다.

## 1.19.0 (2026-11-10)

- 보드 쓰기가 파일 잠금을 지켜 함께 고친 항목을 보존하고, 잠금을 못 잡으면 종료 코드 1 로 알린다.
- `set`, `step` 의 `--exact` 가 없는 항목과 중복 번호를 거절하고 결과 JSON 을 낸다.
- `view` 가 항목 상태와 진행률, 줄 목록을 JSON 으로 읽는다.
- `step-edit`, `step-add` 가 단계 글을 고치거나 번호를 붙여 더하고, `--event` 로 사건 꼬리표를 붙인다.
- `set --if-rev` 가 읽은 뒤 줄이 바뀐 통째 저장을 거절한다.

## 1.18.5 (2026-11-09)

- 오늘 시작 요청문 맨 앞에 전날 미룬 결정과 아침 확인 목록을 모으는 단계를 둔다

## 1.18.4 (2026-11-09)

## 1.18.2 (2026-11-05)

- 창이 보이지 않거나 오래 입력하지 않으면 자동 네트워크 조회를 쉬고, `/board` 를 열면 다시 읽어요.
- 자동 조회가 쉬는 동안 상태 줄에 PR·알림을 확인한 시각과 「조회 쉼」 을 보여요.

## 1.18.1 (2026-11-05)

## 1.18.0 (2026-11-04)

- 「머지 큐」 상자와 보드 항목 제목 옆의 큐 순서 표시를 없앤다. 대신 열린 PR 상자의 PR 마다 「머지 가능」, 「머지 큐 n 번째」, 「머지 중」, 「대기: <이유>」 중 한 줄과 「HH:MM 부터」 를 붙인다
- 대기 이유는 루프의 `AUTO-MERGE-WAIT` 이유를 「체크 대기」, 「미해결 대화 1」 처럼 사람이 읽는 말로 옮긴다
- 머지 줄은 orch 머지 큐를 쓰는 저장소(`queue.auto_merge` 가 켜졌거나 코디네이터가 건 큐가 돈다)에서만 보인다. 기록이 없는 PR 에는 줄을 붙이지 않는다

## 1.17.1 (2026-11-04)

- 문서 표현만 고쳤다. 동작은 바뀌지 않았다

## 1.17.0 (2026-11-04)

- 열린 PR 상자 아래에 「머지 큐」 상자를 더한다. 열린 PR 마다 큐 안의 순서(지금 차례, n 번째, 큐 밖), 대기 이유, 그 상태로 바뀐 시각을 한 줄로 보인다
- 대기 이유는 orch 상주 루프의 `AUTO-MERGE-WAIT` 이유를 그대로 쓴다. 큐 순서는 머지 큐의 차례 기록(`state/queue-turn/<pid>.json`)을, 없으면 루프가 건 큐의 기록과 큐 로그를 읽는다. 새 `bin/merge-queue.ts` 가 읽고 gh 는 부르지 않는다
- 보드 항목에 열린 PR 이 연결돼 있으면 제목 줄 옆에 「#877 큐 2 번째」 처럼 큐 순서를 흐리게 붙인다. 큐 상태를 읽지 못한 PR 은 「큐 상태 모름」 이다

## 1.16.0 (2026-11-04)

## 1.15.0 (2026-11-03)

- `u` 보드 갱신 단축키와 그 요청문을 지운다. 항목 하나의 상태는 `c` 다음 번호나 제목 줄 클릭으로 확인하고, 보드 전체는 orch 상주 루프가 동기화한다

## 1.14.0 (2026-11-03)

- 대기 항목의 제목 줄을 누르거나 `c` 다음 번호로 고르면 재개 요청문을 채운다. 요청문은 대기 사유, 업무 주소, worker, PR 을 담고, 기다리던 답이나 결정, 배포, 외부 회신이 왔는지 확인해 왔으면 다음 단계를 진행하고 아직이면 재촉하거나 우회할 방법을 제안하게 한다
- 대기 사유는 끝나지 않은 단계와, 끝나지 않은 참고 줄 가운데 「대기」, 「기다」, 「회신」 이 든 줄이다. 진행 중 항목의 상태 확인 요청문은 그대로다

## 1.13.0 (2026-11-03)

- directory 소스 마켓플레이스의 폴더에서 읽은 플러그인도 `p` 한 번으로 갱신한다. 그 폴더가 main 이고 추적 파일 변경이 없고 fast-forward 할 수 있으면 `git pull --ff-only origin main` 을 돌리고 입력란에 `/reload-plugins` 를 채운다
- 등록된 폴더는 `--plugin-dir` 로 읽었어도 같은 설치본으로 보고, 아래 세 보호가 작업 중인 변경을 지킨다
- main 이 아니거나, 고치는 중인 파일이 있거나, fast-forward 할 수 없으면 받지 않고 toast 에 이유를 보인다. 받은 뒤에는 머리 줄이 새 version 을 보인다

## 1.12.0 (2026-11-03)

- 진행 중이나 대기 항목의 제목 줄을 클릭하거나 포커스를 두고 Enter 를 누르면 `c` 없이도 그 항목의 상태 확인 요청문을 채운다. 알림 넘기기(`x`) 모드에서는 눌러도 채우지 않는다

## 1.11.0 (2026-11-03)

- `c` 다음 번호로 진행 중이나 대기 항목을 골라 그 항목의 상태 확인 요청문을 입력란에 채운다. 요청문은 지금 상태를 확인하고, 멈춰 있으면 다음 단계를 진행하거나 정할 것을 묻게 한다
- 확인 모드에서 `c` 를 다시 누르거나 `Esc` 를 누르면 창은 남기고 번호만 지운다. 알림 넘기기(`x`)와는 함께 켜지지 않는다

## 1.10.0 (2026-11-02)

- 결정 필요 상자와 수에서 Orca 자동 알림(「Worker stopped without reporting」, 「Agent hit an error」)을 뺀다. worker 가 직접 보낸 질문과 막힘만 남는다
- worker 줄 끝에 「멈춤 N분」, 「멈춤 · 터미널 종료」, 「오류: 계정 한도」, 「입력 대기」 같은 상태를 붙인다. 멈춤 판정은 orch 상주 루프와 같다
- doing 항목의 단계가 worker 없이 `pipeline.idle_min` 넘게 남으면 「⚙ worker 없음 · N시간」 으로 보인다. `board.ts` 가 항목마다 `stepAt` 을 남긴다
- 정할 것 묻기 요청문이 직접 올린 막힘과 자동 알림을 다루는 방법을 담는다
