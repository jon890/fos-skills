# content-preview

외부에 나갈 본문을 등록한 뒤에야 깨진 모양을 발견하고 다시 고치는 수고를 덜어 준다.
본문을 임시 파일에만 쓰면 사용자 화면에는 도구 호출만 보이고 내용은 보이지 않는다.
이 스킬은 본문을 게시될 곳과 비슷하게 렌더링한 HTML 로 띄우고, 사용자가 읽고 응답한 다음 턴에 등록한다.

띄우기 전에 `korean-check` 로 표기를 검사하고, 짧은 글이 아니면 의미 점검까지 거친다.
본문을 고쳐 다시 띄우면 탭을 새로 만들지 않고 보던 탭을 갱신한다.

## 이럴 때 쓴다

- Dooray 댓글과 업무, 메신저에 글을 올리려 한다
- GitHub 이슈나 PR 본문, 리뷰 응답을 등록하려 한다
- 메일, 슬랙 메시지, 위키에 글을 쓰려 한다

"미리보기 보여줘" 라고 말하지 않아도, 외부에 나갈 텍스트를 등록하려는 순간이면 이 스킬이 뜬다.
로컬 파일 작성과 코드 커밋처럼 외부에 나가지 않는 것은 대상이 아니다.

## 사용 예시

제목과 문구는 예시다.

```text
나:   이 브랜치로 PR 열어줘

스킬: 본문을 쓰고 표기 검사와 검토를 거친 뒤 GitHub 모양의 미리보기를 띄웠습니다.
        제목: 로그인 실패 때 재시도 횟수를 제한한다
        확인 범위: 본문과 제목
        반영하지 않은 발견: 「backoff」 를 옮기지 않았습니다. 저장소가 이미 쓰는 표기입니다

나:   두 번째 문단을 줄여 줘

스킬: 같은 탭의 미리보기를 갱신했습니다. 바뀐 블록은 아래와 같습니다.
        AS-IS  재시도 횟수를 제한하지 않아 계정이 잠길 때까지 요청이 이어졌다. ...
        TO-BE  재시도를 다섯 번으로 제한한다.

나:   좋아, 올려

스킬: PR 을 열었습니다.
```

## 받는 것

- 본문 markdown 파일과 그것으로 만든 미리보기 HTML
- 사용자 화면에 열린 미리보기 탭. 같은 파일이 이미 열려 있으면 그 탭을 갱신한다
- 무엇을 띄웠는지와 제목만 담은 짧은 보고. 본문 전문은 채팅에 다시 쓰지 않는다
- 검토에서 반영하지 않은 발견과 그 이유. 검토를 건너뛰었으면 그 사실
- 부분 수정이면 바뀐 블록의 AS-IS 와 TO-BE
- 사용자가 읽고 응답한 다음 턴에 이뤄지는 등록

## 미리보기 없이 등록하는 때

- 사용자가 이번 본문의 등록을 대화에서 명시적으로 미리 승인했으면 미리보기를 생략하고 바로 등록한다. 표기 검사는 그대로 거치고, 결과에 생략한 사실과 본문 파일 경로를 적는다
- 「이 세션의 PR 은 묻지 말고 올려」 처럼 범위를 밝힌 상시 승인은 그 범위 안에서 미리보기를 만들되 응답을 기다리지 않고 등록하고, 결과에 미리보기 경로를 적는다
- 범위 없는 「알아서 해」 같은 일반 위임이나 다른 건에 대한 과거 승인은 승인으로 보지 않는다
- 에이전트 조율 도구가 보낸 작업이라 화면을 볼 사람이 없으면 미리보기 HTML 파일만 만든다. 지시문에 등록이 적혀 있으면 등록하고 그 파일 경로와 등록한 URL 을 보고하며, 없으면 지시한 쪽에 등록할지 묻는다

## 준비

- `python3` 가 필요하다. 미리보기 스타일과 렌더러를 CDN 에서 받으므로 망이 없으면 스타일이 빠진다
- 이 저장소의 `tools/browser-driver/` 를 함께 받으면 그 드라이버로 띄운다. 없으면 기본 브라우저로 띄운다
- 드라이버가 쓸 브라우저 백엔드는 설정 파일의 `previewDriver` 나 환경 변수 `PREVIEW_BROWSER_DRIVER` 로 정한다. 정하지 않으면 드라이버의 자동 감지를 따르고, 그 백엔드가 탭의 워크트리를 대조하지 못하면 그 사실을 알린다
- `korean-check` 스킬을 함께 받는다. 이 저장소가 같이 배포하며, 다른 곳에 두었으면 `KOREAN_CHECK` 로 경로를 준다. 찾지 못하면 표기 검사가 종료 코드 2 로 멈춘다
- 본인 명의로 나가는 글의 문체를 고정하려면 `~/.claude/references/work-writing-persona.md` 를 만든다. 선택이며, 없으면 그 단계를 건너뛴다. 무엇을 적는지는 `references/persona.md` 에 있다

## 함께 쓰는 스킬

- 표기 검사기와 의미 점검의 판정 기준은 `korean-check` 가 맡는다
- 업무 관리나 PR 생성처럼 본문을 쓰게 된 일 자체는 그 일을 맡은 스킬이 한다. 그 스킬도 등록 전에 무엇을 보여 주고 언제 승인받는지는 이 스킬을 따른다
