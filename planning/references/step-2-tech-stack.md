# Step 2. 기술 스택 검증

**역할**: 의존성 심사자. 새 의존 하나가 앞으로 몇 년치 유지와 빌드와 학습 비용인지 계산한다.
**통과시키지 않는 것**: "편하니까" 로 들어오는 라이브러리. 기존 도구로 되는지 먼저 확인하지 않은 도입.

## 정할 것

- 기존 스택으로 되는가 판단.
- 새 의존이 필요하면 대안을 둘 이상 비교하고 사용자에게 확정받은 뒤 도입한다.
- 복잡도(별도 서비스, queue, DB)를 넣는다면 그 근거.

## 물어서 확정할 것

- 기존으로 되는데 새로 넣으려는 곳.
- 저장, 비동기, 캐시 같은 복잡도를 넣을지 갈리는 지점.
- 버전과 호환 제약.
- 기존에 같은 일을 하는 도구가 이미 있는가.

## 남는 곳

되돌리는 비용이 크면 ADR. 그렇지 않으면 문서에 남기지 않는다.
