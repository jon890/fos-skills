# orch: Claude 주간 사용량이 남을 것 같으면 Codex 행을 같은 등급의 Claude 로 띄운다

> 현재 시작 전 모델 선택은 [모델 사용 한도 회피](../exhausted-model-avoid/spec.md)를 따른다. 아래는 Claude 에 남을 사용량을 보고 제공자를 바꾸던 기능의 기록이다.

확인: 2026-11-20

## 목표

Claude 주간 사용량이 초기화 전에 남을 것 같으면, `orch worker launch` 가 모델 표의 Codex 행을 같은 등급의 Claude 로 바꿔 띄운다.
사용자가 남은 양을 보고 코디네이터마다 「Claude 로 띄워」 를 따로 말하지 않아도 된다.

지금 모델 표는 코드 구현, 작은 수정, 일반 설계와 문서 일을 Codex `sol` 에 맡긴다(사용자 결정 2026-11-17, 비용이 Opus 의 약 40%). 그래서 Claude 구독의 주간 사용량이 남은 채 초기화되는 주가 생긴다. 2026-11-20 에는 초기화 약 37시간 전인데 22% 만 쓰였다.

## 범위

이번 범위:

- 띄울 때 Claude 주간 사용량과 초기화 시각을 읽는다.
- 기준을 채우면 정해진 Codex 행을 같은 등급의 Claude 로 바꾸고, 바꾼 이유를 띄우기 기록에 남긴다.
- 모든 저장소의 orch 가 같은 규칙으로 돈다.

범위 밖:

- Codex 쪽 사용량을 보고 거꾸로 바꾸는 것. 한도에 걸렸을 때의 대응은 지금 「사용 한도에 걸렸을 때」 표가 맡는다.
- 이미 떠 있는 worker 를 바꿔 띄우는 것.
- 하위 에이전트와 코디네이터 세션 자신의 모델.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 남을 것 같으면 Claude 로 바꾼다 | 남은 사용량 비율(100 − 주간 사용 %)이 초기화까지 남은 시간 비율(남은 시간 ÷ 7일)보다 크면, impl-planned, impl-explore, small-fix, design 행의 Codex worker 를 같은 등급의 Claude 로 띄운다. 같은 등급은 「사용 한도에 걸렸을 때」 표를 따른다(sol medium → Opus 5.5 medium, sol low → Sonnet 5.5) |
| REQ2 | 기준을 채우지 않으면 지금처럼 띄운다 | 남은 사용량 비율이 남은 시간 비율 이하면 모델 표의 Codex 행 그대로 띄운다 |
| REQ3 | 바꾸지 않는 행 | 화면 판정(visual, Terra), 이미 Claude 인 행, 리뷰 행은 바꾸지 않는다. 리뷰는 지금처럼 만든 쪽과 다른 제공자로 정해진다(만든 쪽이 바뀐 Claude 면 리뷰는 Codex) |
| REQ4 | 바꾼 이유가 남는다 | 바꿔 띄우면 `LAUNCH-EFFECTIVE` 와 띄우기 기록의 `candidateOverride` 에 행, 띄운 worker, 이유(「사용량: 남은 78%, 남은 시간 22%」 꼴)가 남는다. 지시서의 `worker 선택:` 줄과 달라도 이 경우는 거절하지 않는다 |
| REQ5 | 사용량을 읽지 못하면 바꾸지 않는다 | 사용량 출처가 없거나, 읽지 못하거나, 1시간보다 오래된 값이면 바꾸지 않고 `USAGE-UNKNOWN <이유>` 한 줄을 낸다. 띄우기는 막지 않는다 |
| REQ6 | 사람이 끈다 | orch 설정 `routing.usage_boost` 가 `false` 면 바꾸지 않는다. 값이 없으면 켜진 것으로 본다. 지시서에 행과 다른 worker 를 「후보 밖」 으로 적었으면 그 선택이 먼저다 |

## 결정

| ID | 결정 | 답 | 누가 | 근거 |
| --- | --- | --- | --- | --- |
| DECISION1 | 바꾸는 기준 | 남은 사용량 비율이 남은 시간 비율보다 클 때 | 사용자 2026-11-20 | 주 초반에는 Codex 를 쓰다가, 남을 것 같으면 자연스럽게 Claude 로 넘어간다 |
| DECISION2 | 바꾸는 행 | 코드·설계·문서 행 모두(impl-planned, impl-explore, small-fix, design). 화면 판정은 그대로 | 사용자 2026-11-20 | 남은 양을 쓰려면 일이 많은 행을 바꿔야 한다 |
| DECISION3 | 기능 전의 대응 | 초기화(2026-11-22 05:59)까지 코디네이터가 손으로 같은 등급 Claude 로 띄운다 | 사용자 2026-11-20 | 기능을 기다리면 이번 주 남은 양을 쓰지 못한다 |
| DECISION4 | 사용량 출처 | Claude Code 상태 줄이 받는 주간 사용량(사용 %, 초기화 시각). 지금 이 머신은 oh-my-claudecode 의 사용량 캐시에 있다. 출처 위치는 설계가 정한다 | 작성자 | 상태 줄에 보이는 값과 같은 값을 써야 사용자가 판단을 확인할 수 있다 |
| DECISION5 | 오래된 값의 기준 | 1시간 | 작성자 | 상태 줄 캐시는 수 분마다 갱신된다. 1시간 넘게 갱신되지 않았으면 출처가 멈춘 것이다 |
| DECISION6 | 끄는 설정 | `routing.usage_boost: false`. 기본 켜짐 | 사용자 2026-11-20 | 사용자가 켜기를 원했다. 문제가 나면 한 줄로 끈다 |
| DECISION7 | PR 단위 | PR 하나 | 사용자 2026-11-20 | 띄우기 한 곳의 판정과 문서만 바뀐다 |

## 도메인 규칙 변경

도메인 규칙 변경 없음: orch 의 worker 선택 규칙만 바뀐다.
