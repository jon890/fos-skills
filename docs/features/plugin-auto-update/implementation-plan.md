# 자동 갱신 구현 계획

한 PR 에 REQ1~REQ7을 함께 넣는다. 설치본 갱신과 세션 다시 읽기는 서로 연결된 동작이라 나누면 중간 상태를 사용자가 처리해야 한다.

1. 루프의 설정 판정, 머신 잠금, main 버전 확인, 캐시 설치본 갱신, 성공 재확인과 결과 기록을 만든다. 임시 설정 폴더의 여러 scope, 개발용 설치, 경합, 실패 재시도를 테스트한다.
2. 기존 루프의 다시 뜨기 알림에 결과를 붙인다. 새 번들이 없는 실패는 버전당 한 번 알린다.
3. 보드는 설치 기록과 세션 번들 버전을 비교해 새 설치본을 표시하고, 내장 `reload-plugins` 를 세션이 쉴 때 실행한다. 입력란을 건드리지 않는지 테스트한다.
4. 기능 설계와 스킬 안내를 맞춘다. 인수 검증은 임시 폴더의 통합 테스트, `claude plugin test .`, 전체 저장소 테스트와 코드 리뷰로 한다. 실제 설정 폴더 갱신과 머지 뒤 확인은 코디네이터가 맡는다.

인수 검증은 `docs/features/plugin-auto-update/spec.md` 의 REQ1~REQ7을 기준으로 한다. 주된 위험은 오래된 설치 기록, 여러 루프의 경합, 세션 시작 중 명령 호출이다. 실패 시에는 설치본을 건드리지 않고 다음 확인에 재시도한다.
