# CHANGELOG: work-board

work-board 는 스킬이 아닌 mod 이므로 이 파일에서 변경 이력을 시작한다.
버전 등급과 쓰는 형식은 저장소 README 의 「버전과 변경 이력」 을 따른다.

## 1.9.0 (2026-11-02)

- 알림 상자에서 `x` 다음 번호로 그 알림을 에이전트를 거치지 않고 답하지 않음으로 넘긴다. 넘긴 알림은 바로 빠진다
- `z` 는 이 세션에서 마지막으로 넘긴 알림을 되돌린다

## 1.8.0 (2026-11-02)

- Orca 1.4.246 에서 비어 보이던 워커 상태와 결정 필요를 고친다. Orca 조회를 `--full` 로 읽는다

## 1.7.1 (2026-11-02)

- structured 모드 worker 가 일하는데도 「worker 없음」 으로 보이던 문제를 고친다. `worker-list` 항목의 `outcome`, `state`, `terminal`, `workspace` 도 읽는다. 끝난 것(`succeeded`, `failed`, `abandoned`)은 뺀다

## 1.7.0 (2026-11-02)

- 다른 Orca 계정 프로필에서 설치한 플러그인도 보드에서 버전과 갱신 대상을 찾는다

## 1.6.0 (2026-11-02)

- 알림 상자에서 답한 알림을 목록에서 빼고 「답함 n」 수만 흐리게 보인다

## 1.5.0 (2026-11-02)

- 머리 줄에 설치본의 플러그인 version 과 커밋, main 과 비교한 최신 여부를 보인다. 뒤처지면 노란색으로 최신 version 을 보인다
- `p` 는 그 세션 설치본의 scope 로 `claude plugin update` 를 돌리고, 성공하면 입력란에 `/reload-plugins` 를 채운다. 최신이면 보이지 않는다
- 창이 좁으면 단축키가 잘리지 않고 다음 줄로 넘어간다
- 상태 줄은 글이 바뀔 때만 보낸다. SDK 로 실린 세션의 host 에 같은 `ui_status` 메시지가 5초마다 가지 않는다

## 1.4.0 (2026-11-02)

- 결정 필요 아래에 업무 알림 상자를 보인다. 새 알림 수, 항목 줄, 받지 못한 출처, 미분류 알림 수가 보인다
- `1`~`9` 는 그 알림의, `i` 는 새 알림 전체의 답변 요청문을 입력란에 채운다
- 상태 줄 맨 앞에 새 알림 수(「알림 n」)를 붙인다

## 1.3.0 (2026-11-02)

- 결정 블록 여러 개를 묶은 질문은 첫 결정 제목 뒤에 「외 N개」 를 붙여 보인다

## 1.2.0 (2026-11-01)

- 열린 PR 줄마다 작성자(「@login」)를 보인다
- `a` 단축키로 열린 PR 을 작성자 하나의 것만 골라 보인다. 누를 때마다 전체, 작성자 가나다순, 다시 전체로 돈다

## 1.1.0 (2026-11-01)

- 항목의 업무 주소(`board.ts set --task <URL>`)가 있으면 제목의 업무 번호(「#342」)를 그 주소의 링크로 그린다
- 열린 PR 목록과 펼친 보기의 PR 번호를 GitHub PR 링크로 그린다
- 링크는 「[두레이 #342]」, 「[PR #877]」 처럼 머리말과 함께 대괄호로 감싸고, 밑줄과 색(업무 청록, PR 자주)으로 가린다. worker 줄의 PR 번호도 「PR #877」 로 적는다

## 1.0.1 (2026-10-30)

- 질문 payload 가 객체여도 dispatch 와 본문을 읽는다. 끝난 dispatch 의 질문을 결정 필요에서 빼고 재전송 질문은 최신 하나로 묶는다
- worker 목록을 모든 페이지에서 읽고 `pending`, `running` 상태도 진행 중으로 보여 준다

## 1.0.0 (2026-10-28)

- `u` 보드 갱신 버튼이 실제 상태를 대조하고 보드를 고치는 요청문을 입력란에 채운다
- 단계 끝의 `(#665 merge)` 같은 사건 꼬리표를 읽으며, 창에서는 꼬리표를 숨긴다
