상품 조회 캐시의 만료 정책: 고정 TTL 과 이벤트 무효화 비교

고정 TTL 5분을 유지하고, 가격이 바뀔 때만 이벤트로 지운다.

[D1] 같은 표시는 맨 아래 「출처」 의 항목으로 이어진다. 원문으로 확인하지 못한 내용에는 추정 을 달았다.

1권장안

1 고정 TTL 5분은 그대로 둔다.

조회의 대부분은 5분 낡은 값이어도 문제가 없다 [D1]. 만료를 줄이면 DB 조회가 늘어난다.

2 가격이 바뀔 때만 이벤트로 바로 지운다.

가격은 낡으면 주문 금액이 틀린다. 변경 이벤트가 이미 있어 구독만 더하면 된다 [D2].

2선택지 비교

세 방식을 정확도, 비용, 구현 난이도로 비교했다. 노란 줄이 권장안이다.

예 충족 일부 조건부 아니오 미충족 미확인 확인하지 못함. 표는 옆으로 밀어서 본다.

3바꾸는 순서

  1. 가격 변경 이벤트를 구독한다

    상품 서비스의 price-changed 토픽을 읽는 consumer 를 하나 더한다.

  2. 해당 상품의 캐시 키를 지운다

    키는 product:{id} 하나라 범위 삭제가 필요 없다.

  3. 지운 횟수를 지표로 남긴다

    무효화가 몰리는 시간대를 보고 TTL 을 다시 정한다.

이벤트가 늦게 오면 그 사이에는 낡은 가격이 보인다. 주문 시점에는 캐시가 아니라 DB 의 가격으로 다시 계산한다.

용어

TTL
저장한 뒤 정해진 시간이 지나면 저절로 지워지는 만료 시간.
이벤트 무효화
원본이 바뀌었다는 메시지를 받아 캐시를 바로 지우는 방식.

4선택지별 상세

고정 TTL 만

장점

  • 코드 변경이 없다.

단점

  • 가격이 최대 5분 낡는다 [D1].
이벤트 무효화 만
  • 재고, 설명, 이미지 변경까지 모두 구독해야 한다 추정: 변경 종류 6개.

5남은 질문

  • 가격 이벤트가 하루에 몇 건 오는지. 지표가 없어 확인하지 못했다.
