# CHANGELOG: docs-check

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준과 쓰는 형식은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 3.6.0 (2026-10-28)

- `scripts/run_static_check.py` 가 정적 검사를 돌리고 종료 코드와 판정을 표로 낸다. 2단계가 이 스크립트를 부른다
- ADR 색인 검사가 `[001-slug.md](...)` 처럼 파일 이름을 링크 문구로 쓴 형식을 인식한다. 이 형식이면 모든 ADR 이 「본문에만 있다」 로 나오던 오탐을 고쳤다
- 모노레포 판정을 `planning/scripts/overlay_paths.py --skill docs-check` 호출로 바꿨다
- 「조사를 나눠 맡긴다」 에서 Agent 도구 설명과 겹치는 지시를 줄였다

## 3.5.1 (2026-10-25)

- README 를 스킬을 쓰는 사람 관점으로 다시 쓰고, 이 CHANGELOG 를 버전마다 핵심만 남기도록 줄였다. 동작은 바뀌지 않았다

## 3.5.0 (2026-10-24)

- ADR 색인 검사가 ADR 디렉터리의 하위 폴더까지 읽는다. 대체된 ADR 을 하위 폴더로 옮겨도 「INDEX.md 에만 있다」 로 판정하지 않는다
- 대체된 ADR 의 위치와 링크, 색인 갱신은 planning 의 `task-create.md` 규약을 따른다

## 3.4.0 (2026-10-23)

- `static_check.py` 가 `docs/code-architecture.md` 의 책임 설명에 괄호로 셋 이상 늘어놓은 목록을 `WARN LISTED_ITEMS` 로 낸다
- 경고는 종료 코드를 바꾸지 않고 리포트의 `Warning` 후보로 오른다

## 3.3.0 (2026-10-12)

- 검사기의 오탐은 그 자리에서 고치지 않고 위치와 근거를 리포트에 적는다. 검사기 수정은 별도 작업으로 넘긴다

## 3.2.2 (2026-10-05)

- 완료된 계획서의 기본 완료 기준을 운영 반영에서 구현 PR 머지로 바꿨다

## 3.0.0 (2026-09-24)

- 호환성: 「독립 검토」 단계를 없애 단계가 6에서 5로 줄고, 뒤 단계 번호가 하나씩 당겨졌다
- 수정과 재검증 단계에서 실행한 명령과 결과를 함께 보고하고, 일부만 확인했으면 그 범위를 적는다
- `static_check.py` 는 메인이 직접 실행한다

## 2.x

- 실행 절차를 단계마다 통과 조건이 있는 6단계로 정하고, 범위 판정에서 각 문서가 무엇을 담는지 함께 정한다
- 정적 검사를 `scripts/static_check.py` 로 옮기고 앵커 링크도 검사한다. 한글 이름 문서가 검사에서 빠지던 문제를 고쳤다
- `status: superseded` 인 ADR 에는 부패 축과 자명성 축을 적용하지 않는다
- 구현이 끝난 `tasks/` 의 계획서를, 그 결정이 `docs/` 나 ADR 에 남았을 때 제거 후보로 판정한다
- 문서가 계획서를 번호로 가리킨 자리를 `PLAN_REF` 로 찾는다
- 조사를 읽기 전용 하위 에이전트에게 나눠 맡기고, 회신 형식을 리포트의 발견 하나와 같게 받는다
- 표 열 수 검사가 이스케이프된 `\|` 를 열 구분자로 세던 오탐을 고쳤다
- `static_check.py` 를 스킬 번들 경로로 불러, 상대 경로로 불러 종료 코드 2 로 멈추던 문제를 고쳤다

## 1.x

- 버전 체계를 도입했다
- 정적 검사가 미추적 신규 문서와 공백이 든 파일 이름도 검사한다
- 링크 검사가 `dooray://` 같은 앱 스킴과 `/` 로 시작하는 경로를 건너뛴다
- ADR Index 동기화가 본문은 헤딩의 번호만, INDEX 는 표형과 목록형의 등재 항목만 센다. `INDEX.md` 가 없으면 검사하지 않는다
- ADR 줄 수로 과대화를 판정하던 검사를 없앴다. 과대화는 의미 검사가 판정한다
- 범위를 주지 않으면 현재 경로와 변경 파일에서 가장 좁은 범위를 고르고, 정적 위반이 있으면 종료 코드 1 을 낸다
