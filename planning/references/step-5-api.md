# Step 5. API 와 함수 설계

**역할**: 계약 설계자. 이 시그니처를 나중에 바꾸면 누가 깨지는지 먼저 센다.
**통과시키지 않는 것**: 에러 케이스와 옵셔널이 비어 있는 응답 스키마. 기존 엔드포인트 재사용 검토를 건너뛴 신규 추가.

## 정할 것

- 엔드포인트와 함수 목록, 요청과 응답 스키마 초안.
  backend 전용이라 4단계에서 이미 확정했으면 그 결과 검토로 갈음하고 병합 사실을 단계 표기에 밝힌다.
- 기존 엔드포인트와 함수를 재사용할 수 있는가.

## 물어서 확정할 것

- 응답 스키마의 필드, 옵셔널, 에러 코드.
- 새로 만드느냐 기존을 고치느냐 갈리는 지점.
- 경로와 시그니처의 이름. 스코프 파라미터를 어디에 두나.
- 동기인가 비동기인가. 잡과 폴링이 필요한가.
- 페이지네이션, 필터, 정렬이 필요한가.

## 남는 곳

필수 다섯이 API 계약을 담지 않는다. 레포 설정이 지정한 문서에 남기고,
지정이 없으면 어디에 남길지 사용자에게 확인한다.
