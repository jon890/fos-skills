# docs-consolidate

검증한 기능의 문서를 맞추고 공통화할 만한 내용만 근거와 함께 남긴다. 모인 후보의 공통화는 별도 범위로 처리한다.

## 이럴 때 쓴다

- 기능 검증 뒤 공통 후보를 찾을 때
- 관련 기능 묶음의 문서를 공유 계약으로 정리할 때

## 사용 예시

> “이번 기능의 공통 후보를 추출해 줘.”
> 관련 문서를 대조해 후보와 차이를 PR 에 남긴다.

> “이 후보 둘을 공통 계약으로 정리해 줘.”
> 실제 의미가 같은지 확인하고 한곳으로 옮겨 참조로 연결한다.

## 모드

- 후보 추출: 기능 검증 뒤에 돈다. 문서를 대조하고 후보만 남긴다
- 공통화: 후보가 모였고 정리를 작업 범위로 지정했을 때만 돈다. 규칙을 한곳으로 옮긴다

모드마다 실행 시점과 통과 조건이 달라 `SKILL.md` 에 표를 따로 둬요.

## 받는 것

- 기능 문서 대조 결과
- 공통화 후보와 근거 또는 후보 없음
- 공통화 모드에서는 문서 변경과 채택·보류·기각 결과
- implementation·review-fix 가 적은 반복 실패 후보를 저장소 규칙으로 옮긴 결과 (공통화 모드)

## 함께 쓰는 스킬

- `verify`: 스펙과 구현의 일치 확인
- `implementation`, `review-fix`: 반복될 실패를 후보로 적는다. 규칙 파일로 옮기는 일은 이 스킬이 한다
- `docs-audit`: 일반 문서 감사
- `orch`: 실행 시점과 별도 PR 조율
