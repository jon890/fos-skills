# 스킬 피드백 반영 루프 기술 설계

## 요구사항 연결

| ID | 해결 방법 |
| --- | --- |
| REQ1 | `lib/feedback.ts`가 대상 칸을 소유한다. 새 파일은 필수 `--target`을 검사하고, 옛 파일은 `확인 필요`로 읽는다. |
| REQ2 | `feedback collect`가 `orca repo list`의 저장소별 후보를 읽어 대상·상태·PR 결과에 따라 묶는다. 읽기 전용이다. |
| REQ3 | 판정 문서에 core 필요 여부를 첫 기준으로 둔다. doctor는 저장소 몫만 센다. fos-skills에서는 모든 core 몫도 센다. |
| REQ4 | `feedback notify`가 반영 PR과 버전 커밋을 확인하고 원래 파일의 상태를 바꾼다. |
| REQ5 | 상태 변경 후 `findMain`과 `notifyRun`으로 저장소별 메시지 한 통을 보낸다. 성공하면 해당 파일을 휴지통으로 옮긴다. |
| REQ6 | doctor가 남은 반영·기각 알림을 출력한 뒤 휴지통으로 옮긴다. 저장소 몫 `채택 #PR`은 원래 저장소 PR 머지를 확인한다. |
| REQ7 | PR2 범위다. PR1의 조회 결과를 이후 보드 개수 계산에 재사용한다. |
| REQ8 | 기존 `채택 #PR`을 읽고 새 알림 흐름에 넣는다. |

## 책임과 경계

`lib/feedback.ts`는 파일 형식과 상태를 소유한다. `feedback/feedback-candidates.ts`는 CLI 인자와 모아 보기·알림 보내기를 소유한다. `doctor/orch-doctor.ts`는 현재 저장소에 남은 알림 표시와 정리를 소유한다. 후보 파일은 원래 저장소의 `.orch/feedback/`에 남는다. 다른 저장소의 코드나 설정을 고치지 않는다.

| 대상과 상태 | 모아 보기 | 처리 주체 |
| --- | --- | --- |
| core 스킬·확인 필요의 후보·보류 | 판정할 core 후보·보류 | fos-skills 세션 |
| core 스킬·확인 필요의 채택 | 보낼 알림·버전 대기·PR 머지 대기·닫힌 PR·조회 실패 | `feedback notify`는 버전이 오른 경우만 처리 |
| core 스킬·확인 필요의 기각 | 받은 알림 또는 대표 후보 결과 대기 | `feedback notify`가 메시지를 보내고 doctor가 남은 알림 처리 |
| 이 저장소의 후보·보류·채택·기각 | 저장소 몫 | 원래 저장소 세션의 판정과 doctor |
| 반영됨 | 받은 알림 | 메인이 있으면 `feedback notify`, 없으면 원래 저장소 doctor |

## 인터페이스와 데이터

새 파일에는 `- 대상: core 스킬` 또는 `- 대상: 이 저장소`를 스킬 칸 다음에 둔다. 대상 칸이 없는 기존 정규 파일은 읽을 때만 `확인 필요`를 채운다. 저장할 때에는 칸을 보존한다. 상태는 기존 `후보`, `보류(이유)`, `채택 #PR`, `기각(이유)`와 새 `반영됨 #PR (버전)`을 읽는다. 기각의 이유가 `중복: <후보 이름>`이면 같은 저장소의 대표를, `중복: <저장소 이름>/<후보 이름>`이면 다른 저장소의 대표를 가리킨다. 대표가 휴지통으로 옮겨진 뒤에는 기본 휴지통 또는 명령의 `--trash` 폴더에서 결과를 읽는다.

`orch feedback collect`는 묶음별로 `저장소\t대상\t상태\t제목`을 낸다. 묶음은 표의 분류와 같다. 폴더가 없으면 건너뛰며 읽기 실패는 `READ-FAIL`에 저장소와 이유를 낸다. PR 조회나 git·버전 파일 읽기에 실패하면 `조회 실패`로 보이고, 정상적으로 확인했지만 아직 버전 변경이 없을 때만 `버전 대기`로 보인다. `orch feedback notify`는 처리한 후보와 전송·휴지통 결과를 낸다. 사용법 오류는 종료 코드 2, 저장소 목록 자체를 못 읽으면 1, 저장소별 조회·전송 실패는 해당 저장소를 표시하고 다른 저장소는 계속 처리한다.

core PR은 fos-skills 저장소에서 `gh pr view`로 본다. 저장소 몫 PR은 원래 저장소 doctor가 확인한다. core PR의 merge commit이 현재 `main`에 있고, 그 뒤 `.claude-plugin/plugin.json`의 version 값이 실제로 바뀐 첫 커밋이 `main`에 있으면 그 버전을 사용한다. 단순히 현재 버전만 읽으면 PR보다 앞서 배포된 버전을 잘못 알리므로 commit 순서를 비교한다. 닫혔으나 머지되지 않은 PR과 조회 실패는 각각 따로 묶어 재판정한다.

## 실패와 일관성

알림을 놓치지 않도록 파일 상태를 먼저 원자적으로 바꾸고 메시지를 보낸다. 전송 실패나 메인 부재 시 파일을 남겨 doctor가 보여 준다. 전송 성공 후 휴지통 이동이 실패하면 재실행 때 중복 메시지 가능성이 있으므로 파일 단위 결과에 오류를 표시한다. 휴지통 목적지는 기본 `~/.Trash/orch-feedback/`이며 같은 이름이 있어도 기존 파일을 덮지 않는다. 모아 보기는 어떤 파일도 바꾸지 않는다. doctor는 출력 후에만 옮긴다.

## 검증 전략

파일 파서·CLI 테스트에서 필수 대상, 옛 파일 호환, 상태 전이를 확인한다. 가짜 Orca·gh·git을 사용하는 명령 테스트에서 저장소 분류, 버전 순서, 닫힌 PR, 조회 실패, 중복 후보, 메시지 실패와 재시도를 확인한다. doctor 테스트에서 저장소별 개수와 출력 뒤 휴지통 이동을 확인한다. 전체 저장소 검증도 실행한다.
