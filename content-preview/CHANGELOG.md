# CHANGELOG — content-preview

버전은 `SKILL.md` frontmatter 의 `metadata.version` 과 같은 값을 쓴다.
올리는 기준은 저장소 README 의 "버전과 변경 이력" 을 따른다.

## 1.5.0

- **미리보기를 띄우는 경로의 묻혀버린 실패를 없앴다.**
  - AppleScript 가 파일 이름만으로 탭을 찾아, `preview.html` 처럼 흔한 이름이면 다른
    디렉터리의 탭을 갱신하고 앞으로 가져왔다. 전체 `file://` 주소로 대조한다.
  - `xdg-open` 이 실패해도 `set -e` 로 아무 메시지 없이 끝났다. macOS 경로처럼 분기한다.
  - 탭 id 파일을 쓰지 못하면 탭은 열린 채로 조용히 죽었다. 알리고 계속한다.
- **`scripts/export-to-team.sh` 에 방향 보호를 넣었다.**
  팀 쪽 버전이 더 높으면 내보내지 않고 종료 코드 3 으로 끝난다.
  이 저장소가 원본이라는 전제는 이쪽이 뒤처지지 않았을 때만 성립하는데, 검사가 없어
  팀에서 직접 고친 내용을 옛 버전으로 되돌릴 수 있었다. `--apply` 외의 인자도 거부한다.
- **`scripts/install-hooks.sh` 가 워크트리에서 죽지 않는다.**
  워크트리의 `.git` 은 디렉터리가 아니라 파일이라 `mkdir -p .git/hooks` 가 실패했다.
  `git rev-parse --git-common-dir` 로 경로를 받고, 링크 대상도 워크트리가 아닌
  원본 체크아웃으로 잡는다. `.git/hooks` 는 워크트리끼리 공유하기 때문이다.
- `*.tabid` 를 `.gitignore` 에 넣었다. 저장소 안에서 미리보기를 만들면 쌓였다.

## 1.4.0

- **개인 문체 참조를 스킬 밖 `~/.claude/references/` 로 내보냈다.**
  스킬이 참조를 소유하면 스킬을 옮기거나 심링크를 다시 걸 때 경로가 꼬이고,
  저장소가 개인 파일을 무시하는 규칙을 따로 들고 있어야 한다.
  `~/.claude/rules/` 에는 두지 않는다. 하네스가 그 디렉터리를 전역 지침으로 무조건 읽어
  글을 쓰지 않는 세션에도 전문이 실린다 (실측).
- **Dooray 생성기에 `--mode` 를 넣었다.** 업무 본문과 댓글은 화면에서 머리가 다르다.
  `task` 는 프로젝트와 제목과 태그를, `comment` 는 작성자 아바타와 이름을 그린다.
- **Dooray 본문을 다른 렌더러로 미리 보지 않는다는 것을 명시했다.**
  marked 계열은 한 문장씩 줄을 나눈 본문을 한 문단으로 붙이고 TOAST UI 는 줄을 살린다.
  범위 표기의 물결표도 marked 만 취소선으로 읽는다 (실측).
- **`orca` 백엔드가 다른 워크트리에 만든 탭을 갱신 대상에서 뺐다.**
  조사하느라 다른 저장소로 `cd` 한 뒤 띄우면 `갱신` 이라고 출력돼도 사용자 화면은
  그대로였다 (실측). `ORCA_WORKTREE` 를 고정한 경우 탭의 워크트리를 대조한다.
  새로 열 때는 `탭 위치:` 한 줄로 어디에 열렸는지 알린다.

## 1.3.1

- 드라이버 경로 기본값을 `~/.claude/scripts/browser-driver` 로 바꾼다.
  드라이버가 셸 스크립트에서 Python 한 파일로 바뀌면서 확장자 없는 이름이 정본이 됐다.
  `browser-driver.sh` 링크도 남아 있으므로 재설치 전에도 깨지지 않는다.
  환경 변수 이름도 `BROWSER_DRIVER` 로 맞춘다.

## 1.2.0

- **에이전트 IDE 안의 브라우저에서도 미리보기를 갱신한다.**
  AppleScript 가 Chrome 계열과 Safari 만 훑어, IDE 안의 탭을 찾지 못했다.
  재생성할 때마다 탭이 쌓이고 사용자가 오래된 본문을 읽고 판단하는 상태가 그대로 남았다.
  `browser-driver` 가 있으면 그것을 먼저 쓴다. 백엔드 판단을 드라이버에 맡기고
  돌려받은 page id 를 HTML 옆에 남겨 다음 실행이 같은 탭을 다시 쓴다.
- **묻혀버린 실패를 걷었다.** `open` 이 실패해도 "새로 열었다" 로 보고해 열리지 않은 것을 알 수 없었다.
- **개인 문체 참조를 배포에서 뺐다.** 문체는 사람마다 다르므로 사본을 내려보내는 저장소에서는 제외한다.
  참조가 없으면 그 항목을 건너뛰는 동작은 그대로다.
- 자가 점검에 강조 대체와 분량 구간 판단을 넣었다. 댓글에 헤더를 넣지 말라던 옛 지시를 걷어냈다.

## 1.1.0

- **미리보기를 띄우는 `scripts/show-preview.sh` 를 추가하고 브라우저 직접 호출을 걷어냈다.**
  에이전트 브라우저에 탭을 만들면 사용자 화면에 드러나지 않아, 미리보기를 찾지 못하는 일이 실제로 났다.
  미리보기는 사람이 읽어야 하는 산출물이라 기본 브라우저로 띄운다.
  본문을 고쳐 재생성할 때마다 같은 파일의 탭이 쌓이는 문제도 있었다.
  사용자가 오래된 탭을 새 본문으로 읽고 판단할 수 있다.
  스크립트는 같은 파일의 탭을 찾아 갱신하고 앞으로 가져오며, 없을 때만 새로 연다.
  macOS 는 Chrome 계열과 Safari 의 탭을 갱신하고, 그 밖의 환경은 `xdg-open` 으로 새로 열며 그 사실을 알린다.
- SKILL.md 에 「화면에 띄우기」 절을 넣었다. 출력이 `갱신` 인지 `새로 열었다` 인지 확인하라는 지시를 담았다.

## 1.0.0

- **`~/.claude/skills/` 아래의 개인 폴더에서 이 저장소로 옮겼다.** 저장소에 들어간 적이 없어
  다른 스킬처럼 승격 흐름을 타지 못했고, `dooray-task` 와 `create-pr` 이 이 skill 을 가리키기
  시작하면서 팀원 환경에서는 따라갈 대상이 없는 참조가 됐다.
- **HTML 생성기를 `~/.claude/templates/` 에서 skill 번들 안 `scripts/` 로 흡수했다.**
  생성기 호출이 절대경로여서 스킬만 배포하면 팀원 환경에서 반드시 깨진다.
  `Path(__file__).parent` 로 템플릿을 찾으므로 폴더째 옮겨도 동작은 같다.
  승격을 막던 근거로 적혀 있던 "brain-add 와 공유 중" 은 사실이 아니었다.
  brain-add 는 자기 `generate_preview.py` 를 갖고 있고 주석에서 구조만 참고한다.
- SKILL.md 의 승격 메모 절을 지웠다. 승격이 끝나 더 이상 지시할 것이 없다.
