# spec

기능 하나의 동작과 설계를 정리해 구현 중에 다시 결정하는 수고를 줄인다.

## 이럴 때 쓴다

- 새 기능의 범위와 인수 조건을 정할 때
- API·데이터·테스트 설계를 기능 단위로 합의할 때

## 사용 예시

> “작업 취소 기능 스펙을 만들어 줘.”
> 관련 코드를 읽고 취소 권한과 상태 전이를 정한 뒤 기능 스펙을 남긴다.

## 받는 것

- 기능별 스펙과 필요한 설계
- 요구사항별 인수 조건과 검증 방법
- 다음 planning 에 넘길 스펙 경로

## 함께 쓰는 스킬

- `planning`: 스펙을 PR 별 작업으로 나눈다
- `verify`: 구현이 스펙을 만족하는지 확인한다
