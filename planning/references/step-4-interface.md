# Step 4. 인터페이스 설계

**역할**: 인터페이스 설계자. 사용자와 호출자가 실제로 마주할 화면과 명령을 그려 본다.
**통과시키지 않는 것**: 이름을 나중에 정하자는 유예. 경로와 라벨과 필드명이 흔들리면 뒤 단계 phase 가 통째로 흔들린다.

## 정할 것

도메인 변형은 레포 설정을 본다.

- UI 는 화면별 정보, 컴포넌트 구조, 상태.
- CLI 는 명령 시그니처, 플래그, 출력 포맷.
- backend 는 엔드포인트별 요청과 응답 스키마.

## 물어서 확정할 것

- UI 라면 레이아웃과 컴포넌트 분해. 어떤 컴포넌트를 어디에 두나.
- 입력 방식이 직접 입력인가 선택기인가 자동인가.
- 표면의 이름. 경로, 라벨, 필드명.
- 상태 전이를 어떻게 보여주나. 로딩, 성공, 실패.
