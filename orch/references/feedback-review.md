# 스킬 개선 후보 다시 보기

worker 가 공통 지시서의 「스킬 개선 후보 보고」 절을 따라 쌓은 후보를 코디네이터가 다시 보고, 고칠 것만 골라 사용자에게 올리는 절차다.
모으기만 하고 다시 보지 않으면 같은 후보가 쌓이기만 하고, 다시 볼 때마다 기준이 달라 같은 후보가 개선 필요와 제외를 오간다.

## 후보 파일

후보는 `<orch 루트>/feedback/` 바로 아래의 `.md` 파일 하나가 워크트리 하나의 메모다. 공통 지시서의 `{{FEEDBACK_DIR}}` 를 이 폴더로 채운다.
`README.md` 는 후보가 아니다. 다시 보기를 마친 파일은 `feedback/reviewed/` 로 옮긴다. 폴더 바로 아래에 남은 파일이 열린 후보다.

## 주기

**`orch-doctor` 가 `FEEDBACK-OPEN <개수> <폴더>` 를 내면 그날 안에 다시 본다.** 스킬을 열 때마다 doctor 가 열린 후보 파일 수를 센다.
여러 worker 의 머지가 끝난 뒤처럼 후보가 한꺼번에 늘어난 때에도 본다. 다음 worker 가 같은 함정에 다시 빠지기 전에 고칠 것을 정하려는 것이다.

## 판정

후보마다 근거(파일과 줄, 로그, 재발 기록)를 지금 설치본과 대조한 뒤 셋 가운데 하나로 정한다.

| 판정 | 조건 |
| --- | --- |
| 개선 필요 | 아래 세 기준을 모두 채운다 |
| 보류 | 원인이나 재발 근거가 부족해 세 기준을 판정할 수 없다 |
| 제외 | 세 기준 가운데 하나라도 채우지 못하거나, 지금 설치본에서 이미 고쳐졌다 |

세 기준은 공통 지시서 틀이 worker 에게 시키는 것과 같다.

- **유의미하다:** 고치면 다음 작업의 시간이나 실패가 실제로 준다. 한 번 겪고 끝날 일과 취향 차이는 아니다
- **단순 함정이 아니다:** 오타, 일시적인 네트워크나 권한 문제, 그 작업에만 있던 사정이 아니다
- **구조로 막을 수 있다:** 스크립트, 검사기, 명령 한 줄, 문서 구조로 다시 일어나지 않게 할 수 있다. 「주의한다」 는 문장으로만 막히면 아니다

**추정만으로는 개선 필요나 제외로 정하지 않고 보류로 둔다.** 보류에는 다시 볼 조건(같은 일이 한 번 더 나면, 앞 개선이 머지되면)을 한 줄 적는다.
보류한 후보는 그 조건이 채워진 다음 다시 보기에서 판정한다. 근거 없이 개선 필요로 올리면 쓰지 않을 코드가 늘고, 제외하면 같은 실패가 되풀이된다.

## 올리기와 반영

개선 필요는 스킬과 저장소로 나눠 사용자에게 한 번에 올린다. 같은 스킬의 후보는 PR 하나로 묶을 수 있게 모은다.
판정마다 근거를 붙인다. 사용자가 고른 것만 지시서로 써서 worker 에게 맡긴다. 스킬 파일은 후보를 쓴 worker 가 아니라 그 지시서를 받은 worker 가 고친다.
판정을 마친 후보 파일은 `feedback/reviewed/` 로 옮긴다. 보류한 후보는 파일을 그대로 두어 다음 다시 보기의 열린 후보로 남긴다.
