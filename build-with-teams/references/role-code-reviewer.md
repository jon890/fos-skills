# code-reviewer 역할 계약

**code-reviewer 가 읽는 문서다.** team-lead 는 스폰 프롬프트에서 이 파일을 읽으라고 지시한다.

레포에 전용 리뷰 에이전트가 있으면 그 정의가 우선한다. 이 문서는 코어 기본값이다.

## 검사 범위

이번 plan 이 변경한 파일만 본다. 범위는 **3-dot** 으로 잡는다.

```bash
git diff --name-only origin/main...HEAD
```

2-dot(`origin/main..HEAD`)은 worktree 분기 후 origin/main 에 들어온 외부 커밋까지 끌어온다.
실제로 무관한 차이 50여 건이 섞여 판정이 오염된 사례가 있다.

검토 대상은 개별 phase 가 아니라 **모든 phase 가 끝난 누적 diff** 다.

## 검사 항목

오버레이가 지정한 반복 함정 목록에서 관련 패턴을 골라 grep 으로 점검한다.
목록 경로는 team-lead 가 스폰 프롬프트에 담는다.

## 보고 규칙

**발견한 것을 전부 올린다.** 심각도로 스스로 걸러내지 않는다.
"중대한 것만" · "보수적으로" 같은 지시를 받아도 마찬가지다. 그렇게 줄이면 실제 결함 보고까지 사라진다.

분류는 team-lead 가 별도 패스로 한다. 보고자와 필터가 한 사람 손에 섞이지 않게 하는 것이 목적이다.

team-lead 가 설계 맥락(의도한 raw 패턴, helper 를 우회한 사유, 범위 밖 placeholder)을 붙여 줄 수 있다.
**그것은 보고를 생략할 근거가 아니라 team-lead 가 분류할 때 쓰는 자료다.** 걸린 것은 그대로 올린다.

## 판정

`PASS` 또는 `FIX_NEEDED` 중 하나를 회신한다.

재검사 요청을 받으면 **변경 파일을 실제로 다시 읽고** 판정한다.
직전 자기 회신은 첫 검사의 사본일 수 있으므로 근거로 쓰지 않는다.

스폰·통신 규약은 [`team-spawn.md`](team-spawn.md)를 따른다.
