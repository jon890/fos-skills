# ADR 규칙

「원칙 대조」와 「설계 문서」 단계에서 ADR 을 만들거나 대체할 때 읽는다.
ADR 을 남길 조건, 양식 쓰는 법, 대체와 이동 규약을 이 문서가 소유한다(사용자 결정 2026-11-05). 새 ADR 의 항목은 [ADR 양식](../templates/adr.md)이 정한다.
`plan` 과 `docs-audit` 는 이 문서를 가리킨다.

## 남길 조건

**ADR 은 아래 둘 중 하나를 만족할 때만 남긴다.**

- 되돌리는 비용이 크다. 지금 바꾸면 이미 쓴 코드나 데이터를 함께 바꿔야 한다.
- 시스템의 핵심 개념을 정한다. 자료 구조, 동기와 비동기, 동시성 전략, 트랜잭션 경계다.

둘 다 아니면 남기지 않는다. 라이브러리나 제품 선택은 교체 비용이 커도 핵심 개념을 바꾸지 않으면 ADR 이 아니다.
그런 것을 쌓으면 정작 구조를 정한 결정이 목록에서 묻힌다.
장기 기술 결정이 없으면 빈 ADR 을 만들지 않는다.
도메인 정책을 고른 이유는 ADR 에 둘 수 있지만, 지금 따를 규칙과 기준값의 원본은 ADR 이 아니라 도메인 문서다. 경계는 [문서 소유권의 「ADR 과 도메인 문서」](../../spec/references/document-ownership.md#adr-과-도메인-문서)가 정한다.
ADR 목록처럼 여러 plan 이 함께 고치는 색인 파일은 끝에 덧붙여, 동시에 도는 다른 plan 과 같은 줄을 고치지 않는다.

## 구조

파일명은 `docs/adr/NNN-<슬러그>.md` 다. 한 파일에 결정 하나만 담는다.
여러 에이전트가 동시에 PR 을 여는 저장소는 파일 이름과 색인을 [`adr-parallel.md`](adr-parallel.md) 로 정한다.

새 문서는 [ADR 양식](../templates/adr.md)을 읽고 쓴다. 기존 ADR 양식이 있으면 우선한다.

확정한 ADR 의 `status` 는 둘뿐이다. 승인 전 초안은 현재 결정으로 읽지 않고, 기술 설계에서 합의한 뒤 확정한다.

| 값            | 뜻                              |
| ------------ | ------------------------------ |
| `accepted`   | 현재 유효하다                        |
| `superseded` | 다른 ADR 이 이 결정을 뒤엎었다. 이력으로만 읽는다 |

`status` 가 없는 기존 ADR 은 `accepted` 로 읽는다.

**결과** 는 결정한 뒤에 생기는 트레이드오프를 적는다. 얻는 것과 감당할 것을 둘 다 적는다.

## 대체와 이동

**ADR 은 지우지 않는다.**
결정 전체가 번복돼도 `status` 를 `superseded` 로 바꾸고 `대체된 부분` 에 대체한 ADR 을 가리킨다.
지우면 그때 그 판단을 왜 했는지가 사라진다.

- `superseded` 로 바꾼 파일은 `docs/adr/superseded/` 로 옮긴다. 파일 이름과 번호 또는 날짜 식별자는 바꾸지 않는다.
  현행 결정과 대체된 결정을 폴더만 보고 구분하려는 사용자 결정(2026-10-24)이다.
- 같은 변경에서 그 파일을 가리키는 상대 링크를 모두 고친다. 다른 ADR, docs, 코드 주석, README 와 옮긴 ADR 안의 상대 링크도 확인한다.
- 색인 파일(`INDEX.md` 등 저장소가 쓰는 것)은 「현행」 과 「대체됨」 으로 나눠 적는다.
- 일부만 대체돼 `accepted` 이면서 `대체된 부분` 이 있는 ADR 은 옮기지 않는다.
- `대체된 부분` 은 **결정 바로 아래**에 둔다. 결정만 읽고 지나가는 독자가 낡은 결론을 얻는 것을
  막는 것이 목적이라, 문서 끝이나 대안 기각 안에 넣으면 의미가 없다.
- 대체한 쪽 ADR 에서도 원본을 링크해 양방향으로 찾을 수 있게 한다.
- 전체가 대체된 ADR 은 남은 본문 앞에 그것이 당시의 맥락임을 한 줄로 밝힌다.
- 코드와 경로는 결정을 가리키는 데 필요한 만큼만 인용한다. 구현 호출 방법, 작업 내역,
  스택 규칙 반복은 넣지 않는다. 결정과 근거만 남긴다.
- 계획서 번호를 적지 않는다. ADR 은 계획서보다 오래 남으므로 [plan 의 「계획서를 가리키지 않는다」](../../plan/references/task-create.md#계획서를-가리키지-않는다)를 따르고, 근거는 다른 ADR 번호나 PR 번호로 적고 부족하면 내용을 본문에 옮긴다.

## 대체한 뒤 검사

ADR 을 대체한 뒤 위치와 저장소 Markdown 의 ADR 상대 링크를 검사한다. 종료 코드 0 이어야 한다.
검사기는 plan 번들에 있다. `$PLAN_SKILL_DIR` 은 plan 스킬 번들 경로이고, `$ADR_DIR` 은 오버레이가 정한 ADR 경로다. 지정이 없으면 `docs/adr` 다.

```bash
# cwd: 타깃 레포 root
python3 "$PLAN_SKILL_DIR/scripts/check_adr_layout.py" "${ADR_DIR:-docs/adr}"
```

오버레이가 「superseded 폴더 사용 안 함」 으로 정한 저장소(대체된 ADR 을 `docs/adr` 에 그대로 두고 색인으로 구분)는 `--flat` 을 붙인다.
`--flat` 은 폴더 위치와 `status` 검사를 건너뛰고 링크 검사만 한다. 오버레이가 정하지 않았으면 붙이지 않는다.

```bash
# cwd: 타깃 레포 root
python3 "$PLAN_SKILL_DIR/scripts/check_adr_layout.py" "${ADR_DIR:-docs/adr}" --flat
```

코드 주석의 링크와 색인의 「현행」·「대체됨」 구분은 변경 diff 에서 확인한다.
