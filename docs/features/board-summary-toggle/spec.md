# 보드 창: 항목 아래 요약 줄을 눌러 그 항목의 목록만 펼치고 접는다

확인: 2026-11-17

## 목표

보드 창의 접힌 보기에서 항목 아래 요약 줄(「✓ n개」, 「남은 단계 n개」, 「✓ 끝난 worker N」)을 누르면 그 항목의 해당 목록만 펼쳐지고, 다시 누르면 접힌다.
지금은 `d` 로 모든 항목을 한꺼번에 펼쳐야 해서, 항목 하나의 남은 단계나 끝난 worker 를 보려 해도 창 전체가 길어진다.

- 배경: ai-analysis 코디네이터가 사용자 요청을 넘겼다(2026-11-17). 「기존 보드 화면의 다른 접기 동작을 따른다」 는 조건이 붙었다.
- 지금 동작: 접힌 보기는 끝낸 단계를 「✓ n개」, 남은 단계를 「남은 단계 n개」, 끝난 worker 를 「✓ 끝난 worker N」 한 줄로 줄인다. `d` 는 모든 항목을 함께 펼치고 접는다(`extensions/work-board/references/behavior.md` 의 「접힌 보기」, 「펼친 보기」, 「worker 줄 그리기」).
  `d` 의 상태는 창 메모리의 값 하나이고 처음에는 접혀 있으며 파일에 남기지 않는다(`extensions/work-board/hooks/register.js` 의 `expanded`).

## 범위

이번 범위:

- 접힌 보기의 세 요약 줄을 항목별로 펼치고 접는 단추로 바꾼다

범위 밖:

- `d` 의 전체 펼치기 동작과 펼친 보기의 모양. 그대로 둔다
- 펼침 상태를 파일에 저장하는 것
- 완료 칸과 결정 항목의 요약 줄. 지금처럼 `d` 로만 펼친다

### 책임과 경계

표시 동작은 `extensions/work-board/hooks/register.js` 한 파일이 소유한다. 보드 파일, 보드 명령, 데이터 형식은 바뀌지 않는다.
어떤 줄이 어느 단추에 속하는지는 새 순수 함수 `foldLists(rows)` 가 정한다. 끝낸 단계 줄과 남은 단계 줄만 돌려주고 렌더와 분리해 단위로 확인한다.
단추가 있는지는 두 조건을 모두 본다. 요약 수가 0 보다 크고 펼칠 줄이 하나 이상 있어야 한다. 요약 수는 `progress` 필드에서도 나서 줄이 없을 수 있고, 그때 눌러도 아무것도 안 보이는 단추를 만들지 않는다. 줄이 없으면 지금처럼 글만 그린다.

### 인터페이스와 데이터

- 상태: `let folded = new Set()`. 파일에 쓰지 않는다. 종류는 `done`, `todo`, `workers` 다.
- 단추 글: 접힘은 지금 요약 글 그대로(「✓ 2개」, 「남은 단계 1개」, 「✓ 끝난 worker 2」), 펼침은 그 글 뒤에 「 접기」(「✓ 2개 접기」)를 붙인다. 단계 단추 글 안의 띄어쓰기는 줄바꿈 없는 공백(U+00A0)을 쓰고, worker 단추는 보통 공백이다.
- 단계 요약 줄: 지금 단계 줄의 본문 Text 와 단추를 가로 Box(`flexWrap: 'wrap'`)에 둔다. 단추 사이는 「  ·  」 이다. 좁은 창에서 단추가 다음 줄로 넘어가도 본문이 줄바꿈된 뒷줄은 본문 열에서 시작한다.
- 지금 단계가 없으면(모두 끝남) 요약 줄은 「✓ n개」 단추 하나이고, 펼친 줄은 그 줄 위에 놓는다.
- 요약은 `itemView` 가 결정 항목에도 쓰므로 단추 여부를 `checkable` 로 가른다. 결정과 완료 항목은 글만 그린다.
- 끝난 worker: 접힘은 지금처럼 키 `wd` 줄 하나다. 펼침은 키 `wd` 줄(단추)을 두고 그 아래에 끝난 줄을 `wd-<번호>` 키로 그린다. 접으려면 누를 단추가 필요해서 줄이 아니라 단추 줄을 남긴다.
- 대상: 진행 중과 대기 항목(`checkable`)만. 완료 칸과 결정 항목은 지금 그대로다. 펼친 보기(`d`)는 그리지 않는다.
- 새 파일은 없다. 같은 id 의 항목이 사라졌다 다시 생겨도 단추가 없어지는 렌더에서 상태가 지워지므로 접힌 채 나온다.

### 실패와 일관성

해당 없음: 화면 안의 메모리 상태이고 파일, 네트워크, 동시 쓰기가 없다.
렌더 중 `folded` 를 지우는 것은 같은 렌더에서 읽는 값과 맞추려는 것이다. 지우는 일은 멱등이다.
