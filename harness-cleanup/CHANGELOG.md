# CHANGELOG — harness-cleanup

버전은 `SKILL.md` frontmatter의 `metadata.version`과 같은 값을 쓴다.
올리는 기준은 저장소 README의 "버전과 변경 이력"을 따른다.

## 2.2.0

`check_rename_drift.sh` 를 추가했다.

본문에서 절 이름·개념을 바꾸고 그것을 위임받은 참조 문서를 안 고친 경우를 잡는다.
이 저장소에서 네 번 반복된 실패이고, 요약본과 소유자 문서가 서로 다른 것을 지시하게 된다.
사람 눈으로는 안 잡혀서 매번 독립 검토가 발견했다.

만들자마자 죽은 검사였다 — diff 줄이 `-- **이름**` 형태라 마커를 두 겹 벗겨야 하는데
한 겹만 벗겨 양성 표본을 못 잡았다. 대조 표본으로 확인해 고쳤다.

## 2.1.0

**런타임 동작 변화** 감사 축을 추가했다.

모델 역량이 아니라 하네스 자체가 바뀌어 지침의 전제가 깨지는 경우다.
문서끼리 비교해서는 안 보이고, 동작을 재현하거나 공식 문서·도구 설명 원문을 읽어야 드러난다.

이번에 build-with-teams 를 감사하며 세 건을 겪었다.
팀원이 idle 뒤 스스로 종료한다는 전제, 스폰 인자 하나의 유무로 갈리던 우선순위 표,
기본값이 바뀌어 발동할 수 없게 된 폴백 가드다.
셋 다 산문만 읽어서는 정상으로 보였고 공식 문서와 대조해서야 드러났다.

기준점 확정 절에도 "모델 역량과 하네스 런타임 동작은 별개 기준점" 을 명시했다.

## 2.0.0

`adjust-harness`에서 이름을 바꾸고, 프로젝트에서 따로 자란 `harness-cleanup`을 흡수했다.
두 스킬의 절차가 거의 전부 겹치면서 트리거 키워드도 사실상 같아, 나란히 두면 어느 쪽이 뜰지 예측할 수 없었다.

- 문장으로만 있던 측정 지시를 실행 스크립트로 대체했다.
  줄 수 집계, 참조 무결성, 사실 대조, 중복 검출, 문서 명령 실행, 강제 여부 확인이다.
- 근거 등급 "도구 대체"를 주장만으로 승격하지 못하게 했다.
  `check_enforcement.sh`로 gitignore·린트 규칙·검증 grep·도구 제한 중 무엇이 실제로 막는지 판정한다.
  `lint`와 `grep`을 별도 모드로 나눴다 — 종료 코드 관례가 정반대라
  한 모드로 두면 "이미 막힌다"를 "안 막힌다"로 뒤집어 읽는다.
- 유지와 제거 조건을 `references/judgment.md`로 옮겼다.
  본문과 참조 파일이 같은 판정을 함께 소유하던 상태를 풀었다.
- 감사 축에 지시 충돌을 추가하고, 값 하드코딩에 개수·목록 복제를 넣었다.
- 목록을 지우기 전 단일 소스 여부를 판정하는 절차를 넣었다.
  복제를 전제한 기준이 유일한 출처인 표를 지운 사고가 근거다.
- 드리프트 검사를 개수 비교가 아니라 집합 비교로 만들게 했다.
  개수는 항목이 하나 늘고 하나 줄면 상쇄되어 통과한다.
- 대상에 하네스별 역할 정의와 공유 역할 계약을 넣고, 저장소 밖 symlink를 제외했다.
- 사용자 편집 되돌리기, 통째 덮어쓰기, 재작성 시 원본 요소 누락을 "하지 않을 것"에 명시했다.

## 1.0.0

하네스 문서를 현재 모델 역량과 실측 이력 기준으로 교정하는 첫 버전이다.

- 유지와 제거 판정을 근거 등급과 분리했다.
- 실측 사례가 있는 여섯 감사 축을 정했다.
- 감사 흐름을 측정부터 재측정까지 순서로 고정했다.
- 프로젝트 일반 문서의 코드 정합성을 다루는 `docs-check`와 대상을 분리했다.
