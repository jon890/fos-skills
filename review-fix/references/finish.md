# 마무리

「마무리」 단계에서 읽는다. resolve, 규칙 반영, 결과 보고를 이 순서로 한다.

## 리뷰 스레드 resolve

명령과 종료 코드는 `SKILL.md` 의 「마무리」 단계가 소유한다.

resolve 는 「이 지적을 처리했다」 는 표시다.
반영했거나 반영하지 않기로 판단하고 그 판단을 회신한 스레드만 resolve 한다.

resolve 한 뒤 보호 규칙이 풀렸는지 본다.

```bash
gh pr view "$PR" --json mergeStateStatus
```

## 반복될 지적을 저장소 규칙으로 옮긴다

fix 가 끝났다고 항상 옮기지 않는다. **같은 실수가 다른 코드에서도 날 수 있는 지적**만 옮긴다.
1회성 오타, 특정 PR 맥락에서만 성립하는 지적, 칭찬과 단순 확인은 결과 보고에만 남긴다.

넣을 곳, 규칙 문장, 반복 함정 목록 처리는 [planning 의 rule-placement.md](../../planning/references/rule-placement.md) 를 따른다.
모노레포면 지적이 달린 파일이 속한 하위 프로젝트의 것을 쓴다.

ADR 급 결정은 구조화 질문 도구가 있으면 그것으로 사용자에게 확인받는다.

규칙 커밋은 같은 fix PR 에 커밋 하나로 더한다. fix 커밋과 섞지 않는다. 한 번 호출하면 PR 하나다.

## 결과 보고

```
## 완료: PR #<N>

🔀 Conflict 해결 (<건수>)
  - <파일>: <결정 요약>
✅ 적용된 수정 (<건수>)
  - <파일>: <무엇을 수정했는지>
📋 이슈로 등록 (<건수>)
  - #<번호>: <범위가 커서 이슈로 추적>
💬 회신 완료 (<건수>, 스레드 <건수> / 인라인 <건수>)
🧵 스레드 resolve (<건수>)
⏭️ 건너뛴 항목 (<이유>)
📚 저장소 규칙 반영 (<건수>와 넣은 위치, 또는 「없음」)

커밋 (<건수>)
  - <해시> <메시지>
```

**커밋을 목록으로 낸다.** 지적별로 나뉘어 있어 하나가 아니다.
「커밋과 push」 단계가 만든 대응 표의 해시를 읽어 채운다.
규칙 커밋은 이 목록에 함께 적고, base 동기화 커밋은 fix 가 아니므로 「Conflict 해결」 절에서 다룬다.
