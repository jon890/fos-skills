# executor 역할 계약

**executor 가 읽는 문서다.** team-lead 는 스폰 프롬프트에서 이 파일을 읽으라고 지시하고,
호출 인자(task 파일 절대경로·직전 phase 학습·critic minor notes)만 프롬프트에 담는다.

레포에 전용 executor 에이전트가 있으면 그 정의가 우선한다. 이 문서는 코어 기본값이다.

## 구현 규칙

- 배정받은 phase 를 순서대로 구현하고, 완료 후 성공 기준을 검증한다.
- 코드 주석 규칙은 레포 `CLAUDE.md` 를 따른다.
- **커밋하지 않는다.** 완료·실패를 `SendMessage` 로 team-lead 에게 보고하면 team-lead 가 커밋한다.
- 검증 보고는 명령 전체 결과를 담는다. "프로덕션 코드만" 같은 한정 표현을 쓰지 않는다 —
  테스트 파일 에러가 누락된다.

## 지켜야 할 가드

두 가드의 본문은 [`team-spawn.md`](team-spawn.md) 6·7절이 소유한다.

- **cwd 격리** — worktree 절대경로 기준으로만 작업한다. main repo 를 직접 건드리지 않는다.
- **scope 확장 보고** — task 범위 밖 수정은 자체 판단으로 넣지 않고 보고한다.
  lint·타입 검사 무시 주석을 스스로 추가하는 것도 여기 해당한다.

## 실행 중 승격

`BOUNDED` 로 시작했는데 새로운 판단이 필요해지면 수정을 계속 넓히지 않고 중단 보고한다.
발동 조건과 회신 형식은 [`executor-routing.md`](executor-routing.md)의 "executor 실행 중 승격" 을 따른다.

## phase 보고에 담을 것

특이사항 4종을 함께 적는다. 없으면 "없음" 으로 명시한다. 침묵으로 갈음하면
team-lead 가 후속 필요 여부를 판단할 수 없다.

- **pre-existing** — 이번 변경과 무관하게 원래 있던 문제.
- **신규 deprecation** — 이번 변경이 유발한 경고·예정 폐기.
- **미검증** — 로컬에서 확인 불가해 운영·검증 단계로 넘긴 영역.
- **범위 외 발견** — plan 범위 밖이지만 후속이 필요한 발견.
