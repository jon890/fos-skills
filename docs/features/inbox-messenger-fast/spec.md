# inbox: 메신저 멘션과 업무 피드를 1분 주기로 받아 board 에 빨리 보인다

확인: 2026-11-24

## 목표

누가 두레이 메신저 방에서 사용자를 멘션하면 board 에 평균 약 1분, 최악 2-3분 안에 보인다.
업무 피드(업무 댓글 멘션, 새 업무)도 받기 한 번을 수 초로 줄인 뒤 1분 주기로 받는다.

지금은 메신저 멘션이 board 에 보이기까지 평균 약 3-4분, 최악 약 7-8분이다. 지연의 대부분은 업무 피드 받기(`dooray stream list`, 약 35초, 약 27페이지)와 5분 받기 주기([work-inbox](../work-inbox/spec.md) D2, D15)에서 온다. 메신저 조회는 0.5초짜리 요청 하나와 바뀐 방 수만큼이다.
근거: fosbot 세션의 검토 보고서(2026-11-24, 요청 R18). 웹 메신저 WebSocket 은 웹 세션 8시간 제한, 사용자 브라우저 메신저 연결 충돌 위험, 비공개 프로토콜, 사내 정책 미확인으로 보류했다.

## 범위

이번 범위:

- dooray-cli: `stream list --since` 가 시각 없는 원소를 경계 페이지에서 버리지 않게 해, 받기 한 번이 1-2페이지에서 멈추게 한다.
- inbox: 업무 받기를 지난 커서 기준으로 한다. 커서가 없을 때만 지금처럼 15일 전부터 받는다.
- inbox: 메신저 받기와 업무 받기를 출처별 주기(둘 다 기본 1분)로 따로 돌린다. 캐시 나이, 커서, 잠금을 출처별로 본다. 업무 피드는 업무 커서(REQ2)로 이어 받을 수 있을 때만 1분이고, 커서가 없거나 전체 받기가 필요하면 5분이다.
- 사전 조사: 두레이 웹의 실시간 신호(Dooray! News 연결)를 업무 피드에 쓸 수 있는지 읽기 전용으로 실측한다. 구현은 조사 결과를 보고 따로 정한다.

범위 밖:

- 웹 메신저 WebSocket 연결.
- board 의 새 메신저 멘션 toast. 써 보고 필요하면 따로 정한다.
- board 가 조회하는 조건(창이 보이고 마지막 입력 뒤 10분 안). 그대로 둔다.
- 실시간 신호(WebSocket) 연결의 구현. 사전 조사만 한다.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 업무 피드 받기가 경계에서 멈춘다 | `dooray stream list --since <시각>` 이 since 를 넘긴 첫 페이지까지만 읽고 멈춘다. 시각 없는 원소도 그 페이지까지는 남긴다. 지금보다 페이지 수가 줄고 같은 구간의 원소를 빠뜨리지 않는다 |
| REQ2 | 업무 받기가 지난 커서부터 받는다 | inbox 의 업무 받기가 지난 받기의 커서를 since 로 넘긴다. 커서가 없거나 읽지 못하면 지금처럼 15일 전부터 받는다. dooray 가 아닌 adapter 는 지금처럼 받는다 |
| REQ3 | 출처별 주기로 따로 받는다 | board 가 1분마다 부를 때 출처마다 캐시가 그 출처 주기보다 오래됐으면 그 출처 받기만 따로 띄운다. 메신저는 기본 1분이다. 업무 피드는 업무 커서(REQ2)가 동작하면(`skills/inbox/scripts/inbox.ts` 의 `canResumeTask`) 기본 1분, 아니면 5분이다. 한 출처 받기가 도는 중이어도 다른 출처 받기는 막히지 않는다 |
| REQ4 | board 는 받기를 기다리지 않는다 | `inbox.ts board` 는 지금처럼 받기를 따로 띄우고 바로 끝난다. 새 멘션은 다음 board 호출에 보인다 |
| REQ5 | 주기를 바꿀 수 있다 | 출처별 주기는 inbox 설정 값으로 바꾼다. 값이 없으면 REQ3 의 기본값이다 |
| REQ6 | 실패는 지금처럼 알린다 | 메신저 받기나 업무 받기가 실패하면 지금의 출처별 오류 표시와 재시도 규칙을 따른다. 한 출처의 실패가 다른 출처 받기를 막지 않는다 |
| REQ7 | 목표 지연을 측정한다 | 실제 장비에서 메신저 멘션과 업무 댓글 멘션을 보내고 board 에 보이기까지 걸린 시간을 여러 번 재어 평균과 최악을 검증 결과에 남긴다 |
| REQ8 | 실시간 신호를 사전 조사한다 | 두레이 웹 메인 앱의 실시간 연결(Dooray! News, SharedWorker `@dooray/websocket`)의 주소와 인증 방식, 업무 댓글 멘션이 `stream` 신호로 오는지, 사용자 브라우저 연결에 주는 영향을 읽기 전용으로 확인해 보고서로 남긴다. 사용자 세션 연결을 끊을 수 있는 실험은 하지 않는다 |
