# build-with-teams

기능 계획의 구현과 개발 테스트를 executor 에게 맡기고 결과를 모은다. 독립 검증과 머지 절차는 다음 단계로 분리한다.

## 이럴 때 쓴다

- 스펙과 연결된 plan 을 구현할 때
- 중단한 구현을 이어 갈 때

## 사용 예시

> “plan12-run-cancel 을 구현해 줘.”
> phase 를 구현하고 개발 검증을 실행한 뒤 작업 공간과 결과를 verify 에 넘긴다.

## 받는 것

- phase 별 구현 커밋
- 개발 검증 명령과 결과
- verify 에 넘길 스펙·plan·작업 공간·남은 검증

기존 계획은 호환 절차의 리뷰·PR 흐름을 유지한다.

## 함께 쓰는 스킬

- `planning`: 구현 작업을 만든다
- `verify`: 독립 검증을 맡는다
- `orch`: 다음 단계와 PR·머지·정리를 조율한다
