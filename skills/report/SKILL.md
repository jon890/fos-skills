# report

**목표: 넘겨받은 내용이 결론이 첫 화면에 보이는 HTML 보고서 한 파일이 되어, 검사를 통과한 채 기본 브라우저에 떠 있다.**

**이 문서의 `scripts/`, `references/`, `assets/` 는 이 스킬 번들 기준 상대경로다.**
하네스가 알려 주는 스킬 base 디렉터리를 `$SKILL_DIR` 로 두고 붙여 쓴다.

- **넘겨받은 내용만 쓴다.** 웹 검색이나 새 조사를 하지 않는다. 빈 곳은 채우지 않고 「확인하지 못한 것」 에 남긴다. 스킬이 하는 일이 단순해야 매번 같은 결과가 나온다.
- **원문을 바꾸지 않는다.** 줄이는 것은 본문뿐이고, 사실, 수치, 날짜, 출처, 「추정」 표시는 그대로 옮긴다.
- 청중 앞에서 넘기며 말하는 발표는 `presentation`, 외부에 게시할 글은 `content-preview`, 혼자 읽는 설명과 보고서는 `report` 가 맡는다.

## 워크플로우 개요

| 단계 | 이름 | 통과 조건 | reference |
| --- | --- | --- | --- |
| 1 | 재료 모으기 | 보고서에 넣을 원문(대화, 파일, 조사 결과)의 범위가 정해졌다 | |
| 2 | 구성 고르기 | 세 구성 가운데 하나를 골랐고 고른 이유가 한 줄로 있다 | [`layouts.md`](references/layouts.md) |
| 3 | 틀에 채우기 | `$OUT` 에 틀을 복사해 내용을 채웠다 | [`template.html`](assets/template.html) |
| 4 | 검사 | `check-report.ts "$OUT"` 와 `--korean` 이 종료 코드 0 이다 | |
| 5 | 띄우고 알리기 | `open` 을 불렀고 응답에 경로, 구성, 검사 결과가 있다 | |

4단계에서 구조 검사를 끝내 통과하지 못하면 5단계로 가지 않고 실패 내용을 알린다.

## 1. 재료 모으기

보고서에 넣을 원문을 정한다. 사용자가 가리킨 파일, 이번 대화의 조사 결과나 설명, 코드와 문서가 원문이다.
가리킨 것이 없으면 이번 대화에서 바로 앞에 나온 설명이나 조사 결과를 원문으로 본다.

원문에 없는 사실이 필요해 보여도 찾아 넣지 않는다. 필요한 조사는 이 스킬 밖에서 먼저 끝나야 한다.

## 2. 구성 고르기

[`references/layouts.md`](references/layouts.md) 를 읽고 조사 보고서, 개념 설명, 비교·결정 자료 가운데 하나를 고른다.
고른 구성과 이유를 5단계 응답에 한 줄로 쓴다.

## 3. 틀에 채우기

파일 자리를 정한다. git 저장소 안이면 `<저장소>/.omc/previews/`, 밖이면 세션 임시 폴더다.
`$SLUG` 는 주제를 나타내는 영문 소문자, 숫자와 `-` 로 된 이름이다(예: `cache-ttl-policy`).
`$REPORT_TMP` 는 하네스가 시스템 프롬프트로 알려 준 세션 임시 폴더(scratchpad)다. 알려 준 것이 없으면 비워 둔다.

```bash
SLUG="cache-ttl-policy"
REPORT_TMP=""
if ROOT=$(git rev-parse --show-toplevel 2>/dev/null); then DIR="$ROOT/.omc/previews"; else DIR="${REPORT_TMP:-$TMPDIR}"; fi
mkdir -p "$DIR" && OUT="$DIR/$SLUG.html" && echo "$OUT"
```

**같은 주제를 다시 만들면 같은 슬러그로 덮어쓴다.** 브라우저를 새로 고치면 바로 보이고 파일이 쌓이지 않는다.

`assets/template.html` 을 `$OUT` 으로 복사하고 예시 내용을 원문으로 바꾼다.

```bash
cp "$SKILL_DIR/assets/template.html" "$OUT"
```

- `<style>` 과 `<script>` 는 고치지 않는다. 모든 보고서가 같은 모양이어야 읽는 사람이 매번 형식을 새로 익히지 않는다.
- 부품 앞의 `<!-- 부품: ... -->` 주석이 쓰는 법을 알려 준다. 고른 구성에 없는 부품은 지운다.
- 단락 길이, 표, 접는 절, 출처 표기는 `references/layouts.md` 의 「모든 구성에 공통인 규칙」 이 소유한다. 출처 표의 행은 `<tr id="src-표시">` 다.
- 밖의 script, CSS, 글꼴, 이미지를 불러오지 않는다. 이미지가 꼭 필요하면 `data:` 로 넣는다. 본문의 `https://` 링크는 괜찮다.
- `<title>`, 머리의 날짜와 독자, 목차의 절 이름, footer 의 원본을 원문에 맞게 바꾼다.

## 4. 검사

구조 검사(태그 짝, 각주와 출처의 짝, 외부 자원, 파일 이름)와 표기 검사(korean-check 의 금지어)를 돈다.

```bash
node "$SKILL_DIR/scripts/check-report.ts" "$OUT"
node "$SKILL_DIR/scripts/check-report.ts" --korean "$OUT"
```

**구조 검사가 실패하면 출력의 줄과 종류를 보고 고쳐 다시 검사한다. 고쳐 다시 검사하는 것은 두 번까지다.**
그래도 실패하면 깨진 보고서를 띄우지 않는다. 5단계를 건너뛰고 응답에 경로와 남은 위반을 그대로 적는다.

`--korean` 이 종료 코드 1 이면 걸린 낱말을 korean-check 매핑 표의 권장 표현으로 고치고 다시 돈다. 줄 번호는 `--text` 출력의 줄이다.
종료 코드 2 는 korean-check 를 찾지 못한 경우다. 그 스킬이 이 세션에 있으면 base 디렉터리를 `KOREAN_CHECK` 로 주고 다시 돈다.
그래도 없으면 띄우기는 하고 응답에 「표기 검사를 돌리지 못했다」 고 적는다.

검사기가 잡지 못하는 의미 점검(어색한 문장, 빠진 조사)은 korean-check 스킬의 지침대로 본다.

## 5. 띄우고 알리기

```bash
open "$OUT"
```

`open` 이 실패하면(원격 셸, 화면 없음) 다시 시도하지 않고 경로만 알린다.

응답에는 아래 세 줄을 쓴다.

```text
보고서: /절대/경로/cache-ttl-policy.html
구성: 비교·결정 자료(선택지 셋을 놓고 고르는 내용이라서)
검사: 구조 통과, 표기 통과
```
