# 보드에 이 세션의 예약 작업 목록을 보인다

확인: 2026-11-20

## 목표

코디네이터 세션에 걸린 예약 작업(`CronCreate` 로 만든 세션 전용 예약)이 무엇인지, 보드의 「예약」 구역에서 한눈에 본다.
코디네이터가 따로 적지 않아도, 예약을 만들고 지우면 목록이 저절로 맞는다.

지금은 예약 목록을 보려면 세션에 `CronList` 를 물어야 하고, 보드에는 예약을 올릴 방법이 없다(ai-analysis 코디네이터의 요청 R3, 사용자 요청 2026-11-20).

## 범위

이번 범위:

- 보드가 이 세션의 `CronCreate`, `CronDelete` 도구 호출을 지켜보고 예약 목록을 맞춘다.
- 보드에 「예약」 구역을 두고 예약마다 한 줄을 보인다.

범위 밖:

- 다른 세션의 예약, 클라우드 예약(`/schedule` 로 만든 원격 루틴).
- 보드에서 예약을 만들거나 지우는 버튼.
- 세션을 다시 시작한 뒤 예약 되살리기. 세션 전용 예약은 세션과 함께 끝난다.

## 도메인 규칙 변경

도메인 규칙 변경 없음: 보드 화면에 구역 하나를 더한다.

## 기술 설계

- `register.js` 는 `tool.call` 에서 `next(e)` 를 먼저 실행하고 성공 결과만 읽는다. 도구 입력이나 반환값은 바꾸지 않는다. 다음 도구 이벤트에서는 실행이 끝난 예약도 상태에서 정리한다.
- 세션 상태 `$.state` 의 예약 목록에는 ID, cron 식, 프롬프트, 다음 실행 시각과 오프셋, 만료 시각을 둔다. `board.json` 은 건드리지 않는다.
- `schedules.js` 는 예약 결과의 모양을 확인하고 다음 실행·만료·표시 한 줄을 계산한다. 반복 예약은 생성 후 7일에 만료한다. 도구가 준 `nextFireAt` 의 오프셋은 이후 실행 시각에도 유지한다.
- `ui.render` 는 상태를 쓰지 않고 현재 시각에 보일 예약만 「예약」 구역에 그린다. 반복 예약의 다음 실행은 5칸 cron 식을 로컬 시간으로 계산하며, 맞지 않는 월·일·시는 해당 단위로 건너뛴다.

## 이 PR의 구현·검증 계획

1. 예약 만들기·지우기 도구 호출을 관찰하고 세션 상태를 갱신한다.
2. 다음 실행과 만료를 계산해 보드에 표시한다.
3. 성공·실패·다른 입력 모양·종료 시각을 테스트하고 보드 안내와 변경 이력 조각을 고친다.

인수 검증은 `schedules.spec.ts` 로 생성·삭제·표시 내용·종료 시각·도구 결과 보존을, `pane.test.ts` 로 빈 목록에서 구역을 숨기는 REQ4를 확인한다. 저장소의 전체 테스트와 플러그인 테스트도 실행한다.
