# 문서 소유권과 변경

## 양식 사용

문서를 쓰는 스킬이 양식 한 벌을 소유한다. 작성 전에 해당 양식을 읽고 실제 기능의 값으로 바꾼다.
양식의 필수 항목은 유지하고 조건부 항목은 필요할 때만 쓴다. 예시의 결정·날짜·명령은 합의나 실행 증거가 아니다.
기존 저장소의 PRD·flow·ADR 양식이 있으면 우선한다. 기존 문서를 새 양식으로 일괄 재작성하지 않는다.
필수 정보와 연결은 검사기, 의미·결정·실행 증거는 독립 검토가 확인한다. 제목만 채운 문서는 완료가 아니다.

| 문서 | 양식 원본 | 갱신할 때 |
| --- | --- | --- |
| 기능 스펙 | [spec](../templates/spec.md) | 기능 요구사항·인수 조건이 바뀜 |
| 기술 설계 | [technical-design](../../technical-design/templates/design.md) | 모듈 책임·상호작용·검증 전략이 바뀜 |
| 실행 계획 | [index](../../plan/templates/index.json), [phase](../../plan/templates/phase.md) | PR 의 범위·작업·개발 검증이 바뀜 |
| 인수 검증 계획 | [plan](../../plan/templates/verification-plan.md) | 준비 조건·실행 절차·기대값이 바뀜 |
| 인수 검증 결과 | [verify](../../verify/templates/verification-result.md) | 같은 커밋의 실제 실행 결과를 기록 |
| 문서 대조·공통 후보 | [docs-consolidate](../../docs-consolidate/templates/document-review.md) | 기능 검증 뒤 정합성과 후보를 기록 |
| PRD | [spec 기본 양식](../templates/product-requirements.md) | 제품 목적·대상·주요 시나리오·범위가 바뀜 |
| flow | [기술 설계 기본 양식](../../technical-design/templates/system-flow.md) | 시스템 공통 상호작용이 바뀜 |
| ADR | [기술 설계 기본 양식](../../technical-design/templates/adr.md) | 장기 결정의 맥락·대안·선택 이유를 기록·대체 |

## 사실은 한곳에

PRD 는 제품 목적·범위를, 기능 spec 은 상세 요구사항을 소유한다. PRD 에 모든 요구사항과 진행률을 복제하지 않는다.
flow 는 시스템 공통 흐름을, 기능 design 은 상세 상호작용을 소유한다. 공통 문서에는 필요한 상세 링크를 둔다.
정확한 API/DB 스키마는 원본 코드·스키마가 소유한다. 다른 문서는 동작·이유와 원본 링크를 남긴다.
ADR 은 현재 구조의 전체 목록이 아니다. 결정을 뒤집으면 새 ADR 에 대체 관계를 기록하고 현재 사실의 책임 문서를 맞춘다.
기존 ADR 의 당시 맥락을 새 결정으로 덮어쓰지 않는다. 오타·깨진 링크 수정과 결정 변경을 구분한다.

## 변경 순서와 충돌

technical-design 에서 이번 기능이 바꾸는 책임 문서만 식별한다. 영향이 없는 전역 문서는 수정하지 않는다.
이번 기능이 공유 권한·상태·호출 의미를 바꾸면 구현 전에 그 결정을 해결하고 해당 구현 PR 에 책임 문서를 맞춘다.
docs-consolidate 는 검증한 구현과 문서를 대조하고, 의미 변경은 spec/technical-design/implementation 으로 반환한다.
현재 사실의 필수 수정은 후속 공통화까지 미루지 않는다. 반복 표현 정리·관련 없는 낡은 문서는 후속 후보로 남긴다.

orch 는 동시에 진행할 계획의 변경 파일과 책임 문서를 대조한다. 같은 공유 문서를 바꾸면 담당을 한 worker 로 모으거나 순차 실행한다.
공유 계약을 먼저 바꿔야 하면 선행 PR 을 머지한 뒤 소비 기능의 계획을 구체화한다. 파일 잠금 시스템·중앙 진행표는 추가하지 않는다.
각 worker 는 자기 기능·계획 문서를 소유하고, 같은 전역 파일을 모두 갱신하게 하지 않는다.

## 계획과 증거의 수명

[계획 수명 규칙](../../plan/references/plan-lifecycle.md)이 보존·삭제와 증거 인계를 소유한다.
문서 점검은 이 규칙으로 완료 계획을 분류한다. 진행 중인 계획이나 유일한 결정·증거를 자동 삭제하지 않는다.
