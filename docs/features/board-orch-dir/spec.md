# 보드 파일의 기본 위치를 저장소의 .orch/board.json 으로 옮긴다

확인: 2026-11-26

## 목표

보드 파일을 orch 가 쓰는 `.orch/` 아래에 둔다. 지금 기본 위치 `.omc/` 는 다른 플러그인(OMC)의 폴더라, orch 의 보드가 거기 있는 것이 어색하다.
근거: 요청 R35(AiSdtSkill, 사용자 결정 2026-11-26).

## 범위

이번 범위:

- orch 의 보드 파일 규칙(`lib/board-file.ts`, `modules/work-board/path.ts`)과 work-board 창(`extensions/work-board/hooks/register.js` 의 `BOARD_PATHS`)의 기본 위치.
- git 저장소 밖 세션의 홈 보드 위치.
- 옛 위치의 보드와, 설정에 옛 위치를 직접 적은 저장소를 옮기는 명령.

범위 밖:

- `finish.board` 로 다른 경로를 고르는 길(그대로 둔다).
- 다른 저장소에서 옮기는 명령을 실제로 돌리는 일. 각 저장소 메인 세션에 요청으로 보낸다.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 기본 위치 | `finish.board` 가 없으면 orch 명령, 루프, 보드 창 모두 git 루트의 `.orch/board.json` 을 쓴다. `orch board` 의 board-file 출력이 새 경로를 낸다 |
| REQ2 | 옮기기 전 읽기 | 새 파일이 없고 옛 파일(`.omc/board.json`, 있으면 `.omc/handoffs/board.json`)이 있으면 옛 파일을 그대로 읽고 쓴다. 보드가 비어 보이지 않는다. 읽는 도중 자동으로 옮기지 않는다 |
| REQ3 | 알림 | 옛 위치를 쓰는 동안 `orch doctor` 가 옮기라고 알리고 옮기는 명령을 보여 준다 |
| REQ4 | 옮기는 명령 | 기존 `.orch` 이전 명령(`migrate-orch-dir`)이 보드도 옮긴다. 미리보기(바꿀 것만 출력)와 적용을 나눈다. 새 파일이 이미 있으면 덮지 않고 충돌로 알린다 |
| REQ5 | 직접 적은 설정 | `finish.board` 가 어느 저장소의 `.omc/board.json`(또는 `.omc/handoffs/board.json`)을 가리키면, 옮기는 명령이 그 파일을 그 저장소의 `.orch/board.json` 으로 옮기고 같은 파일을 가리키는 설정을 함께 고친다. 같은 보드를 쓰는 묶음은 설정을 한 번에 고친다 |
| REQ6 | 홈 보드 | git 저장소 밖 세션의 보드는 `~/.orch/board.json` 이다. 옛 `~/.omc/board.json` 은 REQ2, REQ4 와 같이 다룬다 |

도메인 규칙 변경 없음: 보드 항목과 단계의 뜻은 그대로이고 파일 위치만 바뀐다.
