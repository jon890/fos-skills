# 알림함 리액션 기술 설계

## 요구사항 연결

| ID | 해결 방법 |
| --- | --- |
| REQ1 | 두레이 adapter 가 업무 id 와 댓글 id 로 호출한다 |
| REQ2 | 두레이 adapter 는 댓글 멘션인지, 공통 명령은 현재 「새 알림」인지 확인한다 |
| REQ3 | 공통 명령이 미리보기와 확인을 처리한다 |
| REQ4 | 성공하면 기존 답변과 같은 방식으로 캐시에 「답함」을 쓴다 |
| REQ5 | 사람 단위 설정의 `reactionEmoji` 를 읽고, 명령에 `--emoji` 가 있으면 그 값을 우선한다 |
| REQ6 | inbox 스킬이 알림 내용과 맥락을 읽어 대화에서 항목별 권장 동작과 이유를 보여 준다 |
| REQ7 | 두레이 adapter 가 세션 오류에 넘김과 세션 갱신 안내를 붙인다 |
| REQ8 | 두레이 adapter 가 CLI 버전을 확인한다 |
| REQ9 | 후속 PR에서 dooray-cli의 메신저 명령을 설계한다 |
| REQ10 | 두레이 adapter 가 메신저 멘션에도 같은 리액션 동작을 하고, 0.36.0 보다 낮으면 미리보기부터 거절한다 |

## 책임과 경계

[`Adapter`](../../../skills/inbox/scripts/lib/model.ts) 에 선택 동작 `react(item, emoji, { confirmed })` 를 더한다. adapter 는 지원하는 항목인지 확인하고, 확인받은 호출만 실행한다. 공통 CLI 는 상태 확인, 미리보기, 성공 상태 저장을 맡는다.

## 인터페이스와 데이터

`react <id> [--emoji <이름>] [--yes]` 를 추가한다. [사람 단위 설정](../../../skills/inbox/references/config.md)의 `reactionEmoji` 는 문자열이며 기본값은 `+1` 이다. 이모지 이름의 유효성은 dooray-cli 가 판단한다. 답함 표시는 기존 보드의 상태와 새 알림 수 계산을 따른다.

## 실패와 일관성

업무 댓글은 등록 직전에 `dooray --version` 이 0.35.0 이상인지 확인한다. 0.35.0 의 사전 배포판이거나 버전을 확인할 수 없으면 거절한다. 실제 등록은 `dooray post comment react --id <업무 id> --comment-id <댓글 id> --emoji=<이름>` 으로 부른다.

메신저 멘션은 미리보기에서도 0.36.0 이상인지 먼저 확인한다. 그보다 낮으면 리액션 명령 자체가 없으므로 확인을 받기 전에 거절하고 넘김을 권한다. 실제 등록은 `dooray messenger react <대화방 id> <메시지 id> --emoji=<이름>` 으로 부른다. 종료 코드 3 은 업무 댓글과 같은 세션 오류로 다룬다.

확인된 리액션끼리는 항목별 잠금을 써서 중복 실행을 막는다. 잠금을 잡은 뒤 현재 상태를 읽고, CLI 성공 뒤 기존 캐시 쓰기 잠금으로 답함을 저장한다. 받기가 이미 저장한 답함을 보존하는 규칙도 그대로 적용된다. CLI 실패는 상태를 바꾸지 않는다. 원격 등록 이후 캐시 쓰기만 실패하면 재실행에서 원격 중복 리액션 처리 결과를 따른다.

## 검증 전략

가짜 Runner 를 붙인 inbox 명령으로 업무 댓글과 메신저 멘션 각각의 미리보기, 상태 변경, 버전과 세션 오류, CLI 오류 전달을 검증한다. 스킬의 권장 기준과 처리 흐름은 스펙과 대조한다. 실제 두레이에는 리액션을 등록하지 않는다.
